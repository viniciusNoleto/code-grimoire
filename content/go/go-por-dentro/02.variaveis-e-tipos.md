Go é estaticamente tipado: toda variável tem um tipo fixo, conhecido na compilação. Mas quase nunca você escreve o tipo, porque o compilador deduz pelo valor.

### As formas de declarar

```go
var count int            // tipo explícito, começa com o valor zero (0)
var name = "Ana"         // tipo deduzido: string
var x, y int = 1, 2      // várias de uma vez

city := "Manaus"         // declaração curta: só dentro de funções
a, b := 10, "dez"        // várias, de tipos diferentes

var (                    // bloco: comum no topo do arquivo
	maxRetries = 3
	debug      bool
)
```

| Forma | Onde | Quando aparece |
| --- | --- | --- |
| `x := valor` | Só dentro de função | A forma mais comum de longe. |
| `var x T` | Qualquer lugar | Quando você quer o valor zero, ou em nível de pacote. |
| `var x T = valor` | Qualquer lugar | Quando o tipo deduzido não é o desejado (`var ratio float64 = 1`). |

`:=` **declara**; `=` **atribui** a uma variável que já existe. Em `a, err := f()`, basta uma das variáveis da esquerda ser nova; as outras são reaproveitadas. Por isso `err` aparece com `:=` várias vezes na mesma função sem erro.

::note{type="pitfall" title="Sombreamento"}
Dentro de um bloco (`if`, `for`), `:=` cria uma variável **nova** com o mesmo nome, que esconde a de fora. Bug clássico:
```go
var user *User
if cond {
	user, err := load() // user aqui é OUTRA variável; a de fora continua nil
	_ = err
}
```
Use `=` quando a intenção é atribuir à variável de fora.
::

### O valor zero

Em Go **não existe variável não inicializada**. Toda variável declarada sem valor recebe o valor zero do seu tipo:

| Tipo | Valor zero |
| --- | --- |
| números (`int`, `float64`…) | `0` |
| `bool` | `false` |
| `string` | `""` (string vazia, nunca `nil`) |
| ponteiros, slices, maps, channels, funções, interfaces | `nil` |
| structs | cada campo com seu valor zero |

Bons tipos em Go são feitos para que o valor zero já seja útil: um `sync.Mutex` zerado é um mutex destravado, um `bytes.Buffer` zerado é um buffer vazio pronto para uso. Você vai ver muito `var mu sync.Mutex` sem nenhuma inicialização.

### Os tipos básicos

| Tipo | Observação |
| --- | --- |
| `int`, `uint` | Inteiro do tamanho da máquina (64 bits nos servidores de hoje). Use `int` por padrão. |
| `int8` `int16` `int32` `int64`, `uint8`…`uint64` | Tamanho fixo, para protocolos, arquivos binários, bancos. |
| `float64`, `float32` | Ponto flutuante. Use `float64` por padrão. |
| `bool` | `true` / `false`. Não existe "truthy": `if n` com `n int` não compila. |
| `string` | Sequência **imutável** de bytes, normalmente UTF-8. |
| `byte` | Apelido de `uint8`: um byte. |
| `rune` | Apelido de `int32`: um caractere Unicode (code point). |
| `complex128` | Números complexos. Raro fora de computação científica. |

### Conversões são sempre explícitas

Go não converte tipos sozinho, nem entre `int` e `int64`. A conversão tem a forma `Tipo(valor)`:

```go
var i int = 42
var f float64 = float64(i) * 1.5
var u uint8 = uint8(i)

total := i + int(f)        // int + float64 não compila sem converter

// string ↔ número NÃO é conversão: use strconv
s := strconv.Itoa(42)               // "42"
n, err := strconv.Atoi("42")        // 42, nil
string(65)                          // "A" (o caractere 65!), não "65": o go vet avisa
```

### string, byte e rune

Uma `string` é uma fatia de bytes. `len(s)` conta **bytes**, não letras, e `s[i]` devolve um **byte**. Para percorrer caracteres, use `range`, que decodifica UTF-8 e entrega runes:

```go
s := "pão"
fmt.Println(len(s))   // 4: o "ã" ocupa 2 bytes em UTF-8
fmt.Println(s[1])     // 195: um byte, não uma letra

for i, r := range s { // i = posição em bytes, r = rune
	fmt.Println(i, string(r))
}
// 0 p
// 1 ã
// 3 o

b := []byte(s)        // cópia mutável dos bytes
r := []rune(s)        // cópia como caracteres: len(r) == 3
```

Literais: `"texto com \n escapes"`, `` `raw string, multilinha, sem escapes` `` (crases, muito usada em SQL, regex e JSON) e `'a'` (aspas simples: uma **rune**, não uma string).

### Constantes e iota

```go
const Pi = 3.14159
const (
	StatusOK       = 200
	StatusNotFound = 404
)

type Weekday int

const (
	Sunday Weekday = iota // 0
	Monday                // 1: repete a expressão anterior com iota+1
	Tuesday               // 2
)

const (
	_  = iota             // ignora o 0
	KB = 1 << (10 * iota) // 1 << 10 = 1024
	MB                    // 1 << 20
	GB                    // 1 << 30
)
```

`iota` é um contador que vale 0 na primeira linha de cada bloco `const` e sobe 1 a cada linha. É o jeito Go de fazer enums: um tipo próprio (`Weekday`) mais constantes com `iota`.

Constantes sem tipo explícito (`const Pi = 3.14159`) são "constantes não tipadas": têm precisão arbitrária e se adaptam ao tipo de onde são usadas. Por isso `time.Sleep(2 * time.Second)` funciona sem conversão.

### O identificador vazio `_`

`_` é um lugar para jogar fora um valor. Aparece em três situações:

```go
_, err := fmt.Println("x")        // ignora um dos retornos
for _, v := range items { }       // ignora o índice
import _ "github.com/lib/pq"      // importa só pelo efeito colateral (registrar driver)
var _ io.Reader = (*File)(nil)    // garante em compilação que *File implementa io.Reader
```

### Tipos próprios

```go
type UserID int64        // tipo NOVO, baseado em int64
type Celsius float64

var id UserID = 10
var n int64 = id         // não compila: UserID e int64 são tipos diferentes
var n2 int64 = int64(id) // ok

type Alias = int64       // com "=": só outro nome para o MESMO tipo (raro)
```

Criar tipos como `UserID` impede misturar um ID com um número qualquer e permite pendurar métodos neles ([capítulo de structs](#structs-e-metodos)).
