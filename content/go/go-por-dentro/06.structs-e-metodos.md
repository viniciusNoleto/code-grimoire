Go não tem classes. O que faz esse papel é a combinação de **struct** (os dados), **métodos** (funções penduradas num tipo) e **interfaces** (o comportamento, próximo capítulo). Não há herança: há composição.

### Struct

```go
type User struct {
	ID        int64
	Name      string
	Email     string
	Age       int
	Active    bool
	CreatedAt time.Time
	tags      []string // minúscula: só visível dentro do pacote
}

u := User{Name: "Ana", Email: "ana@x.com"} // campos não citados ficam com valor zero
u.Active = true
fmt.Println(u.Name)

var empty User          // todos os campos zerados
pt := Point{1, 2}       // posicional: só em structs pequenas e estáveis

point := struct{ X, Y int }{1, 2} // struct anônima: comum em testes e JSON pontual
```

Atribuir uma struct a outra variável **copia** todos os campos. Structs se comparam com `==` se todos os campos forem comparáveis.

### Ponteiros: `&` e `*`

Um ponteiro guarda o endereço de uma variável. Go tem ponteiros, mas sem aritmética de ponteiros: são seguros.

| Símbolo | Onde | Significa |
| --- | --- | --- |
| `*T` | num tipo | "ponteiro para T": `var p *User` |
| `&x` | numa expressão | "o endereço de x": `p := &u` |
| `*p` | numa expressão | "o valor apontado por p": `(*p).Name` |

```go
func birthday(u *User) {  // recebe ponteiro: altera o original
	u.Age++               // Go desreferencia sozinho: não precisa de (*u).Age
}

ana := User{Name: "Ana"}
birthday(&ana)            // passa o endereço

p := &User{Name: "Bia"}   // forma mais comum: ponteiro para um literal
var none *User            // nil: acessar none.Name dá panic
```

`new(T)` aloca um `T` zerado e devolve `*T`. Desde o Go 1.26, `new` também aceita um valor, o que resolve o problema de criar ponteiro para um literal (útil em campos opcionais):

```go
n := new(int)            // *int apontando para 0
age := new(30)           // *int apontando para 30 (Go 1.26+)
cfg := Config{Timeout: new(5 * time.Second)}
```

::note{type="tip" title="Quando usar ponteiro"}
Use `*T` quando a função precisa alterar o valor, quando a struct é grande (evita copiar) ou quando "ausente" é um estado válido (`nil`). Para tipos pequenos e imutáveis (`time.Time`, coordenadas), passe por valor. Retornar `&local` de uma função é seguro: o compilador move a variável para o heap ("escape analysis"), não há ponteiro solto.
::

### Construtores: só funções

Não existe construtor na linguagem. A convenção é uma função `NewTipo` que devolve o valor pronto, quase sempre como ponteiro:

```go
func NewServer(addr string, timeout time.Duration) *Server {
	return &Server{
		addr:    addr,
		timeout: timeout,
		routes:  make(map[string]Handler),
	}
}

srv := NewServer(":8080", 5*time.Second)
```

Quando o valor zero já serve, nem há construtor: `var buf bytes.Buffer` e pronto.

### Métodos

Um método é uma função com um **receptor**, escrito entre `func` e o nome:

```go
type Rect struct{ W, H float64 }

func (r Rect) Area() float64 {   // receptor de VALOR: recebe uma cópia
	return r.W * r.H
}

func (r *Rect) Scale(f float64) { // receptor de PONTEIRO: altera o original
	r.W *= f
	r.H *= f
}

r := Rect{W: 2, H: 3}
r.Area()       // 6
r.Scale(2)     // Go converte para (&r).Scale(2) sozinho
```

| Receptor | Quando |
| --- | --- |
| `(r *T)` | O método altera o valor, a struct é grande, ou ela contém um `sync.Mutex`. É o caso mais comum. |
| `(r T)` | Tipos pequenos, imutáveis, ou tipos que já são referências (map, slice, func). |

Convenções que ajudam a ler: o receptor tem nome **curto**, uma ou duas letras derivadas do tipo (`s *Server`, `r Rect`, `u *User`), nunca `this` ou `self`. Se um método do tipo usa ponteiro, normalmente todos usam. Métodos podem ser definidos em qualquer tipo declarado no mesmo pacote, não só em structs:

```go
type Celsius float64
func (c Celsius) String() string { return fmt.Sprintf("%.1f°C", c) }
```

### Embedding: composição no lugar de herança

Colocar um tipo dentro de uma struct **sem nome de campo** promove os campos e métodos dele:

```go
type Timestamps struct {
	CreatedAt time.Time
	UpdatedAt time.Time
}

func (t *Timestamps) Touch() { t.UpdatedAt = time.Now() }

type Post struct {
	Timestamps          // embutido: sem nome de campo
	Title      string
}

p := Post{Title: "Olá"}
p.Touch()               // método promovido de Timestamps
fmt.Println(p.UpdatedAt) // campo promovido
p.Timestamps.CreatedAt  // o acesso completo também funciona
```

Não é herança: `Post` **não é** um `Timestamps` (não pode ser passado onde se espera `Timestamps`), ele **tem** um. O efeito prático é reaproveitar campos e métodos. Muito comum embutir `sync.Mutex` numa struct para ter `c.Lock()` e `c.Unlock()` direto nela.

### Tags de struct

O texto entre crases depois do tipo é uma **tag**: metadados que bibliotecas leem por reflexão.

```go
type Product struct {
	ID      int64   `json:"id"`
	Name    string  `json:"name" validate:"required"`
	Price   float64 `json:"price,omitempty"` // omite do JSON se for zero
	Secret  string  `json:"-"`               // nunca vai para o JSON
	OwnerID int64   `json:"owner_id" db:"owner_id"`
}
```

Para o código Go, a tag não muda nada; quem lê é o `encoding/json`, o driver de banco, o validador. Lembre: só campos **exportados** (maiúscula) são vistos por essas bibliotecas. Um campo `name` minúsculo nunca aparece no JSON, com ou sem tag.
