Desde o Go 1.18, funções e tipos podem receber **parâmetros de tipo**, escritos entre **colchetes**. A biblioteca padrão (`slices`, `maps`, `cmp`, `iter`, `errors.AsType`) já usa bastante; no código de aplicação eles aparecem menos, sobretudo em utilitários.

### Funções genéricas

```go
func Map[T, U any](items []T, f func(T) U) []U {
	out := make([]U, 0, len(items))
	for _, it := range items {
		out = append(out, f(it))
	}
	return out
}

names := Map(users, func(u User) string { return u.Name }) // T=User, U=string inferidos
lens := Map[string, int](names, func(s string) int { return len(s) }) // explícito
```

Leia `func Map[T, U any](items []T, ...)` como "Map, para quaisquer tipos T e U, recebe um slice de T…". **Colchetes logo depois do nome** são sempre parâmetros de tipo; colchetes em outros lugares são índices e slices. Na chamada, os tipos quase sempre são inferidos pelos argumentos.

### Restrições: o que T pode ser

A palavra depois do parâmetro (`any`, `comparable`…) é a **restrição**: uma interface que diz quais tipos são aceitos e, portanto, o que se pode fazer com T dentro da função.

| Restrição | Aceita | Permite |
| --- | --- | --- |
| `any` | qualquer tipo | atribuir, passar adiante, guardar |
| `comparable` | tipos comparáveis com `==` | `==`, `!=`, ser chave de map |
| `cmp.Ordered` | inteiros, floats, strings | `<`, `>`, `<=`, `>=` |
| interface com métodos | tipos com aqueles métodos | chamar os métodos |
| `~int \| ~float64` | união de tipos | os operadores que todos têm em comum (`+`, `*`…) |

```go
func Index[T comparable](s []T, v T) int {
	for i := range s {
		if s[i] == v {
			return i
		}
	}
	return -1
}

type Number interface {
	~int | ~int64 | ~float64   // união: um destes
}

func Sum[T Number](nums []T) T {
	var total T                // valor zero de T
	for _, n := range nums {
		total += n
	}
	return total
}

type Celsius float64
Sum([]Celsius{20, 22.5})       // aceito por causa do ~
```

O **til** `~float64` significa "float64 **ou qualquer tipo cujo tipo base seja float64**", como `Celsius`. Sem o til, só `float64` exato passaria. Interfaces com união (`|`) só podem ser usadas como restrição, nunca como tipo de variável.

### Tipos genéricos

```go
type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

var s Stack[int]           // tipos genéricos precisam do argumento explícito
s.Push(1)
cache := NewCache[string, *User]()
```

Os métodos de um tipo genérico repetem os parâmetros no receptor (`*Stack[T]`). Um método pode ainda declarar **parâmetros de tipo próprios** (`func (r *Rand) N[Int intType](n Int) Int`), mas esses métodos não servem para satisfazer interfaces :version[Go 1.27].

::note{type="tip" title="Quando é genérico de verdade"}
Se a função só chama métodos, uma interface comum resolve e é mais simples de ler. Generics servem quando o código é o mesmo para vários tipos e você quer manter o tipo concreto na saída: coleções, utilitários de slices e maps, caches, pools, resultados tipados.
::

### Iteradores: range sobre funções

Desde o Go 1.23, `for range` aceita uma **função** com uma das formas abaixo. É o jeito padrão de expor "algo que pode ser percorrido" sem montar um slice inteiro na memória.

```go
// pacote iter
type Seq[V any]     func(yield func(V) bool)
type Seq2[K, V any] func(yield func(K, V) bool)
```

O iterador chama `yield` para cada elemento. Se `yield` devolver `false`, o laço do lado de fora deu `break`, e o iterador precisa parar.

```go
func Countdown(n int) iter.Seq[int] {
	return func(yield func(int) bool) {
		for i := n; i > 0; i-- {
			if !yield(i) {       // o for de fora parou
				return
			}
		}
	}
}

for v := range Countdown(3) {    // 3 2 1
	fmt.Println(v)
}
```

Na biblioteca padrão, iteradores aparecem com nomes como `All`, `Keys`, `Values`, `Backward`, `Lines`, `SplitSeq`:

```go
for k, v := range maps.All(m) { }               // iter.Seq2[K, V]
keys := slices.Collect(maps.Keys(m))            // iterador → slice
sorted := slices.Sorted(maps.Keys(m))
for i, v := range slices.Backward(s) { }        // de trás para frente
for line := range strings.Lines(text) { }       // linha por linha
for part := range strings.SplitSeq(csv, ",") { } // Split sem alocar o slice
```

Ao ler código, uma função que devolve `iter.Seq[...]` ou `iter.Seq2[...]` é "algo para usar num `for range`". O `yield` dentro dela é o ponto em que cada elemento sai para o laço.
