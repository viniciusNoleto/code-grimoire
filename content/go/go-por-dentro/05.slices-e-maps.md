Go tem três coleções embutidas: o **array** (tamanho fixo, raro no dia a dia), o **slice** (a lista que você usa sempre) e o **map** (dicionário chave → valor). Entender o slice por dentro evita a maior parte das surpresas da linguagem.

### Array: tamanho faz parte do tipo

```go
var grid [3]int             // [0 0 0]
primes := [5]int{2, 3, 5, 7, 11}
auto := [...]string{"a", "b"} // o compilador conta: [2]string
```

`[3]int` e `[4]int` são tipos diferentes, e atribuir um array **copia todos os elementos**. Por isso arrays aparecem pouco: o que você usa é o slice, que é uma janela sobre um array.

### Slice: uma janela sobre um array

```go
names := []string{"Ana", "Bia"}    // literal: sem tamanho entre os colchetes
names = append(names, "Caio")       // append devolve o slice (talvez novo)

nums := make([]int, 3)              // [0 0 0]: len 3
buf := make([]int, 0, 100)          // vazio, mas com espaço para 100 (cap)

var empty []int                     // nil: len 0, e mesmo assim append funciona
fmt.Println(len(names), cap(names))
```

Por dentro, um slice é um cabeçalho com três campos: um **ponteiro** para um array, o **len** (quantos elementos estão visíveis) e o **cap** (quanto cabe até o fim do array). Copiar um slice copia só esse cabeçalho; os dois continuam apontando para o mesmo array.

| Campo do cabeçalho | Exemplo | Significado |
| --- | --- | --- |
| ponteiro | → array `[10 20 30 _ _]` | Onde os dados moram de verdade. |
| `len` | 3 | Quantos elementos o slice enxerga (`s[0]` a `s[2]`). |
| `cap` | 5 | Quanto cabe a partir do início do slice até o fim do array. `append` usa esse espaço sem realocar. |

### append e o porquê de `s = append(s, …)`

```go
s := make([]int, 0, 2)
s = append(s, 1)       // cabe: escreve no mesmo array
s = append(s, 2)       // cabe
s = append(s, 3)       // não cabe: aloca um array maior, copia, devolve o novo
s = append(s, 4, 5, 6) // vários de uma vez
s = append(s, other...) // concatena outro slice
```

Quando falta espaço, `append` cria um array novo (aproximadamente o dobro) e devolve um slice apontando para ele. Por isso o resultado **sempre** é atribuído de volta: `s = append(s, x)`. Se você souber o tamanho final, `make([]T, 0, n)` evita realocações.

### Fatiamento: `s[início:fim]`

```go
nums := []int{10, 20, 30, 40, 50}
nums[1:3]  // [20 30]: do índice 1 até o 3, sem incluir o 3
nums[:2]   // [10 20]
nums[3:]   // [40 50]
nums[:]    // tudo

part := nums[1:3]
part[0] = 99          // altera nums também! nums == [10 99 30 40 50]
```

::note{type="pitfall" title="Fatiar não copia"}
Um subslice compartilha o array do original: mexer num mexe no outro, e um `append` no subslice pode sobrescrever elementos do original que estavam depois dele. Quando precisar de independência, copie: `c := slices.Clone(part)` ou `copy(dst, src)`. A forma de três índices `nums[1:3:3]` limita o cap do subslice, forçando o próximo `append` a realocar.
::

### Slices de structs e de slices

```go
users := []User{
	{Name: "Ana", Age: 30},  // o tipo do elemento pode ser omitido no literal
	{Name: "Bia", Age: 25},
}

matrix := [][]int{
	{1, 2},
	{3, 4},
}
```

### Map

```go
ages := map[string]int{
	"ana": 30,
	"bia": 25, // vírgula final obrigatória quando o } fica na linha de baixo
}
ages["caio"] = 40   // inserir ou atualizar
delete(ages, "bia") // remover (não faz nada se não existir)
fmt.Println(len(ages))

counts := make(map[string]int)    // map vazio pronto para uso
var broken map[string]int         // nil: ler funciona, ESCREVER dá panic
```

Ler uma chave que não existe devolve o **valor zero**, sem erro. Isso deixa contadores triviais (`counts[word]++`), mas não distingue "não existe" de "existe com valor zero". Para isso existe o idioma **vírgula-ok**:

```go
age, ok := ages["dora"]   // ok == false se a chave não existe
if !ok {
	fmt.Println("não cadastrada")
}

if age, ok := ages["ana"]; ok { // forma compacta, muito comum
	fmt.Println(age)
}
```

| Fato sobre maps | Consequência |
| --- | --- |
| A ordem do `range` é **aleatória** de propósito | Para ordem estável, ordene as chaves: `slices.Sorted(maps.Keys(m))`. |
| A chave precisa ser comparável com `==` | `string`, números, structs simples, arrays servem; slices, maps e funções não. |
| Map não é seguro para escrita concorrente | Duas goroutines escrevendo derrubam o programa: proteja com `sync.Mutex`. |
| Copiar um map copia a referência | Os dois nomes mexem no mesmo map. Para clonar: `maps.Clone(m)`. |

Um conjunto (set) em Go é um map com valor vazio: `seen := map[string]struct{}{}` e `seen[k] = struct{}{}`. O `struct{}` não ocupa memória. Também se vê `map[string]bool`, mais fácil de ler.

### Os pacotes slices e maps

Antes dos generics, Go obrigava a escrever laços para tudo. Hoje a biblioteca padrão tem as operações comuns:

```go
// import "cmp", "maps" e "slices"

slices.Contains(names, "Ana")        // true
slices.Index(names, "Bia")           // 1, ou -1
slices.Sort(nums)                    // ordena no lugar
slices.SortFunc(users, func(a, b User) int { return cmp.Compare(a.Age, b.Age) })
slices.Reverse(nums)
slices.Max(nums); slices.Min(nums)
slices.Equal(a, b)
nums = slices.Insert(nums, 1, 99)    // insere no índice 1
nums = slices.Delete(nums, 0, 2)     // remove [0:2]
slices.Clone(nums)

keys := slices.Sorted(maps.Keys(ages)) // chaves ordenadas
maps.Clone(ages)

min(3, 1, 2); max(a, b)              // embutidas desde o Go 1.21
clear(ages)                          // esvazia map (ou zera slice)
```

### Copiar e comparar

`copy(dst, src)` copia elementos e devolve quantos copiou (o mínimo entre os dois `len`). Slices e maps **não** se comparam com `==` (só com `nil`); use `slices.Equal` e `maps.Equal`. Arrays e structs simples se comparam com `==` normalmente.
