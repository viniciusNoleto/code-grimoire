Funções em Go são simples e explícitas: sem sobrecarga, sem parâmetros opcionais e sem valores padrão. O que elas têm de diferente é poder **devolver vários valores**, e é isso que sustenta o tratamento de erros da linguagem inteira.

### Assinatura

```go
func add(a int, b int) int {
	return a + b
}

func add2(a, b int) int { return a + b }   // parâmetros seguidos do mesmo tipo

func divide(a, b float64) (float64, error) { // dois retornos
	if b == 0 {
		return 0, errors.New("divisão por zero")
	}
	return a / b, nil
}

result, err := divide(10, 2)
q, _ := divide(10, 2)                        // ignora o erro (evite)
```

Leia `func divide(a, b float64) (float64, error)` como: "divide recebe dois float64 e devolve um float64 e um error". O padrão `(valor, error)` aparece em praticamente toda função que pode falhar.

::note{type="note" title="Argumentos são sempre copiados"}
Go passa tudo **por valor**: a função recebe uma cópia. Para a função alterar algo do chamador, passe um ponteiro (`*T`). Slices, maps e channels parecem "por referência" porque a cópia é de um pequeno cabeçalho que aponta para os mesmos dados ([capítulo de slices](#slices-e-maps)).
::

### Retornos nomeados

```go
func split(sum int) (x, y int) { // x e y são variáveis, já com valor zero
	x = sum * 4 / 9
	y = sum - x
	return                         // "return nu": devolve x e y
}
```

Nomear retornos documenta o que cada um significa e é necessário para o `defer` alterar o retorno (abaixo). O `return` sem valores atrapalha a leitura em funções longas; prefira usá-lo só em funções curtas.

### Variádicas

```go
func sum(nums ...int) int { // nums é um []int
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

sum()            // 0
sum(1, 2, 3)     // 6
values := []int{4, 5}
sum(values...)   // "espalha" o slice nos argumentos
```

É assim que `fmt.Println(a ...any)` e `append(s, items...)` aceitam qualquer número de argumentos.

### Funções são valores

```go
type Op func(int, int) int     // um tipo de função

apply := func(f Op, a, b int) int { return f(a, b) }
apply(func(a, b int) int { return a * b }, 3, 4)   // 12

slices.SortFunc(users, func(a, b User) int {       // muito comum na biblioteca padrão
	return cmp.Compare(a.Age, b.Age)
})
```

### Closures

Uma função anônima enxerga e **compartilha** as variáveis de onde foi criada:

```go
func counter() func() int {
	n := 0
	return func() int {
		n++          // o mesmo n a cada chamada: ele sobrevive à função counter
		return n
	}
}

next := counter()
next() // 1
next() // 2
```

### defer: "faça isso quando a função terminar"

`defer` agenda uma chamada para rodar **quando a função atual retornar**, por qualquer caminho: `return` normal, retorno antecipado de erro ou panic. É o substituto do `try/finally`.

```go
func readConfig(path string) ([]byte, error) {
	f, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	defer f.Close() // logo depois de abrir; roda em qualquer saída abaixo

	return io.ReadAll(f)
}
```

| Regra | Consequência |
| --- | --- |
| Os argumentos são avaliados **na hora do `defer`** | `defer fmt.Println(i)` imprime o `i` daquele momento. |
| Vários `defer` rodam em **ordem inversa** (pilha) | Abre A, abre B → fecha B, fecha A. |
| Roda no fim da **função**, não do bloco | `defer` dentro de um `for` acumula até a função terminar: num laço com muitos arquivos, extraia para uma função. |

Padrões que você vai ver: `defer f.Close()`, `defer mu.Unlock()` logo após `mu.Lock()`, `defer resp.Body.Close()`, `defer cancel()` depois de criar um context, `defer tx.Rollback()` depois de abrir uma transação.

### panic e recover

`panic` para o fluxo normal: a função para, os `defer` rodam e o pânico sobe pela pilha até derrubar o programa, imprimindo o stack trace. Acontece sozinho em erros de programação (índice fora do slice, ponteiro `nil`, escrita em map `nil`) ou chamando `panic(valor)`.

```go
func safeDiv(a, b int) (result int, err error) {
	defer func() {
		if r := recover(); r != nil {   // recover só funciona dentro de um defer
			err = fmt.Errorf("recuperado: %v", r) // altera o retorno nomeado
		}
	}()
	return a / b, nil                   // b == 0 → panic: integer divide by zero
}
```

::note{type="pitfall" title="panic não é exceção"}
Em Go, falha esperada (arquivo não existe, entrada inválida, rede caiu) é **valor de erro**, nunca panic. `panic` é para bugs e situações impossíveis. `recover` aparece quase só em fronteiras: o servidor HTTP da biblioteca padrão recupera o panic de um handler para não derrubar os outros. Funções chamadas `MustAlgo` (`regexp.MustCompile`, `template.Must`) dão panic em vez de devolver erro; são usadas na inicialização, com valores fixos no código.
::

### init

```go
func init() {
	// roda automaticamente, uma vez, antes do main
}
```

Cada arquivo pode ter funções `init`. Elas rodam depois que as variáveis do pacote são inicializadas e antes do `main`. Bibliotecas usam para registrar algo (drivers de banco, formatos de imagem). No seu código, prefira inicialização explícita.
