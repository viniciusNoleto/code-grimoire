O Laravel captura toda exceção não tratada, decide se deve **registrá-la** (report) e como **mostrá-la** ao cliente (render). Os dois passos são configuráveis em `bootstrap/app.php`.

### Configurar o tratamento

```php
->withExceptions(function (Exceptions $exceptions): void {
    $exceptions->report(function (PagamentoRecusado $e) {
        Log::channel('pagamentos')->warning($e->getMessage(), ['pedido' => $e->pedidoId]);
    })->stop();                                   // stop(): não segue para o log padrão

    $exceptions->render(function (EstoqueInsuficiente $e, Request $request) {
        if ($request->expectsJson()) {
            return response()->json(['message' => $e->getMessage()], 409);
        }
    });

    $exceptions->dontReport([PedidoJaPago::class]);        // não registra
    $exceptions->context(fn () => ['loja_id' => tenant()?->id]);   // contexto em todos os relatos
    $exceptions->shouldRenderJsonWhen(fn (Request $r) => $r->is('api/*'));
})
```

### Exceções próprias

```php
class EstoqueInsuficiente extends Exception
{
    public function __construct(public Produto $produto)
    {
        parent::__construct("Estoque insuficiente para {$produto->nome}.");
    }

    public function render(Request $request): Response|false   // false: usa o render padrão
    {
        return $request->expectsJson()
            ? response()->json(['message' => $this->getMessage(), 'produto' => $this->produto->id], 409)
            : false;
    }

    public function report(): bool { return false; }   // não registra no log
}
```

### Exceções que o Laravel já converte

| Exceção | Resposta |
| --- | --- |
| `ValidationException` | 422 (JSON) ou redirect com erros |
| `AuthenticationException` | 401 (JSON) ou redirect para login |
| `AuthorizationException` | 403 |
| `ModelNotFoundException`, `NotFoundHttpException` | 404 |
| `ThrottleRequestsException` | 429 |
| `HttpException` (via `abort()`) | O status informado |

Para páginas personalizadas, crie `resources/views/errors/404.blade.php`, `500.blade.php` etc.

### Registrar sem interromper

```php
try {
    $this->sincronizarComErp($pedido);
} catch (Throwable $e) {
    report($e);                       // registra e segue a execução
}

$valor = rescue(fn () => Http::get($url)->json('valor'), 0);   // em caso de erro: registra e devolve 0
```

### Logs

```php
Log::info('Pedido criado', ['pedido_id' => $pedido->id, 'total' => $pedido->total]);
Log::warning('Estoque baixo', ['produto' => $produto->id]);
Log::error('Falha no gateway', ['erro' => $e->getMessage()]);
Log::channel('slack')->critical('Gateway fora do ar');
Log::stack(['daily', 'slack'])->error('...');
Log::withContext(['request_id' => $id]);           // em todas as próximas linhas desta requisição
```

Níveis, do menos ao mais grave: `debug`, `info`, `notice`, `warning`, `error`, `critical`, `alert`, `emergency`. `LOG_LEVEL` define o mínimo gravado.

```php
// config/logging.php: canais
'stack'  => ['driver' => 'stack', 'channels' => ['daily', 'slack']],
'daily'  => ['driver' => 'daily', 'path' => storage_path('logs/laravel.log'), 'days' => 14],
'stderr' => ['driver' => 'monolog', 'handler' => StreamHandler::class, 'handler_with' => ['stream' => 'php://stderr']],  // containers
'slack'  => ['driver' => 'slack', 'url' => env('LOG_SLACK_WEBHOOK_URL'), 'level' => 'critical'],
```

Em containers e plataformas como Laravel Cloud e Kubernetes, envie os logs para `stderr` e deixe a plataforma coletar.

### Ferramentas

| Ferramenta | Uso |
| --- | --- |
| `php artisan pail` | Logs em tempo real no terminal, com filtros |
| Telescope | Painel de desenvolvimento: requisições, queries, jobs, exceções |
| Sentry, Flare, Bugsnag | Rastreamento de erros em produção, com agrupamento e alertas |
| Nightwatch | Monitoramento oficial de produção (pago) |
