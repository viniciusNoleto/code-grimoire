Facades, contracts e helpers são três formas de acessar o mesmo serviço do container. Escolher entre elas é questão de estilo e de testabilidade, não de funcionalidade.

### Como uma facade funciona

`Cache::get('x')` parece um método estático, mas não é. A classe `Cache` estende `Illuminate\Support\Facades\Facade` e só informa qual serviço do container ela representa, pelo método `getFacadeAccessor()`. Quando você chama um método estático que não existe na facade, o PHP aciona o `__callStatic` da classe base, que:

1. Lê o nome devolvido por `getFacadeAccessor()` (no caso, `'cache'`).
2. Pede esse serviço ao container (`app('cache')`), guardando a instância para as próximas chamadas.
3. Chama o método pedido nesse objeto, com os mesmos argumentos, e devolve o resultado.

```php [vendor/laravel/framework/src/Illuminate/Support/Facades/Cache.php]
namespace Illuminate\Support\Facades;

class Cache extends Facade
{
    protected static function getFacadeAccessor(): string
    {
        return 'cache';     // nome do binding no container
    }
}
```

```php [app/Http/Controllers/CotacaoController.php]
Cache::get('chave');
// equivale a: app('cache')->get('chave');
```

Ou seja: a facade é só um atalho estático para um **objeto comum** que mora no container. Por isso ela pode ser trocada em testes, e por isso o objeto real pode ser configurado (driver de cache, disco, canal de log) sem mudar quem chama.

Você pode criar sua própria facade para um serviço da aplicação:

```php [app/Facades/Pagamento.php]
namespace App\Facades;

use App\Services\GatewayPagamento;
use Illuminate\Support\Facades\Facade;

class Pagamento extends Facade
{
    protected static function getFacadeAccessor(): string
    {
        return GatewayPagamento::class;   // pode ser o nome da classe registrada no container
    }
}
```

```php [app/Http/Controllers/CheckoutController.php]
use App\Facades\Pagamento;

Pagamento::cobrar($pedido);   // app(GatewayPagamento::class)->cobrar($pedido)
```

As facades mais usadas e o serviço por trás de cada uma:

| Facade | Serviço no container | Classe real |
| --- | --- | --- |
| `Cache` | `cache` | `Illuminate\Cache\CacheManager` |
| `DB` | `db` | `Illuminate\Database\DatabaseManager` |
| `Log` | `log` | `Illuminate\Log\LogManager` |
| `Storage` | `filesystem` | `Illuminate\Filesystem\FilesystemManager` |
| `Auth` | `auth` | `Illuminate\Auth\AuthManager` |
| `Route` | `router` | `Illuminate\Routing\Router` |
| `Mail` | `mail.manager` | `Illuminate\Mail\MailManager` |
| `Queue` | `queue` | `Illuminate\Queue\QueueManager` |

### Três formas, o mesmo serviço

O mesmo objeto do container pode ser alcançado de três jeitos. O resultado é idêntico; muda a leitura do código e a facilidade de testar.

```php [app/Services/CotacaoService.php]
namespace App\Services;

use Illuminate\Contracts\Cache\Repository;
use Illuminate\Support\Facades\Cache;

class CotacaoService
{
    public function __construct(private Repository $cache) {}   // 2. injeção do contract

    public function hoje(string $moeda): float
    {
        $a = Cache::get("cotacao.$moeda");          // 1. facade
        $b = $this->cache->get("cotacao.$moeda");   // 2. contract injetado
        $c = cache("cotacao.$moeda");               // 3. helper

        return $a;   // $a, $b e $c vêm do mesmo objeto de cache
    }
}
```

| Forma | Exemplo | Vantagem | Desvantagem | Quando preferir |
| --- | --- | --- | --- | --- |
| Facade | `Cache::get('k')` | Curta, não precisa de construtor | A dependência fica escondida no meio do método | Controllers, rotas, providers, código de borda |
| Injeção (contract) | `__construct(private Repository $cache)` | Dependência visível; a classe funciona fora do Laravel | Mais código no construtor | Classes de domínio, serviços reutilizáveis |
| Helper | `cache('k')`, `config('app.name')`, `now()` | O mais curto de todos | Mesma desvantagem da facade; nem todo serviço tem helper | Views Blade, código de uma linha |

::note{type="tip" title="Regra prática"}
Se uma classe usa muitas facades diferentes, ela provavelmente faz coisas demais. Injetar as dependências torna isso visível: um construtor com oito parâmetros incomoda, oito facades espalhadas não.
::

### Contracts

Contracts são as interfaces do framework, em `Illuminate\Contracts\*`. Cada serviço do Laravel implementa um contract, e o container já sabe qual classe entregar para cada um. Depender da interface deixa o código desacoplado da implementação concreta: a classe não sabe se o cache é Redis ou arquivo, se o e-mail vai por SMTP ou por API.

| Contract | O que representa | Facade equivalente |
| --- | --- | --- |
| `Illuminate\Contracts\Cache\Repository` | Um store de cache | `Cache` |
| `Illuminate\Contracts\Queue\Queue` | Uma conexão de fila | `Queue` |
| `Illuminate\Contracts\Mail\Mailer` | O envio de e-mail | `Mail` |
| `Illuminate\Contracts\Filesystem\Filesystem` | Um disco de arquivos | `Storage` |
| `Illuminate\Contracts\Auth\Guard` | Um guard de autenticação | `Auth` |
| `Illuminate\Contracts\Events\Dispatcher` | O despacho de eventos | `Event` |
| `Illuminate\Contracts\Config\Repository` | A configuração | `Config` |

Caso de uso: um serviço de cotação que guarda o resultado em cache. Recebendo o contract, ele pode ser testado com um cache em memória sem depender de facade nem de container.

```php [app/Services/CotacaoService.php]
namespace App\Services;

use Illuminate\Contracts\Cache\Repository as Cache;

class CotacaoService
{
    public function __construct(private Cache $cache) {}

    public function hoje(string $moeda): float
    {
        return $this->cache->remember("cotacao.$moeda", 3600, fn () => $this->buscarNaApi($moeda));
    }
}
```

```php [tests/Unit/CotacaoServiceTest.php]
use Illuminate\Cache\ArrayStore;
use Illuminate\Cache\Repository;

$servico = new CotacaoService(new Repository(new ArrayStore()));   // sem container, sem facade
```

### Real-time facades

Qualquer classe da aplicação vira facade sem criar o arquivo da facade: basta importar o namespace dela com o prefixo `Facades\`. O Laravel gera a facade em tempo de execução (em `storage/framework/cache`), com `getFacadeAccessor()` devolvendo a classe original.

```php [app/Services/CotacaoService.php]
namespace App\Services;

class CotacaoService
{
    public function hoje(string $moeda): float { /* ... */ }
}
```

```php [app/Http/Controllers/CotacaoController.php]
namespace App\Http\Controllers;

use Facades\App\Services\CotacaoService;   // note o prefixo Facades\

class CotacaoController extends Controller
{
    public function show(string $moeda)
    {
        // resolve App\Services\CotacaoService do container e chama hoje()
        return ['valor' => CotacaoService::hoje($moeda)];
    }
}
```

Quando usar: quando você quer a comodidade da chamada estática **e** a possibilidade de mockar em teste (`CotacaoService::shouldReceive('hoje')`), sem escrever uma facade para cada serviço. Em classes de domínio, a injeção pelo construtor continua sendo mais clara.

### Facades em testes

Como a facade só aponta para um objeto do container, o teste pode trocar esse objeto. Há duas formas:

| Forma | O que faz | Quando usar |
| --- | --- | --- |
| `Facade::shouldReceive()` | Troca o serviço por um mock do Mockery e define o que ele deve receber e devolver | Verificar uma chamada específica com argumentos exatos |
| `Facade::fake()` | Troca o serviço por uma implementação falsa que **registra** o que aconteceu sem executar (não envia e-mail, não enfileira) | Verificar depois, com `assert*`, o que foi enviado/despachado |

```php [tests/Feature/CotacaoTest.php]
class CotacaoTest extends TestCase
{
    use Illuminate\Support\Facades\Cache;

    public function test_usa_a_cotacao_do_cache(): void
    {
        Cache::shouldReceive('get')
            ->once()
            ->with('cotacao')
            ->andReturn(5.4);

        $this->get('/cotacao')->assertJson(['valor' => 5.4]);
    }
}
```

```php [tests/Feature/PedidoTest.php]
class PedidoTest extends TestCase
{
    use App\Mail\PedidoConfirmado;
    use Illuminate\Support\Facades\Mail;

    public function test_envia_confirmacao_ao_finalizar(): void
    {
        Mail::fake();          // também: Queue, Bus, Event, Notification, Storage, Http

        $this->post('/pedidos', ['produto_id' => 1])->assertCreated();

        Mail::assertSent(PedidoConfirmado::class);
        Mail::assertSent(PedidoConfirmado::class, fn ($mail) => $mail->hasTo('ana@exemplo.com'));
        Mail::assertNotSent(PedidoCancelado::class);
    }
}
```

Os fakes disponíveis e o que cada um intercepta:

| Fake | Intercepta | Asserções comuns |
| --- | --- | --- |
| `Mail::fake()` | Envio de mailables | `assertSent`, `assertQueued`, `assertNothingSent` |
| `Notification::fake()` | Notificações | `assertSentTo`, `assertNothingSent` |
| `Queue::fake()` | Jobs enfileirados | `assertPushed`, `assertPushedOn`, `assertNotPushed` |
| `Bus::fake()` | Jobs despachados, batches e chains | `assertDispatched`, `assertBatched`, `assertChained` |
| `Event::fake()` | Eventos (listeners não rodam) | `assertDispatched`, `assertListening` |
| `Storage::fake('s3')` | Um disco, trocado por pasta temporária | `assertExists`, `assertMissing` |
| `Http::fake()` | Requisições do HTTP Client | `assertSent`, `assertSentCount` |
