Estes métodos executam a query e devolvem resultados; tudo o que vem antes deles (where, orderBy…) só monta o SQL.

### `all()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
Model::all(array|string $columns = ['*']): Collection
```

Todos os registros da tabela. `$columns` limita as colunas. É estático e **não aceita filtros antes**; para filtrar, use `get()`.

```php [app/Http/Controllers/PedidoController.php]
$todos = Pedido::all();
-- SQL: select * from "pedidos"

$enxuto = Pedido::all(['id', 'numero']);
-- SQL: select "id", "numero" from "pedidos"
```

### `get()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
->get(array|string $columns = ['*']): Collection
```

Executa a query montada e devolve uma Collection (vazia se nada casar, nunca `null`).

```php [app/Http/Controllers/PedidoController.php]
$pendentes = Pedido::where('status', 'pendente')->get();
-- SQL: select * from "pedidos" where "status" = ?

$pendentes = Pedido::where('status', 'pendente')->get(['id', 'total']);
-- SQL: select "id", "total" from "pedidos" where "status" = ?
```

### Buscar pela chave primária: família `find`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
->find(mixed $id, array|string $columns = ['*']): ?Model|Collection
```

- `$id` escalar → um Model ou `null`.
- `$id` array → uma Collection com os que existirem.
- `$columns` → colunas a trazer.

```php [app/Http/Controllers/PedidoController.php]
Pedido::find(10);                 // Pedido ou null
-- SQL: select * from "pedidos" where "pedidos"."id" = ? limit 1

Pedido::find([1, 2, 3]);          // Collection
-- SQL: select * from "pedidos" where "pedidos"."id" in (1, 2, 3)
--      (ids inteiros vão direto no SQL, sem binding)

Pedido::find(10, ['id', 'total']);
-- SQL: select "id", "total" from "pedidos" where "pedidos"."id" = ? limit 1
```

Variações:

| Método | Se não achar |
| --- | --- |
| `find($id)` | `null` |
| `findOrFail($id, $columns)` | Lança `ModelNotFoundException` (o Laravel responde 404). Com array, falha se faltar **qualquer** id. |
| `findMany(array $ids, $columns)` | Collection vazia (sempre Collection) |
| `findOr($id, $columns, Closure $callback)` | Executa e devolve o retorno do callback. `$columns` pode ser omitido: `findOr($id, fn () => ...)` |
| `findOrNew($id, $columns)` | Nova instância vazia (não salva) |

```php [app/Http/Controllers/PedidoController.php]
$pedido = Pedido::findOrFail($id);
-- SQL: select * from "pedidos" where "pedidos"."id" = ? limit 1
--      nenhuma linha → lança ModelNotFoundException (vira 404)

$pedido = Pedido::findOr($id, fn () => redirect('/pedidos'));
-- SQL: a mesma; nenhuma linha → executa o callback
```

### O primeiro resultado: família `first`

```php [vendor/laravel/framework/src/Illuminate/Database/Concerns/BuildsQueries.php]
->first(array|string $columns = ['*']): ?Model
```

Aplica `LIMIT 1` e devolve o primeiro Model ou `null`. Sem `orderBy`, "primeiro" depende do banco; ordene quando importar.

| Método | Comportamento |
| --- | --- |
| `first($columns)` | Model ou `null` |
| `firstOrFail($columns)` | Model ou `ModelNotFoundException` |
| `firstOr($columns, Closure $callback)` | Model ou o retorno do callback; `$columns` pode ser omitido |
| `firstWhere($column, $operator = null, $value = null, $boolean = 'and')` | Atalho para `where(...)->first()`. Aceita as mesmas formas do `where` |
| `firstOrNew(array $attributes, array $values = [])` | Busca; se não achar, instancia **sem salvar**. [Seção 21](#inserir-e-atualizar) |
| `firstOrCreate(array $attributes, array $values = [])` | Busca; se não achar, **cria**. [Seção 21](#inserir-e-atualizar) |

```php [app/Http/Controllers/UserController.php]
$admin = User::where('email', $email)->firstOrFail();
-- SQL: select * from "users" where "email" = ? limit 1

$user = User::firstWhere('email', $email);
-- SQL: select * from "users" where "email" = ? limit 1

$user = User::firstWhere('idade', '>', 18);
-- SQL: select * from "users" where "idade" > ? limit 1
```

### `sole()`: exatamente um

```php [vendor/laravel/framework/src/Illuminate/Database/Concerns/BuildsQueries.php]
->sole(array|string $columns = ['*']): Model
```

Exige que a query case **exatamente uma** linha. Zero → `ModelNotFoundException`; mais de uma → `MultipleRecordsFoundException`. Útil quando duplicidade seria um bug.

```php [app/Services/ConfiguracaoService.php]
$config = Configuracao::where('chave', 'tema')->sole();
-- SQL: select * from "configuracoes" where "chave" = ? limit 2
--      busca até 2 linhas: 0 = não encontrado, 2 = mais de um, 1 = ok
```

### Um único valor: `value()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
->value(string $column): mixed
```

Devolve só o valor de uma coluna do primeiro registro, sem montar o Model.

```php [app/Http/Controllers/UserController.php]
$email = User::where('id', 5)->value('email');
-- SQL: select "email" from "users" where "id" = ? limit 1
```

Variações: `valueOrFail($column)` lança exceção se não houver registro; `soleValue($column)` exige exatamente um.

### Uma coluna de vários registros: `pluck()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
->pluck(string $column, ?string $key = null): Collection
```

- `$column`: coluna cujos valores formam a lista.
- `$key`: se informado, vira a chave de cada item.

```php [app/Http/Controllers/UserController.php]
User::pluck('email');                    // ['a@x.com', 'b@x.com']
-- SQL: select "email" from "users"

User::pluck('nome', 'id');               // [1 => 'Ana', 2 => 'Bia'] — ótimo para <select>
-- SQL: select "nome", "id" from "users"

$users->pluck('perfil.cidade');          // em Collection já carregada, aceita notação de ponto
// sem SQL: trabalha sobre a Collection que já está na memória
```

Com accessors: `pluck` na query lê a coluna crua do banco; para usar accessors, faça `->get()->pluck(...)`.

### Existe ou não?

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->exists(): bool
->doesntExist(): bool
```

Executam um `SELECT EXISTS`, bem mais leve que `count() > 0`.

```php [app/Http/Controllers/UserController.php]
if (User::where('email', $email)->exists()) { /* e-mail em uso */ }
-- SQL: select exists(select * from "users" where "email" = ?) as "exists"
```

Também existem `existsOr(Closure)` e `doesntExistOr(Closure)`, que executam o callback quando o resultado é falso.

### Processar muitos registros sem estourar a memória

`get()` carrega tudo na memória. Para milhares de linhas, use uma destas:

| Método | Como funciona | Quando usar |
| --- | --- | --- |
| `chunk(int $count, callable $callback)` | Busca em blocos com `LIMIT/OFFSET`; chama o callback com cada Collection | Leitura em lote. Retorne `false` no callback para parar |
| `chunkById(int $count, callable $callback, ?string $column = null, ?string $alias = null)` | Blocos usando `WHERE id > último` | Quando você **altera** os registros durante o loop (com `chunk`, alterações deslocam o OFFSET e pulam linhas) |
| `chunkByIdDesc(...)` | Igual, em ordem decrescente | Processar do mais novo ao mais antigo |
| `each(callable $callback, int $count = 1000)` | `chunk` por baixo, mas o callback recebe um Model por vez | Código mais simples que `chunk` |
| `eachById(callable $callback, int $count = 1000, ...)` | `chunkById` com um Model por vez | Alterar registros um a um |
| `lazy(int $chunkSize = 1000)` | Devolve uma `LazyCollection` que busca em blocos sob demanda | Encadear métodos de Collection em grandes volumes |
| `lazyById(int $chunkSize = 1000, ?string $column = null, ?string $alias = null)` / `lazyByIdDesc` | Lazy com paginação por id | Lazy + alterações |
| `cursor()` | Uma única query; hidrata um Model por vez via generator do PHP | Mínimo de memória para Models; **não** suporta eager loading (`with`) |

```php [app/Console/Commands/ProcessarPedidosPendentes.php]
Pedido::where('status', 'pendente')->chunkById(500, function ($pedidos) {
    foreach ($pedidos as $pedido) {
        $pedido->update(['status' => 'expirado']);
    }
});
-- SQL do 1º bloco:  select * from "pedidos" where "status" = ? order by "id" asc limit 500
-- SQL dos próximos: select * from "pedidos" where "status" = ? and "id" > ? order by "id" asc limit 500
--                   (? = último id do bloco anterior)

User::where('ativo', true)->each(fn (User $u) => $u->notify(new Aviso));
-- SQL (chunk por offset, 1000 por vez):
--      select * from "users" where "ativo" = ? order by "users"."id" asc limit 1000 offset 0
--      select * from "users" where "ativo" = ? order by "users"."id" asc limit 1000 offset 1000 ...

foreach (User::cursor() as $user) { /* um por vez */ }
-- SQL: select * from "users"   (uma única query, lida linha a linha)

User::lazy()->filter(fn ($u) => $u->idade > 18)->each(...);
-- SQL: igual ao each(): blocos de 1000 com limit/offset, buscados sob demanda
```

### `query()`, `newQuery()` e `newModelQuery()`

- `Model::query()`: Builder novo, com global scopes. O jeito normal de começar.
- `$model->newQuery()`: o mesmo, a partir de uma instância.
- `$model->newModelQuery()`: Builder **sem** global scopes e sem eager loads padrão.
- `$model->newQueryWithoutScopes()`: sem global scopes, mantendo o resto.

### Criar instância sem consultar

- `new Pedido(['total' => 10])`: instância nova, ainda não salva (respeita `$fillable`).
- `Pedido::make([...])`: o mesmo, via Builder.
- `Pedido::hydrate($arrayDeLinhas)`: transforma arrays crus (ex.: de `DB::select`) em Models "existentes", sem consultar.
- `Pedido::fromQuery('select ...', $bindings)`: executa SQL cru e devolve Models.
