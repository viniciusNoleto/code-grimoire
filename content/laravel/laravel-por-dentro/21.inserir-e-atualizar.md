Há dois caminhos: pelo **Model** (dispara eventos, casts, mutators e timestamps) ou pela **query** (uma instrução SQL direta, mais rápida, sem eventos). Escolher o caminho errado é a causa mais comum de "meu observer não rodou".

| Via Model (dispara eventos) | Via query (não dispara) |
| --- | --- |
| `save`, `create`, `update` em instância, `delete` em instância, `firstOrCreate`, `updateOrCreate`, `increment` em instância | `Model::where(...)->update()`, `->delete()`, `insert`, `upsert`, `->increment()` em query |

### `save()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
$model->save(array $options = []): bool
```

Faz `INSERT` se o Model é novo (`$model->exists === false`) ou `UPDATE` apenas dos campos alterados se já existe. Atualiza timestamps. `$options['touch'] = false` evita atualizar os `$touches` do pai.

```php [app/Http/Controllers/PedidoController.php]
$pedido = new Pedido;
$pedido->user_id = 1;
$pedido->total = 99.90;
$pedido->save();           // agora $pedido->id está preenchido
-- SQL: insert into "pedidos" ("user_id", "total", "updated_at", "created_at")
--      values (?, ?, ?, ?) returning "id"
--      (o returning devolve o id gerado, que o Laravel coloca em $pedido->id)

$pedido->total = 120;
$pedido->save();           // só a coluna alterada entra no UPDATE
-- SQL: update "pedidos" set "total" = ?, "updated_at" = ? where "id" = ?

$pedido->save();           // nada mudou
-- SQL: nenhuma query
```

Variações:

- `saveOrFail()`: salva dentro de uma transação e lança exceção em falha.
- `saveQuietly()`: salva **sem disparar eventos**.
- `push()`: salva o Model **e todos os relacionamentos carregados**, recursivamente.

### `create()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
Model::create(array $attributes = []): Model
```

Instancia, preenche via mass assignment (respeita `$fillable`) e salva. Devolve o Model salvo.

```php [app/Http/Controllers/UserController.php]
$user = User::create([
    'nome' => 'Ana',
    'email' => 'ana@x.com',
    'senha' => Hash::make('segredo'),
]);
-- SQL: insert into "users" ("nome", "email", "senha", "updated_at", "created_at")
--      values (?, ?, ?, ?, ?) returning "id"
```

Campos fora do `$fillable` simplesmente não aparecem na lista de colunas.

Variações:

- `forceCreate(array $attributes)`: ignora `$fillable`/`$guarded`.
- `createQuietly(array $attributes)`: sem eventos.
- `forceCreateQuietly(...)`: as duas coisas.

### `fill()` e `forceFill()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
$model->fill(array $attributes): static
```

Preenche atributos sem salvar, respeitando `$fillable`. `forceFill()` ignora a proteção.

```php [app/Http/Controllers/PedidoController.php]
$pedido->fill($request->validated())->save();
$user->forceFill(['is_admin' => true])->save();
```

### `update()` em instância e em query

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
$model->update(array $attributes = [], array $options = []): bool   // instância
Model::where(...)->update(array $values): int                        // query: linhas afetadas
```

- Na **instância**: `fill($attributes)` + `save()`. Respeita `$fillable`, dispara eventos.
- Na **query**: um único `UPDATE ... WHERE`. Não carrega Models, não dispara eventos, não aplica mutators; atualiza `updated_at` automaticamente.

```php [app/Http/Controllers/PedidoController.php]
$pedido->update(['status' => 'pago']);                 // instância
-- SQL: update "pedidos" set "status" = ?, "updated_at" = ? where "id" = ?

Pedido::where('status', 'pendente')                    // query: um UPDATE para todas as linhas
    ->where('created_at', '<', now()->subDays(30))
    ->update(['status' => 'expirado']);
-- SQL: update "pedidos" set "status" = ?, "updated_at" = ?
--      where "status" = ? and "created_at" < ?
```

Variações: `updateQuietly()` (instância, sem eventos), `updateOrFail()` (instância, transação + exceção), `forceFill()->save()`.

### Buscar ou criar

| Método | Se encontrar | Se não encontrar |
| --- | --- | --- |
| `firstOrNew(array $attributes, array $values = [])` | Devolve o existente | Nova instância com `$attributes + $values`, **não salva** |
| `firstOrCreate(array $attributes, array $values = [])` | Devolve o existente | **Cria** com `$attributes + $values` |
| `createOrFirst(array $attributes, array $values = [])` | (em erro de unique) busca e devolve o existente | Tenta criar primeiro |
| `updateOrCreate(array $attributes, array $values = [])` | **Atualiza** com `$values` | Cria com `$attributes + $values` |

- **`$attributes`**: as condições de busca (viram `WHERE`).
- **`$values`**: campos extras usados ao criar (ou ao atualizar, no `updateOrCreate`); **não entram** na busca.

```php [app/Http/Controllers/TagController.php]
$tag = Tag::firstOrCreate(['slug' => 'laravel'], ['nome' => 'Laravel']);
-- SQL: select * from "tags" where ("slug" = ?) limit 1
// se não achou:
--      insert into "tags" ("slug", "nome", "updated_at", "created_at") values (?, ?, ?, ?) returning "id"

Estoque::updateOrCreate(
    ['produto_id' => 5, 'deposito_id' => 2],  // busca
    ['quantidade' => 40]                       // valor novo
);
-- SQL: select * from "estoques" where ("produto_id" = ? and "deposito_id" = ?) limit 1
// se achou:
--      update "estoques" set "quantidade" = ?, "updated_at" = ? where "id" = ?
// se não achou:
--      insert into "estoques" ("produto_id", "deposito_id", "quantidade", "updated_at", "created_at")
--      values (?, ?, ?, ?, ?) returning "id"
```

`createOrFirst` (*Laravel 10.20+*) inverte a ordem: tenta o `INSERT` e, se o banco recusar por violação de índice único, busca o existente. É mais seguro contra corrida entre requisições simultâneas, mas exige índice único nas colunas de `$attributes`. `firstOrCreate` usa `createOrFirst` internamente nas versões recentes.

`$model->wasRecentlyCreated` diz se o registro acabou de ser criado.

### Incrementar e decrementar

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
$model->increment(string $column, float|int $amount = 1, array $extra = [])
$model->decrement(string $column, float|int $amount = 1, array $extra = [])
```

- `$amount`: quanto somar/subtrair.
- `$extra`: outras colunas a atualizar na mesma query.

Usa `SET coluna = coluna + ?`, que é seguro com acessos simultâneos (diferente de ler, somar no PHP e salvar).

```php [app/Http/Controllers/PostController.php]
$post->increment('visualizacoes');
-- SQL: update "posts" set "visualizacoes" = "visualizacoes" + 1, "updated_at" = ? where "id" = ?

$produto->decrement('estoque', 3, ['ultima_venda' => now()]);
-- SQL: update "produtos" set "estoque" = "estoque" - 3, "ultima_venda" = ?, "updated_at" = ?
--      where "id" = ?

Produto::where('categoria', 'promo')->increment('preco', 5);          // em massa
-- SQL: update "produtos" set "preco" = "preco" + 5, "updated_at" = ? where "categoria" = ?

Produto::where('id', 1)->incrementEach(['vendas' => 1, 'estoque' => -1]); // várias colunas
-- SQL: update "produtos" set "vendas" = "vendas" + 1, "estoque" = "estoque" + -1, "updated_at" = ?
--      where "id" = ?
```

A conta é feita **pelo banco** (`coluna = coluna + 1`), por isso é segura com acessos simultâneos.

Variações: `incrementQuietly` / `decrementQuietly` (instância, sem eventos), `incrementEach` / `decrementEach`.

### `insert()` em massa

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
Model::insert(array $values): bool
```

Insere uma ou várias linhas em um único SQL. **Sem** eventos, mass assignment, casts ou timestamps automáticos.

```php [app/Services/AuditoriaService.php]
Log::insert([
    ['acao' => 'login', 'created_at' => now()],
    ['acao' => 'logout', 'created_at' => now()],
]);
-- SQL: insert into "logs" ("acao", "created_at") values (?, ?), (?, ?)

Log::insertOrIgnore([...]);
-- SQL: insert into "logs" ... on conflict do nothing
```

Variações: `insertOrIgnore` (ignora duplicados e outros erros), `insertGetId(array $values)` (devolve o id), `insertUsing(array $columns, $query)` (insere a partir de um SELECT).

### `upsert()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Builder.php]
Model::upsert(array $values, array|string $uniqueBy, ?array $update = null): int
```

- **`$values`**: linhas a inserir.
- **`$uniqueBy`**: colunas que identificam se a linha já existe (precisam de índice único ou PK; ignoradas no MySQL, que usa os índices da tabela).
- **`$update`**: colunas a atualizar quando a linha já existe. `null` atualiza todas.

```php [app/Console/Commands/ImportarVoos.php]
Voo::upsert(
    [
        ['origem' => 'BVB', 'destino' => 'MAO', 'preco' => 450],   // → values (?, ?, ?, ?, ?)
        ['origem' => 'BVB', 'destino' => 'BSB', 'preco' => 900],   // → , (?, ?, ?, ?, ?)
    ],
    uniqueBy: ['origem', 'destino'],   // → on conflict ("origem", "destino")
    update: ['preco']                  // → do update set "preco" = "excluded"."preco"
);
-- SQL: insert into "voos" ("origem", "destino", "preco", "updated_at", "created_at")
--      values (?, ?, ?, ?, ?), (?, ?, ?, ?, ?)
--      on conflict ("origem", "destino") do update
--      set "preco" = "excluded"."preco", "updated_at" = "excluded"."updated_at"
```

O `uniqueBy` vira o `on conflict (...)`: o PostgreSQL exige um índice único (ou a chave primária) exatamente nessas colunas, senão a query falha. `excluded` é a linha que você tentou inserir; `"excluded"."preco"` é o preço novo.

Uma única query para milhares de linhas, sem eventos. Timestamps são preenchidos se o Model os usa.

### `touch()`

```php [vendor/laravel/framework/src/Illuminate/Database/Eloquent/Model.php]
$model->touch(?string $attribute = null): bool
```

Atualiza só `updated_at` (ou a coluna informada) para agora. `touchQuietly()` faz o mesmo sem eventos.

```php [app/Http/Controllers/PostController.php]
$post->touch();
-- SQL: update "posts" set "updated_at" = ? where "id" = ?

$user->touch('ultimo_acesso');
-- SQL: update "users" set "ultimo_acesso" = ? where "id" = ?
```
