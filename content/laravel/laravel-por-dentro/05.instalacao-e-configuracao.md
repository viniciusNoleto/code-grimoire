Um projeto Laravel é configurado por arquivos em `config/`, que leem valores do `.env`. Saber como essas duas camadas se relacionam evita os bugs mais comuns de produção.

### Criar um projeto

```bash
laravel new loja                    # instalador oficial: pergunta starter kit, testes e banco
composer create-project laravel/laravel loja   # alternativa sem o instalador
php artisan serve                   # servidor de desenvolvimento em http://localhost:8000
```

Para ambiente local, as opções oficiais são o **Herd** (macOS e Windows, PHP e Nginx nativos) e o **Sail** (Docker). O Laravel 11 e o 12 exigem PHP 8.2+; o Laravel 13 exige PHP 8.3+.

### `.env` e `config/`

O `.env` guarda valores que mudam por ambiente e segredos; nunca vai para o Git. Os arquivos de `config/` leem esses valores com `env()` e definem padrões.

```php
// config/services.php
'pagamento' => [
    'key' => env('PAGAMENTO_KEY'),
    'timeout' => env('PAGAMENTO_TIMEOUT', 10),   // segundo argumento: valor padrão
],

// no código da aplicação
$chave = config('services.pagamento.key');
config(['services.pagamento.timeout' => 30]);    // altera em tempo de execução (só nesta requisição)
```

::note{type="pitfall" title="Cuidado"}
Chame `env()` **apenas** dentro de `config/`. Depois de `php artisan config:cache` (feito em todo deploy), o `.env` não é mais lido e `env()` fora de `config/` devolve `null`.
::

```bash
php artisan config:show database     # mostra a configuração final de um arquivo
php artisan config:publish cors      # Laravel 11+: publica um arquivo de config que vem oculto
php artisan env:encrypt              # gera .env.encrypted para versionar com segurança
```

### Ambiente

```php
app()->environment();                        // 'local', 'production'…
app()->environment(['local', 'staging']);    // true se for um deles
app()->isProduction();
app()->isLocal();
```

`APP_ENV` define o ambiente e `APP_DEBUG` liga as páginas de erro detalhadas. Nunca deixe `APP_DEBUG=true` em produção: a página de erro mostra variáveis de ambiente e trechos de código.

### Estrutura de diretórios (Laravel 11+)

| Pasta | Conteúdo |
| --- | --- |
| `app/Http/Controllers` | Controllers |
| `app/Models` | Models Eloquent |
| `app/Providers` | Service Providers (por padrão, só o `AppServiceProvider`) |
| `bootstrap/app.php` | Rotas, middlewares e exceções |
| `bootstrap/providers.php` | Lista de providers |
| `config/` | Configuração |
| `database/` | Migrations, factories, seeders |
| `public/` | Único diretório exposto pelo servidor web: `index.php` e assets compilados |
| `resources/` | Views Blade, CSS e JS de origem, traduções |
| `routes/` | `web.php`, `console.php`; `api.php` e `channels.php` quando instalados |
| `storage/` | Logs, cache de framework, sessões e arquivos enviados |
| `tests/` | `Feature` e `Unit` |

Pastas como `app/Jobs`, `app/Events`, `app/Policies` e `app/Http/Middleware` só aparecem quando você cria o primeiro arquivo com `php artisan make:*`.

### Modo de manutenção

```bash
php artisan down --secret="acesso-equipe"   # quem acessar /acesso-equipe ganha um cookie e navega normalmente
php artisan down --render="errors::503" --retry=60
php artisan up
```
