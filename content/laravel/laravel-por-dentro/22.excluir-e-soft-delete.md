Excluir pela instância dispara eventos; excluir pela query não. Soft delete troca a exclusão real por uma marcação de data, e pruning apaga registros antigos de forma agendada.

### Excluir

| Método | O que faz | Eventos |
| --- | --- | --- |
| `$model->delete()` | Exclui aquele registro | Sim |
| `$model->deleteOrFail()` | Igual, em transação; lança exceção em falha | Sim |
| `$model->deleteQuietly()` | Exclui sem eventos | Não |
| `Model::destroy(mixed $ids)` | Aceita id, vários ids, array ou Collection. Carrega cada Model e chama `delete()` | Sim |
| `Model::where(...)->delete()` | Um único `DELETE ... WHERE` | Não |
| `Model::truncate()` | Apaga **tudo** e reinicia o autoincremento | Não |

```php
$pedido->delete();
-- SQL: delete from "pedidos" where "id" = ?

Pedido::destroy(1);
Pedido::destroy(1, 2, 3);
Pedido::destroy([1, 2, 3]);
-- SQL: carrega e exclui um por um, para disparar eventos:
--      select * from "pedidos" where "pedidos"."id" in (1, 2, 3)
--      delete from "pedidos" where "id" = ?      (repetido para cada Model)

Pedido::where('status', 'rascunho')->delete();
-- SQL: delete from "pedidos" where "status" = ?   (um único comando)

Pedido::truncate();
-- SQL: truncate "pedidos" restart identity cascade
```

`destroy()` devolve quantos registros foram excluídos. Relacionamentos não são apagados automaticamente; use `cascadeOnDelete()` na foreign key da migration ou o evento `deleting`.

### Soft Deletes

Com a trait `SoftDeletes`, `delete()` preenche a coluna `deleted_at` em vez de apagar, e todas as consultas passam a ignorar registros com `deleted_at` preenchido.

```php
use Illuminate\Database\Eloquent\SoftDeletes;

class Pedido extends Model
{
    use SoftDeletes;
}
// migration: $table->softDeletes();   // cria deleted_at nullable
```

| Método | Efeito |
| --- | --- |
| `$pedido->delete()` | Marca `deleted_at = agora` |
| `$pedido->trashed()` | `true` se está na lixeira |
| `$pedido->restore()` | Limpa `deleted_at` (dispara `restoring`/`restored`) |
| `$pedido->restoreQuietly()` | Restaura sem eventos |
| `$pedido->forceDelete()` | Apaga de verdade (dispara `forceDeleting`/`forceDeleted`) |
| `$pedido->forceDeleteQuietly()` | Apaga de verdade, sem eventos |
| `Pedido::withTrashed()` | Inclui os excluídos na consulta |
| `Pedido::onlyTrashed()` | Só os excluídos |
| `Pedido::withoutTrashed()` | Volta ao padrão (útil após `withTrashed`) |
| `Pedido::onlyTrashed()->restore()` | Restaura em massa |
| `Pedido::forceDestroy($ids)` | `destroy` definitivo (versões recentes) |

```php
$pedido->delete();                        // com SoftDeletes vira UPDATE
-- SQL: update "pedidos" set "deleted_at" = ?, "updated_at" = ? where "id" = ?

Pedido::all();                            // toda consulta ganha o filtro do SoftDeletes
-- SQL: select * from "pedidos" where "pedidos"."deleted_at" is null

$pedido = Pedido::withTrashed()->find($id);
-- SQL: select * from "pedidos" where "pedidos"."id" = ? limit 1   (sem o filtro)

if ($pedido->trashed()) {                 // só olha deleted_at; sem SQL
    $pedido->restore();
    -- SQL: update "pedidos" set "deleted_at" = ?, "updated_at" = ? where "id" = ?   (? = null)
}

Pedido::onlyTrashed()->get();
-- SQL: select * from "pedidos" where "pedidos"."deleted_at" is not null

$pedido->forceDelete();
-- SQL: delete from "pedidos" where "id" = ?

// Relacionamentos também podem incluir excluídos
$user->pedidos()->withTrashed()->get();
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null
```

`restore()` e `forceDelete()` também funcionam numa query de relacionamento: `$pedido->historico()->restore()`. Restaurar em massa assim não dispara eventos.

Na rota, para encontrar Models na lixeira com route model binding: `Route::get(...)->withTrashed();`.

### Pruning: limpeza automática

Para apagar periodicamente registros que não servem mais, use a trait `Prunable` (exclusão Model a Model, com eventos) ou `MassPrunable` (uma query `DELETE`, sem eventos).

```php
use Illuminate\Database\Eloquent\Prunable;

class Log extends Model
{
    use Prunable;

    public function prunable(): Builder
    {
        return static::where('created_at', '<=', now()->subMonths(6));
    }

    protected function pruning(): void
    {
        // opcional: roda antes de apagar cada um (ex.: remover arquivos)
    }
}

-- SQL ao rodar model:prune com Prunable (busca em blocos, exclui um por um, com eventos):
--      select * from "logs" where "created_at" <= ? order by "id" asc limit 1000
--      delete from "logs" where "id" = ?
// SQL com MassPrunable (um DELETE por bloco, sem eventos):
--      delete from "logs" where "ctid" in (
--          select "logs"."ctid" from "logs" where "created_at" <= ? limit 1000
--      )
//      (o PostgreSQL não aceita DELETE ... LIMIT; o Laravel usa o ctid, id interno da linha)
```

Agende o comando (em `routes/console.php`):

```php
Schedule::command('model:prune')->daily();
// opções: --model="App\Models\Log"  --except="..."  --chunk=1000  --pretend (só mostra quantos)
```

Com `SoftDeletes`, o pruning faz `forceDelete`.
