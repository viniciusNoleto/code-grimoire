Autenticação responde "quem é você?". O Laravel separa isso em **guards**, que dizem como a requisição é autenticada (sessão, token), e **providers**, que dizem de onde vem o usuário (Eloquent, banco).

### Guards e providers

```php
// config/auth.php
'defaults' => ['guard' => 'web'],
'guards' => [
    'web'   => ['driver' => 'session', 'provider' => 'users'],   // cookie de sessão
    'admin' => ['driver' => 'session', 'provider' => 'admins'],  // segundo tipo de usuário
],
'providers' => [
    'users'  => ['driver' => 'eloquent', 'model' => App\Models\User::class],
    'admins' => ['driver' => 'eloquent', 'model' => App\Models\Admin::class],
],
```

O Sanctum adiciona o guard `sanctum`, que aceita tanto a sessão (SPA) quanto tokens de API.

### Login e logout manuais

```php
public function login(Request $request)
{
    $credenciais = $request->validate(['email' => 'required|email', 'password' => 'required']);

    if (! Auth::attempt($credenciais, remember: $request->boolean('lembrar'))) {
        return back()->withErrors(['email' => 'Credenciais inválidas.'])->onlyInput('email');
    }

    $request->session()->regenerate();          // evita fixação de sessão
    return redirect()->intended('/painel');     // volta para a página que exigiu login
}

public function logout(Request $request)
{
    Auth::logout();
    $request->session()->invalidate();
    $request->session()->regenerateToken();     // novo token CSRF
    return redirect('/');
}
```

`Auth::attempt` aceita condições extras: `Auth::attempt([...$credenciais, 'ativo' => true])`. Outros métodos: `Auth::login($user)`, `Auth::loginUsingId(1)`, `Auth::once($credenciais)` (só nesta requisição), `Auth::guard('admin')->attempt(...)`.

### O usuário autenticado

```php
$user = auth()->user();          // ou Auth::user(), $request->user()
$id   = Auth::id();
Auth::check();                    // está logado?
Auth::guard('admin')->user();

Route::get('/painel', ...)->middleware('auth');           // 401 (JSON) ou redireciona para login
Route::get('/api/me', ...)->middleware('auth:sanctum');
```

### Starter kits e Fortify

Você raramente escreve telas de login do zero:

| Opção | O que entrega |
| --- | --- |
| Starter kits (*Laravel 12+*: React, Vue, Livewire) | Login, registro, recuperação de senha, verificação de e-mail, perfil e testes |
| Fortify | Só o backend de autenticação (rotas e lógica), sem telas; base dos starter kits |
| Breeze e Jetstream | Starter kits das versões anteriores; ainda comuns em projetos existentes |

### Sanctum: SPA e tokens de API

O Sanctum resolve dois cenários:

- **SPA no mesmo domínio** (ou subdomínio): autenticação por cookie de sessão, com CSRF. Configure `SANCTUM_STATEFUL_DOMAINS` e use `$middleware->statefulApi()` em `bootstrap/app.php`.
- **Apps mobile e integrações**: tokens pessoais enviados em `Authorization: Bearer`.

```php
use Laravel\Sanctum\HasApiTokens;

class User extends Authenticatable
{
    use HasApiTokens;
}

// emitir token
$token = $user->createToken('app-android', ['pedidos:ler', 'pedidos:criar'], now()->addDays(30));
return ['token' => $token->plainTextToken];          // texto puro só aparece agora

// usar
Route::get('/pedidos', ...)->middleware(['auth:sanctum', 'abilities:pedidos:ler']);
$request->user()->tokenCan('pedidos:criar');

// revogar
$request->user()->currentAccessToken()->delete();    // logout deste dispositivo
$user->tokens()->delete();                           // todos os dispositivos
```

O token é guardado com hash (SHA-256) na tabela `personal_access_tokens`. Configure expiração em `config/sanctum.php` e agende `php artisan sanctum:prune-expired`.

### Sanctum ou Passport?

| Necessidade | Escolha |
| --- | --- |
| Seu próprio frontend ou app consumindo sua API | Sanctum |
| Terceiros acessando a API em nome dos usuários (fluxos OAuth2, "Entrar com sua loja") | Passport |
| Login com Google, GitHub etc. | Socialite (é cliente OAuth, não servidor) |

### Verificação de e-mail e reset de senha

```php
class User extends Authenticatable implements MustVerifyEmail { }   // envia e-mail de verificação no registro

Route::get('/painel', ...)->middleware(['auth', 'verified']);
```

```php
// reset de senha (os starter kits já fazem isso)
$status = Password::sendResetLink($request->only('email'));

$status = Password::reset(
    $request->only('email', 'password', 'password_confirmation', 'token'),
    function (User $user, string $senha) {
        $user->forceFill(['password' => $senha])->setRememberToken(Str::random(60));
        $user->save();
        event(new PasswordReset($user));
    }
);
```

### Hashing de senhas

```php
$hash = Hash::make('segredo');            // bcrypt por padrão; argon2id configurável
Hash::check('segredo', $hash);            // true
Hash::needsRehash($hash);                 // true se o custo/algoritmo mudou

protected function casts(): array { return ['password' => 'hashed']; }   // faz o hash ao atribuir
```

::note{type="pitfall" title="Segurança"}
Nunca use `md5`, `sha1` ou `bcrypt()` com custo baixo para senhas, e nunca guarde senhas criptografadas (reversíveis). Hash é de mão única.
::
