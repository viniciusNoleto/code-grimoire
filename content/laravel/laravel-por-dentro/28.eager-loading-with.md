Eager loading carrega os relacionamentos de **todos** os registros com uma query extra por relacionamento, em vez de uma query por registro. É a principal ferramenta de desempenho do Eloquent.

### O problema N+1

```php
$users = User::all();
-- SQL: select * from "users"                                    (1 query)

foreach ($users as $user) {
    echo $user->perfil->cidade;
    -- SQL: select * from "perfis" where "perfis"."user_id" = ? ... limit 1
    --      (+1 query POR usuário → 101 queries para 100 users)
}

$users = User::with('perfil')->get();   // 2 queries, qualquer quantidade
-- SQL: select * from "users"
--      select * from "perfis" where "perfis"."user_id" in (1, 2, 3, ...)
```

### `with()` e todas as formas de argumento

```php
->with(array|string $relations, string|Closure|null $callback = null)
```

| Forma | Exemplo | Efeito |
| --- | --- | --- |
| String | `with('posts')` | Um relacionamento |
| Vários argumentos ou array | `with('posts', 'perfil')` / `with(['posts', 'perfil'])` | Vários |
| Aninhado com ponto | `with('posts.comentarios.autor')` | Carrega cada nível |
| Aninhado em array | `with(['posts' => ['comentarios', 'tags']])` | Vários filhos de um mesmo nível |
| Colunas | `with('posts:id,user_id,titulo')` | Só essas colunas (inclua as chaves) |
| Com restrição | `with(['posts' => fn ($q) => $q->where(...)])` | Filtra/ordena os carregados |
| String + Closure | `with('posts', fn ($q) => $q->latest())` | Mesmo efeito, outra sintaxe |

```php
User::with([
    'perfil',
    -- SQL: select * from "perfis" where "perfis"."user_id" in (1, 2, 3)

    'posts' => fn ($q) => $q->where('publicado', true)->latest()->limit(5),
    -- SQL: select * from (
    --          select *, row_number() over (partition by "posts"."user_id" order by "created_at" desc) as "laravel_row"
    --          from "posts" where "posts"."user_id" in (1, 2, 3) and "publicado" = ?
    --      ) as "laravel_table" where "laravel_row" <= 5 order by "laravel_row"

    'posts.tags',
    -- SQL: usa os ids dos posts carregados acima
    --      select "tags".*, "post_tag"."post_id" as "pivot_post_id", "post_tag"."tag_id" as "pivot_tag_id"
    --      from "tags" inner join "post_tag" on "tags"."id" = "post_tag"."tag_id"
    --      where "post_tag"."post_id" in (10, 11, 12)

    'empresa:id,nome',
    -- SQL: select "id", "nome" from "empresas" where "empresas"."id" in (4, 7)
])->get();
-- SQL executado primeiro: select * from "users"
```

O `row_number()` é como o Laravel 11+ aplica o `limit(5)` **por usuário**: ele numera os posts de cada user e mantém só os 5 primeiros de cada um.

Regras importantes:

- A Closure **filtra os relacionados**, não o Model principal. Todos os users vêm; alguns com `posts` vazio.
- `limit` dentro do `with` limita por pai a partir do Laravel 11. Em versões anteriores, limitava o total.
- Ao restringir colunas, inclua as chaves de ligação (`id`, `user_id`). Sem elas, a relação volta vazia.
- No `belongsTo`, a chave fica no Model principal: `Post::with('autor:id,nome')` exige que `posts.user_id` esteja no select de `Post`.

### Filtrar e carregar juntos: `withWhereHas`

```php
->withWhereHas(string $relation, ?Closure $callback = null, string $operator = '>=', int $count = 1)
```

```php
// só users com post publicado, e carrega apenas os publicados
User::withWhereHas('posts', fn ($q) => $q->where('publicado', true))->get();
-- SQL 1 (escolhe os users):
--      select * from "users" where exists (
--          select * from "posts" where "users"."id" = "posts"."user_id" and "publicado" = ?
--      )
-- SQL 2 (escolhe os posts desses users):
--      select * from "posts" where "posts"."user_id" in (1, 4) and "publicado" = ?
```

O mesmo filtro aparece duas vezes: no `exists` (escolhe os users) e no eager load (escolhe os posts).

Comparação:

| Método | Users retornados | Posts carregados |
| --- | --- | --- |
| `with('posts', $filtro)` | Todos | Só os que passam no filtro |
| `whereHas('posts', $filtro)` | Só os que têm post que passa | Nenhum |
| `withWhereHas('posts', $filtro)` | Só os que têm post que passa | Só os que passam |

### Contagens e agregações: `withCount` e família

Adicionam uma coluna calculada por subquery, **sem** carregar os registros.

```php
->withCount(mixed $relations)
->withSum(string|array $relation, string $column)
->withAvg / withMin / withMax (mesma assinatura)
->withExists(string|array $relation)
->withAggregate(string|array $relations, string $column, string $function)
```

| Chamada | Atributo criado |
| --- | --- |
| `withCount('posts')` | `posts_count` |
| `withSum('pedidos', 'total')` | `pedidos_sum_total` |
| `withAvg('avaliacoes', 'nota')` | `avaliacoes_avg_nota` |
| `withMin('pedidos', 'total')` | `pedidos_min_total` |
| `withMax('pedidos', 'total')` | `pedidos_max_total` |
| `withExists('posts')` | `posts_exists` (bool) |
| `withCount('posts as qtd')` | `qtd` (apelido) |

```php
User::withCount([
    'posts',
    -- → (select count(*) from "posts" where "users"."id" = "posts"."user_id") as "posts_count"
    'posts as posts_publicados_count' => fn ($q) => $q->where('publicado', true),
    -- → (select count(*) from "posts" where "users"."id" = "posts"."user_id" and "publicado" = ?)
    --   as "posts_publicados_count"
])->withSum('pedidos', 'total')->get();
    -- → (select sum("pedidos"."total") from "pedidos" where "users"."id" = "pedidos"."user_id")
    --   as "pedidos_sum_total"
-- SQL completo: select "users".*, (subquery 1), (subquery 2), (subquery 3) from "users"

User::withCount('posts')->orderByDesc('posts_count')->get();   // ordenar por contagem
-- SQL: select "users".*, (select count(*) ...) as "posts_count" from "users" order by "posts_count" desc

User::has('posts', '>', 5)->withCount('posts')->get();         // filtrar por contagem
-- SQL: select "users".*, (select count(*) ...) as "posts_count" from "users"
--      where (select count(*) from "posts" where "users"."id" = "posts"."user_id") > 5
--      (no PostgreSQL, where e having não enxergam o apelido posts_count; por isso has())
```

Tudo numa só query: cada agregação é uma subquery na lista de colunas. Por isso o `withCount` precisa vir depois do `select`, que substituiria essa lista.

Com `select`: chame `withCount` **depois** do `select`, senão o `select` apaga a coluna.

### `load()`: carregar depois

Para um Model ou Collection já obtido (comum em route model binding):

| Método | Equivale a |
| --- | --- |
| `load($relations)` | `with` |
| `loadMissing($relations)` | `with`, só para o que ainda não foi carregado |
| `loadCount($relations)` | `withCount` |
| `loadSum($relation, $column)`, `loadAvg`, `loadMin`, `loadMax` | `withSum` etc. |
| `loadExists($relations)` | `withExists` |
| `loadAggregate($relations, $column, $function)` | `withAggregate` |
| `loadMorph($relation, array $relations)` | `morphWith` (abaixo) |
| `loadMorphCount($relation, array $relations)` | Contagem por tipo polimórfico |

```php
public function show(Pedido $pedido)
{
    $pedido->load(['itens.produto', 'cliente']);
    -- SQL: select * from "itens" where "itens"."pedido_id" in (10)
    --      select * from "produtos" where "produtos"."id" in (3, 8, 9)
    --      select * from "clientes" where "clientes"."id" in (2)

    $pedido->loadCount('itens');
    -- SQL: select "id", (select count(*) from "itens" where "pedidos"."id" = "itens"."pedido_id") as "itens_count"
    --      from "pedidos" where "pedidos"."id" in (10)

    return view('pedidos.show', compact('pedido'));
}

$users = User::all();
$users->load('perfil');               // funciona em Collection: uma query para todos
-- SQL: select * from "perfis" where "perfis"."user_id" in (1, 2, 3)
```

### Eager loading padrão no Model: `$with`, `without`, `withOnly`

```php
class Pedido extends Model
{
    protected $with = ['cliente'];         // sempre carregado
    protected $withCount = ['itens'];      // sempre contado
}

Pedido::without('cliente')->get();       // remove um do padrão
Pedido::withOnly('itens')->get();        // ignora o $with e usa só este
```

Use `$with` com moderação: ele pesa em todas as consultas, inclusive onde o relacionamento não é usado.

### Polimórficos: `morphWith` e `morphWithCount`

Um `morphTo` aponta para Models diferentes, e cada um pode precisar de relacionamentos diferentes.

```php
use Illuminate\Database\Eloquent\Relations\MorphTo;

Atividade::with(['alvo' => function (MorphTo $morphTo) {
    $morphTo->morphWith([
        Post::class => ['autor'],
        Video::class => ['canal'],
    ]);
    $morphTo->morphWithCount([
        Post::class => ['comentarios'],
    ]);
}])->get();
-- SQL: select * from "atividades"
--      uma query por tipo encontrado em alvo_type:
--      select * from "posts" where "posts"."id" in (5, 9)
--      select * from "videos" where "videos"."id" in (2)
--      e os relacionamentos de cada tipo:
--      select * from "users" where "users"."id" in (1, 3)       -- autor dos posts
--      select * from "canais" where "canais"."id" in (6)        -- canal dos vídeos

$atividades->loadMorph('alvo', [Post::class => ['autor'], Video::class => ['canal']]);
-- SQL: as mesmas consultas por tipo, feitas depois do get()
```

`constrain([...])` aplica filtros diferentes por tipo dentro do `morphTo`.

### Proibir lazy loading

No `AppServiceProvider::boot()`:

```php
Model::preventLazyLoading(! app()->isProduction());
```

Em desenvolvimento, acessar um relacionamento não carregado lança `LazyLoadingViolationException`. É a melhor forma de encontrar N+1. Para registrar em vez de lançar:

```php
Model::handleLazyLoadingViolationUsing(function ($model, $relation) {
    Log::warning("N+1: ".get_class($model)."::{$relation}");
});
```

### Eager loading automático

:version[Laravel 12.8+] O Laravel pode detectar o acesso lazy e carregar a relação para a Collection inteira de uma vez.

```php
// global, no AppServiceProvider
Model::automaticallyEagerLoadRelationships();

// ou só numa Collection
$pedidos = Pedido::all()->withRelationshipAutoloading();
```

A documentação oficial marca esse recurso como **beta**: o comportamento pode mudar mesmo em versões de correção. Por isso, `with` explícito continua mais previsível; prefira-o quando souber o que vai usar.
