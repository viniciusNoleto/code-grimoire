O Laravel foi desenhado para ser testável: cada serviço do framework tem um fake, o banco é recriado entre testes e as requisições HTTP são simuladas sem servidor. Um pleno avançado escreve testes como parte da entrega, não depois.

### Estrutura e execução

- `tests/Feature`: testes que passam pela aplicação inteira (rotas, banco, filas). A maior parte dos seus testes.
- `tests/Unit`: lógica isolada, sem framework (cálculos, value objects).
- `phpunit.xml`: variáveis do ambiente de teste (`DB_CONNECTION`, `QUEUE_CONNECTION=sync`, `CACHE_STORE=array`, `MAIL_MAILER=array`).

```bash
php artisan test
php artisan test --filter=PedidoTest
php artisan test --parallel --processes=4
php artisan test --coverage --min=80
php artisan make:test PedidoTest            # Feature
php artisan make:test CalculoFreteTest --unit
```

O mesmo teste em **Pest** (padrão nos projetos novos) e em **PHPUnit**:

```php
// Pest
it('cria um pedido', function () {
    $user = User::factory()->create();

    $this->actingAs($user)
        ->postJson('/api/pedidos', ['itens' => [['produto_id' => 1, 'quantidade' => 2]]])
        ->assertCreated();

    expect(Pedido::count())->toBe(1);
});

// PHPUnit
class PedidoTest extends TestCase
{
    use RefreshDatabase;

    public function test_cria_um_pedido(): void
    {
        $user = User::factory()->create();

        $this->actingAs($user)->postJson('/api/pedidos', [...])->assertCreated();

        $this->assertDatabaseCount('pedidos', 1);
    }
}
```

### Banco nos testes

| Trait | Como limpa o banco | Quando usar |
| --- | --- | --- |
| `RefreshDatabase` | Migra uma vez e envolve cada teste numa transação desfeita no fim | Padrão |
| `DatabaseTransactions` | Só a transação, sem migrar | Banco já migrado |
| `DatabaseTruncation` | Trunca as tabelas | Testes que não funcionam dentro de transação (Dusk) |

```php
protected $seed = true;                       // roda o DatabaseSeeder antes de cada teste
$this->seed(PlanoSeeder::class);              // seeder específico
```

::note{type="pitfall" title="Atenção"}
SQLite em memória é rápido, mas não tem `jsonb`, `ilike` e outras funções do PostgreSQL. Se você usa recursos específicos do banco, rode os testes no mesmo banco de produção (um container PostgreSQL no CI).
::

### Testes HTTP

```php
$response = $this->actingAs($user)                     // ou actingAs($user, 'sanctum')
    ->withHeaders(['X-Loja' => 1])
    ->getJson('/api/pedidos?status=pago');

$response->assertOk()                                  // 200
    ->assertJsonCount(3, 'data')
    ->assertJsonPath('data.0.numero', 'A1')
    ->assertJsonStructure(['data' => [['id', 'numero', 'total']], 'meta'])
    ->assertJsonMissingPath('data.0.custo_interno')
    ->assertJson(fn (AssertableJson $json) => $json->has('data', 3)->etc());

$this->postJson('/api/pedidos', [])->assertUnprocessable()->assertJsonValidationErrors(['itens']);
$this->deleteJson("/api/pedidos/{$outro->id}")->assertForbidden();
$this->getJson('/api/pedidos')->assertUnauthorized();

$this->post('/login', $dados)->assertRedirect('/painel')->assertSessionHasNoErrors();
$this->get('/pedidos')->assertViewIs('pedidos.index')->assertViewHas('pedidos')->assertSee('A1');
```

| Assertion | Status |
| --- | --- |
| `assertOk`, `assertCreated`, `assertNoContent` | 200, 201, 204 |
| `assertUnauthorized`, `assertForbidden`, `assertNotFound` | 401, 403, 404 |
| `assertUnprocessable`, `assertTooManyRequests`, `assertServerError` | 422, 429, 5xx |
| `assertStatus(409)` | Qualquer código |

### Assertions de banco

```php
$this->assertDatabaseHas('pedidos', ['numero' => 'A1', 'status' => 'pago']);
$this->assertDatabaseMissing('pedidos', ['numero' => 'A1']);
$this->assertDatabaseCount('itens', 2);
$this->assertSoftDeleted($pedido);
$this->assertModelExists($pedido);
$this->assertModelMissing($pedido);
```

### Fakes

Fakes substituem o serviço real e registram o que foi pedido, para você verificar sem enviar e-mails, chamar APIs ou rodar jobs:

```php
Queue::fake();
// ... ação ...
Queue::assertPushed(ProcessarNotaFiscal::class, fn ($job) => $job->pedido->is($pedido));
Queue::assertPushedOn('fiscal', ProcessarNotaFiscal::class);
Queue::assertNothingPushed();

Bus::fake();                 Bus::assertChained([...]);  Bus::assertBatched(fn ($b) => $b->jobs->count() === 10);
Event::fake([PedidoPago::class]);   Event::assertDispatched(PedidoPago::class);   // só esse evento é falsificado
Mail::fake();                Mail::assertQueued(PedidoConfirmado::class, fn ($m) => $m->hasTo($user->email));
Notification::fake();        Notification::assertSentTo($user, PedidoEnviado::class);
Storage::fake('s3');         Http::fake([...]);           Process::fake();

$this->freezeTime();                         // now() fica parado
$this->travelTo(now()->addDays(4));          // avança o relógio
$this->travel(5)->minutes();
```

Para testar o próprio job, crie-o e chame `handle()` diretamente, injetando dependências falsas.

### Mocks

```php
$this->mock(GatewayPagamento::class, function (MockInterface $mock) {
    $mock->shouldReceive('cobrar')->once()->with(Mockery::on(fn ($p) => $p->total == 100))->andReturn(new Cobranca('ok'));
});

$espiao = $this->spy(Auditoria::class);      // verifica depois, sem definir antes
// ...
$espiao->shouldHaveReceived('registrar')->once();

$this->instance(GatewayPagamento::class, new GatewayFake);   // substitui no container
```

::note{type="tip" title="Regra prática"}
Mocke as fronteiras (APIs externas, gateways, relógio), não as suas próprias classes de domínio. Mocks demais acoplam o teste à implementação.
::

### O que testar

- **Cada endpoint**: caminho feliz, validação (422), não autenticado (401), outro usuário (403/404).
- **Regras de negócio**: cálculos e transições de estado, com casos de borda.
- **Policies**: quem pode e quem não pode.
- **Jobs, listeners e comandos**: que fazem o efeito esperado e que são despachados quando deveriam.
- **Bugs corrigidos**: um teste que reproduz o bug, para ele não voltar.

### Testes de arquitetura e de navegador

```php
// Pest: regras de arquitetura
arch('models estendem Model')->expect('App\Models')->toExtend(Model::class);
arch('controllers não usam DB direto')->expect('App\Http\Controllers')->not->toUse('Illuminate\Support\Facades\DB');
arch()->preset()->laravel();
arch()->expect(['dd', 'dump', 'ray'])->not->toBeUsed();
```

O **Dusk** (e o plugin de navegador do Pest) testa a interface num Chrome real: cliques, formulários, JavaScript.
