Perguntas no estilo de entrevista técnica para pleno. Tente responder antes de abrir cada uma.

### Arquitetura e HTTP

::question
#title
O que acontece entre a requisição chegar ao servidor e o controller rodar?

#default
O `public/index.php` carrega o autoload e cria a aplicação (o container). Os providers são registrados e inicializados, a requisição passa pelos middlewares globais, o router encontra a rota, aplica os middlewares do grupo e da rota, faz o route model binding e resolve o controller pelo container, injetando as dependências ([seção 1](#ciclo-de-vida)).
::

::question
#title
Qual a diferença entre `register()` e `boot()` num Service Provider?

#default
O `register()` de todos os providers roda primeiro e só deve registrar bindings. O `boot()` roda depois, quando todos os serviços já existem, e é onde se usa outros serviços: Gates, rate limiters, observers, macros.
::

::question
#title
Quando usar `singleton`, `scoped` e `bind`?

#default
`bind` cria uma instância nova a cada resolução; `singleton` cria uma para a vida inteira do processo; `scoped` cria uma por requisição ou job. Em Octane e workers de fila, estado de requisição em `singleton` vaza entre requisições, por isso existe o `scoped`.
::

::question
#title
Uma facade é uma classe estática?

#default
Não. Ela repassa a chamada, via `__callStatic`, para um objeto resolvido do container. Por isso pode ser trocada por mock ou fake em testes.
::

::question
#title
Por que `env()` devolve `null` em produção dentro de um controller?

#default
Porque depois de `config:cache` o `.env` não é lido. `env()` só deve aparecer em `config/`; o código usa `config()`.
::

::question
#title
Como o route model binding decide entre 404 e o registro?

#default
O nome do parâmetro da rota precisa ser igual ao da variável tipada com o Model. O Laravel busca pela chave da rota (id, ou a coluna em `{post:slug}`) e lança `ModelNotFoundException` (404) se não achar.
::

::question
#title
Onde fica a regra de validação, a autorização e a regra de negócio de um `store`?

#default
Validação no Form Request, autorização na Policy (chamada no `authorize()` do Form Request ou com `Gate::authorize`), regra de negócio numa Action ou Service. O controller só orquestra.
::

### Banco e Eloquent

::question
#title
O que é o problema N+1 e como evitá-lo?

#default
Carregar uma lista e acessar um relacionamento em cada item gera uma query por item. Use `with()` (ou `withCount` para contagens) e ligue `Model::preventLazyLoading()` em desenvolvimento para ser avisado.
::

::question
#title
Por que um observer `updated` não rodou depois de `Pedido::where(...)->update([...])`?

#default
Update por query é um único SQL; os Models não são carregados, então eventos, casts e mutators não rodam. Para disparar eventos, atualize cada Model (por exemplo com `each->update()` ou `chunkById`).
::

::question
#title
Diferença entre `$user->pedidos` e `$user->pedidos()`?

#default
A propriedade executa a query (uma vez) e devolve a Collection. O método devolve o relacionamento como query builder, para continuar filtrando, contar ou criar registros no banco.
::

::question
#title
Quando usar `firstOrCreate`, `updateOrCreate` e `upsert`?

#default
Os dois primeiros trabalham com um registro e disparam eventos. `upsert` grava muitos registros numa única query, sem eventos, e exige índice único nas colunas de identificação.
::

::question
#title
Como evitar que dois pedidos comprem o último item do estoque?

#default
Numa transação, leia a linha com `lockForUpdate()` antes de baixar o estoque, ou faça a baixa atômica com `decrement` condicionado (`where('estoque', '>=', $qtd)`) e verifique as linhas afetadas.
::

::question
#title
Por que nunca editar uma migration que já rodou em produção?

#default
A tabela `migrations` registra que ela já foi aplicada, então a alteração não roda em produção, e os ambientes passam a ter schemas diferentes. Crie uma nova migration.
::

::question
#title
O que `$fillable` protege e o que ele não protege?

#default
Protege `create`, `fill` e `update` com arrays contra campos inesperados. Não protege atribuição direta, `forceFill`, `insert`, `upsert` nem updates por query.
::

### Segurança e autenticação

::question
#title
Sanctum ou Passport?

#default
Sanctum para o seu próprio SPA ou app mobile (cookie de sessão ou tokens pessoais). Passport quando terceiros precisam acessar a API em nome dos usuários via OAuth2.
::

::question
#title
Por que regenerar a sessão após o login?

#default
Para impedir fixação de sessão: um id de sessão conhecido pelo atacante antes do login passaria a valer como sessão autenticada.
::

::question
#title
`{{ }}` e `{!! !!}` no Blade?

#default
`{{ }}` escapa HTML e protege contra XSS. `{!! !!}` imprime cru e só deve receber conteúdo confiável ou sanitizado.
::

::question
#title
O Eloquent impede SQL injection em todos os casos?

#default
Valores passam por bindings, então sim para valores. Nomes de coluna (`orderBy($request->campo)`) e SQL cru concatenado não são protegidos; valide colunas com uma lista permitida e use `?` no SQL cru.
::

::question
#title
403 ou 404 quando o usuário tenta ver um recurso de outra pessoa?

#default
403 informa que o recurso existe. Para não revelar a existência (por exemplo, ids sequenciais), responda 404 com `Response::denyAsNotFound()` na policy ou filtrando a query pelo usuário.
::

### Filas, eventos e serviços

::question
#title
Por que um job não encontrou o registro que acabou de ser criado?

#default
Foi despachado dentro de uma transação e o worker pegou o job antes do commit. Use `afterCommit()` ou `'after_commit' => true` na conexão.
::

::question
#title
O que acontece com os workers depois de um deploy sem `queue:restart`?

#default
Continuam executando o código antigo carregado na memória, até serem reiniciados.
::

::question
#title
Qual a relação entre `timeout` do job e `retry_after` da conexão?

#default
`retry_after` deve ser maior que o `timeout` do job mais longo. Se for menor, o job volta para a fila enquanto ainda roda e é executado duas vezes.
::

::question
#title
Por que jobs precisam ser idempotentes?

#default
Podem rodar mais de uma vez (novas tentativas, worker morto no meio). Executar duas vezes deve ter o mesmo efeito que uma.
::

::question
#title
Fila, `defer()` ou `afterResponse()`?

#default
Fila para trabalho longo, que precisa de novas tentativas ou de outro processo. `defer()` e `afterResponse()` rodam no mesmo processo depois da resposta: só para tarefas curtas e toleráveis a falha.
::

::question
#title
Como garantir que um cron agendado não rode duas vezes ao mesmo tempo com vários servidores?

#default
`withoutOverlapping()` impede sobreposição no mesmo servidor; `onOneServer()` garante um só servidor. Os dois exigem cache compartilhado com suporte a locks.
::

::question
#title
`Cache::remember` ou `Cache::flexible`?

#default
`remember` recalcula quando a chave expira, e muitas requisições podem recalcular ao mesmo tempo. `flexible` entrega o valor antigo enquanto recalcula em segundo plano dentro de uma janela, evitando o pico.
::

### Testes, performance e produção

::question
#title
`RefreshDatabase` recria o banco a cada teste?

#default
Não. Migra uma vez por execução e envolve cada teste numa transação que é desfeita no fim.
::

::question
#title
Como testar que um e-mail é enviado sem enviá-lo?

#default
`Mail::fake()` antes da ação e `Mail::assertSent` ou `assertQueued` depois. O mesmo padrão vale para filas, eventos, notificações, HTTP e storage.
::

::question
#title
O que `php artisan optimize` faz e qual o risco?

#default
Cacheia configuração, rotas, views e eventos. O risco é `env()` fora de `config/` e rotas com closure, que deixam de funcionar.
::

::question
#title
Quais cuidados o Octane exige?

#default
O processo atende várias requisições, então estado estático e singletons com dados da requisição vazam entre usuários. Use `scoped()`, evite estado global e reinicie workers com `--max-requests`.
::

::question
#title
Como fazer uma migration que remove uma coluna sem derrubar a aplicação durante o deploy?

#default
Em dois deploys: primeiro publique o código que não usa mais a coluna; no seguinte, rode a migration que a remove.
::
