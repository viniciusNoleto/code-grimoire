Um Model do Eloquent é uma classe PHP que representa uma tabela; cada instância representa uma linha. Quase tudo o que você chama nele, porém, não está escrito na classe Model: é repassado para outras classes.

### A cadeia de encaminhamento

Quando você chama `User::where(...)`, o PHP não encontra `where` no Model. O método mágico `__callStatic` cria uma instância e chama `__call`, que repassa a chamada a um **Eloquent Builder** (`Illuminate\Database\Eloquent\Builder`). Se o Eloquent Builder também não conhece o método, ele repassa ao **Query Builder** (`Illuminate\Database\Query\Builder`), que gera o SQL.

```php [app/Http/Controllers/UserController.php]
User::where('ativo', 1)->orderBy('nome')->get();
-- SQL: select * from "users" where "ativo" = ? order by "nome" asc
//
// User (Model)  -> não tem where()
//   -> Eloquent\Builder -> não tem where() próprio para isso
//     -> Query\Builder::where() monta o SQL
// get() volta ao Eloquent\Builder, que transforma as linhas em objetos User
```

Por isso a lista de "métodos de um Model" é a soma de:

1. Métodos da classe `Model` (save, delete, fresh, toArray…).
2. Métodos do `Eloquent\Builder` (find, first, with, whereHas…).
3. Métodos do `Query\Builder` (where, join, groupBy…).
4. Métodos de **traits** que o Model usa (`SoftDeletes`, `HasFactory`, `HasUuids`…).
5. O que **o seu projeto** criou: scopes, métodos próprios, macros, repositories.

### Estático ou instância?

- **Chamada estática** (`User::find(1)`) inicia uma query nova. Funciona para qualquer método do Builder.
- **Chamada em instância** (`$user->save()`) age sobre aquele registro.
- `User::query()` devolve explicitamente um Eloquent Builder vazio. É útil para montar filtros aos poucos e dá autocompletar melhor na IDE.

```php [app/Http/Controllers/UserController.php]
$query = User::query();
if ($request->filled('nome')) {
    $query->where('nome', 'like', "%{$request->nome}%");
}
$users = $query->get();
-- SQL com o filtro: select * from "users" where "nome"::text like ?
-- SQL sem o filtro: select * from "users"
```

### O que cada chamada devolve

Saber o tipo de retorno evita metade dos erros:

| Chamada | Retorna | Detalhe |
| --- | --- | --- |
| `where()` | O próprio Builder | Só acrescenta a condição; nenhuma query roda ainda |
| `orderBy()` | O próprio Builder | Acrescenta a ordenação; dá para continuar encadeando |
| `with()` | O próprio Builder | Marca relacionamentos para eager loading, carregados quando a query rodar |
| `get()` | `Eloquent\Collection` de Models | Executa a query; vazia (não `null`) se nada casar |
| `all()` | `Eloquent\Collection` de Models | Estático no Model: `select *` sem filtros. Não existe depois de `where()` |
| `first()` | Um Model ou `null` | Executa com `limit 1`; teste o `null` antes de usar |
| `find($id)` | Um Model ou `null` | Busca pela chave primária. Com array de ids (`find([1, 2])`), devolve uma Collection |
| `firstOrFail()` | Um Model, ou lança `ModelNotFoundException` | A exceção vira resposta 404 automaticamente |
| `findOrFail($id)` | Um Model, ou lança `ModelNotFoundException` | Igual ao `find`, sem precisar testar `null` |
| `count()` | `int` | `select count(*)`; não carrega Models |
| `sum('coluna')` | Número (`int`/`float`), `0` se não houver linhas | Agregação feita no banco |
| `exists()` | `bool` | `select exists(...)`: o jeito mais barato de saber se há registro |
| `paginate()` | `LengthAwarePaginator` | Itens da página atual + total e links; faz duas queries (dados e `count`) |
| `create([...])` | O Model criado | Já salvo, com `id` e timestamps preenchidos |
| `save()` | `bool` | Chamado na instância: `true` se gravou, `false` se um evento cancelou |
| `update([...])` em query | `int` | Número de linhas afetadas; não carrega Models nem dispara eventos deles |
| `update([...])` em instância | `bool` | Atualiza aquele registro, dispara eventos `updating`/`updated` |

O erro mais comum é tratar o retorno de uma família como o de outra: chamar `->nome` no resultado de `get()` (é uma Collection, não um Model), ou esperar que `first()` lance 404 (ele devolve `null`). E chamar `where()` sem `get()`/`first()` no fim: você fica com um Builder, e nenhuma query foi feita.

### Como ler este guia

Cada item traz o que faz, a assinatura com os parâmetros explicados e um exemplo. Assinaturas mostram os parâmetros na ordem real; `?` indica opcional. Os recursos marcados com uma versão (por exemplo, *Laravel 11+*) não existem em versões mais antigas. O guia segue o Laravel 11 a 13; a [seção 16.14](#criar-e-configurar-laravel-13-configuração-por-atributos-php) mostra a configuração por atributos PHP introduzida no 13.

Nos exemplos, as linhas `// SQL:` aparecem com fundo e cores próprias: são a consulta que a linha de PHP acima gera no **PostgreSQL**. Dentro de uma cadeia de métodos, `// →` mostra o trecho que aquele método acrescenta. Cada `?` destacado é um *binding*: o valor vai separado do SQL, o que protege contra SQL injection. Para ler só o PHP, desligue o SQL no botão do índice. Para ver o SQL do seu próprio código, use `toRawSql()` ([seção 35](#depuracao)).
