Depois de definido, um relacionamento serve para três coisas: ler os relacionados, filtrar o Model principal pela existência deles, e criar ou ligar registros relacionados.

### Propriedade vs. método

Esta é a distinção mais importante dos relacionamentos:

| Forma | Retorna | Executa query? |
| --- | --- | --- |
| `$user->pedidos` (propriedade) | Collection (ou Model/`null` em hasOne/belongsTo) | Sim, na primeira vez; depois fica em cache no objeto |
| `$user->pedidos()` (método) | Objeto de relação (um Builder) | Não, até você chamar `get()`, `count()` etc. |

```php
$user->pedidos;                                   // todos, carregados e guardados
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null

$user->pedidos()->where('status', 'pago')->get(); // filtra no banco
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null
--      and "status" = ?

$user->pedidos()->count();                        // COUNT no banco (rápido)
-- SQL: select count(*) as aggregate from "pedidos"
--      where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null

$user->pedidos->count();                          // carrega TODOS e conta no PHP (lento)
-- SQL: a primeira query deste bloco; a contagem acontece no PHP
```

### Filtrar pela existência: `has` e `whereHas`

```php
->has(string $relation, string $operator = '>=', int $count = 1, string $boolean = 'and', ?Closure $callback = null)
->whereHas(string $relation, ?Closure $callback = null, string $operator = '>=', int $count = 1)
```

- `$relation`: nome do relacionamento. Aceita ponto para aninhar (`'pedidos.itens'`).
- `$operator` + `$count`: quantos relacionados precisam existir.
- `$callback`: filtros aplicados aos relacionados.

```php
User::has('pedidos')->get();                       // ao menos 1 pedido
-- SQL: select * from "users"
--      where exists (select * from "pedidos" where "users"."id" = "pedidos"."user_id")

User::has('pedidos', '>=', 3)->get();              // 3 ou mais: troca o exists por contagem
-- SQL: select * from "users"
--      where (select count(*) from "pedidos" where "users"."id" = "pedidos"."user_id") >= 3

User::has('pedidos.itens')->get();                 // exists dentro de exists
-- SQL: select * from "users" where exists (
--          select * from "pedidos" where "users"."id" = "pedidos"."user_id"
--          and exists (select * from "itens" where "pedidos"."id" = "itens"."pedido_id")
--      )

User::whereHas('pedidos', function ($q) {
    $q->where('total', '>', 500);                  // → entra dentro do exists
})->get();
-- SQL: select * from "users" where exists (
--          select * from "pedidos" where "users"."id" = "pedidos"."user_id" and "total" > ?
--      )

User::whereHas('pedidos', fn ($q) => $q->where('status', 'pago'), '>=', 2)->get();
-- SQL: select * from "users" where (
--          select count(*) from "pedidos" where "users"."id" = "pedidos"."user_id" and "status" = ?
--      ) >= 2
```

### Negação: `doesntHave` e `whereDoesntHave`

```php
User::doesntHave('pedidos')->get();                                  // nunca comprou
-- SQL: select * from "users"
--      where not exists (select * from "pedidos" where "users"."id" = "pedidos"."user_id")

User::whereDoesntHave('pedidos', fn ($q) => $q->where('status', 'pago'))->get(); // sem pedidos pagos
-- SQL: select * from "users" where not exists (
--          select * from "pedidos" where "users"."id" = "pedidos"."user_id" and "status" = ?
--      )

User::whereDoesntHave('pedidos.itens')->get();
-- SQL: ... where not exists (select * from "pedidos" where ... and exists (select * from "itens" ...))
```

Variações com OR: `orHas`, `orWhereHas`, `orDoesntHave`, `orWhereDoesntHave`.

### Atalho: `whereRelation`

```php
->whereRelation(string $relation, Closure|string|array $column, $operator = null, $value = null)
```

Equivale a `whereHas` com um único `where`, em uma linha.

```php
Post::whereRelation('comentarios', 'aprovado', true)->get();
-- SQL: select * from "posts" where exists (
--          select * from "comentarios" where "posts"."id" = "comentarios"."post_id" and "aprovado" = ?
--      )

Pedido::whereRelation('itens', 'quantidade', '>', 10)->get();
-- SQL: ... where exists (select * from "itens" where "pedidos"."id" = "itens"."pedido_id" and "quantidade" > ?)
```

Variações: `orWhereRelation`, `whereDoesntHaveRelation`, `orWhereDoesntHaveRelation` (versões recentes), `whereMorphRelation`, `orWhereMorphRelation`.

### Polimórficos: `whereHasMorph` e afins

```php
->whereHasMorph(string $relation, string|array $types, ?Closure $callback = null, string $operator = '>=', int $count = 1)
```

- `$types`: classes a considerar; `'*'` para todas.
- O callback recebe `($query, $type)`, permitindo filtros diferentes por tipo.

```php
Comentario::whereHasMorph('comentavel', [Post::class, Video::class], function ($q, $type) {
    $coluna = $type === Post::class ? 'titulo' : 'nome';
    $q->where($coluna, 'like', '%laravel%');
})->get();
-- SQL: um bloco por tipo, unidos com OR
--      select * from "comentarios" where (
--          ("comentarios"."comentavel_type" = ? and exists (
--              select * from "posts" where "comentarios"."comentavel_id" = "posts"."id" and "titulo"::text like ?))
--          or
--          ("comentarios"."comentavel_type" = ? and exists (
--              select * from "videos" where "comentarios"."comentavel_id" = "videos"."id" and "nome"::text like ?))
--      )

Comentario::whereMorphedTo('comentavel', $post)->get();    // de um pai específico
-- SQL: select * from "comentarios"
--      where ("comentarios"."comentavel_type" = ? and "comentarios"."comentavel_id" = ?)
```

Variações: `orWhereHasMorph`, `whereDoesntHaveMorph`, `hasMorph`, `doesntHaveMorph`, `whereNotMorphedTo`.

### Filtrar pelo pai: `whereBelongsTo` e `whereAttachedTo`

```php
Pedido::whereBelongsTo($user)->get();
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ?

Pedido::whereBelongsTo($users)->get();              // aceita Collection
-- SQL: select * from "pedidos" where "pedidos"."user_id" in (?, ?, ?)

Pedido::whereBelongsTo($user, 'comprador')->get();  // nome do relacionamento explícito
-- SQL: select * from "pedidos" where "pedidos"."comprador_id" = ?

Post::whereAttachedTo($tag)->get();                 // belongsToMany (Laravel 12+)
-- SQL: select * from "posts" where exists (
--          select * from "tags" inner join "post_tag" on "tags"."id" = "post_tag"."tag_id"
--          where "posts"."id" = "post_tag"."post_id" and "tags"."id" in (?)
--      )
```

### Criar relacionados: `save`, `create` e variantes

Funcionam em `hasOne`, `hasMany`, `morphOne`, `morphMany` e `belongsToMany`. Preenchem a chave estrangeira por você.

| Método | Recebe | Efeito |
| --- | --- | --- |
| `save(Model $model)` | Instância | Define a FK e salva |
| `saveMany(iterable $models)` | Várias instâncias | Idem, para cada uma |
| `create(array $attributes)` | Array | Cria com a FK preenchida (respeita `$fillable`) |
| `createMany(iterable $records)` | Lista de arrays | Cria vários |
| `createQuietly` / `createManyQuietly` / `saveQuietly` / `saveManyQuietly` | Idem | Sem eventos |
| `forceCreate(array $attributes)` | Array | Ignora `$fillable` |
| `firstOrNew`, `firstOrCreate`, `updateOrCreate` | Como na [seção 21](#inserir-e-atualizar) | Restritos aos relacionados |

```php
$user->pedidos()->create(['total' => 150]);          // a FK entra sozinha
-- SQL: insert into "pedidos" ("total", "user_id", "updated_at", "created_at")
--      values (?, ?, ?, ?) returning "id"

$user->pedidos()->save(new Pedido(['total' => 90]));
-- SQL: o mesmo insert

$post->comentarios()->createMany([
    ['texto' => 'Ótimo'],
    ['texto' => 'Concordo'],
]);
-- SQL: um insert por item

$user->perfil()->updateOrCreate([], ['bio' => 'Dev']);  // hasOne: cria ou atualiza o único perfil
-- SQL: select * from "perfis" where "perfis"."user_id" = ? and "perfis"."user_id" is not null limit 1
--      depois update "perfis" set "bio" = ?, ... where "id" = ?   (ou insert, se não existir)
```

No `belongsToMany`, `save` e `create` aceitam um segundo argumento com dados do pivô: `$user->roles()->create(['nome' => 'editor'], ['expira_em' => $data])`.

### `belongsTo`: `associate` e `dissociate`

```php
$pedido->cliente()->associate($cliente);   // sem SQL: só preenche cliente_id em memória
$pedido->save();
-- SQL: update "pedidos" set "cliente_id" = ?, "updated_at" = ? where "id" = ?

$pedido->cliente()->dissociate();          // cliente_id = null em memória
$pedido->save();
-- SQL: update "pedidos" set "cliente_id" = ?, "updated_at" = ? where "id" = ?   (? = null)
```

`associate` aceita o Model ou o id. Lembre de chamar `save()`.

### `belongsToMany`: ligar e desligar

Todos aceitam id, array de ids, Model ou Collection. Alteram só a tabela pivô.

| Método | Assinatura | Efeito |
| --- | --- | --- |
| `attach` | `attach($ids, array $attributes = [], bool $touch = true)` | Insere linhas no pivô. Não verifica duplicados |
| `detach` | `detach($ids = null, bool $touch = true)` | Remove ligações; sem argumento remove **todas** |
| `sync` | `sync($ids, bool $detaching = true)` | Deixa o pivô **exatamente** com estes ids: adiciona os novos e remove os ausentes |
| `syncWithoutDetaching` | `syncWithoutDetaching($ids)` | Adiciona os que faltam, não remove nada |
| `syncWithPivotValues` | `syncWithPivotValues($ids, array $values, bool $detaching = true)` | `sync` aplicando os mesmos valores de pivô a todos |
| `toggle` | `toggle($ids, bool $touch = true)` | Liga os desligados e desliga os ligados |
| `updateExistingPivot` | `updateExistingPivot($id, array $attributes, bool $touch = true)` | Altera colunas do pivô de uma ligação existente |

```php
$user->roles()->attach(1);
-- SQL: insert into "role_user" ("role_id", "user_id") values (?, ?)

$user->roles()->attach([1, 2], ['expira_em' => now()->addYear()]);
-- SQL: insert into "role_user" ("expira_em", "role_id", "user_id") values (?, ?, ?), (?, ?, ?)

$user->roles()->attach([
    1 => ['expira_em' => $data1],      // valores diferentes por id
    2 => ['expira_em' => $data2],
]);

$user->roles()->detach(3);
-- SQL: delete from "role_user" where "role_user"."user_id" = ? and "role_user"."role_id" in (3)

$user->roles()->detach();               // remove todas
-- SQL: delete from "role_user" where "role_user"."user_id" = ?

$retorno = $user->roles()->sync([1, 2, 5]);
// ['attached' => [5], 'detached' => [3], 'updated' => []]
-- SQL: lê o que existe e aplica só a diferença
--      select * from "role_user" where "role_user"."user_id" = ?
--      delete from "role_user" where "role_user"."user_id" = ? and "role_user"."role_id" in (3)
--      insert into "role_user" ("role_id", "user_id") values (?, ?)      -- só o 5

$user->roles()->sync([1 => ['ativo' => true], 2 => ['ativo' => false]]);
$user->roles()->syncWithoutDetaching([7]);       // como sync, mas sem o delete
$post->curtidas()->toggle(auth()->id());         // insert se não existe, delete se existe

$user->roles()->updateExistingPivot($roleId, ['ativo' => false]);
-- SQL: update "role_user" set "ativo" = ? where "role_user"."user_id" = ? and "role_id" in (?)
```

`$touch = true` faz o `updated_at` do pai ser atualizado quando o pivô muda (se `$touches` estiver configurado).

### Pertence a este pai?

```php
$post->autor()->is($user);      // compara sem consultar o banco
$post->autor()->isNot($user);
$user->roles()->where('roles.id', $roleId)->exists();  // belongsToMany
$user->roles->contains($roleId);                        // na Collection já carregada
```
