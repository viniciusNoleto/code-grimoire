Middleware é uma camada que envolve a requisição: roda código antes de ela chegar ao controller, depois que a resposta é gerada, ou interrompe o fluxo (por exemplo, devolvendo 401).

### Estrutura

```bash
php artisan make:middleware GarantirAssinaturaAtiva
```

```php [app/Http/Middleware/GarantirAssinaturaAtiva.php]
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class GarantirAssinaturaAtiva
{
    public function handle(Request $request, Closure $next): Response
    {
        if (! $request->user()?->assinaturaAtiva()) {
            return redirect()->route('planos');     // interrompe: o controller não roda
        }

        $response = $next($request);                // passa para a próxima camada

        $response->headers->set('X-Plano', $request->user()->plano);  // depois do controller
        return $response;
    }
}
```

### Registrar e aplicar

:version[Laravel 11+] Tudo em `bootstrap/app.php`:

```php [bootstrap/app.php]
return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(web: __DIR__.'/../routes/web.php')
    ->withMiddleware(function (Middleware $middleware): void {
    $middleware->append(RegistrarTempoDeResposta::class);        // global, no fim da fila
    $middleware->prepend(ForcarJson::class);                     // global, no início
    $middleware->web(append: [DefinirIdioma::class]);            // grupo web
    $middleware->api(prepend: [ForcarJson::class]);              // grupo api
    $middleware->alias(['assinante' => GarantirAssinaturaAtiva::class]);
    $middleware->priority([...]);                                // ordem relativa forçada
    })
    ->create();
```

```php [routes/web.php]
Route::get('/painel', ...)->middleware('assinante');
Route::get('/painel', ...)->middleware(['auth', GarantirAssinaturaAtiva::class]);
Route::get('/publico', ...)->withoutMiddleware(['auth']);
```

### Parâmetros

Um middleware pode receber argumentos vindos da rota. Eles chegam no `handle()` depois de `$request` e `$next`, sempre como **strings**. Na rota, os argumentos vão depois de `:` e são separados por vírgula.

```php [app/Http/Middleware/ExigirPapel.php]
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class ExigirPapel
{
    public function handle(Request $request, Closure $next, string ...$papeis): Response
    {
        abort_unless($request->user()->temAlgumPapel($papeis), 403);

        return $next($request);
    }
}
```

```php [bootstrap/app.php]
return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(web: __DIR__.'/../routes/web.php')
    ->withMiddleware(function (Middleware $middleware): void {
        $middleware->alias(['papel' => ExigirPapel::class]);
    })
    ->create();
```

```php [routes/web.php]
Route::get('/admin', ...)->middleware('papel:admin,editor');   // $papeis = ['admin', 'editor']
```

#### `abort_unless` e a família `abort`

`abort_unless($condicao, $status)` lê-se "aborte, **a menos que** a condição seja verdadeira". Se a condição for `false`, ele lança uma `HttpException` com o status informado e a execução para ali: nem o `return $next(...)` nem o controller rodam. O Laravel transforma essa exceção na resposta de erro (a página `errors/403.blade.php` no site, ou `{"message": "..."}` em JSON para requisições de API).

```php [app/Http/Middleware/ExigirPapel.php]
abort_unless($request->user()->temAlgumPapel($papeis), 403);

// é o mesmo que:
if (! $request->user()->temAlgumPapel($papeis)) {
    abort(403);
}
```

| Helper | Aborta quando | Exemplo |
| --- | --- | --- |
| `abort($status, $mensagem)` | Sempre | `abort(404, 'Pedido não encontrado')` |
| `abort_if($cond, $status)` | A condição é **verdadeira** | `abort_if($pedido->cancelado, 410)` |
| `abort_unless($cond, $status)` | A condição é **falsa** | `abort_unless($user->is_admin, 403)` |

`abort_if` e `abort_unless` são espelhos: escolha o que deixa a frase mais natural. "Aborte se o pedido estiver cancelado" é `abort_if`; "aborte a menos que seja admin" é `abort_unless`. Ambos aceitam uma mensagem e cabeçalhos: `abort_unless($ok, 403, 'Sem permissão', ['X-Motivo' => 'papel'])`.

### Middleware terminável

Às vezes você quer fazer algo **depois** que o usuário já recebeu a resposta, para não deixá-lo esperando: gravar métricas, registrar auditoria, enviar dados para um serviço de analytics. Código colocado depois do `$next($request)` no `handle()` ainda roda antes da resposta ser enviada. Já o método `terminate()` roda depois que a resposta foi entregue ao cliente.

```php [app/Http/Middleware/RegistrarTempoDeResposta.php]
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Log;
use Symfony\Component\HttpFoundation\Response;

class RegistrarTempoDeResposta
{
    private float $inicio;

    public function handle(Request $request, Closure $next): Response
    {
        $this->inicio = microtime(true);

        return $next($request);
    }

    public function terminate(Request $request, Response $response): void
    {
        // o usuário já recebeu a página; isto não atrasa nada para ele
        Log::info('tempo de resposta', [
            'rota' => $request->path(),
            'status' => $response->getStatusCode(),
            'ms' => round((microtime(true) - $this->inicio) * 1000),
        ]);
    }
}
```

Por padrão, o Laravel cria **uma instância nova** do middleware para chamar o `terminate()`, diferente da que rodou o `handle()`. No exemplo, `$this->inicio` estaria vazio. Para o `terminate` receber a mesma instância usada no `handle`, registre o middleware como singleton no container:

```php [app/Providers/AppServiceProvider.php]
class AppServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->singleton(RegistrarTempoDeResposta::class);
    }
}
```

Casos de uso: log de tempo de resposta, auditoria ("usuário X acessou Y"), contagem de visualizações, limpeza de arquivos temporários gerados na requisição.

::note{type="pitfall" title="Cuidado"}
O envio antecipado da resposta depende do servidor: funciona no PHP-FPM (que tem `fastcgi_finish_request()`). No `php artisan serve` e em alguns servidores, o cliente espera o `terminate()` terminar. Para trabalho pesado, use um job na fila em vez de `terminate()`.
::

### Middlewares nativos que você vai usar

| Alias | O que faz |
| --- | --- |
| `auth` / `auth:sanctum` | Exige usuário autenticado (no guard indicado) |
| `guest` | Só para não autenticados (telas de login) |
| `verified` | E-mail verificado |
| `can:update,post` | Autorização via policy ([seção 37](#autorizacao)) |
| `throttle:api` | Rate limit |
| `signed` | URL assinada válida |
| `password.confirm` | Pede a senha de novo antes de ações sensíveis |
| `cache.headers:public;max_age=3600;etag` | Cabeçalhos de cache HTTP |

#### `password.confirm`: confirmar a senha antes de ações sensíveis

Estar logado não basta para tudo. Se alguém deixa o computador desbloqueado, outra pessoa pode usar a sessão aberta para trocar o e-mail da conta, ver chaves de API ou excluir a conta. O middleware `password.confirm` pede que o usuário **digite a senha de novo** antes de acessar a rota, mesmo já autenticado.

Como funciona:

1. O usuário acessa uma rota protegida, por exemplo `/configuracoes/seguranca`.
2. O middleware verifica na sessão a chave `auth.password_confirmed_at`. Se ela não existe ou é mais antiga que o prazo, redireciona para a rota nomeada `password.confirm`, guardando a URL pretendida.
3. O usuário digita a senha; a sua rota de confirmação confere com `Hash::check()`, grava o horário na sessão com `$request->session()->passwordConfirmed()` e redireciona de volta.
4. Pelas próximas 3 horas (configurável), outras rotas com `password.confirm` passam direto.

```php [routes/web.php]
Route::get('/configuracoes/seguranca', [SegurancaController::class, 'show'])
    ->middleware(['auth', 'password.confirm']);

// tela e envio da confirmação (os starter kits já trazem prontas)
Route::get('/confirmar-senha', fn () => view('auth.confirm-password'))
    ->middleware('auth')->name('password.confirm');

Route::post('/confirmar-senha', function (Request $request) {
    if (! Hash::check($request->password, $request->user()->password)) {
        return back()->withErrors(['password' => 'Senha incorreta.']);
    }

    $request->session()->passwordConfirmed();   // grava auth.password_confirmed_at = agora

    return redirect()->intended();              // volta para a página que pediu a confirmação
})->middleware(['auth', 'throttle:6,1']);
```

O prazo fica em `config/auth.php`, na chave `password_timeout` (em segundos, padrão 10800 = 3 horas). Também dá para passar um prazo por rota: `password.confirm:password.confirm,300` (rota de confirmação, 5 minutos).

Os grupos `web` e `api` já incluem cookies, sessão, proteção CSRF (só `web`) e `SubstituteBindings` (que faz o route model binding).
