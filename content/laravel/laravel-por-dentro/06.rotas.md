Uma rota liga um método HTTP e uma URL a um controller ou closure. As rotas web ficam em `routes/web.php` (com sessão, cookies e CSRF) e as de API em `routes/api.php` (sem estado, prefixo `/api`).

### Definindo rotas

```php [routes/web.php]
use Illuminate\Support\Facades\Route;

Route::get('/pedidos', [PedidoController::class, 'index']);
Route::post('/pedidos', [PedidoController::class, 'store']);
Route::put('/pedidos/{pedido}', [PedidoController::class, 'update']);
Route::patch('/pedidos/{pedido}', ...);
Route::delete('/pedidos/{pedido}', ...);

Route::match(['get', 'post'], '/busca', BuscaController::class);   // controller de ação única
Route::any('/webhook', WebhookController::class);

Route::redirect('/antigo', '/novo', 301);
Route::view('/sobre', 'paginas.sobre', ['ano' => 2026]);   // devolve uma view sem controller
```

Formulários HTML só enviam GET e POST. Para PUT, PATCH e DELETE, envie POST com `@method('PUT')` no Blade.

### Parâmetros e restrições

```php [routes/web.php]
Route::get('/usuarios/{id}', fn (string $id) => ...);
Route::get('/usuarios/{nome?}', fn (?string $nome = 'visitante') => ...);   // opcional

Route::get('/pedidos/{id}', ...)->whereNumber('id');
Route::get('/arquivos/{uuid}', ...)->whereUuid('uuid');
Route::get('/categoria/{tipo}', ...)->whereIn('tipo', ['livro', 'filme']);
Route::get('/posts/{slug}', ...)->where('slug', '[a-z0-9-]+');
```

Uma restrição global, que vale para todas as rotas com `{id}`, fica no provider:

```php [app/Providers/AppServiceProvider.php]
class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Route::pattern('id', '[0-9]+');
    }
}
```

### Nomes e geração de URLs

Dê nome às rotas e gere URLs pelo nome. Assim, mudar o caminho não quebra links.

```php [routes/web.php]
Route::get('/pedidos/{pedido}', [PedidoController::class, 'show'])->name('pedidos.show');
```

```php [app/Http/Controllers/PedidoController.php]
route('pedidos.show', $pedido);                        // http://app.test/pedidos/10
route('pedidos.show', ['pedido' => 10, 'aba' => 'itens']);  // parâmetros extras viram query string
url('/ajuda');                                         // URL absoluta de um caminho
to_route('pedidos.show', $pedido);                     // resposta de redirecionamento

request()->routeIs('pedidos.*');                       // a rota atual casa com o padrão?
```

#### URLs assinadas

Uma URL assinada é uma URL comum com um parâmetro extra, `signature`, calculado com a `APP_KEY` da aplicação (um HMAC) a partir da URL inteira, incluindo os outros parâmetros. Quem recebe o link consegue usá-lo, mas não consegue alterá-lo: trocar `pedido=10` por `pedido=11` muda a URL, e a assinatura deixa de bater. Como só o servidor conhece a `APP_KEY`, ninguém de fora consegue gerar uma assinatura válida.

Isso permite liberar uma ação **sem exigir login**, só para quem recebeu o link. Casos de uso típicos:

- Link de "cancelar inscrição" no rodapé de um e-mail marketing.
- Download de um recibo ou boleto enviado por e-mail.
- Confirmação de e-mail (o próprio Laravel usa URL assinada no `verification.verify`).
- Convite para entrar numa equipe, válido por 48 horas.

```php [app/Mail/ReciboDisponivel.php]
use Illuminate\Support\Facades\URL;

// permanente: vale enquanto a APP_KEY não mudar
$url = URL::signedRoute('newsletter.sair', ['assinante' => 42]);
// https://loja.com/newsletter/sair/42?signature=7b3c...

// temporária: acrescenta ?expires=<timestamp>, também protegido pela assinatura
$url = URL::temporarySignedRoute('pedidos.recibo', now()->addHour(), ['pedido' => 10]);
// https://loja.com/recibo/10?expires=1767225600&signature=a91f...
```

A validação é feita pelo middleware `signed`, que devolve **403** se a assinatura não bater ou se o `expires` já passou:

```php [routes/web.php]
Route::get('/recibo/{pedido}', [ReciboController::class, 'show'])
    ->name('pedidos.recibo')
    ->middleware('signed');

Route::get('/newsletter/sair/{assinante}', [NewsletterController::class, 'sair'])
    ->name('newsletter.sair')
    ->middleware('signed');
```

Também dá para validar à mão, por exemplo para mostrar uma página amigável em vez do 403:

```php [app/Http/Controllers/ReciboController.php]
class ReciboController extends Controller
{
    public function show(Request $request, Pedido $pedido)
    {
        if (! $request->hasValidSignature()) {
            return view('recibo.link-expirado');
        }

        return Storage::download($pedido->recibo_path);
    }
}
```

| Recurso | O que faz |
| --- | --- |
| `URL::signedRoute($nome, $params)` | Assinatura sem prazo |
| `URL::temporarySignedRoute($nome, $prazo, $params)` | Assinatura que expira |
| `middleware('signed')` | 403 se inválida ou expirada |
| `middleware('signed:relative')` + `absolute: false` | Assina só o caminho, ignorando o domínio (útil atrás de proxy que muda o host) |
| `$request->hasValidSignature()` | Valida manualmente |
| `$request->hasValidSignatureWhileIgnoring(['utm_source'])` | Valida ignorando parâmetros que serviços de e-mail acrescentam |

::note{type="pitfall" title="Cuidado"}
Trocar a `APP_KEY` invalida todas as URLs assinadas já enviadas. E a URL assinada não identifica quem a usa: qualquer pessoa com o link tem acesso. Não use para ações que precisam saber qual usuário está agindo.
::

### Grupos

Grupos aplicam atributos comuns a várias rotas:

```php [routes/web.php]
Route::middleware(['auth', 'verified'])
    ->prefix('admin')                 // URLs começam com /admin
    ->name('admin.')                  // nomes começam com admin.
    ->group(function () {
        Route::get('/relatorios', ...)->name('relatorios');   // admin.relatorios

        Route::controller(PedidoAdminController::class)->group(function () {
            Route::get('/pedidos', 'index');                   // método do controller pelo nome
            Route::post('/pedidos/{pedido}/cancelar', 'cancelar');
        });
    });

Route::domain('{loja}.meusite.com')->group(...);   // roteamento por subdomínio
```

### Route model binding

Quando o parâmetro da rota tem o mesmo nome de uma variável tipada com um Model, o Laravel busca o registro e responde 404 se não existir.

```php [routes/web.php]
Route::get('/posts/{post}', fn (Post $post) => $post);          // busca por id
Route::get('/posts/{post:slug}', fn (Post $post) => $post);     // busca por outra coluna

// escopo: o comentário precisa pertencer ao post
Route::get('/posts/{post}/comentarios/{comentario:slug}', fn (Post $post, Comentario $comentario) => ...)
    ->scopeBindings();

Route::get('/posts/{post}', ...)->withTrashed();                 // inclui soft deleted

Route::get('/posts/{post:slug}', ...)
    ->missing(fn (Request $r) => to_route('posts.index'));        // em vez de 404

Route::get('/categorias/{categoria}', fn (Categoria $categoria) => ...);  // enum PHP: 404 se o valor não existir no enum
```

O comportamento padrão de busca é configurável no Model com `getRouteKeyName()` ou `resolveRouteBinding()` ([seção 16.12](#criar-e-configurar-chave-usada-nas-rotas)).

### Rotas de recurso

Uma única linha registra as sete rotas de um CRUD, todas apontando para métodos de nome padronizado no controller.

```php [routes/web.php]
Route::resource('pedidos', PedidoController::class);
Route::apiResource('pedidos', PedidoController::class);          // sem create e edit
Route::resource('pedidos', PedidoController::class)->only(['index', 'show']);
Route::resource('pedidos', PedidoController::class)->except(['destroy']);
```

| Verbo | URL | Método | Nome |
| --- | --- | --- | --- |
| GET | `/pedidos` | `index` | `pedidos.index` |
| GET | `/pedidos/create` | `create` | `pedidos.create` |
| POST | `/pedidos` | `store` | `pedidos.store` |
| GET | `/pedidos/{pedido}` | `show` | `pedidos.show` |
| GET | `/pedidos/{pedido}/edit` | `edit` | `pedidos.edit` |
| PUT/PATCH | `/pedidos/{pedido}` | `update` | `pedidos.update` |
| DELETE | `/pedidos/{pedido}` | `destroy` | `pedidos.destroy` |

#### Recursos aninhados e `shallow()`

Quando um recurso só existe dentro de outro (os itens de um pedido), o nome com ponto cria rotas aninhadas: `pedidos.itens` gera URLs como `/pedidos/{pedido}/itens/{item}`.

```php [routes/web.php]
Route::resource('pedidos.itens', ItemController::class)
    ->parameters(['itens' => 'item']);   // ver a nota abaixo sobre o singular
```

O problema: para ver, editar ou excluir um item, o id do item já basta, porque ele é único na tabela. Exigir o pedido na URL (`/pedidos/5/itens/31`) só deixa a URL mais longa e abre a chance de inconsistência (item 31 com pedido 6 na URL). O `shallow()` ("raso") resolve isso: mantém o pai na URL **só onde ele é necessário**, nas ações que trabalham com a coleção (listar e criar, porque o item novo ainda não tem id e precisa saber a qual pedido pertence). As ações sobre um item específico ficam diretas.

```php [routes/web.php]
Route::resource('pedidos.itens', ItemController::class)
    ->parameters(['itens' => 'item'])
    ->shallow();
```

| Verbo | Sem `shallow()` | Com `shallow()` | Nome com `shallow()` |
| --- | --- | --- | --- |
| GET | `/pedidos/{pedido}/itens` | `/pedidos/{pedido}/itens` | `pedidos.itens.index` |
| GET | `/pedidos/{pedido}/itens/create` | `/pedidos/{pedido}/itens/create` | `pedidos.itens.create` |
| POST | `/pedidos/{pedido}/itens` | `/pedidos/{pedido}/itens` | `pedidos.itens.store` |
| GET | `/pedidos/{pedido}/itens/{item}` | `/itens/{item}` | `itens.show` |
| GET | `/pedidos/{pedido}/itens/{item}/edit` | `/itens/{item}/edit` | `itens.edit` |
| PUT/PATCH | `/pedidos/{pedido}/itens/{item}` | `/itens/{item}` | `itens.update` |
| DELETE | `/pedidos/{pedido}/itens/{item}` | `/itens/{item}` | `itens.destroy` |

Os métodos do controller mudam de assinatura conforme a rota: os que mantêm o pai recebem o pedido, os rasos não.

```php [app/Http/Controllers/ItemController.php]
class ItemController extends Controller
{
    public function index(Pedido $pedido) { return $pedido->itens; }

    public function store(Request $request, Pedido $pedido) { return $pedido->itens()->create($request->validated()); }

    public function show(Item $item) { return $item; }          // sem o pedido

    public function destroy(Item $item) { $item->delete(); }    // sem o pedido
}
```

::note{type="pitfall" title="Nomes em português"}
O Laravel tira o singular do nome do recurso com regras do inglês: `itens` vira `iten`, e o parâmetro da rota fica `{iten}`. Com `->parameters(['itens' => 'item'])` você define o nome certo, e o route model binding volta a casar com a variável `$item`.
::

### Rate limiting nas rotas

Os limites nomeados são definidos no método `boot()` do `AppServiceProvider` com a facade `RateLimiter`, e aplicados nas rotas com o middleware `throttle`:

```php [app/Providers/AppServiceProvider.php]
namespace App\Providers;

use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        RateLimiter::for('api', function (Request $request) {
            return $request->user()
                ? Limit::perMinute(120)->by($request->user()->id)
                : Limit::perMinute(30)->by($request->ip());
        });

        RateLimiter::for('login', fn (Request $r) => [
            Limit::perMinute(5)->by($r->input('email').$r->ip()),
            Limit::perHour(100)->by($r->ip()),                    // vários limites ao mesmo tempo
        ]);
    }
}
```

```php [routes/web.php]
Route::post('/login', ...)->middleware('throttle:login');
Route::middleware('throttle:60,1')->group(...);          // 60 por minuto, sem limiter nomeado
```

Ao estourar, o cliente recebe 429 com os cabeçalhos `Retry-After` e `X-RateLimit-*`.

#### Rota de fallback

Quando nenhuma rota casa com a URL pedida, o Laravel responde 404 com a página de erro padrão. `Route::fallback()` registra uma rota que roda **nesse caso**, antes do 404 genérico: ela é sempre avaliada por último, não importa em que linha do arquivo foi declarada.

```php [routes/api.php]
// API: devolve JSON no formato da sua API em vez da página HTML de 404
Route::fallback(fn () => response()->json(['message' => 'Rota não encontrada'], 404));
```

```php [routes/web.php]
// site: página "não encontrado" própria, com o layout do site
Route::fallback(fn () => response()->view('erros.nao-encontrado', [], 404));

// SPA: qualquer URL desconhecida devolve o app, e o roteador do front decide
Route::fallback(fn () => view('app'));
```

Diferenças importantes:

- A fallback passa pelo middleware do arquivo em que foi declarada (`web` em `routes/web.php`), então tem sessão, usuário logado e cookies. A página de erro `resources/views/errors/404.blade.php` não passa por tudo isso.
- Ela só pega URLs que **não casaram com nenhuma rota**. Um `findOrFail()` ou um route model binding que não acha o registro continua gerando o 404 padrão, não a fallback.
- Não esqueça o status: sem o `404` explícito, a resposta sai com 200, e buscadores indexam a página como conteúdo válido.
