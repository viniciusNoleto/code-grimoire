Todo filtro devolve o próprio Builder, então você encadeia quantos quiser; filtros encadeados viram `AND`, e as versões `or...` viram `OR`.

### `where()` e seus parâmetros

```php
->where(Closure|string|array $column, mixed $operator = null, mixed $value = null, string $boolean = 'and')
```

- **`$column`**: nome da coluna (aceita `tabela.coluna` e `coluna->chave_json`), um array de condições ou uma Closure para agrupar.
- **`$operator`**: `=`, `<`, `>`, `<=`, `>=`, `<>`, `!=`, `like`, `not like`, `ilike` (PostgreSQL), `between` não (use `whereBetween`). Com **dois** argumentos, o segundo é o valor e o operador é `=`.
- **`$value`**: o valor comparado. É enviado como *binding* (protegido contra SQL injection). Pode ser uma Closure ou Builder para comparar com uma subquery.
- **`$boolean`**: `'and'` ou `'or'`; é o que `orWhere` passa por baixo. Raramente você o usa diretamente.

```php
User::where('ativo', true);
-- SQL: where "ativo" = ?

User::where('idade', '>=', 18);
-- SQL: where "idade" >= ?

User::where('nome', 'like', 'Ana%');
-- SQL: where "nome"::text like ?

User::where('config->tema', 'escuro');      // coluna JSON
-- SQL: where ("config"->>'tema') = ?
```

**Forma de array** (várias condições `AND` de uma vez):

```php
User::where(['ativo' => true, 'tipo' => 'admin']);           // chave => valor
-- SQL: where ("ativo" = ? and "tipo" = ?)

User::where([['idade', '>', 18], ['cidade', '=', 'Manaus']]); // [coluna, operador, valor]
-- SQL: where ("idade" > ? and "cidade" = ?)
```

**Comparar com `null`**: `where('coluna', null)` vira `IS NULL`. Mesmo assim, prefira `whereNull` pela clareza.

**Subquery como valor:**

```php
Pedido::where('total', '>', fn ($q) => $q->selectRaw('avg(total)')->from('pedidos'));
-- SQL: select * from "pedidos" where "total" > (select avg(total) from "pedidos")
```

### `orWhere()` e agrupamento com Closure

`orWhere` tem a mesma assinatura (sem `$boolean`). Cuidado com a precedência: `AND` liga mais forte que `OR`.

```php
// ERRADO: traz gerentes inativos
User::where('ativo', 1)->where('tipo', 'admin')->orWhere('tipo', 'gerente');
-- SQL: select * from "users" where "ativo" = ? and "tipo" = ? or "tipo" = ?

// CERTO
User::where('ativo', 1)->where(function ($q) {
    $q->where('tipo', 'admin')->orWhere('tipo', 'gerente');
});
-- SQL: select * from "users" where "ativo" = ? and ("tipo" = ? or "tipo" = ?)
```

A Closure recebe um Builder novo; o que você coloca nele vira um bloco entre parênteses. Regra prática: **sempre agrupe**\*\* \*\***`orWhere` dentro de uma Closure** quando houver outros filtros.

### Negação: `whereNot()` / `orWhereNot()`

Nega uma condição ou um grupo inteiro.

```php
Produto::whereNot('status', 'arquivado');
-- SQL: select * from "produtos" where not "status" = ?

Produto::whereNot(fn ($q) => $q->where('liquidacao', true)->orWhere('preco', '<', 10));
-- SQL: select * from "produtos" where not ("liquidacao" = ? or "preco" < ?)
```

### Mesma condição em várias colunas: `whereAny`, `whereAll`, `whereNone`

:version[Laravel 10.47+ (whereNone 11+)]

```php
->whereAny(array $columns, $operator = null, $value = null, $boolean = 'and')
```

```php
User::whereAny(['nome', 'email', 'telefone'], 'like', "%{$busca}%");
-- SQL: where ("nome"::text like ? or "email"::text like ? or "telefone"::text like ?)

Post::whereAll(['titulo', 'conteudo'], 'like', '%laravel%');
-- SQL: where ("titulo"::text like ? and "conteudo"::text like ?)

Post::whereNone(['titulo', 'conteudo'], 'like', '%spam%');
-- SQL: where not ("titulo"::text like ? or "conteudo"::text like ?)
```

Há também `orWhereAny`, `orWhereAll` e `orWhereNone`.

### Listas: `whereIn` / `whereNotIn`

```php
->whereIn(string $column, mixed $values, string $boolean = 'and', bool $not = false)
```

`$values` pode ser array, Collection, Closure ou Builder (subquery).

```php
User::whereIn('id', [1, 2, 3]);
-- SQL: where "id" in (?, ?, ?)

User::whereNotIn('status', ['banido', 'suspenso']);
-- SQL: where "status" not in (?, ?)

User::whereIn('id', Pedido::select('user_id')->where('total', '>', 1000)); // subquery
-- SQL: where "id" in (select "user_id" from "pedidos" where "total" > ?)

User::whereIntegerInRaw('id', [1, 2, 3]);
-- SQL: where "id" in (1, 2, 3)   (sem bindings)
```

Com array vazio, `whereIn('id', [])` gera `where 0 = 1` (nada é retornado) e `whereNotIn('id', [])` gera `where 1 = 1`.

Variações: `orWhereIn`, `orWhereNotIn`, e `whereIntegerInRaw` / `whereIntegerNotInRaw` (para listas enormes de inteiros, sem bindings; mais rápido).

### Nulos: `whereNull` / `whereNotNull`

```php
->whereNull(string|array $columns, string $boolean = 'and', bool $not = false)
```

```php
User::whereNull('email_verified_at');
-- SQL: where "email_verified_at" is null

User::whereNotNull(['telefone', 'cpf']);   // array = todas as colunas
-- SQL: where "telefone" is not null and "cpf" is not null
```

Com `or`: `orWhereNull`, `orWhereNotNull`.

### Intervalos: `whereBetween` e companhia

```php
->whereBetween(string $column, iterable $values, string $boolean = 'and', bool $not = false)
```

`$values` = `[mínimo, máximo]`, inclusivos.

```php
Pedido::whereBetween('total', [100, 500]);
-- SQL: where "total" between ? and ?

Pedido::whereNotBetween('created_at', [$inicio, $fim]);
-- SQL: where "created_at" not between ? and ?

Pedido::whereBetweenColumns('pago_em', ['criado_em', 'vence_em']); // entre duas colunas
-- SQL: where "pago_em" between "criado_em" and "vence_em"

Pedido::whereValueBetween(150, ['minimo', 'maximo']);  // valor entre colunas (Laravel 12+)
-- SQL: where ? between "minimo" and "maximo"
```

Variações `or...` e `...Not...` existem para todas.

### Datas

Extraem a parte da data/hora da coluna antes de comparar. Todas aceitam `(coluna, operador, valor)` ou `(coluna, valor)`.

| Método | Compara |
| --- | --- |
| `whereDate('created_at', '2026-10-31')` | Só a data |
| `whereMonth('created_at', '10')` | Mês |
| `whereDay('created_at', '31')` | Dia do mês |
| `whereYear('created_at', '>=', 2025)` | Ano |
| `whereTime('created_at', '>', '18:00')` | Hora |

```sql
where "created_at"::date = ?                 -- whereDate
where extract(month from "created_at") = ?   -- whereMonth
where extract(day from "created_at") = ?     -- whereDay
where extract(year from "created_at") >= ?   -- whereYear
where "created_at"::time > ?                 -- whereTime
where "vence_em" < ?                         -- wherePast (? = agora)
where "vence_em"::date = ?                   -- whereToday
```

Atalhos relativos ao momento atual (*Laravel 11+*): `wherePast('vence_em')`, `whereFuture('vence_em')`, `whereNowOrPast(...)`, `whereNowOrFuture(...)`, `whereToday(...)`, `whereBeforeToday(...)`, `whereAfterToday(...)`, `whereTodayOrBefore(...)`, `whereTodayOrAfter(...)`. Aceitam array de colunas.

::note{type="pitfall" title="Desempenho"}
Funções como `DATE(coluna)` impedem o uso de índices. Em tabelas grandes, prefira `whereBetween('created_at', [$inicioDia, $fimDia])`.
::

### Coluna contra coluna: `whereColumn`

```php
->whereColumn(string|array $first, ?string $operator = null, ?string $second = null, ?string $boolean = 'and')
```

```php
Pedido::whereColumn('updated_at', '>', 'created_at');
-- SQL: where "updated_at" > "created_at"

Pedido::whereColumn([['pago', '=', 'total'], ['updated_at', '>', 'created_at']]);
-- SQL: where ("pago" = "total" and "updated_at" > "created_at")
```

`orWhereColumn` também existe.

### Texto: `whereLike` e busca full-text

*`whereLike` é Laravel 11+.*

```php
->whereLike(string $column, string $value, bool $caseSensitive = false)
```

```php
User::whereLike('nome', '%silva%');                       // sem diferenciar maiúsculas
-- SQL: where "nome"::text ilike ?

User::whereLike('codigo', 'AB%', caseSensitive: true);
-- SQL: where "codigo"::text like ?

User::whereNotLike('email', '%@teste.com');
-- SQL: where "email"::text not ilike ?
```

Variações: `orWhereLike`, `orWhereNotLike`.

#### Busca full-text: o que é e para que serve

Full-text é um tipo de **índice especial para texto** que permite buscar por palavras de forma rápida e com noção de relevância. Ele existe para resolver os limites do `LIKE '%termo%'` em colunas de texto longo, como descrições, artigos e comentários.

**Por que `LIKE` não basta.** Um índice comum (B-tree) organiza os valores pelo início do texto, como um dicionário. Com `LIKE 'lara%'` o banco consegue usá-lo; com `LIKE '%laravel%'` (curinga no começo) não, e precisa ler **todas as linhas** da tabela e procurar o trecho dentro de cada texto. Além disso, o `LIKE` compara caracteres literalmente: não sabe o que é uma palavra, não ordena por relevância e não acha "relacionamentos eloquent" num texto que diz "Eloquent e seus relacionamentos".

**Como o índice full-text funciona.** Ao criar o índice, o banco quebra o texto de cada linha em palavras (*tokens*), descarta palavras muito comuns (*stopwords*, como "de", "the") e monta um **índice invertido**: para cada palavra, a lista de linhas onde ela aparece, como o índice remissivo no fim de um livro.

```text
Texto da linha 1: "Aprendendo Eloquent no Laravel"
Texto da linha 2: "Relacionamentos no Eloquent"
Texto da linha 3: "Filas no Laravel"

Índice invertido:
  aprendendo      -> [1]
  eloquent        -> [1, 2]
  laravel         -> [1, 3]
  relacionamentos -> [2]
  filas           -> [3]
```

Buscar "eloquent laravel" vira consultar duas entradas do índice e cruzar as listas, sem ler a tabela inteira. O banco também calcula uma **pontuação de relevância** para cada linha (quantas palavras casaram, quão raras elas são).

|  | `LIKE '%termo%'` | Full-text |
| --- | --- | --- |
| Usa índice | Não (lê a tabela toda) | Sim (índice invertido) |
| Unidade de busca | Trecho de caracteres | Palavras |
| Ordem das palavras | Precisa ser exata | Indiferente |
| Relevância | Não tem | Calcula pontuação |
| Acha parte de palavra ("lara") | Sim | Não por padrão (só com `lara*` em modo booleano) |
| Bancos | Todos | MySQL/MariaDB e PostgreSQL (SQLite não é suportado pelo `whereFullText`) |

Use full-text para caixas de busca em textos longos. Para buscas curtas e exatas (código, e-mail, prefixo de nome), `where`/`whereLike` com índice comum continua melhor. Para busca avançada (tolerância a erros de digitação, sinônimos, facetas), o caminho é o **Laravel Scout** com Meilisearch, Typesense ou Algolia.

#### 1. Criar o índice na migration

```php
Schema::table('posts', function (Blueprint $table) {
    $table->fullText('conteudo')->language('portuguese');
    -- SQL: create index "posts_conteudo_fulltext" on "posts"
    --      using gin ((to_tsvector('portuguese', "conteudo")))

    $table->fullText(['titulo', 'conteudo'])->language('portuguese');
    -- SQL: create index "posts_titulo_conteudo_fulltext" on "posts"
    --      using gin ((to_tsvector('portuguese', "titulo") || to_tsvector('portuguese', "conteudo")))
});
```

O PostgreSQL só usa o índice quando a busca repete **a mesma expressão** dele: mesmas colunas e mesmo idioma. Um índice criado com `language('portuguese')` não atende a uma busca sem `'language' => 'portuguese'`, porque essa usa `english` por padrão. Sem índice a busca ainda funciona, mas lê a tabela inteira.

#### 2. Assinatura do `whereFullText`

```php
->whereFullText(string|array $columns, string $value, array $options = [], string $boolean = 'and')
->orWhereFullText(string|array $columns, string $value, array $options = [])
```

- **`$columns`**: coluna ou array de colunas (no MySQL, igual ao índice).
- **`$value`**: o texto buscado. Vai como binding (`?`), protegido contra SQL injection.
- **`$options`**: depende do banco (tabela abaixo).
- **`$boolean`**: `'and'` ou `'or'`; o `orWhereFullText` passa `'or'`.

| Opção | Banco | Valores | Efeito |
| --- | --- | --- | --- |
| `mode` | MySQL | (padrão) natural, `'boolean'` | Natural: busca por relevância. Booleano: aceita operadores (abaixo) |
| `expanded` | MySQL | `true` | Expansão de consulta: faz uma segunda busca com palavras dos melhores resultados |
| `language` | PostgreSQL | `'english'` (padrão), `'portuguese'`… | Idioma usado para reduzir palavras ao radical (*stemming*) e remover stopwords |
| `mode` | PostgreSQL | (padrão) plain, `'phrase'`, `'websearch'` | Como o texto vira consulta: palavras soltas, frase exata ou sintaxe de buscador |

#### 3. Exemplos e o SQL gerado

```php
Post::whereFullText('conteudo', 'eloquent relacionamentos')->get();
-- SQL: select * from "posts"
--      where (to_tsvector('english', "conteudo")) @@ plainto_tsquery('english', ?)
```

Várias colunas:

```php
Post::whereFullText(['titulo', 'conteudo'], 'laravel')->get();
-- SQL: select * from "posts"
--      where (to_tsvector('english', "titulo") || to_tsvector('english', "conteudo"))
--            @@ plainto_tsquery('english', ?)
```

**Modo booleano (MySQL)**: o texto aceita operadores.

```php
Post::whereFullText('conteudo', '+laravel -wordpress "query builder" eloq*', ['mode' => 'boolean'])->get();
// Opção só do MySQL. No PostgreSQL, o equivalente é 'mode' => 'websearch' (exemplo mais abaixo),
// que aceita "frase exata", -palavra e or.
```

| Operador | Significado |
| --- | --- |
| `+laravel` | A palavra é obrigatória |
| `-wordpress` | A palavra não pode aparecer |
| `"query builder"` | Frase exata |
| `eloq*` | Palavras que começam com "eloq" |
| sem operador | Opcional; só aumenta a relevância |

**Expansão de consulta (MySQL)**:

```php
Post::whereFullText('conteudo', 'orm', ['expanded' => true])->get();
// Opção só do MySQL; o PostgreSQL não tem expansão de consulta.
```

**Idioma e modos (PostgreSQL)**: com `language: portuguese`, "relacionamentos" e "relacionamento" viram o mesmo radical e casam entre si.

```php
Post::whereFullText('conteudo', 'relacionamentos eloquent', ['language' => 'portuguese'])->get();
-- SQL: where (to_tsvector('portuguese', "conteudo")) @@ plainto_tsquery('portuguese', ?)

Post::whereFullText('conteudo', 'query builder', ['mode' => 'phrase'])->get();
-- SQL: where (to_tsvector('english', "conteudo")) @@ phraseto_tsquery('english', ?)

Post::whereFullText('conteudo', '"query builder" -wordpress', ['mode' => 'websearch'])->get();
-- SQL: where (to_tsvector('english', "conteudo")) @@ websearch_to_tsquery('english', ?)
```

#### 4. Ordenar por relevância

`whereFullText` só **filtra**; não ordena pelos mais relevantes. Para isso, repita a expressão num `orderByRaw` (ou `selectRaw` para ver a pontuação):

```php
$termo = 'eloquent relacionamentos';

Post::whereFullText('conteudo', $termo, ['language' => 'portuguese'])
    -- → where (to_tsvector('portuguese', "conteudo")) @@ plainto_tsquery('portuguese', ?)
    ->selectRaw(
        "posts.*, ts_rank(to_tsvector('portuguese', conteudo), plainto_tsquery('portuguese', ?)) as relevancia",
        [$termo]
    )
    -- → select posts.*, ts_rank(...) as relevancia
    ->orderByDesc('relevancia')
    -- → order by "relevancia" desc
    ->get();

-- SQL completo:
-- select posts.*, ts_rank(to_tsvector('portuguese', conteudo), plainto_tsquery('portuguese', ?)) as relevancia
-- from "posts"
-- where (to_tsvector('portuguese', "conteudo")) @@ plainto_tsquery('portuguese', ?)
-- order by "relevancia" desc
```

#### 5. Cuidados

- Sem o índice, o MySQL recusa a consulta (erro "Can't find FULLTEXT index matching the column list").
- O MySQL ignora palavras curtas: no InnoDB, menos de 3 caracteres (configuração `innodb_ft_min_token_size`). "BD" ou "JS" não são encontrados.
- Stopwords não são buscáveis.
- Em testes com SQLite, `whereFullText` não funciona; rode esses testes em MySQL ou PostgreSQL.

### Colunas JSON

Use `->` para entrar no JSON.

```php
User::where('preferencias->idioma', 'pt');
-- SQL: where ("preferencias"->>'idioma') = ?

User::whereJsonContains('preferencias->idiomas', 'pt');          // array contém
-- SQL: where ("preferencias"->'idiomas')::jsonb @> ?             (? = '["pt"]')

User::whereJsonContains('preferencias->idiomas', ['pt', 'en']);  // contém todos
-- SQL: where ("preferencias"->'idiomas')::jsonb @> ?             (? = '["pt","en"]')

User::whereJsonDoesntContain('tags', 'spam');
-- SQL: where not ("tags")::jsonb @> ?

User::whereJsonLength('preferencias->idiomas', '>', 1);
-- SQL: where jsonb_array_length(("preferencias"->'idiomas')::jsonb) > ?

User::whereJsonContainsKey('preferencias->tema');                // chave existe
-- SQL: where coalesce(("preferencias")::jsonb ?? 'tema', false)
--      (?? é o operador ? do PostgreSQL, escapado para não virar binding)

User::whereJsonDoesntContainKey('preferencias->tema');
-- SQL: where not coalesce(("preferencias")::jsonb ?? 'tema', false)
```

### Subqueries: `whereExists` e afins

```php
User::whereExists(function ($q) {
    $q->select(DB::raw(1))
      ->from('pedidos')
      ->whereColumn('pedidos.user_id', 'users.id');
});
-- SQL: select * from "users"
--      where exists (select 1 from "pedidos" where "pedidos"."user_id" = "users"."id")
```

Variações: `whereNotExists`, `orWhereExists`, `orWhereNotExists`. Em Models com relacionamento definido, `whereHas` ([seção 27](#consultar-relacionamentos)) faz o mesmo de forma mais legível.

### SQL cru: `whereRaw`

```php
->whereRaw(string $sql, array $bindings = [], string $boolean = 'and')
```

```php
Pedido::whereRaw('total * 1.1 > ?', [200]);
-- SQL: select * from "pedidos" where total * 1.1 > ?
```

Repare que o trecho cru vai sem crases: o Laravel não mexe no texto de `whereRaw`.

::note{type="pitfall" title="Segurança"}
Nunca concatene entrada do usuário no `$sql`; use `?` e `$bindings`. Variação: `orWhereRaw`.
::

### *Dynamic where*: `whereNomeDaColuna`

O Builder entende métodos `where` seguidos do nome da coluna em StudlyCase.

```php
User::whereEmail('ana@x.com')->first();
-- SQL: select * from "users" where "email" = ? limit 1

User::whereNomeAndCidade('Ana', 'Manaus')->get();
-- SQL: select * from "users" where "nome" = ? and "cidade" = ?

User::whereNomeOrApelido('Ana', 'Ana')->get();
-- SQL: select * from "users" where "nome" = ? or "apelido" = ?
```

Isso é nativo. Não confunda com scopes como `byToken` ([seção 24](#scopes)), que são criados por você.

### Filtros condicionais: `when()` e `unless()`

```php
->when(mixed $value, callable $callback, ?callable $default = null)
```

- `$value`: se for verdadeiro, executa `$callback`. Pode ser uma Closure que retorna o valor.
- `$callback`: recebe `($query, $value)`.
- `$default`: executado quando `$value` é falso (opcional).

```php
Pedido::query()
    ->when($request->status, fn ($q, $status) => $q->where('status', $status))
    ->when($request->boolean('recentes'),
        fn ($q) => $q->latest(),
        fn ($q) => $q->orderBy('numero'))
    ->get();
-- SQL com status = 'pago' e recentes = true:
--      select * from "pedidos" where "status" = ? order by "created_at" desc
-- SQL sem status e recentes = false:
--      select * from "pedidos" order by "numero" asc
```

`unless()` é o inverso: executa quando o valor é falso.

### `tap()`: reaproveitar filtros

`tap(callable $callback)` passa a query para o callback (uma Closure ou um objeto invocável) e continua a cadeia. É uma forma de mover filtros repetidos para classes próprias.

```php
Pedido::query()->tap(new FiltroPorPeriodo($inicio, $fim))->get();
```

### Locks (concorrência)

Usados dentro de transações para impedir que outra transação altere as linhas lidas.

```php
DB::transaction(function () use ($id) {
    $conta = Conta::lockForUpdate()->find($id);
    -- SQL: select * from "contas" where "contas"."id" = ? limit 1 for update

    $conta->decrement('saldo', 100);
    -- SQL: update "contas" set "saldo" = "saldo" - 100, "updated_at" = ? where "id" = ?
});

Conta::sharedLock()->find($id);   // outros leem, não alteram
-- SQL: select * from "contas" where "contas"."id" = ? limit 1 for share
```

`lock(bool|string $value = true)` permite passar uma cláusula de lock específica.
