O Laravel não impõe uma arquitetura além do MVC, e isso dá liberdade e risco. Esta seção reúne os padrões mais usados para manter um projeto grande organizado.

### Onde cada coisa vai

| Responsabilidade | Lugar |
| --- | --- |
| Validar entrada HTTP | Form Request |
| Autorizar | Policy ou Gate |
| Regra de negócio de um caso de uso | Action |
| Operações relacionadas de um domínio | Service |
| Consulta reutilizável | Scope local, query object ou Builder próprio ([seção 34.5](#metodos-proprios-e-macros-builder-personalizado)) |
| Formato da resposta | API Resource |
| Efeitos colaterais (e-mail, integrações) | Evento + listener, job |
| Regras de tipo/estado | Enum, cast, value object |
| Dados entre camadas | DTO |

### Actions

Uma classe por caso de uso, com um único método público. Fácil de achar, testar e reutilizar em controller, comando, job e teste.

```php
class CriarPedido
{
    public function __construct(
        private CalculadoraDeFrete $frete,
        private Estoque $estoque,
    ) {}

    public function executar(User $cliente, DadosDoPedido $dados): Pedido
    {
        return DB::transaction(function () use ($cliente, $dados) {
            $this->estoque->reservar($dados->itens);

            $pedido = $cliente->pedidos()->create([
                'frete' => $this->frete->calcular($dados->cep, $dados->itens),
                'total' => $dados->subtotal(),
            ]);
            $pedido->itens()->createMany($dados->itensParaSalvar());

            PedidoCriado::dispatch($pedido);
            return $pedido;
        });
    }
}

// controller, comando, job: todos reutilizam
$pedido = app(CriarPedido::class)->executar($user, DadosDoPedido::fromRequest($request));
```

### DTOs

Objetos imutáveis que carregam dados validados entre camadas, com tipos explícitos em vez de arrays soltos:

```php
final readonly class DadosDoPedido
{
    /** @param array<ItemDoPedido> $itens */
    public function __construct(
        public string $cep,
        public array $itens,
        public ?string $cupom = null,
    ) {}

    public static function fromRequest(StorePedidoRequest $request): self
    {
        return new self(
            cep: $request->validated('cep'),
            itens: array_map(ItemDoPedido::fromArray(...), $request->validated('itens')),
            cupom: $request->validated('cupom'),
        );
    }
}
```

O pacote `spatie/laravel-data` gera DTOs com validação e transformação para JSON.

### Enums

```php
enum StatusPedido: string
{
    case Pendente = 'pendente';
    case Pago = 'pago';
    case Cancelado = 'cancelado';

    public function rotulo(): string
    {
        return match ($this) {
            self::Pendente => 'Aguardando pagamento',
            self::Pago => 'Pago',
            self::Cancelado => 'Cancelado',
        };
    }

    public function podeTransicionarPara(self $novo): bool
    {
        return $this === self::Pendente && $novo !== self::Pendente;
    }
}

// cast no Model, regra de validação e route binding: seções 25.6, 10.4 e 6.5
```

### Services, repositories e camadas

- **Service**: agrupa operações de um domínio que compartilham dependências (`PagamentoService` com `cobrar`, `estornar`, `consultar`). Útil quando várias actions usariam o mesmo cliente externo.
- **Repository**: isolar o Eloquent atrás de uma interface só compensa se você realmente troca a fonte de dados ou precisa de testes sem banco. Em muitos projetos Laravel, ele vira uma camada que repete métodos do Eloquent ([seção 34.2](#metodos-proprios-e-macros-o-padrão-repository-o-que-é-this-model)). Scopes e query objects resolvem a reutilização de consultas com menos código.

### Organização por domínio

Em projetos grandes, agrupar por domínio em vez de por tipo deixa cada área coesa:

```text
app/
  Domain/
    Pedidos/
      Actions/CriarPedido.php
      Models/Pedido.php
      Events/PedidoPago.php
      Policies/PedidoPolicy.php
    Pagamentos/
      ...
  Http/
    Controllers/Pedidos/PedidoController.php
```

Mantenha as convenções do Laravel funcionando (descoberta de policies e listeners) ou registre manualmente o que sair do padrão.

### Consistência e idempotência

- Agrupe escritas relacionadas em `DB::transaction` ([seção 14.4](#db-transacoes-e-seeders-transações)).
- Efeitos externos só depois do commit: jobs com `afterCommit`, listeners `ShouldQueueAfterCommit`.
- Operações repetíveis (webhooks, jobs, pagamentos) devem ser idempotentes: identifique a operação (id do evento, chave de idempotência) e ignore repetições.
- Concorrência em recursos disputados: lock no banco (`lockForUpdate`) ou no cache ([seção 44.5](#cache-e-locks-locks-atômicos)).

### Criando pacotes

Código reaproveitado entre projetos vira um pacote Composer com um Service Provider:

```php
class RastreamentoServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->mergeConfigFrom(__DIR__.'/../config/rastreamento.php', 'rastreamento');
    }

    public function boot(): void
    {
        $this->publishes([__DIR__.'/../config/rastreamento.php' => config_path('rastreamento.php')], 'rastreamento-config');
        $this->loadMigrationsFrom(__DIR__.'/../database/migrations');
        $this->loadRoutesFrom(__DIR__.'/../routes/api.php');
        $this->loadViewsFrom(__DIR__.'/../resources/views', 'rastreamento');
        if ($this->app->runningInConsole()) $this->commands([SincronizarRastreios::class]);
    }
}
```

```json
"extra": { "laravel": { "providers": ["Loja\\Rastreamento\\RastreamentoServiceProvider"] } }
```

A chave `extra.laravel` faz o Laravel registrar o provider automaticamente (package discovery). Para testar pacotes fora de uma aplicação, use o **Orchestra Testbench**.

### Qualidade de código

| Ferramenta | Função |
| --- | --- |
| Pint | Formatação (padrão Laravel), `./vendor/bin/pint` |

| Rector | Atualizações automáticas de código e versões |
| Pest arch | Regras de arquitetura como testes ([seção 51.8](#testes-testes-de-arquitetura-e-de-navegador)) |
