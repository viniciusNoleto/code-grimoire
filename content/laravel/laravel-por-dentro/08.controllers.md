Controllers agrupam a lógica que responde a requisições relacionadas. A boa prática é mantê-los finos: recebem a requisição, delegam o trabalho e devolvem a resposta.

### Criar

```bash
php artisan make:controller PedidoController
php artisan make:controller PedidoController --resource --model=Pedido --requests   # 7 métodos + Form Requests
php artisan make:controller PedidoController --api --model=Pedido                   # sem create/edit
php artisan make:controller BaixarReciboController --invokable                      # ação única
```

### Controller de ação única

Um controller comum agrupa várias ações sobre o mesmo recurso (`index`, `show`, `store`…). Mas há ações que não se encaixam em nenhum CRUD: baixar um recibo, reenviar um e-mail de confirmação, exportar um relatório, aprovar um pedido. Colocar `baixarRecibo()` dentro do `PedidoController` faz ele crescer com métodos que não têm nada a ver uns com os outros.

O controller de ação única resolve isso: é uma classe com **um só método público, `__invoke()`**, e o próprio nome da classe descreve a ação. O PHP chama `__invoke()` quando o objeto é usado como função, e o Laravel aproveita isso: na rota você passa só a classe, sem nome de método.

```bash
php artisan make:controller BaixarReciboController --invokable
```

```php [app/Http/Controllers/BaixarReciboController.php]
namespace App\Http\Controllers;

use App\Models\Pedido;
use Illuminate\Support\Facades\Storage;

class BaixarReciboController extends Controller
{
    public function __construct(private GeradorDeRecibo $gerador) {}   // injeção continua funcionando

    public function __invoke(Pedido $pedido)
    {
        if (! Storage::exists($pedido->recibo_path)) {
            $this->gerador->gerar($pedido);
        }

        return Storage::download($pedido->recibo_path);
    }
}
```

```php [routes/web.php]
use App\Http\Controllers\BaixarReciboController;

Route::get('/pedidos/{pedido}/recibo', BaixarReciboController::class)   // sem [Classe, 'metodo']
    ->name('pedidos.recibo');
```

| | Controller de recurso | Controller de ação única |
| --- | --- | --- |
| Métodos públicos | Vários (`index`, `store`…) | Só `__invoke()` |
| Na rota | `[PedidoController::class, 'show']` | `BaixarReciboController::class` |
| Nome | O recurso (`PedidoController`) | A ação (`AprovarPedidoController`) |
| Quando usar | CRUD de um recurso | Uma ação isolada, fora do CRUD |

Quando a ação cresce, a classe pode ganhar métodos `private` auxiliares sem atrapalhar as outras ações, porque não há outras. É também o formato natural para endpoints de webhook (`WebhookStripeController`) e páginas únicas (`PainelController`).

### Middleware no controller

:version[Laravel 11+] Implemente `HasMiddleware`:

```php [app/Http/Controllers/PedidoController.php]
namespace App\Http\Controllers;

use Illuminate\Routing\Controllers\HasMiddleware;
use Illuminate\Routing\Controllers\Middleware;

class PedidoController extends Controller implements HasMiddleware
{
    public static function middleware(): array
    {
        return [
            'auth',
            new Middleware('can:admin', only: ['destroy']),
            new Middleware('throttle:10,1', except: ['index', 'show']),
        ];
    }
}
```

:version[Laravel 13+] Também com atributos na classe e nos métodos:

```php [app/Http/Controllers/ComentarioController.php]
use Illuminate\Routing\Attributes\Controllers\Authorize;
use Illuminate\Routing\Attributes\Controllers\Middleware;

#[Middleware('auth')]
class ComentarioController
{
    #[Middleware('assinante')]
    #[Authorize('create', [Comentario::class, 'post'])]
    public function store(Post $post) { /* ... */ }
}
```

### Controllers enxutos

```php [app/Http/Controllers/PedidoController.php]
class PedidoController extends Controller
{
    public function store(StorePedidoRequest $request, CriarPedido $criarPedido)
    {
        $pedido = $criarPedido->executar($request->user(), $request->validated());  // regra de negócio fora do controller

        return (new PedidoResource($pedido))->response()->setStatusCode(201);
    }
}
```

| Responsabilidade | Onde colocar |
| --- | --- |
| Validar entrada | Form Request ([seção 10](#validacao)) |
| Autorizar | Policy ([seção 37](#autorizacao)) |
| Regra de negócio | Action ou Service ([seção 53](#arquitetura-da-aplicacao)) |
| Efeitos colaterais (e-mail, integrações) | Eventos, jobs ([seções 39](#filas-e-jobs) e 40) |
| Formato do JSON | API Resource ([seção 11](#respostas-e-api-resources)) |

::note{type="pitfall" title="Atenção"}
No Laravel 11+, o `Controller` base criado no projeto está vazio. `$this->authorize()` e `$this->validate()` só existem se você adicionar as traits `AuthorizesRequests` e `ValidatesRequests`. Prefira `Gate::authorize()` e `$request->validate()`.
::
