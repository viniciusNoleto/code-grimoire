O Laravel protege contra os ataques mais comuns por padrão. Esta seção mostra o que ele faz sozinho e onde você pode desligar a proteção sem perceber.

### CSRF

Ataque: um site malicioso faz o navegador do usuário enviar um POST para sua aplicação com o cookie de sessão dele. Proteção: todo POST, PUT, PATCH e DELETE das rotas `web` precisa de um token que só suas páginas conhecem.

```html
<form method="POST" action="/perfil">
    @csrf    {{-- <input type="hidden" name="_token" value="..."> --}}
</form>
```

Requisições AJAX enviam o token no cabeçalho `X-XSRF-TOKEN` (o Axios faz isso sozinho a partir do cookie `XSRF-TOKEN`). Para excluir rotas (webhooks de terceiros):

```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->validateCsrfTokens(except: ['webhooks/*']);
})
```

:version[Laravel 13+] O middleware passou a se chamar `PreventRequestForgery` e verifica também a origem da requisição, além do token.

### XSS

Ataque: um usuário grava `<script>` num campo e o código roda no navegador de quem visualiza. Proteção: `{{ }}` no Blade escapa o HTML.

```html
{{ $comentario->texto }}        {{-- seguro --}}
{!! $comentario->texto !!}       {{-- PERIGOSO se o conteúdo veio do usuário --}}
```

Se você precisa exibir HTML vindo do usuário (editor rico), limpe-o antes com um sanitizador (por exemplo `mews/purifier`) e só então use `{!! !!}`. Em APIs consumidas por SPA, o escape é responsabilidade do frontend.

### SQL injection

O Eloquent e o Query Builder usam bindings, então valores nunca entram no SQL como texto. Os riscos aparecem quando você escreve SQL ou nomes de coluna:

```php
// PERIGOSO: entrada do usuário concatenada
User::whereRaw("email = '{$request->email}'")->first();
// SEGURO
User::whereRaw('email = ?', [$request->email])->first();

// PERIGOSO: nome de coluna vindo da requisição (colunas não usam binding)
Pedido::orderBy($request->ordenar)->get();
// SEGURO: lista de colunas permitidas
$request->validate(['ordenar' => [Rule::in(['created_at', 'total', 'numero'])]]);
```

### Mass assignment

::note{type="pitfall" title="Segurança"}
Nunca passe `$request->all()` para `create()` ou `update()`. Use `$request->validated()` e mantenha `$fillable` explícito ([seções 16.6](#criar-e-configurar-mass-assignment-fillable-e-guarded) e 32).
::

### Rate limiting e força bruta

Limite login, recuperação de senha, envio de código por SMS e endpoints caros ([seção 6.7](#rotas-rate-limiting-nas-rotas)). Para controle manual:

```php
$chave = 'login:'.Str::lower($request->email).'|'.$request->ip();

if (RateLimiter::tooManyAttempts($chave, 5)) {
    $segundos = RateLimiter::availableIn($chave);
    throw ValidationException::withMessages(['email' => "Muitas tentativas. Tente em {$segundos}s."]);
}

RateLimiter::hit($chave, 60);          // conta uma tentativa por 60s
RateLimiter::clear($chave);            // após login bem-sucedido
```

### Criptografia

```php
$cifrado = Crypt::encryptString('4111 1111 1111 1111');   // AES-256 com a APP_KEY
$texto   = Crypt::decryptString($cifrado);                 // DecryptException se adulterado

protected function casts(): array { return ['cpf' => 'encrypted']; }   // criptografa a coluna
```

:version[Laravel 11+] Para trocar a `APP_KEY` sem perder dados, coloque a chave antiga em `APP_PREVIOUS_KEYS`; o Laravel tenta descriptografar com ela quando a atual falha.

::note{type="pitfall" title="Cuidado"}
Colunas com cast `encrypted` não podem ser usadas em `where`, porque cada valor cifrado é diferente. Se precisar buscar, guarde também um hash determinístico (por exemplo `hash_hmac`) em outra coluna.
::

### CORS, proxies e HTTPS

```bash
php artisan config:publish cors     # config/cors.php: origens, métodos e cabeçalhos permitidos
```

```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->trustProxies(at: '*');      // atrás de load balancer: confia em X-Forwarded-*
})

// AppServiceProvider::boot()
if (app()->isProduction()) {
    URL::forceScheme('https');               // versões recentes também têm URL::forceHttps()
}
```

Sem `trustProxies`, atrás de um balanceador o Laravel enxerga o IP do balanceador e acha que a requisição é HTTP, o que quebra o rate limit por IP e gera URLs `http://`.

### Uploads

- Valide tipo pelo conteúdo (`mimes`, `File::types`) e tamanho.
- Gere o nome do arquivo (`store()` faz isso); não use o nome enviado pelo cliente.
- Guarde arquivos privados fora de `public/` e sirva com URL temporária ou controller com autorização ([seção 45](#arquivos-storage)).
- Nunca permita upload de `.php`, `.phtml` ou `.svg` sem tratamento em pasta servida pelo servidor web.

### Checklist de produção

| Item | Por quê |
| --- | --- |
| `APP_DEBUG=false` | A página de erro de debug expõe variáveis e código |
| `APP_KEY` definida e secreta | Criptografa cookies, sessões e dados |
| `.env` fora do Git | Segredos |
| `composer audit` e atualização de dependências | Vulnerabilidades conhecidas |
| HTTPS e cookies `secure` (`SESSION_SECURE_COOKIE=true`) | Sessão não trafega em texto puro |
| Logs sem dados sensíveis | Senhas, tokens e documentos não vão para o log |
| Autorização em toda rota que expõe dados de um usuário | IDOR: trocar o id na URL não pode mostrar dados alheios |
