O Service Container é o objeto que cria as classes da aplicação e entrega a cada uma as dependências que ela pede. Quase tudo no Laravel (controllers, jobs, listeners, comandos, middlewares) é construído por ele.

### Injeção automática (autowiring)

Se a dependência é uma classe concreta, o container resolve sozinho, sem configuração, lendo os tipos do construtor via Reflection.

```php
class RelatorioController extends Controller
{
    public function __construct(
        private GeradorDeRelatorio $gerador,     // injetado no construtor
    ) {}

    public function show(Request $request, Pedido $pedido)  // injeção no método + route model binding
    {
        return $this->gerador->para($pedido, $request->user());
    }
}
```

A injeção funciona no construtor de controllers, jobs, listeners, middlewares e comandos, e também nos métodos `handle()` de jobs, comandos e listeners, nos métodos de controllers e em closures de rota.

### `bind`, `singleton`, `scoped` e `instance`

Você só precisa registrar algo no container quando ele não consegue adivinhar: interfaces, classes que precisam de valores primitivos (chaves de API) ou objetos que devem ser compartilhados. O registro fica no `register()` de um Service Provider.

| Método | Quantas instâncias | Uso típico |
| --- | --- | --- |
| `bind(Abstrato, Closure\|Concreto)` | Uma nova a cada resolução | Objetos com estado próprio |
| `singleton(...)` | Uma só durante toda a vida da aplicação | Clientes de API, serviços sem estado |
| `scoped(...)` | Uma por requisição ou job | Serviços com estado da requisição; seguro no Octane e nas filas |
| `instance(Abstrato, $objeto)` | O objeto que você passou | Objeto já construído, mocks em testes |

```php
public function register(): void
{
    $this->app->singleton(GatewayPagamento::class, function (Application $app) {
        return new GatewayPagamento(
            chave: config('services.pagamento.key'),
            http: $app->make(HttpClient::class),
        );
    });

    $this->app->scoped(CarrinhoAtual::class);   // recriado a cada requisição/job
}
```

### Interface para implementação

Ligar uma interface a uma classe concreta permite trocar a implementação sem mexer em quem a usa.

```php
$this->app->bind(Notificador::class, NotificadorWhatsApp::class);

class AvisoService
{
    public function __construct(private Notificador $notificador) {}   // recebe NotificadorWhatsApp
}
```

:version[Laravel 12+] O mesmo pode ser declarado com atributos, sem provider:

```php
use Illuminate\Container\Attributes\Bind;
use Illuminate\Container\Attributes\Singleton;

#[Bind(NotificadorWhatsApp::class)]
#[Bind(NotificadorFake::class, environments: ['local', 'testing'])]
interface Notificador {}

#[Singleton]        // ou #[Scoped]
class GatewayPagamento {}
```

### Binding contextual

Quando duas classes usam a mesma interface mas precisam de implementações diferentes:

```php
$this->app->when(FotoController::class)
    ->needs(Filesystem::class)
    ->give(fn () => Storage::disk('local'));

$this->app->when([VideoController::class, UploadController::class])
    ->needs(Filesystem::class)
    ->give(fn () => Storage::disk('s3'));

// valor primitivo
$this->app->when(GatewayPagamento::class)
    ->needs('$chave')
    ->giveConfig('services.pagamento.key');
```

### Atributos contextuais

:version[Laravel 11+] Atributos no parâmetro dizem ao container o que injetar, sem provider:

```php
use Illuminate\Container\Attributes\{Config, Storage, DB, Log, Cache, CurrentUser, RouteParameter};

public function __construct(
    #[Config('app.timezone')] private string $fuso,
    #[Storage('s3')] private Filesystem $arquivos,
    #[DB('pgsql')] private Connection $conexao,
    #[Log('daily')] private LoggerInterface $log,
    #[Cache('redis')] private Repository $cache,
) {}

Route::get('/perfil', fn (#[CurrentUser] User $user) => $user)->middleware('auth');
```

Outros disponíveis: `#[Auth('web')]`, `#[Context('chave')]`, `#[Give(Classe::class)]`, `#[RequestAttribute]`, `#[RouteParameter]` e `#[Tag('relatorios')]`.

### Resolver manualmente

```php
$gateway = app(GatewayPagamento::class);                 // helper
$gateway = app()->make(GatewayPagamento::class);
$gateway = resolve(GatewayPagamento::class);
$relatorio = app()->makeWith(Relatorio::class, ['mes' => 10]);  // passa parâmetros extras

app()->call([$servico, 'executar']);   // chama um método injetando as dependências dele
```

::note{type="pitfall" title="Cuidado"}
Chamar `app()` espalhado pelo código esconde dependências (é o padrão *service locator*). Prefira receber no construtor; use `app()` em pontos de borda, como closures e helpers.
::

### Tags, extend e eventos de resolução

```php
$this->app->tag([RelatorioVendas::class, RelatorioEstoque::class], 'relatorios');
$relatorios = $this->app->tagged('relatorios');          // iterável com todos

$this->app->extend(Notificador::class, fn ($n, $app) => new NotificadorComLog($n));  // decorator

$this->app->resolving(Notificador::class, fn ($n, $app) => $n->setLocale('pt_BR'));
```
