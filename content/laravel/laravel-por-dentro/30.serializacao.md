Quando um Model sai da aplicação (resposta de API, `dd`, cache), ele vira array ou JSON. Estes recursos controlam quais atributos aparecem e como.

### `toArray()` e `toJson()`

```php
$user->toArray();                      // atributos + relacionamentos carregados, com casts e $appends
$user->attributesToArray();            // só atributos, sem relacionamentos
$user->relationsToArray();             // só relacionamentos
$user->toJson(int $options = 0);       // string JSON
$user->toJson(JSON_PRETTY_PRINT);
(string) $user;                        // o mesmo que toJson()
```

Retornar um Model ou Collection numa rota/controller gera JSON automaticamente:

```php
Route::get('/users/{user}', fn (User $user) => $user->load('perfil'));
```

Relacionamentos aparecem em snake_case (`perfilPublico()` → `"perfil_publico"`).

### Esconder e mostrar: `$hidden` e `$visible`

```php
protected $hidden = ['senha', 'remember_token'];    // lista negra
protected $visible = ['id', 'nome', 'email'];       // lista branca (o resto some)
```

Relacionamentos também podem entrar nessas listas, pelo nome do método.

Ajustes pontuais (em instância ou Collection):

| Método | Efeito |
| --- | --- |
| `makeVisible('senha')` | Mostra um atributo escondido |
| `makeHidden('email')` | Esconde um atributo visível |
| `setVisible([...])` | Substitui a lista branca |
| `setHidden([...])` | Substitui a lista negra |
| `mergeVisible([...])` / `mergeHidden([...])` | Acrescenta às listas |

```php
return $user->makeVisible('telefone')->toArray();
return User::all()->makeHidden(['email', 'cpf']);
```

### Acrescentar atributos calculados: `$appends`

Accessors sem coluna ([seção 25.2](#accessors-e-casts-atributos-calculados-sem-coluna)) não aparecem no JSON por padrão.

```php
protected $appends = ['nome_completo'];
```

Em tempo de execução:

```php
$user->append('nome_completo');                 // um ou array
$user->setAppends(['nome_completo', 'idade']);  // substitui a lista
$user->setAppends([]);                          // remove todos
User::all()->append('nome_completo');           // em Collection
```

::note{type="pitfall" title="Cuidado"}
Um accessor em `$appends` que acessa relacionamento causa N+1 ao serializar listas.
::

### Formato de datas

```php
'pago_em' => 'datetime:d/m/Y'                 // por atributo, no cast
protected function serializeDate(DateTimeInterface $date): string   // global no Model
{
    return $date->format('d/m/Y H:i');
}
```

### API Resources: quando o Model não basta

Para APIs, o Laravel recomenda **API Resources** em vez de depender de `$hidden`/`$appends`: uma camada que define o JSON explicitamente.

```php
// php artisan make:resource UserResource
class UserResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'nome' => $this->nome,
            'pedidos' => PedidoResource::collection($this->whenLoaded('pedidos')),
            'total_pedidos' => $this->whenCounted('pedidos'),
        ];
    }
}

return new UserResource($user);
return UserResource::collection(User::paginate());
```

`whenLoaded` inclui a relação só se ela foi carregada com `with`/`load`, evitando N+1. No Laravel 12+, `$user->toResource()` e `$users->toResourceCollection()` encontram o Resource pela convenção de nome.
