Um relacionamento é um método público do Model que retorna um objeto de relação. Os parâmetros de chave são opcionais quando você segue as convenções (`user_id`, `id`); informe-os só quando o banco foge delas.

### Resumo dos tipos

| Tipo | Exemplo | Onde fica a chave estrangeira |
| --- | --- | --- |
| `hasOne` | User tem um Perfil | Na tabela do filho (`perfis.user_id`) |
| `belongsTo` | Perfil pertence a User | Na própria tabela (`perfis.user_id`) |
| `hasMany` | User tem muitos Pedidos | Na tabela do filho |
| `belongsToMany` | User tem muitas Roles e vice-versa | Tabela pivô (`role_user`) |
| `hasOneThrough` | Mecânico → Carro → Dono | Em cadeia |
| `hasManyThrough` | País → Users → Posts | Em cadeia |
| `morphOne` / `morphMany` | Post e Video têm Imagem/Comentários | Colunas `*_id` + `*_type` no filho |
| `morphTo` | Comentário pertence a Post **ou** Video | Na própria tabela |
| `morphToMany` / `morphedByMany` | Post e Video têm muitas Tags | Pivô polimórfico (`taggables`) |

### `hasOne`

```php
$this->hasOne(string $related, ?string $foreignKey = null, ?string $localKey = null)
```

- `$related`: classe do Model relacionado.
- `$foreignKey`: coluna na tabela **relacionada** que aponta para este Model. Padrão: `nome_deste_model_id` (`user_id`).
- `$localKey`: coluna **deste** Model que é referenciada. Padrão: a PK (`id`).

```php
public function perfil(): HasOne
{
    return $this->hasOne(Perfil::class);
    // equivale a: hasOne(Perfil::class, 'user_id', 'id')
}

$user->perfil;
-- SQL: select * from "perfis" where "perfis"."user_id" = ? and "perfis"."user_id" is not null limit 1
--      ? = $user->id
```

### `belongsTo`

```php
$this->belongsTo(string $related, ?string $foreignKey = null, ?string $ownerKey = null, ?string $relation = null)
```

- `$foreignKey`: coluna **nesta** tabela. Padrão: nome do método + `_id` (método `autor()` → `autor_id`).
- `$ownerKey`: coluna referenciada na tabela do pai. Padrão: PK.
- `$relation`: nome do relacionamento; quase nunca necessário.

```php
public function autor(): BelongsTo
{
    return $this->belongsTo(User::class, 'user_id');   // método 'autor' mas coluna 'user_id'
}

$post->autor;
-- SQL: select * from "users" where "users"."id" = ? limit 1      (? = $post->user_id)
```

**`withDefault()`**: devolve um Model vazio em vez de `null` quando não há pai (evita `if` no Blade).

```php
return $this->belongsTo(User::class)->withDefault();
return $this->belongsTo(User::class)->withDefault(['nome' => 'Anônimo']);
return $this->belongsTo(User::class)->withDefault(fn ($user, $post) => $user->nome = 'Visitante');
```

`withDefault` também funciona em `hasOne`, `hasOneThrough` e `morphOne`.

### `hasMany`

```php
$this->hasMany(string $related, ?string $foreignKey = null, ?string $localKey = null)
```

Mesmos parâmetros do `hasOne`, mas retorna uma Collection.

```php
public function pedidos(): HasMany
{
    return $this->hasMany(Pedido::class);
}
```

Você pode acrescentar filtros e ordem na própria definição:

```php
public function pedidosPagos(): HasMany
{
    return $this->hasMany(Pedido::class)->where('status', 'pago')->latest();
}

$user->pedidos;
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null

$user->pedidosPagos;
-- SQL: select * from "pedidos" where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null
--      and "status" = ? order by "created_at" desc
```

**`chaperone()`** (*Laravel 11+*): ao carregar os filhos, preenche automaticamente o pai em cada um, evitando N+1 em `$pedido->user` dentro de um loop.

```php
return $this->hasMany(Pedido::class)->chaperone();
```

`chaperone()` também funciona em `morphMany` e pode ser ligado só numa consulta: `Post::with(['comentarios' => fn ($q) => $q->chaperone()])->get()`.

### "Um de muitos": `latestOfMany`, `oldestOfMany`, `ofMany`

Transformam um `hasMany` em `hasOne` que escolhe um registro específico.

```php
public function ultimoPedido(): HasOne
{
    return $this->hasOne(Pedido::class)->latestOfMany();          // maior id (ou coluna informada)
}

$user->ultimoPedido;
-- SQL: junta com uma subquery que acha o maior id do usuário
--      select * from "pedidos"
--      inner join (
--          select max("pedidos"."id") as "id_aggregate", "pedidos"."user_id"
--          from "pedidos" where "pedidos"."user_id" = ? group by "pedidos"."user_id"
--      ) as "ultimoPedido"
--      on "ultimoPedido"."id_aggregate" = "pedidos"."id"
--      and "ultimoPedido"."user_id" = "pedidos"."user_id"
--      where "pedidos"."user_id" = ? and "pedidos"."user_id" is not null limit 1

public function primeiroPedido(): HasOne
{
    return $this->hasOne(Pedido::class)->oldestOfMany('created_at');   // → min("created_at")
}

public function maiorPedido(): HasOne
{
    return $this->hasOne(Pedido::class)->ofMany('total', 'max');       // → max("total")
}

// ofMany com várias colunas e filtro extra
return $this->hasOne(Preco::class)->ofMany(
    ['publicado_em' => 'max', 'id' => 'max'],
    fn ($q) => $q->where('publicado_em', '<', now())                  // → entra na subquery
);
```

O formato exato varia entre versões, mas a ideia é sempre esta: uma subquery com `max`/`min` agrupada pelo pai. Por isso funciona também com eager loading de muitos usuários de uma vez.

Ou, a partir de um `hasMany` existente: `$this->pedidos()->one()->latestOfMany()`.

### `belongsToMany` (muitos para muitos)

```php
$this->belongsToMany(
    string $related,
    ?string $table = null,
    ?string $foreignPivotKey = null,
    ?string $relatedPivotKey = null,
    ?string $parentKey = null,
    ?string $relatedKey = null,
    ?string $relation = null
)
```

- `$table`: tabela pivô. Padrão: os dois nomes no singular, em ordem alfabética, unidos por `_` (`role_user`).
- `$foreignPivotKey`: coluna do pivô que aponta para **este** Model (`user_id`).
- `$relatedPivotKey`: coluna do pivô que aponta para o **outro** Model (`role_id`).
- `$parentKey`: coluna deste Model referenciada (PK).
- `$relatedKey`: coluna do outro Model referenciada (PK).

```php
public function roles(): BelongsToMany
{
    return $this->belongsToMany(Role::class, 'usuario_papel', 'usuario_id', 'papel_id');
}
```

Métodos de configuração da pivô:

| Método | Efeito |
| --- | --- |
| `withPivot('expira_em', 'ativo')` | Traz colunas extras do pivô em `$role->pivot->expira_em` |
| `withTimestamps()` | Preenche `created_at`/`updated_at` do pivô |
| `as('assinatura')` | Renomeia `pivot` para `$role->assinatura` |
| `using(PapelUsuario::class)` | Usa um Model de pivô próprio (estende `Pivot`), com casts e eventos |
| `wherePivot('ativo', true)` | Filtra pela coluna do pivô |
| `wherePivotIn`, `wherePivotNotIn`, `wherePivotBetween`, `wherePivotNotBetween`, `wherePivotNull`, `wherePivotNotNull` | Filtros do pivô |
| `orderByPivot('created_at', 'desc')` | Ordena pela coluna do pivô |
| `withPivotValue('tipo', 'admin')` | Filtra **e** preenche esse valor ao fazer `attach`/`create` |

```php
public function rolesAtivas(): BelongsToMany
{
    return $this->belongsToMany(Role::class)
        ->withPivot('expira_em')            // → "role_user"."expira_em" as "pivot_expira_em"
        ->withTimestamps()                  // → "role_user"."created_at" / "updated_at" as "pivot_..."
        ->wherePivot('ativo', true);        // → and "role_user"."ativo" = ?
}

foreach ($user->rolesAtivas as $role) {
    echo $role->pivot->expira_em;
}
-- SQL: select "roles".*,
--             "role_user"."user_id" as "pivot_user_id",
--             "role_user"."role_id" as "pivot_role_id",
--             "role_user"."expira_em" as "pivot_expira_em",
--             "role_user"."created_at" as "pivot_created_at",
--             "role_user"."updated_at" as "pivot_updated_at"
--      from "roles"
--      inner join "role_user" on "roles"."id" = "role_user"."role_id"
--      where "role_user"."user_id" = ? and "role_user"."ativo" = ?
```

As colunas `pivot_*` são as que viram `$role->pivot->...`. O `withPivot` e o `withTimestamps` só acrescentam colunas a essa lista.

Ordenação decrescente pelo pivô: `orderByPivotDesc('created_at')`. Model de pivô com id autoincremento: `public $incrementing = true;` no Model pivô (no Laravel 13, `#[Table(incrementing: true)]`). Models de pivô não podem usar `SoftDeletes`; se precisar, transforme o pivô num Model comum com `hasMany` dos dois lados.

### `hasOneThrough` e `hasManyThrough`

```php
$this->hasManyThrough(
    string $related,       // destino final
    string $through,       // model intermediário
    ?string $firstKey = null,   // FK no intermediário que aponta para este model
    ?string $secondKey = null,  // FK no destino que aponta para o intermediário
    ?string $localKey = null,   // PK deste model
    ?string $secondLocalKey = null // PK do intermediário
)
```

```php
// Pais -> users (pais_id) -> posts (user_id)
class Pais extends Model
{
    public function posts(): HasManyThrough
    {
        return $this->hasManyThrough(Post::class, User::class);
    }
}

$pais->posts;
-- SQL: select "posts".*, "users"."pais_id" as "laravel_through_key"
--      from "posts"
--      inner join "users" on "users"."id" = "posts"."user_id"
--      where "users"."pais_id" = ?
```

Sintaxe alternativa a partir de relações existentes (*Laravel 10+*):

```php
return $this->through('users')->has('posts');
// ou dinâmica: $this->throughUsers()->hasPosts();
```

`hasOneThrough` tem os mesmos parâmetros e devolve um registro.

### Polimórficos um-para-um/muitos: `morphOne`, `morphMany`, `morphTo`

Um mesmo Model filho pode pertencer a vários tipos de pai. A tabela do filho tem duas colunas: `{nome}_id` e `{nome}_type` (migration: `$table->morphs('comentavel')`).

```php
$this->morphMany(string $related, string $name, ?string $type = null, ?string $id = null, ?string $localKey = null)
$this->morphOne(string $related, string $name, ?string $type = null, ?string $id = null, ?string $localKey = null)
$this->morphTo(?string $name = null, ?string $type = null, ?string $id = null, ?string $ownerKey = null)
```

- `$name`: prefixo das colunas (`comentavel` → `comentavel_id`, `comentavel_type`).
- `$type` / `$id`: nomes das colunas, se fugirem do padrão.
- `morphTo` sem argumentos usa o nome do método como prefixo.

```php
class Post extends Model
{
    public function comentarios(): MorphMany
    {
        return $this->morphMany(Comentario::class, 'comentavel');
    }
    public function imagem(): MorphOne
    {
        return $this->morphOne(Imagem::class, 'imageavel');
    }
}

class Comentario extends Model
{
    public function comentavel(): MorphTo
    {
        return $this->morphTo();
    }
}

$post->comentarios;
-- SQL: select * from "comentarios"
--      where "comentarios"."comentavel_type" = ? and "comentarios"."comentavel_id" = ?
--      and "comentarios"."comentavel_id" is not null
--      (? do _type = 'App\Models\Post' ou o apelido do morph map)

$comentario->comentavel;   // um Post ou um Video
-- SQL: lê comentavel_type para saber a tabela; se for Post:
--      select * from "posts" where "posts"."id" = ? limit 1
```

`morphOne` também aceita `latestOfMany()`, `oldestOfMany()` e `ofMany()`.

### Polimórficos muitos-para-muitos: `morphToMany` e `morphedByMany`

```php
$this->morphToMany(string $related, string $name, ?string $table = null, ?string $foreignPivotKey = null, ?string $relatedPivotKey = null, ?string $parentKey = null, ?string $relatedKey = null, ?string $relation = null, bool $inverse = false)
$this->morphedByMany(string $related, string $name, ?string $table = null, ...)
```

```php
// tabela taggables: tag_id, taggable_id, taggable_type
class Post extends Model
{
    public function tags(): MorphToMany
    {
        return $this->morphToMany(Tag::class, 'taggable');
    }
}

class Tag extends Model
{
    public function posts(): MorphToMany
    {
        return $this->morphedByMany(Post::class, 'taggable');
    }
    public function videos(): MorphToMany
    {
        return $this->morphedByMany(Video::class, 'taggable');
    }
}

$post->tags;
-- SQL: select "tags".*, "taggables"."taggable_id" as "pivot_taggable_id",
--             "taggables"."tag_id" as "pivot_tag_id", "taggables"."taggable_type" as "pivot_taggable_type"
--      from "tags"
--      inner join "taggables" on "tags"."id" = "taggables"."tag_id"
--      where "taggables"."taggable_id" = ? and "taggables"."taggable_type" = ?
```

Aceitam os mesmos métodos de pivô do `belongsToMany` (`withPivot`, `withTimestamps`, `wherePivot`…).

### Morph map

Por padrão, a coluna `*_type` guarda o nome completo da classe (`App\Models\Post`). Se você renomear a classe, os dados quebram. Defina apelidos no `AppServiceProvider`:

```php
use Illuminate\Database\Eloquent\Relations\Relation;

Relation::enforceMorphMap([
    'post' => Post::class,
    'video' => Video::class,
]);
```

`enforceMorphMap` também lança erro se um Model sem apelido for usado. `morphMap` faz o mesmo sem exigir. `Relation::getMorphedModel('post')` e `$model->getMorphClass()` consultam o mapa.

### Relacionamentos com escopo e dinâmicos

- **Filtro na definição**: qualquer método do Builder (`where`, `orderBy`, scopes) pode vir depois do `hasMany(...)`.
- **`Model::resolveRelationUsing('nome', fn ($model) => ...)`**: define um relacionamento em tempo de execução, útil em pacotes. Prefira métodos normais no seu código.

```php
User::resolveRelationUsing('cliente', fn (User $u) => $u->belongsTo(Cliente::class, 'cliente_id'));
```

**Relacionamento com atributos pendentes**: `withAttributes` ([seção 24.5](#scopes-pending-attributes-withattributes)) também funciona na definição de um relacionamento. A relação filtra por esses valores e os preenche ao criar por ela.

```php
public function postsDestaque(): HasMany
{
    return $this->posts()->withAttributes(['destaque' => true]);
}

$user->postsDestaque()->create(['titulo' => 'Novo']);   // destaque = true
```

### `$touches`: atualizar o pai

```php
class Comentario extends Model
{
    protected $touches = ['post'];   // ao salvar o comentário, post->updated_at = agora

    public function post(): BelongsTo { return $this->belongsTo(Post::class); }
}
```

Útil para invalidar caches baseados em `updated_at` do pai.
