Eventos desacoplam "o que aconteceu" de "o que fazer a respeito". O código que conclui um pedido dispara `PedidoPago`; e-mail, nota fiscal e métricas são listeners independentes, que podem ser adicionados sem mexer no fluxo principal.

### Criar evento e listener

```bash
php artisan make:event PedidoPago
php artisan make:listener EnviarComprovante --event=PedidoPago
```

```php [app/Events/PedidoPago.php]
class PedidoPago
{
    use Dispatchable, SerializesModels;

    public function __construct(public Pedido $pedido) {}
}

class EnviarComprovante
{
    public function handle(PedidoPago $event): void      // o tipo do parâmetro liga o listener ao evento
    {
        Mail::to($event->pedido->user)->send(new Comprovante($event->pedido));
    }
}
```

:version[Laravel 11+] Listeners em `app/Listeners` são descobertos automaticamente pelo tipo do parâmetro do `handle`. Registro manual, quando preciso:

```php [app/Providers/AppServiceProvider.php]
class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Event::listen(PedidoPago::class, EnviarComprovante::class);
        Event::listen(function (PedidoPago $event) { /* closure */ });
    }
}
```

```bash
php artisan event:list
```

### Disparar

```php [app/Actions/ConfirmarPagamento.php]
PedidoPago::dispatch($pedido);
event(new PedidoPago($pedido));
PedidoPago::dispatchIf($pedido->pago, $pedido);
```

### Listeners na fila

```php [app/Listeners/EmitirNotaFiscal.php]
class EmitirNotaFiscal implements ShouldQueue
{
    public $queue = 'fiscal';
    public $tries = 3;

    public function shouldQueue(PedidoPago $event): bool   // decide se vai para a fila
    {
        return $event->pedido->total > 0;
    }

    public function handle(PedidoPago $event): void { /* ... */ }

    public function failed(PedidoPago $event, Throwable $e): void { /* ... */ }
}
```

Para listeners que só devem rodar após o commit da transação, implemente `ShouldQueueAfterCommit` (ou `ShouldHandleEventsAfterCommit` no evento).

Um listener que retorna `false` interrompe a propagação para os listeners seguintes (só nos síncronos).

### Subscribers

Uma classe que escuta vários eventos:

```php [app/Listeners/AuditoriaSubscriber.php]
class AuditoriaSubscriber
{
    public function subscribe(Dispatcher $events): array
    {
        return [
            PedidoPago::class => 'registrarPagamento',
            PedidoCancelado::class => 'registrarCancelamento',
        ];
    }
}

Event::subscribe(AuditoriaSubscriber::class);
```

### Eventos de aplicação ou eventos de Model?

|  | Eventos de Model ([seção 29](#eventos-e-observers)) | Eventos de aplicação |
| --- | --- | --- |
| Disparo | Automático em `save`, `delete`… | Você decide quando |
| Significado | "Uma linha mudou" | "Algo do negócio aconteceu" |
| Exemplo | `updated` em `Pedido` | `PedidoPago`, `AssinaturaCancelada` |

Prefira eventos de aplicação para regras de negócio: `updated` dispara em qualquer alteração e não diz **por que** o pedido mudou.
