O Model dispara eventos em cada etapa do ciclo de vida; você pode reagir a eles com Closures no `booted()`, com uma classe Observer ou com classes de evento. Eventos só disparam em operações **via Model** ([seção 21](#inserir-e-atualizar)), nunca em updates/deletes por query.

### Lista de eventos

Eventos terminados em **-ing** rodam **antes** da operação; retornar `false` neles **cancela** a operação. Os terminados em **-ed** rodam depois.

| Evento | Quando |
| --- | --- |
| `retrieved` | Após carregar um registro do banco |
| `creating` / `created` | Antes / depois de um INSERT |
| `updating` / `updated` | Antes / depois de um UPDATE (só se algo mudou) |
| `saving` / `saved` | Antes / depois de INSERT **ou** UPDATE (envolve os dois acima) |
| `deleting` / `deleted` | Antes / depois de excluir (ou soft delete) |
| `trashed` | Após soft delete |
| `forceDeleting` / `forceDeleted` | Exclusão definitiva com SoftDeletes |
| `restoring` / `restored` | Restaurar de soft delete |
| `replicating` | Ao chamar `replicate()` |

Ordem num `save()` de registro novo: `saving` → `creating` → INSERT → `created` → `saved`.

### Closures no `booted()`

```php
protected static function booted(): void
{
    static::creating(function (Pedido $pedido) {
        $pedido->numero = Str::upper(Str::random(8));
    });

    static::updating(function (Pedido $pedido) {
        if ($pedido->isDirty('status') && $pedido->status === 'cancelado') {
            $pedido->cancelado_em = now();
        }
    });

    static::deleting(function (Pedido $pedido) {
        if ($pedido->status === 'pago') {
            return false;   // impede a exclusão
        }
        $pedido->itens()->delete();
    });
}
```

Para rodar o listener em fila: `static::created(queueable(function (Pedido $p) { ... }));`.

### Observers

Agrupam vários eventos numa classe. `php artisan make:observer PedidoObserver --model=Pedido`.

```php
class PedidoObserver
{
    public function created(Pedido $pedido): void
    {
        Mail::to($pedido->cliente)->send(new PedidoRecebido($pedido));
    }

    public function updated(Pedido $pedido): void { /* ... */ }
    public function deleted(Pedido $pedido): void { /* ... */ }
}
```

Registro:

```php
use Illuminate\Database\Eloquent\Attributes\ObservedBy;

#[ObservedBy([PedidoObserver::class])]
class Pedido extends Model {}

// ou no AppServiceProvider::boot()
Pedido::observe(PedidoObserver::class);
```

Se o observer implementar `ShouldHandleEventsAfterCommit`, os métodos só rodam depois que a transação do banco for confirmada. Isso evita, por exemplo, enviar e-mail de um pedido cuja transação falhou.

### Classes de evento: `$dispatchesEvents`

Mapeia eventos do Model para classes de evento comuns do Laravel, tratadas por listeners.

```php
protected $dispatchesEvents = [
    'created' => PedidoCriado::class,
    'deleted' => PedidoExcluido::class,
];
```

### Silenciar eventos

| Forma | Alcance |
| --- | --- |
| `saveQuietly()`, `updateQuietly()`, `deleteQuietly()`, `createQuietly()`, `restoreQuietly()`, `forceDeleteQuietly()`, `incrementQuietly()`, `touchQuietly()`, `replicateQuietly()` | Uma operação, de um Model |
| `Pedido::withoutEvents(fn () => ...)` | Tudo dentro da Closure. O dispatcher é compartilhado, então **nenhum** Model dispara eventos ali dentro, não só `Pedido` |
| `Pedido::unsetEventDispatcher()` / `setEventDispatcher()` | Desliga / religa manualmente (útil em testes) |

```php
$pedido = Pedido::withoutEvents(function () {
    return Pedido::create([...]);
});
```

### Eventos personalizados

Você pode registrar nomes próprios com `$observables` e disparar com `fireModelEvent`. É raro; prefira eventos comuns do Laravel (`event(new ...)`) para ações de negócio.
