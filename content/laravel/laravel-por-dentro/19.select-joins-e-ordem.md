Estes métodos controlam **quais colunas**, **em que ordem** e **quantas linhas** voltam, além de combinar tabelas.

### Escolher colunas

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->select(array|mixed $columns = ['*'])
->addSelect(array|mixed $column)
->selectRaw(string $expression, array $bindings = [])
->distinct()
```

- `select` **substitui** as colunas; `addSelect` **acrescenta**.
- Aceita apelido: `'nome as cliente'`.
- `selectRaw` para expressões SQL; `DB::raw()` também funciona dentro de `select`.

```php [app/Http/Controllers/UserController.php]
User::select('id', 'nome', 'email as contato')->get();
-- SQL: select "id", "nome", "email" as "contato" from "users"

User::select('id')->addSelect('nome')->get();
-- SQL: select "id", "nome" from "users"

Pedido::selectRaw('status, count(*) as total')->groupBy('status')->get();
-- SQL: select status, count(*) as total from "pedidos" group by "status"

User::distinct()->pluck('cidade');
-- SQL: select distinct "cidade" from "users"
```

::note{type="pitfall" title="Cuidado"}
Ao limitar colunas, inclua as chaves usadas por relacionamentos (`id`, `user_id`), senão o eager loading volta vazio.
::

**Subquery como coluna** (`addSelect` com Builder):

```php [app/Http/Controllers/UserController.php]
User::addSelect(['ultimo_pedido' => Pedido::select('created_at')
    ->whereColumn('user_id', 'users.id')
    ->latest()
    ->limit(1)
])->get();
-- SQL: select "users".*, (
--          select "created_at" from "pedidos"
--          where "user_id" = "users"."id"
--          order by "created_at" desc limit 1
--      ) as "ultimo_pedido"
--      from "users"
// Resultado: $user->ultimo_pedido
```

### Ordenar

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->orderBy(string|Closure|Expression $column, string $direction = 'asc')
```

| Método | Efeito |
| --- | --- |
| `orderBy('nome')` / `orderBy('nome', 'desc')` | Ordena; chame várias vezes para desempate |
| `orderByDesc('total')` | Atalho para `desc` |
| `latest(?string $column = null)` | `ORDER BY created_at DESC` (ou a coluna informada) |
| `oldest(?string $column = null)` | `ORDER BY created_at ASC` |
| `inRandomOrder(string $seed = '')` | Ordem aleatória; a semente repete a mesma ordem |
| `orderByRaw('array_position(array[\'novo\', \'pago\'], status)')` | SQL cru |
| `reorder(?string $column = null, string $direction = 'asc')` | Apaga as ordenações anteriores (inclusive de scopes) e, opcionalmente, define uma nova |
| `reorderDesc($column)` | `reorder` em ordem decrescente (versões recentes) |

```sql
order by "nome" asc                               -- orderBy('nome')
order by "total" desc                             -- orderByDesc('total')
order by "created_at" desc                        -- latest()
order by "created_at" asc                         -- oldest()
order by RANDOM()                                 -- inRandomOrder()
order by array_position(array['novo', 'pago'], status)   -- orderByRaw(...)
```

Ordenar por subquery (ex.: usuários pelo pedido mais recente):

```php [app/Http/Controllers/UserController.php]
User::orderByDesc(
    Pedido::select('created_at')->whereColumn('user_id', 'users.id')->latest()->limit(1)
)->get();
-- SQL: select * from "users"
--      order by (
--          select "created_at" from "pedidos"
--          where "user_id" = "users"."id" order by "created_at" desc limit 1
--      ) desc
```

### Limitar e pular

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->limit(int $value)   // apelido: take()
->offset(int $value)  // apelido: skip()
->forPage(int $page, int $perPage = 15)
```

```php [app/Http/Controllers/PostController.php]
Post::latest()->take(5)->get();
-- SQL: select * from "posts" order by "created_at" desc limit 5

Post::orderBy('id')->skip(20)->take(10)->get();
-- SQL: select * from "posts" order by "id" asc limit 10 offset 20

Post::forPage(3, 10)->get();   // página 3, 10 por página
-- SQL: select * from "posts" limit 10 offset 20
```

Para paginação com links e total, use `paginate()` ([seção 20](#agregacoes-e-paginacao)).

### Agrupar

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->groupBy(...$groups)
->having(string $column, ?string $operator = null, mixed $value = null, string $boolean = 'and')
->havingRaw(string $sql, array $bindings = [])
->havingBetween(string $column, iterable $values)
```

`having` filtra **depois** do agrupamento (sobre resultados de `count`, `sum`…); `where` filtra antes.

```php [app/Services/RelatorioService.php]
Pedido::select('user_id', DB::raw('sum(total) as gasto'))   // → select "user_id", sum(total) as gasto
    ->groupBy('user_id')                                    // → group by "user_id"
    ->havingRaw('sum(total) > ?', [1000])                   // → having sum(total) > ?
    ->get();
-- SQL: select "user_id", sum(total) as gasto from "pedidos" group by "user_id" having sum(total) > ?
//
// No PostgreSQL o having não enxerga apelidos do select (having gasto > ? dá erro),
// por isso aqui a expressão é repetida com havingRaw.
```

Variações: `orHaving`, `orHavingRaw`, `havingNull`, `havingNotNull`.

### Joins

```php [vendor/laravel/framework/src/Illuminate/Database/Query/Builder.php]
->join(string $table, Closure|string $first, ?string $operator = null, ?string $second = null, string $type = 'inner', bool $where = false)
```

- `$table`: tabela a juntar (aceita `'tabela as apelido'`).
- `$first`, `$operator`, `$second`: a condição `ON`.
- `$first` como Closure: para condições múltiplas.
- `$type` e `$where`: usados internamente por `leftJoin`, `joinWhere` etc.

```php [app/Http/Controllers/PedidoController.php]
Pedido::join('users', 'users.id', '=', 'pedidos.user_id')
    ->select('pedidos.*', 'users.nome')
    ->get();
-- SQL: select "pedidos".*, "users"."nome" from "pedidos"
--      inner join "users" on "users"."id" = "pedidos"."user_id"

User::leftJoin('pedidos', 'pedidos.user_id', '=', 'users.id')->get();
-- SQL: select * from "users" left join "pedidos" on "pedidos"."user_id" = "users"."id"

User::rightJoin(...);
-- SQL: ... right join ...

User::crossJoin('cores');
-- SQL: select * from "users" cross join "cores"

// Condições múltiplas no ON
User::join('pedidos', function ($join) {
    $join->on('users.id', '=', 'pedidos.user_id')
         ->where('pedidos.status', '=', 'pago');   // where no join = valor com binding
})->get();
-- SQL: select * from "users"
--      inner join "pedidos" on "users"."id" = "pedidos"."user_id" and "pedidos"."status" = ?
```

Join com subquery:

```php [app/Services/RelatorioService.php]
$ultimos = Pedido::select('user_id', DB::raw('max(created_at) as ultimo'))->groupBy('user_id');
// (ainda não executa: vira a subquery abaixo)

User::joinSub($ultimos, 'ultimos', fn ($join) => $join->on('users.id', '=', 'ultimos.user_id'))
    ->get();
-- SQL: select * from "users"
--      inner join (
--          select "user_id", max(created_at) as ultimo from "pedidos" group by "user_id"
--      ) as "ultimos" on "users"."id" = "ultimos"."user_id"
```

Variações: `leftJoinSub`, `rightJoinSub`, `joinLateral` / `leftJoinLateral` (MySQL 8+/PostgreSQL), `joinWhere`, `leftJoinWhere`.

::note{type="pitfall" title="Atenção"}
Com joins, colunas de mesmo nome se sobrescrevem no Model (`id` de `users` pode virar o `id` de `pedidos`). Sempre use `select('pedidos.*', ...)`. Em muitos casos, um relacionamento com `with` ou `whereHas` substitui o join com mais clareza.
::

### Unions

```php [app/Http/Controllers/UserController.php]
$primeiros = User::where('vip', true);

User::where('ativo', false)->union($primeiros)->get();   // remove duplicados
-- SQL: (select * from "users" where "ativo" = ?) union (select * from "users" where "vip" = ?)

User::where(...)->unionAll($primeiros)->get();           // mantém duplicados
-- SQL: (select * from "users" where ...) union all (select * from "users" where "vip" = ?)
```

As duas queries precisam ter as mesmas colunas.

### Expressões cruas

| Método | Uso |
| --- | --- |
| `DB::raw('expressão')` | Dentro de `select`, `orderBy`, `groupBy` |
| `selectRaw($sql, $bindings)` | Colunas |
| `whereRaw` / `orWhereRaw` | Filtros ([seção 18.13](#filtros-where-sql-cru-whereraw)) |
| `havingRaw` / `orHavingRaw` | Após agrupamento |
| `orderByRaw($sql, $bindings)` | Ordenação |
| `groupByRaw($sql, $bindings)` | Agrupamento |

Tudo que for valor do usuário vai em `$bindings` com `?`.

### `fromSub` e `from`

```php [app/Services/RelatorioService.php]
User::fromSub(Pedido::select('user_id')->distinct(), 'compradores')->count();
-- SQL: select count(*) as aggregate
--      from (select distinct "user_id" from "pedidos") as "compradores"
```

Raramente necessário com Models; `from('outra_tabela')` troca a tabela da query.
