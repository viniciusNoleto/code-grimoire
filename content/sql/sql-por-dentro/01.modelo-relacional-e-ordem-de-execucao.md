Um banco relacional guarda dados em **tabelas** (relações) formadas por **linhas** com as mesmas **colunas**. Cada tabela tem uma **chave primária** que identifica a linha, e tabelas se relacionam por **chaves estrangeiras**. SQL é **declarativo**: você descreve o resultado que quer, e o *planejador* do PostgreSQL decide como buscá-lo (que índice usar, em que ordem juntar as tabelas).

### Hierarquia no PostgreSQL

- **Cluster**: uma instância do servidor (um processo `postgres`, uma porta, um diretório de dados).
- **Database**: bancos isolados dentro do cluster. Uma conexão acessa um database só.
- **Schema**: namespace dentro do database (`public` é o padrão). `search_path` define onde o nome de uma tabela é procurado.
- **Objetos**: tabelas, views, índices, funções, tipos, sequences.

```text [psql]
psql -h localhost -U app -d loja

\l              lista databases          \dt          lista tabelas
\d pedidos      descreve uma tabela      \di          lista índices
\dn             lista schemas            \df          lista funções
\x auto         saída expandida          \timing on   mostra o tempo de cada consulta
\e              abre o editor            \q           sai
```

### A ordem lógica de um SELECT

Você escreve `SELECT` primeiro, mas ele é avaliado quase por último. Entender essa ordem explica a maioria dos erros de iniciante: por que não dá para usar um alias do `SELECT` no `WHERE`, por que `WHERE` não aceita agregados e por que `ORDER BY` aceita aliases.

::flow-diagram
---
label: "Ordem lógica de avaliação de um SELECT: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT"
steps:
  - { title: "FROM", sub: "de onde vêm as linhas (e JOINs)", highlight: true }
  - { title: "WHERE", sub: "filtra linhas", note: "aliases do SELECT ainda não existem" }
  - { title: "GROUP BY", sub: "agrupa" }
  - { title: "HAVING", sub: "filtra grupos", note: "aceita agregados" }
  - { title: "SELECT", sub: "calcula a saída", highlight: true, note: "janelas e aliases nascem aqui" }
  - { title: "ORDER BY", sub: "ordena", note: "aceita aliases" }
  - { title: "LIMIT", sub: "corta" }
---
::

```sql [ordem.sql]
SELECT cliente_id, sum(total) AS gasto      -- 5. calcula as colunas de saída
FROM pedidos                                -- 1. de onde vêm as linhas
WHERE status = 'pago'                       -- 2. filtra linhas (antes de agrupar)
GROUP BY cliente_id                         -- 3. agrupa
HAVING sum(total) > 1000                    -- 4. filtra grupos (aceita agregados)
ORDER BY gasto DESC                         -- 6. ordena (aceita alias do SELECT)
LIMIT 10;                                   -- 7. corta

-- ❌ WHERE gasto > 1000   → "column gasto does not exist": o alias ainda não existe no passo 2
-- ❌ WHERE sum(total) > 1000 → agregados não são permitidos em WHERE: use HAVING
```
