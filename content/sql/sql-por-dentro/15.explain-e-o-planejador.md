O planejador estima o custo de vários planos possíveis usando estatísticas das tabelas (quantas linhas, valores mais comuns, histogramas) e escolhe o mais barato. `EXPLAIN` mostra o plano escolhido; `EXPLAIN ANALYZE` **executa** a consulta e mostra tempos e linhas reais.

```sql [explain.sql]
EXPLAIN (ANALYZE, BUFFERS)          -- PG 18: BUFFERS já vem por padrão com ANALYZE
SELECT c.nome, count(*)
FROM pedidos p JOIN clientes c ON c.id = p.cliente_id
WHERE p.criado_em >= now() - interval '7 days'
GROUP BY c.nome;

-- ⚠ ANALYZE executa de verdade: para UPDATE/DELETE, envolva em BEGIN ... ROLLBACK
```

### Como ler

- **De dentro para fora**: os nós mais indentados rodam primeiro e alimentam os de cima.
- **`cost=início..total`** é estimativa em unidades arbitrárias. **`actual time`** é em milissegundos, **por loop**: multiplique por `loops`.
- **Compare `rows` estimado com o real.** Erros de 10x ou mais levam a planos ruins (ex.: Nested Loop onde Hash Join seria melhor). Rode `ANALYZE`, aumente `default_statistics_target` da coluna ou crie estatísticas estendidas (`CREATE STATISTICS`) para colunas correlacionadas.
- **`Buffers: shared hit`** são páginas lidas da memória; `read`, do disco.

| Nó | O que é |
| --- | --- |
| `Seq Scan` | Lê a tabela inteira. Normal para tabelas pequenas ou consultas que pegam muitas linhas. |
| `Index Scan` | Percorre o índice e busca cada linha na tabela. |
| `Index Only Scan` | Responde só com o índice (depende do *visibility map* atualizado pelo VACUUM). |
| `Bitmap Index/Heap Scan` | Junta posições de um ou mais índices e lê as páginas em ordem física. Meio-termo para muitas linhas. |
| `Nested Loop` | Para cada linha de fora, busca as de dentro. Ótimo com poucas linhas externas e índice no lado interno. |
| `Hash Join` | Monta uma tabela hash do lado menor e varre o maior. Bom para volumes grandes com igualdade. |
| `Merge Join` | Junta duas entradas já ordenadas. |
| `Sort`, `Incremental Sort` | Ordena. `Sort Method: external merge Disk` indica que `work_mem` não bastou. |
| `HashAggregate`, `GroupAggregate` | Agrupamentos. |
| `Memoize` | Cache de resultados do lado interno de um Nested Loop. |
| `Gather` | Junta resultados de workers paralelos. |

### Achar as consultas que importam

```sql [pg_stat_statements.sql]
CREATE EXTENSION pg_stat_statements;   -- precisa estar em shared_preload_libraries

SELECT calls, round(total_exec_time) AS ms_total, round(mean_exec_time, 1) AS ms_medio,
       rows, left(query, 80) AS consulta
FROM pg_stat_statements
ORDER BY total_exec_time DESC        -- o que mais consome no total, não o mais lento uma vez
LIMIT 10;
```

Também ajuda `auto_explain` (registra o plano de consultas lentas no log) e, no PG 19, as extensões `pg_plan_advice` e `pg_stash_advice` para estabilizar decisões do planejador.
