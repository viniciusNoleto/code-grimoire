Uma função de janela calcula um valor para cada linha **olhando para outras linhas relacionadas**, sem reduzir o resultado como o `GROUP BY` faz. A cláusula `OVER` define a janela: `PARTITION BY` separa em grupos, `ORDER BY` ordena dentro do grupo, e o *frame* (`ROWS`, `RANGE`, `GROUPS`) delimita quais linhas entram no cálculo.

::workbench{demo="window-functions" title="funções de janela"}
Vendas mensais de dois vendedores. Escolha a função e ligue ou desligue o `PARTITION BY vendedor`.
::

```sql [janelas.sql]
SELECT
  vendedor, mes, valor,
  row_number() OVER w                      AS n,          -- 1, 2, 3, 4 (sem empates)
  rank()       OVER (PARTITION BY vendedor ORDER BY valor DESC) AS rk,   -- 1, 2, 2, 4
  dense_rank() OVER (PARTITION BY vendedor ORDER BY valor DESC) AS drk,  -- 1, 2, 2, 3
  sum(valor)   OVER (PARTITION BY vendedor ORDER BY mes) AS acumulado,
  avg(valor)   OVER (PARTITION BY vendedor ORDER BY mes ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS media_3m,
  valor - lag(valor) OVER (PARTITION BY vendedor ORDER BY mes) AS variacao,
  round(100.0 * valor / sum(valor) OVER (PARTITION BY vendedor), 1) AS pct_do_total,
  ntile(4) OVER (ORDER BY valor) AS quartil
FROM vendas
WINDOW w AS (PARTITION BY vendedor ORDER BY mes);   -- janela nomeada, reutilizável

-- Top N por grupo: os 2 produtos mais vendidos de cada categoria
SELECT * FROM (
  SELECT categoria, produto, qtd,
         row_number() OVER (PARTITION BY categoria ORDER BY qtd DESC) AS pos
  FROM vendas_por_produto
) t WHERE pos <= 2;      -- funções de janela não podem ir no WHERE: filtre por fora
```

::note{type="pitfall" title="O frame padrão"}
Com `ORDER BY` na janela, o frame padrão é `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`: por isso `sum()` vira soma acumulada, e linhas empatadas no `ORDER BY` entram juntas. Por isso também `last_value()` parece "errado": ele vê só até a linha atual. Use `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` para a partição inteira.
::
