Restrições são regras que o banco garante para qualquer aplicação, script ou pessoa que escreva nele. Uma validação só na aplicação some na primeira vez que alguém roda um UPDATE manual.

```sql [schema.sql]
CREATE TABLE clientes (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  email      text NOT NULL UNIQUE,
  nome       text NOT NULL CHECK (length(nome) BETWEEN 2 AND 120),
  cidade     text,
  criado_em  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE pedidos (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  cliente_id  bigint NOT NULL REFERENCES clientes (id) ON DELETE RESTRICT,
  status      text NOT NULL DEFAULT 'novo'
              CHECK (status IN ('novo', 'pago', 'enviado', 'cancelado')),
  total       numeric(12,2) NOT NULL CHECK (total >= 0),
  criado_em   timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE itens_pedido (
  pedido_id   bigint REFERENCES pedidos (id) ON DELETE CASCADE,
  produto_id  bigint REFERENCES produtos (id),
  qtd         integer NOT NULL CHECK (qtd > 0),
  PRIMARY KEY (pedido_id, produto_id)          -- chave composta
);

-- Postgres NÃO cria índice automático para colunas de FK: crie você
CREATE INDEX ON pedidos (cliente_id);
CREATE INDEX ON itens_pedido (produto_id);
```

| ON DELETE | Ao apagar o pai |
| --- | --- |
| `NO ACTION` / `RESTRICT` | Erro se houver filhos (padrão; `NO ACTION` pode ser adiado até o fim da transação). |
| `CASCADE` | Apaga os filhos junto. Ótimo para partes do agregado (itens de um pedido), perigoso para o resto. |
| `SET NULL` / `SET DEFAULT` | Desliga o vínculo. Desde o 15, dá para listar colunas: `SET NULL (gerente_id)`. |

### Restrições avançadas

```sql [constraints.sql]
-- UNIQUE que trata NULLs como iguais (PG 15)
ALTER TABLE usuarios ADD CONSTRAINT documento_unico UNIQUE NULLS NOT DISTINCT (documento);

-- Unicidade parcial: um único endereço principal por cliente
CREATE UNIQUE INDEX um_principal ON enderecos (cliente_id) WHERE principal;

-- EXCLUDE: nenhuma reserva da mesma sala pode se sobrepor no tempo
CREATE EXTENSION IF NOT EXISTS btree_gist;
CREATE TABLE reservas (
  sala_id int NOT NULL,
  periodo tstzrange NOT NULL,
  EXCLUDE USING gist (sala_id WITH =, periodo WITH &&)
);

-- PG 18: chave primária temporal com WITHOUT OVERLAPS
CREATE TABLE precos (
  produto_id bigint,
  vigencia daterange,
  valor numeric(12,2),
  PRIMARY KEY (produto_id, vigencia WITHOUT OVERLAPS)
);

-- Constraint adiável: checada só no COMMIT (útil para trocas circulares)
ALTER TABLE x ADD CONSTRAINT fk FOREIGN KEY (y) REFERENCES z DEFERRABLE INITIALLY DEFERRED;
```

### ALTER TABLE sem susto

```sql [alter.sql]
ALTER TABLE clientes ADD COLUMN telefone text;                       -- instantâneo
ALTER TABLE clientes ADD COLUMN ativo boolean NOT NULL DEFAULT true; -- instantâneo desde o PG 11
ALTER TABLE clientes RENAME COLUMN cidade TO municipio;
ALTER TABLE clientes ALTER COLUMN nome TYPE varchar(200);             -- pode reescrever a tabela inteira
ALTER TABLE clientes DROP COLUMN telefone;

-- Adicionar restrição em tabela grande sem travar escritas por muito tempo:
ALTER TABLE pedidos ADD CONSTRAINT total_positivo CHECK (total >= 0) NOT VALID; -- vale para linhas novas
ALTER TABLE pedidos VALIDATE CONSTRAINT total_positivo;                         -- valida as antigas, lock leve
```
