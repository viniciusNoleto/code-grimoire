Escolher o tipo certo evita conversões, perda de precisão e migrações caras depois. A tabela abaixo resume o que usar e o que evitar no PostgreSQL.

| Use | Para | Evite / atenção |
| --- | --- | --- |
| `bigint`, `integer` | Inteiros. IDs em `bigint`: 2 bilhões de linhas chegam mais rápido do que parece. | `smallint` só com motivo. |
| `numeric(12,2)` | Dinheiro e tudo que exige exatidão decimal. | `real`/`double precision` para dinheiro (0,1 + 0,2 ≠ 0,3). O tipo `money` depende de locale. |
| `text` | Strings em geral. Mesmo desempenho que `varchar`. | `char(n)` (preenche com espaços). Limite de tamanho? Use `CHECK (length(x) <= n)` ou `varchar(n)`. |
| `timestamptz` | Instantes no tempo. Guarda em UTC e converte para o `TimeZone` da sessão. | `timestamp` sem fuso para eventos reais: ambíguo entre servidores e horário de verão. |
| `date`, `time`, `interval` | Datas de calendário, horas, durações (`now() - interval '7 days'`). | `timetz` quase nunca faz sentido. |
| `boolean` | Verdadeiro/falso (e `NULL`). | Strings "S"/"N". |
| `uuid` | Identificadores globais. `uuidv7()` :version[18] gera UUIDs ordenados no tempo, bons para índices B-tree. | `gen_random_uuid()` (v4) espalha inserções pelo índice inteiro. |
| `jsonb` | Dados semiestruturados, indexáveis ([capítulo 17](#jsonb)). | `json` (texto, sem índice, preserva duplicatas) salvo motivo específico. |
| `text[]`, `int[]` | Arrays: tags, listas curtas. | Arrays para relacionamentos que precisam de FK. |
| `tstzrange`, `daterange`, `int4range` | Intervalos com operadores de sobreposição (reservas, vigências). | Duas colunas início/fim quando precisa impedir sobreposição. |
| `ENUM` | Conjunto fixo e pequeno de valores. | Valores que mudam com frequência: remover valor de enum é difícil. Uma tabela de referência ou `CHECK` é mais flexível. |
| `bytea` | Binários pequenos. | Arquivos grandes: guarde num storage de objetos e salve a URL. |
| `inet`, `cidr`, `macaddr` | Endereços de rede, com operadores próprios. | IPs em `text`. |

### Chaves geradas

```sql [identity.sql]
-- ✅ moderno (padrão SQL): identity
CREATE TABLE clientes (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  nome text NOT NULL
);

-- legado: serial cria uma sequence "solta", com permissões e dono separados
CREATE TABLE antigo (id bigserial PRIMARY KEY);

-- UUID ordenado no tempo (PG 18)
CREATE TABLE eventos (id uuid PRIMARY KEY DEFAULT uuidv7(), payload jsonb);
```

### Colunas geradas :version[18]

```sql [generated.sql]
CREATE TABLE itens (
  preco numeric(12,2) NOT NULL,
  qtd integer NOT NULL,
  total numeric(12,2) GENERATED ALWAYS AS (preco * qtd) VIRTUAL,     -- PG 18: calculada na leitura (padrão)
  busca tsvector GENERATED ALWAYS AS (to_tsvector('portuguese', nome)) STORED  -- gravada em disco, indexável
);
```

### Conversões e literais

`'42'::int` (sintaxe do Postgres) e `CAST('42' AS int)` (padrão SQL) fazem o mesmo. Strings usam aspas simples; aspas duplas são para **identificadores** (`"NomeComMaiuscula"`). Nomes sem aspas são convertidos para minúsculas, então prefira `snake_case` sempre.
