Datas são a fonte mais comum de bugs silenciosos em relatórios. Quase todos vêm de três confusões: **qual "agora"** você está usando, **em qual fuso** um instante é interpretado e **onde termina** um intervalo.

### timestamptz: o que é guardado de verdade

Apesar do nome, `timestamptz` **não guarda o fuso**. Ele converte o valor recebido para UTC e guarda só o instante. Na leitura, converte para o `TimeZone` da sessão. Por isso o mesmo registro aparece com horas diferentes para sessões em fusos diferentes, e está correto: é o mesmo instante.

```sql [fusos.sql]
SET TIME ZONE 'America/Manaus';
SELECT timestamptz '2026-11-06 14:00-04';     -- 2026-11-06 14:00:00-04
SET TIME ZONE 'UTC';
SELECT timestamptz '2026-11-06 14:00-04';     -- 2026-11-06 18:00:00+00 (mesmo instante)

-- AT TIME ZONE converte nos dois sentidos, e o tipo do resultado muda:
SELECT timestamptz '2026-11-06 18:00+00' AT TIME ZONE 'America/Manaus';  -- timestamp 2026-11-06 14:00 (hora de parede local)
SELECT timestamp '2026-11-06 14:00' AT TIME ZONE 'America/Manaus';       -- timestamptz: interpreta 14h como hora de Manaus
```

Use sempre nomes de fuso IANA (`America/Manaus`), nunca abreviações (`BRT`) nem deslocamentos fixos (`-04`) para regras de negócio: nomes acompanham mudanças de horário de verão e de legislação.

### Qual "agora"?

| Função | Valor | Use para |
| --- | --- | --- |
| `now()` = `current_timestamp` | Início da **transação**. Igual em todas as instruções dela. | Padrão: todas as linhas de uma operação ficam com o mesmo carimbo. |
| `statement_timestamp()` | Início da instrução atual. | Logs por instrução dentro de transações longas. |
| `clock_timestamp()` | Hora real, muda a cada chamada, inclusive dentro de uma mesma consulta. | Medir duração dentro de funções; nunca como DEFAULT de lote. |
| `current_date`, `localtimestamp` | Data e hora de parede no fuso da sessão. | Cuidado: dependem do `TimeZone` da conexão. |

### Truncar, extrair e agrupar

| Expressão | Resultado |
| --- | --- |
| `date_trunc('month', timestamptz '2026-11-06 14:30-04', 'America/Manaus')` | `2026-11-01 00:00:00-04` (o 3º argumento, PG 12, trunca no fuso certo) |
| `extract(dow FROM date '2026-11-06')` | `5` (sexta; domingo = 0; `isodow` usa segunda = 1, domingo = 7) |
| `extract(epoch FROM timestamptz '2026-11-06 00:00Z')` | segundos desde 1970 (retorna `numeric` desde o PG 14) |
| `date_bin('15 minutes', timestamp '2026-11-06 14:37', timestamp '2026-01-01')` | `2026-11-06 14:30:00` (PG 14: baldes de qualquer tamanho) |
| `date '2026-11-06' - date '2026-01-01'` | `309` (inteiro, em dias) |
| `age(date '2026-11-06', date '1990-05-20')` | `36 years 5 mons 17 days` |
| `date '2026-01-31' + interval '1 month'` | `2026-02-28 00:00:00` (ajusta para o último dia do mês) |
| `to_char(timestamp '2026-11-06 14:05', 'DD/MM/YYYY HH24:MI')` | `06/11/2026 14:05` (`TMMonth` traduz conforme `lc_time`) |
| `to_date('06/11/2026', 'DD/MM/YYYY')` | `2026-11-06` |
| `make_date(2026, 11, 6)`, `make_interval(days => 3)` | construtores a partir de números |

### Aplicando: relatórios corretos

```sql [relatorios.sql]
-- ❌ BETWEEN com timestamps perde o último dia inteiro depois de 00:00:00
WHERE criado_em BETWEEN '2026-11-01' AND '2026-11-30'

-- ✅ intervalo semiaberto: inclui o início, exclui o fim (e usa o índice)
WHERE criado_em >= '2026-11-01' AND criado_em < '2026-12-01'

-- Vendas por dia NO FUSO DA LOJA, com dias sem venda aparecendo como zero
SELECT d.dia::date, coalesce(sum(p.total), 0) AS total
FROM generate_series(date '2026-11-01', date '2026-11-30', interval '1 day') AS d(dia)
LEFT JOIN pedidos p
  ON (p.criado_em AT TIME ZONE 'America/Manaus')::date = d.dia::date
GROUP BY 1 ORDER BY 1;

-- Pedidos por hora do dia (para escalar equipe de suporte)
SELECT extract(hour FROM criado_em AT TIME ZONE 'America/Manaus') AS hora, count(*)
FROM pedidos GROUP BY 1 ORDER BY 1;

-- Assinaturas que vencem nos próximos 7 dias
SELECT * FROM assinaturas WHERE vence_em >= now() AND vence_em < now() + interval '7 days';
```

::note{type="pitfall" title="interval '1 day' não é '24 hours'"}
Em fusos com horário de verão, somar `interval '1 day'` a um `timestamptz` mantém a mesma hora de parede (o dia pode ter 23 ou 25 horas); somar `'24 hours'` soma exatamente 24 horas. Manaus não tem horário de verão, mas um sistema com clientes em outros países tem. Escolha conforme a regra de negócio ("amanhã no mesmo horário" vs "daqui a 24 horas").
::
