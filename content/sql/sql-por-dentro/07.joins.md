Um JOIN combina linhas de duas tabelas segundo uma condição. O tipo de JOIN decide o que acontece com as linhas que **não têm par**.

::workbench{demo="join-types" title="tipos de JOIN"}
Três clientes e cinco pedidos. Um pedido não tem cliente (`NULL`) e outro aponta para um cliente que não existe (tabela sem FK, só para o exemplo). Escolha o tipo e veja o SQL e o resultado.
::

```sql [joins.sql]
-- INNER: só pares que casam
SELECT c.nome, p.id, p.total FROM clientes c JOIN pedidos p ON p.cliente_id = c.id;

-- LEFT: todos os clientes, com ou sem pedido (colunas de p viram NULL)
SELECT c.nome, count(p.id) AS pedidos FROM clientes c LEFT JOIN pedidos p ON p.cliente_id = c.id GROUP BY c.nome;

-- ❗ Filtro do lado direito no WHERE transforma o LEFT em INNER:
SELECT ... FROM clientes c LEFT JOIN pedidos p ON p.cliente_id = c.id WHERE p.status = 'pago';      -- some quem não tem pedido
SELECT ... FROM clientes c LEFT JOIN pedidos p ON p.cliente_id = c.id AND p.status = 'pago';        -- ✅ mantém todos

-- SEMI JOIN: clientes que têm pelo menos um pedido (sem duplicar linhas)
SELECT * FROM clientes c WHERE EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.id);

-- ANTI JOIN: clientes sem pedido. Use NOT EXISTS, nunca NOT IN com coluna que aceita NULL
SELECT * FROM clientes c WHERE NOT EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.id);

-- SELF JOIN: funcionário e seu gerente
SELECT f.nome, g.nome AS gerente FROM funcionarios f LEFT JOIN funcionarios g ON g.id = f.gerente_id;

-- USING: quando a coluna tem o mesmo nome nos dois lados
SELECT * FROM pedidos JOIN itens_pedido USING (pedido_id);
```

### LATERAL: um JOIN que enxerga a linha da esquerda

Uma subconsulta em `JOIN LATERAL` pode referenciar colunas da tabela à esquerda, como um loop "para cada linha, rode esta consulta". É a forma idiomática de "os N últimos de cada grupo".

```sql [lateral.sql]
-- Os 3 pedidos mais recentes de cada cliente
SELECT c.nome, ult.id, ult.total, ult.criado_em
FROM clientes c
CROSS JOIN LATERAL (
  SELECT id, total, criado_em
  FROM pedidos p
  WHERE p.cliente_id = c.id
  ORDER BY criado_em DESC
  LIMIT 3
) ult;
-- Com índice em pedidos (cliente_id, criado_em DESC), cada busca interna é um index scan curto.
-- LEFT JOIN LATERAL (...) ON true mantém clientes sem pedido.
```
