Lógica que precisa valer para qualquer cliente do banco pode morar nele: funções, procedures, triggers e views.

```sql [funcoes.sql]
-- Função SQL: pode ser embutida pelo planejador
CREATE FUNCTION total_cliente(p_cliente bigint) RETURNS numeric
LANGUAGE sql STABLE AS $$
  SELECT coalesce(sum(total), 0) FROM pedidos WHERE cliente_id = p_cliente AND status = 'pago'
$$;

-- PL/pgSQL: variáveis, IF, loops, exceções
CREATE FUNCTION transferir(origem bigint, destino bigint, valor numeric) RETURNS void
LANGUAGE plpgsql AS $$
DECLARE saldo_atual numeric;
BEGIN
  SELECT saldo INTO saldo_atual FROM contas WHERE id = origem FOR UPDATE;
  IF saldo_atual < valor THEN
    RAISE EXCEPTION 'saldo insuficiente: % < %', saldo_atual, valor USING ERRCODE = 'P0001';
  END IF;
  UPDATE contas SET saldo = saldo - valor WHERE id = origem;
  UPDATE contas SET saldo = saldo + valor WHERE id = destino;
END $$;

-- PROCEDURE pode fazer COMMIT no meio (processar em lotes)
CREATE PROCEDURE arquivar_em_lotes() LANGUAGE plpgsql AS $$
BEGIN
  LOOP
    DELETE FROM logs WHERE id IN (SELECT id FROM logs WHERE criado_em < now() - interval '90 days' LIMIT 5000);
    EXIT WHEN NOT FOUND;
    COMMIT;
  END LOOP;
END $$;
CALL arquivar_em_lotes();
```

**Volatilidade** diz ao planejador o que ele pode otimizar: `IMMUTABLE` (mesma entrada, mesma saída sempre; pode ir em índices), `STABLE` (constante dentro de uma consulta, pode ler tabelas) e `VOLATILE` (padrão; pode mudar a cada chamada, como `random()`). Marcar errado dá resultados errados ou impede otimizações.

### Triggers

```sql [triggers.sql]
CREATE FUNCTION tocar_atualizado_em() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.atualizado_em := now();
  RETURN NEW;
END $$;

CREATE TRIGGER pedidos_atualizado_em
BEFORE UPDATE ON pedidos
FOR EACH ROW
WHEN (OLD.* IS DISTINCT FROM NEW.*)
EXECUTE FUNCTION tocar_atualizado_em();

-- Auditoria com tabelas de transição (uma execução por instrução, não por linha)
CREATE TRIGGER auditar AFTER UPDATE ON precos
REFERENCING OLD TABLE AS antes NEW TABLE AS depois
FOR EACH STATEMENT EXECUTE FUNCTION registrar_auditoria();
```

Triggers são invisíveis para quem lê o código da aplicação. Use para invariantes de dados (timestamps, auditoria, contadores desnormalizados), não para regras de negócio complexas.

### Views e materialized views

```sql [views.sql]
-- View: consulta salva, sempre atual, sem armazenar dados
CREATE VIEW pedidos_pagos AS SELECT * FROM pedidos WHERE status = 'pago';

-- Materialized view: resultado gravado, atualizado quando você mandar
CREATE MATERIALIZED VIEW vendas_mensais AS
SELECT date_trunc('month', criado_em) AS mes, sum(total) AS total FROM pedidos GROUP BY 1;
CREATE UNIQUE INDEX ON vendas_mensais (mes);                 -- exigido pelo CONCURRENTLY
REFRESH MATERIALIZED VIEW CONCURRENTLY vendas_mensais;       -- não bloqueia leituras
```
