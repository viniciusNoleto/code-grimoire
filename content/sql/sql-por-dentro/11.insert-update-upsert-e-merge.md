Escrever dados também tem recursos que poupam idas e voltas: devolver o que foi gerado, atualizar com base em outra tabela e inserir ou atualizar de forma atômica.

```sql [dml.sql]
-- Várias linhas de uma vez, devolvendo o que foi gerado
INSERT INTO clientes (email, nome) VALUES
  ('ana@ex.com', 'Ana'),
  ('bruno@ex.com', 'Bruno')
RETURNING id, criado_em;

INSERT INTO resumo_diario (dia, total)
SELECT criado_em::date, sum(total) FROM pedidos GROUP BY 1;

-- UPDATE com JOIN (FROM) e DELETE com JOIN (USING)
UPDATE pedidos p SET status = 'cancelado'
FROM clientes c
WHERE c.id = p.cliente_id AND c.bloqueado AND p.status = 'novo';

DELETE FROM sessoes s USING usuarios u
WHERE u.id = s.usuario_id AND u.removido;

-- PG 18: RETURNING com OLD e NEW
UPDATE produtos SET preco = preco * 1.1 WHERE categoria = 'teclado'
RETURNING id, old.preco AS antes, new.preco AS depois;
```

### Upsert: INSERT … ON CONFLICT

```sql [upsert.sql]
INSERT INTO estoque (produto_id, qtd) VALUES (42, 5)
ON CONFLICT (produto_id)                        -- precisa de UNIQUE/PK nessa(s) coluna(s)
DO UPDATE SET qtd = estoque.qtd + EXCLUDED.qtd, -- EXCLUDED = a linha que você tentou inserir
              atualizado_em = now()
WHERE estoque.bloqueado = false
RETURNING *;

INSERT INTO visitas_unicas (usuario_id, dia) VALUES (7, current_date)
ON CONFLICT DO NOTHING;                         -- ignora duplicata
-- PG 19: ON CONFLICT DO SELECT ... RETURNING devolve a linha que já existia
```

O upsert é **atômico**: duas transações tentando inserir a mesma chave ao mesmo tempo não geram duplicata nem erro, ao contrário do padrão "SELECT, se não existe, INSERT" da aplicação.

### MERGE

```sql [merge.sql]
-- Sincronizar a tabela de produtos com uma carga vinda do fornecedor (PG 15+)
MERGE INTO produtos p
USING carga_fornecedor c ON p.sku = c.sku
WHEN MATCHED AND c.descontinuado THEN DELETE
WHEN MATCHED THEN UPDATE SET preco = c.preco, nome = c.nome
WHEN NOT MATCHED THEN INSERT (sku, nome, preco) VALUES (c.sku, c.nome, c.preco)
WHEN NOT MATCHED BY SOURCE THEN UPDATE SET ativo = false   -- PG 17: produtos que sumiram da carga
RETURNING merge_action(), p.sku;                           -- PG 17
```

Use `ON CONFLICT` para upserts concorrentes de uma linha (ele é seguro sob concorrência); `MERGE` para sincronizações em lote com várias regras, normalmente feitas por um único processo.

### Cargas grandes: COPY

```sql [copy.sql]
COPY produtos (sku, nome, preco) FROM '/dados/produtos.csv' WITH (FORMAT csv, HEADER true);  -- arquivo no servidor
\copy produtos FROM 'produtos.csv' WITH (FORMAT csv, HEADER)  -- psql: arquivo na sua máquina
COPY (SELECT * FROM pedidos WHERE criado_em > '2026-10-01') TO STDOUT WITH (FORMAT csv, HEADER);
-- PG 17: ON_ERROR ignore pula linhas inválidas · PG 19: COPY ... TO (FORMAT json)
TRUNCATE logs RESTART IDENTITY;   -- esvazia a tabela inteira de forma instantânea (lock exclusivo)
```
