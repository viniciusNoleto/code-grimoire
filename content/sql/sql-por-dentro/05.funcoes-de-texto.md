Manipular texto no banco evita trazer milhares de linhas para a aplicação só para limpar ou formatar um campo. Antes das funções, três conceitos que mudam o resultado delas:

- **Caracteres não são bytes.** Num banco UTF-8 (o padrão), `'ç'` ocupa 2 bytes. `length()` conta caracteres; `octet_length()` conta bytes. Limites de colunas `varchar(n)` são em caracteres.
- **NULL contamina.** O operador `||` devolve `NULL` se qualquer parte for nula. `concat()` e `concat_ws()` ignoram nulos. Num relatório com campos opcionais, essa diferença decide se a linha aparece vazia.
- **Collation decide comparação e ordem.** Ela define se `'a' < 'B'`, como acentos são ordenados e se `'ã' = 'a'`. Ela vem do database ou da coluna e pode ser trocada por expressão: `ORDER BY nome COLLATE "pt-BR-x-icu"`.

### Juntar e formatar

| Expressão | Resultado | Observação |
| --- | --- | --- |
| `'Boa' \|\| ' ' \|\| 'Vista'` | `Boa Vista` | Padrão SQL. |
| `'a' \|\| NULL` | `NULL` | Qualquer parte nula anula tudo. |
| `concat('a', NULL, 'b')` | `ab` | Ignora nulos; converte números sozinha. |
| `concat_ws(', ', 'Manaus', NULL, 'AM')` | `Manaus, AM` | Separador só entre valores não nulos. Ideal para endereços. |
| `format('Olá %s, %s pedidos', 'Ana', 3)` | `Olá Ana, 3 pedidos` | Como `printf`. |
| `format('SELECT * FROM %I WHERE n = %L', 'Pedidos', 'O''Neil')` | `SELECT * FROM "Pedidos" WHERE n = 'O''Neil'` | `%I` cita identificador, `%L` cita literal: a forma segura de montar SQL dinâmico em PL/pgSQL. |

### Maiúsculas, tamanho e extração

| Expressão | Resultado | Observação |
| --- | --- | --- |
| `upper('ação')` / `lower('AÇÃO')` | `AÇÃO` / `ação` | Respeitam acentos (dependem da collation). |
| `initcap('joão da silva')` | `João Da Silva` | Capitaliza toda palavra, inclusive "Da". Para nomes, ajuste exceções na aplicação. |
| `length('ação')` / `octet_length('ação')` | `4` / `6` | Caracteres vs bytes. |
| `left('PostgreSQL', 4)` / `right('PostgreSQL', 3)` | `Post` / `SQL` | Negativo tira do outro lado: `left('PostgreSQL', -3)` → `Postgr`. |
| `substring('PostgreSQL' FROM 5 FOR 3)` | `gre` | Posições começam em 1. `substr(s, 5, 3)` é igual. |
| `position('SQL' IN 'PostgreSQL')` | `8` | 0 se não achar. `strpos(s, 'SQL')` é igual. |
| `starts_with('PostgreSQL', 'Post')` | `true` | Mais legível que `LIKE 'Post%'` e pode usar índice com `text_pattern_ops`. |
| `split_part('a,b,c', ',', 2)` | `b` | Índice negativo conta do fim (PG 14): `split_part('a,b,c', ',', -1)` → `c`. |
| `string_to_array('a,b,,c', ',')` | `{a,b,"",c}` | Vira array. `string_to_table` (PG 14) vira linhas. |

### Limpar e substituir

| Expressão | Resultado | Observação |
| --- | --- | --- |
| `trim('  oi  ')` | `oi` | Também `ltrim`, `rtrim` e `btrim(s, 'x')` para outros caracteres. |
| `lpad('42', 5, '0')` | `00042` | Códigos com zeros à esquerda. Corta se o texto for maior que o tamanho. |
| `replace('2026-11-06', '-', '/')` | `2026/11/06` | Substitui todas as ocorrências de uma substring exata. |
| `translate('ação', 'çã', 'ca')` | `acao` | Troca caractere por caractere (posição a posição). Rápido para mapeamentos simples. |
| `unaccent('São João')` | `Sao Joao` | Extensão `unaccent`. Remove acentos de forma completa (melhor que `translate`). |
| `regexp_replace('(92) 99876-5432', '\D', '', 'g')` | `92998765432` | Sem a flag `'g'`, troca só a primeira ocorrência. |
| `normalize('é', NFC)` | `é` | PG 13. Unifica formas Unicode ("e" + acento combinante vira "é"): textos colados de PDFs costumam vir decompostos. |

### Expressões regulares

O Postgres usa expressões regulares POSIX estendidas, com os atalhos `\d`, `\w`, `\s`. Os operadores são `~` (casa, diferencia maiúsculas), `~*` (sem diferenciar), `!~` e `!~*`. Evite `SIMILAR TO`: é uma mistura confusa de LIKE e regex.

| Expressão | Resultado | Observação |
| --- | --- | --- |
| `'pedido #4821' ~ '#\d+'` | `true` | Teste. |
| `regexp_match('pedido #4821', '#(\d+)')` | `{4821}` | Primeira ocorrência; array com os grupos. Pegue com `(…)[1]`. |
| `regexp_matches('a1 b2', '([a-z])(\d)', 'g')` | 2 linhas: `{a,1}`, `{b,2}` | Todas as ocorrências, uma linha cada. |
| `regexp_count('a1b22c333', '\d+')` | `3` | PG 15, junto com `regexp_substr`, `regexp_instr` e `regexp_like`. |
| `regexp_split_to_table('a  b c', '\s+')` | 3 linhas: `a`, `b`, `c` | Divide por padrão. |

### Aplicando: limpeza e slugs

```sql [limpeza.sql]
-- Normalizar telefones vindos de uma importação: só dígitos, com DDD
UPDATE clientes
SET telefone = regexp_replace(telefone, '\D', '', 'g')
WHERE telefone ~ '\D';

-- Separar "Nome Sobrenome" de forma tolerante a espaços extras
SELECT split_part(trim(nome), ' ', 1)                         AS primeiro_nome,
       nullif(regexp_replace(trim(nome), '^\S+\s*', ''), '')  AS resto
FROM clientes;

-- Slug para URL: "Teclado Mecânico MX — Edição 2026!" → "teclado-mecanico-mx-edicao-2026"
CREATE EXTENSION IF NOT EXISTS unaccent;
SELECT trim(BOTH '-' FROM regexp_replace(lower(unaccent(titulo)), '[^a-z0-9]+', '-', 'g')) AS slug
FROM produtos;
```

### Comparar sem diferenciar maiúsculas e acentos

Há três caminhos, com custos diferentes:

| Abordagem | Como | Vantagens | Desvantagens |
| --- | --- | --- | --- |
| Índice de expressão | `CREATE INDEX ON clientes (lower(email))` e consultar com `lower(email) = lower($1)` | Simples, funciona em qualquer versão. | Toda consulta precisa repetir a mesma expressão, ou o índice não é usado. |
| `citext` | Extensão; tipo `citext` na coluna. | Transparente: `=` já ignora maiúsculas; `UNIQUE` funciona. | Não ignora acentos; tipo extra para mapear no ORM. |
| Collation não determinística (ICU) | `CREATE COLLATION ci_ai (provider = icu, locale = 'und-u-ks-level1', deterministic = false)` e `nome text COLLATE ci_ai` | Ignora maiúsculas *e* acentos; `UNIQUE` respeita isso. | `LIKE` só passou a funcionar com elas no PG 18; índices B-tree não servem para prefixo; um pouco mais lenta. |

::note{type="pitfall" title="Função em índice precisa ser IMMUTABLE"}
`unaccent()` é marcada como `STABLE` (depende de um dicionário que pode mudar), então `CREATE INDEX ON t (unaccent(nome))` falha. A solução comum é uma função wrapper `IMMUTABLE` que chama `unaccent('unaccent', $1)` com o dicionário explícito. Assim você assume a responsabilidade de reindexar se o dicionário mudar.
::

### Formatar números

```sql [to_char.sql]
SELECT to_char(1234567.891, 'FM9G999G999D00');   -- G e D seguem lc_numeric: '1.234.567,89' em pt_BR, '1,234,567.89' em C/en
SELECT to_char(0.4567 * 100, 'FM990D0') || '%';  -- '45,7%' em pt_BR (to_char não multiplica por 100)
SELECT to_char(42, 'FM00000');                    -- '00042' (FM remove o espaço do sinal)
-- Em geral, formate na aplicação (Intl.NumberFormat); no banco, prefira devolver numeric.
```
