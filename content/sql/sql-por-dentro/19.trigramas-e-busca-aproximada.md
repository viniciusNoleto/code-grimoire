A busca textual entende palavras. Trigramas entendem **grafia**: servem para nomes próprios, códigos, e-mails, erros de digitação e para acelerar `LIKE '%x%'`, casos em que stemming não ajuda ou atrapalha.

### Como funciona

A extensão `pg_trgm` quebra cada palavra em todas as sequências de 3 caracteres, depois de colocar dois espaços antes e um depois dela e passar tudo para minúsculas. A **similaridade** entre dois textos é a fração de trigramas em comum: trigramas compartilhados divididos pelo total de trigramas distintos dos dois.

```sql [show_trgm.sql]
CREATE EXTENSION pg_trgm;
SELECT show_trgm('gato');                     -- {"  g"," ga",ato,gat,"to "}
SELECT similarity('Joao Silva', 'Joao Slva'); -- alta apesar do erro
SELECT 'Joao Slva' % 'Joao Silva';            -- true se similaridade >= pg_trgm.similarity_threshold (0.3)
```

### Operadores e funções

| Operador / função | Significado | Exemplo de uso |
| --- | --- | --- |
| `similarity(a, b)`, `a % b` | Similaridade entre os textos inteiros; `%` compara com `pg_trgm.similarity_threshold`. | Deduplicar cadastros de clientes. |
| `word_similarity(a, b)`, `a <% b` | Quanto `a` parece com **algum trecho** de `b`. | Busca de "silva" dentro de "Maria da Silva Pereira". |
| `strict_word_similarity`, `<<%` | Como o anterior, mas o trecho precisa respeitar limites de palavras. | Evitar casar "ana" com "banana". |
| `a <-> b` | Distância (1 − similaridade). Com índice GiST, permite `ORDER BY` por proximidade. | "Os 10 nomes mais parecidos com o digitado." |
| `LIKE`, `ILIKE`, `~`, `~*` | Com índice de trigramas, passam a usar índice mesmo com `%` no começo ou regex. | `WHERE email ILIKE '%@empresa.com'` |

### GIN ou GiST?

```sql [trgm-indices.sql]
-- GIN: melhor para filtrar (%, LIKE, ILIKE, regex). Mais rápido na busca, maior, mais caro de atualizar.
CREATE INDEX clientes_nome_trgm_gin ON clientes USING gin (nome gin_trgm_ops);

-- GiST: suporta ORDER BY nome <-> 'termo' (vizinho mais próximo). Menor; buscas um pouco mais lentas.
CREATE INDEX clientes_nome_trgm_gist ON clientes USING gist (nome gist_trgm_ops);

-- Autocompletar tolerante a erros: os 10 mais parecidos
SELECT nome, nome <-> 'Joao Slva' AS distancia
FROM clientes
WHERE nome % 'Joao Slva'
ORDER BY nome <-> 'Joao Slva'
LIMIT 10;

-- Ajustar o limiar por sessão (mais alto = menos resultados e mais rápido)
SET pg_trgm.similarity_threshold = 0.45;
```

### Vantagens e desvantagens

| Vantagens | Desvantagens |
| --- | --- |
| Tolera erros de digitação, letras trocadas e abreviações. Independe de idioma; ótimo para nomes, marcas, códigos. Acelera `LIKE '%x%'` e regex, que nenhum outro índice atende. | Não entende linguagem: "consultas" e "consulta" são só parecidas, e sinônimos não existem. Termos com menos de 3 caracteres geram poucos trigramas e quase não filtram. Índices grandes (muitas entradas por linha) e escrita mais cara. Limiar baixo em tabelas grandes retorna muitos candidatos e fica lento. |

**Combinação comum**: busca textual para conteúdo (artigos, descrições) e trigramas para nomes e para o "você quis dizer" quando a busca textual não retorna nada. A extensão `fuzzystrmatch` complementa com `levenshtein()` (número de edições entre duas strings) e algoritmos fonéticos como `soundex` e `metaphone`, pensados para inglês.
