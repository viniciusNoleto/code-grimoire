O `SELECT` é a instrução que você mais escreve. Além do básico de filtros e ordenação, o que mais causa bug é o `NULL`, que não se comporta como um valor comum.

```sql [select.sql]
SELECT id, nome, email
FROM clientes
WHERE cidade IN ('Manaus', 'Boa Vista')
  AND criado_em >= now() - interval '30 days'
  AND nome ILIKE 'an%'                  -- ILIKE: sem diferenciar maiúsculas
ORDER BY criado_em DESC NULLS LAST
LIMIT 20 OFFSET 40;

SELECT
  nome,
  CASE WHEN total >= 1000 THEN 'alto' WHEN total >= 100 THEN 'médio' ELSE 'baixo' END AS faixa,
  coalesce(apelido, nome) AS exibicao,   -- primeiro valor não nulo
  nullif(desconto, 0) AS desconto,       -- vira NULL se for 0 (evita divisão por zero)
  total BETWEEN 10 AND 20 AS na_faixa    -- inclusivo nas duas pontas
FROM ...;

-- DISTINCT ON (extensão do Postgres): o pedido mais recente de cada cliente
SELECT DISTINCT ON (cliente_id) cliente_id, id, criado_em
FROM pedidos
ORDER BY cliente_id, criado_em DESC;
```

### NULL e a lógica de três valores

`NULL` significa "desconhecido", não "vazio". Qualquer comparação com `NULL` dá `NULL`, e `WHERE` só mantém linhas em que a condição é `true`.

| Expressão | Resultado |
| --- | --- |
| `NULL = NULL` | `NULL` (não `true`) |
| `NULL IS NULL` | `true` |
| `NULL IS NOT DISTINCT FROM NULL` | `true` (igualdade que trata NULL como valor) |
| `true AND NULL` / `false AND NULL` | `NULL` / `false` |
| `true OR NULL` / `false OR NULL` | `true` / `NULL` |
| `5 NOT IN (1, NULL)` | `NULL`: a armadilha do `NOT IN` ([capítulo 07](#joins)) |
| `count(coluna)` | ignora NULLs; `count(*)` conta linhas |

::note{type="pitfall" title="Armadilha"}
`WHERE status <> 'cancelado'` não retorna linhas com `status` nulo. Se elas devem aparecer: `WHERE status IS DISTINCT FROM 'cancelado'`. E `ORDER BY` põe NULLs **por último** em ordem crescente e **primeiro** em decrescente; controle com `NULLS FIRST/LAST`.
::
