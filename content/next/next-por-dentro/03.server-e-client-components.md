No App Router, **todo componente é :server[Server Component] por padrão**. Ele roda no servidor (no build ou por requisição), pode ser `async`, acessa banco, sistema de arquivos e segredos, e seu código **nunca vai para o navegador**. O resultado não é HTML puro, é o *RSC payload*: uma descrição serializada da árvore que o React no cliente sabe montar.

Um :client[Client Component] é o componente React que você já conhece: tem estado, efeitos, handlers de evento e APIs do navegador. Ele também é renderizado no servidor para gerar o HTML inicial (SSR), e depois é **hidratado** no navegador, onde ganha interatividade.

| Preciso de… | Server | Client |
| --- | --- | --- |
| Buscar dados, acessar banco ou segredos | sim | não (use Server Action ou API) |
| `useState`, `useEffect`, `useReducer`, context | não | sim |
| `onClick`, `onChange` | não | sim |
| `window`, `localStorage`, Workers, EventSource | não | sim (em efeitos) |
| Manter bibliotecas pesadas fora do bundle (markdown, syntax highlight) | sim | não |

### 'use client' marca uma fronteira de módulos

A diretiva `'use client'` no topo de um arquivo diz: "a partir deste módulo, tudo o que ele **importa** também entra no bundle do cliente". Ela não precisa estar em cada componente interativo, só no ponto de entrada. O que atravessa a fronteira são **props**, e elas precisam ser serializáveis: dados, Promises, JSX e Server Actions passam; funções comuns e instâncias de classe não.

A exceção que salva a arquitetura: **JSX passado como `children` ou outra prop** continua sendo Server Component, mesmo dentro de um Client Component. Quem o importou foi o servidor.

::workbench{demo="rsc-boundary" title="Onde fica a fronteira"}
Marque `'use client'` em qualquer componente. Tudo que ele importa vira cliente; o que entra via `children` continua no servidor. Os tamanhos são ilustrativos.
::

```tsx [app/produto/Tabs.tsx]
'use client';
import { useState } from 'react';

// Client: precisa de estado. Recebe o conteúdo pronto via props.
export function Tabs({ descricao, avaliacoes }: { descricao: React.ReactNode; avaliacoes: React.ReactNode }) {
  const [aba, setAba] = useState<'desc' | 'aval'>('desc');
  return (
    <div>
      <button onClick={() => setAba('desc')}>Descrição</button>
      <button onClick={() => setAba('aval')}>Avaliações</button>
      {aba === 'desc' ? descricao : avaliacoes}
    </div>
  );
}
```

```tsx [app/produto/page.tsx]
import { Tabs } from './Tabs';
import { Avaliacoes } from './Avaliacoes';  // Server Component: lê o banco
import { Markdown } from './Markdown';      // Server Component: lib pesada fica no servidor

export default async function Page() {
  const produto = await getProduto();
  return (
    <Tabs
      descricao={<Markdown texto={produto.descricao} />}
      avaliacoes={<Avaliacoes produtoId={produto.id} />}
    />
  );
}
```

::note{type="pitfall" title="Armadilhas"}
Colocar `'use client'` no layout raiz transforma o app inteiro em cliente. Context providers são Client Components: crie um `Providers.tsx` com `'use client'` que recebe `children` e use-o no layout. Para garantir que um módulo com segredos nunca seja importado pelo cliente, adicione `import 'server-only'` no topo; o build falha se alguém tentar.
::
