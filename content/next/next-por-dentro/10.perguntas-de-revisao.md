Tente responder antes de abrir.

::question
#title
Um Client Component roda no servidor?

#default
Sim, na primeira carga ele é renderizado no servidor para gerar HTML (SSR) e depois hidratado no navegador. "Client" significa que o código também vai para o bundle do navegador e pode ter estado e efeitos, não que roda só lá. Por isso acessar `window` no corpo do componente quebra: faça isso em `useEffect`.
::

::question
#title
Como colocar um Server Component dentro de um Client Component?

#default
Não importando. Passe-o como `children` ou outra prop JSX a partir de um Server Component pai. O Client Component recebe o resultado já renderizado e só decide onde exibir.
::

::question
#title
O que torna uma rota dinâmica?

#default
Ler dados específicos da requisição: `cookies()`, `headers()`, `searchParams`, `connection()`, ou buscar dados não cacheados no modelo Cache Components. Com PPR, isso torna dinâmico só o trecho dentro do `<Suspense>`, e o resto da página continua na casca estática.
::

::question
#title
Diferença entre `updateTag` e `revalidateTag`?

#default
`updateTag` só funciona em Server Actions e garante que a resposta da própria action já traga o dado novo (read-your-writes). `revalidateTag(tag, perfil)` marca como obsoleto com stale-while-revalidate: o próximo visitante ainda pode ver o valor antigo enquanto o novo é gerado.
::

::question
#title
Por que não ler `cookies()` dentro de `'use cache'`?

#default
A entrada de cache é compartilhada entre requisições. Ler o cookie de um usuário ali dentro faria o resultado vazar para outros. Leia fora e passe como argumento: ele entra na chave e cada valor gera sua própria entrada.
::

::question
#title
Server Actions são seguras por padrão?

#default
O Next protege contra CSRF (checa origem, aceita só POST) e criptografa variáveis capturadas em closures, mas a action continua sendo um endpoint público. Valide todo argumento e verifique autenticação e autorização dentro dela.
::

::question
#title
Por que o layout não atualiza quando mudo de página?

#default
Layouts são preservados em navegações entre rotas filhas: não remontam e não re-renderizam no servidor só por mudar a página. Isso preserva estado e evita trabalho. Para algo que depende da rota atual, use `usePathname()` num Client Component ou mova para a página. `template.tsx` remonta a cada navegação, se for isso que você quer.
::

::question
#title
Quando usar Route Handler em vez de Server Action?

#default
Route Handler quando outro cliente precisa de uma URL estável (webhooks, app móvel, integrações), para métodos além de POST, respostas não-HTML (arquivos, streams SSE) ou cache HTTP. Server Action para mutações disparadas pela sua própria UI.
::

::question
#title
Qual a diferença entre `loading.tsx` e um `<Suspense>` manual?

#default
Nenhuma em mecanismo: `loading.tsx` é um Suspense em volta da página inteira do segmento. Suspense manual é mais granular e permite mostrar a casca da página com só os trechos lentos em fallback, o que costuma dar uma experiência melhor.
::

::question
#title
O que muda entre o modelo de cache antigo e Cache Components?

#default
Antes, o cache era configurado por rota (`revalidate`, `dynamic`) e por `fetch`, e várias camadas eram implícitas. Com Cache Components nada é cacheado sem você pedir: tudo é dinâmico por padrão, e você marca funções e componentes com `'use cache'`, controlando validade com `cacheLife` e invalidação com `cacheTag`.
::
