**Route Handlers** (`route.ts`) são endpoints HTTP usando as APIs padrão da web, `Request` e `Response`. Use para webhooks, APIs consumidas por terceiros ou apps móveis, downloads e streams. Para o seu próprio front-end, Server Components (leitura) e Server Actions (escrita) normalmente dispensam uma API.

```ts [app/api/pedidos/[id]/route.ts]
import { NextResponse, type NextRequest } from 'next/server';

export async function GET(req: NextRequest, ctx: RouteContext<'/api/pedidos/[id]'>) {
  const { id } = await ctx.params;
  const pedido = await db.pedido.findUnique({ where: { id } });
  if (!pedido) return NextResponse.json({ erro: 'não encontrado' }, { status: 404 });
  return NextResponse.json(pedido);
}

export async function PATCH(req: NextRequest, ctx: RouteContext<'/api/pedidos/[id]'>) {
  const corpo = await req.json();
  /* valida, autoriza, atualiza */
  return new Response(null, { status: 204 });
}
```

### Server-Sent Events num Route Handler

Conectando com o material de React: um Route Handler pode devolver um `ReadableStream` com `text/event-stream`, e o cliente consome com `EventSource`.

```ts [app/api/stream/route.ts]
export async function GET(req: Request) {
  const enc = new TextEncoder();

  const stream = new ReadableStream({
    start(controller) {
      let id = Number(req.headers.get('last-event-id') ?? 0);
      const enviar = (event: string, data: unknown) =>
        controller.enqueue(enc.encode(`id: ${++id}\nevent: ${event}\ndata: ${JSON.stringify(data)}\n\n`));

      const t = setInterval(() => enviar('status', { em: Date.now() }), 1000);
      req.signal.addEventListener('abort', () => { clearInterval(t); controller.close(); });
    },
  });

  return new Response(stream, {
    headers: { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache, no-transform' },
  });
}
// Em plataformas serverless, confira o tempo máximo de execução da função.
```

### proxy.ts (antigo middleware.ts)

No Next 16, `middleware.ts` virou `proxy.ts`, que roda no runtime Node.js. Ele intercepta a requisição **antes** do roteamento: redirecionar, reescrever URL, ajustar headers e cookies, fazer checagens leves de sessão. O `middleware.ts` ainda funciona para quem precisa do runtime Edge, mas está depreciado.

```ts [proxy.ts]
import { NextResponse, type NextRequest } from 'next/server';

export default function proxy(request: NextRequest) {
  const temSessao = request.cookies.has('sessao');

  if (!temSessao && request.nextUrl.pathname.startsWith('/conta')) {
    const login = new URL('/login', request.url);
    login.searchParams.set('volta', request.nextUrl.pathname);
    return NextResponse.redirect(login);
  }
  return NextResponse.next();
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],  // não roda em assets
};
```

::note{type="pitfall" title="Não confie só no proxy"}
O proxy é uma primeira barreira e uma ótima forma de redirecionar cedo, mas não deve ser o único lugar que verifica autorização. Em 2025 uma vulnerabilidade permitiu pular o middleware com um header forjado, e apps que só checavam ali ficaram expostos. Verifique a sessão também perto do dado: na camada de acesso a dados, nos Server Components e nas Server Actions.
::
