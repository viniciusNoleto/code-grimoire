Com `cacheComponents: true`, a regra fica simples: **nada é cacheado implicitamente**. Todo código dinâmico roda na requisição, e você marca explicitamente o que pode ser reaproveitado com `'use cache'`. Pense na diretiva como um `Cache-Control` no nível do componente ou da função.

```ts [next.config.ts]
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  cacheComponents: true,     // modelo explícito com 'use cache' (padrão em apps novos desde 16.4)
  partialPrefetching: true,  // prefetch granular (16.3+)
};

export default nextConfig;
```

### As três peças

- **`'use cache'`** no topo de um arquivo, de uma função ou de um componente `async`. O compilador gera a chave a partir dos **argumentos e das variáveis capturadas**, então argumentos diferentes geram entradas diferentes.
- **`cacheLife(perfil)`** define a validade. Perfis embutidos: `'seconds'`, `'minutes'`, `'hours'`, `'days'`, `'weeks'`, `'max'`. Você pode criar perfis próprios no `next.config`.
- **`cacheTag(tag)`** rotula a entrada para invalidação sob demanda.

```ts [app/loja/data.ts]
import { cacheLife, cacheTag } from 'next/cache';

export async function getProduto(slug: string) {
  'use cache';
  cacheLife('hours');
  cacheTag('produtos', `produto-${slug}`);
  return db.produto.findUnique({ where: { slug } });
}

// Componente cacheado: sua UI entra na casca estática (PPR)
export async function Categorias() {
  'use cache';
  cacheLife('days');
  const lista = await db.categoria.findMany();
  return <nav>{lista.map(c => <Link key={c.id} href={`/c/${c.slug}`}>{c.nome}</Link>)}</nav>;
}
```

::note{type="pitfall" title="Regra que mais gera erro"}
Dentro de `'use cache'` você não pode ler `cookies()`, `headers()` nem `searchParams`: o resultado seria compartilhado entre usuários. Leia o valor fora e passe como argumento; ele passa a fazer parte da chave. E no modelo Cache Components, dado não cacheado fora de um `<Suspense>` é erro de build: o Next exige que você diga se aquilo é casca (cacheado) ou buraco (dinâmico com fallback).
::

### Invalidar depois de uma mutação

| API | Onde | Comportamento |
| --- | --- | --- |
| `updateTag(tag)` | só Server Actions | Expira e lê de novo na mesma requisição. O usuário vê a própria alteração imediatamente (read-your-writes). |
| `revalidateTag(tag, 'max')` | Actions e Route Handlers | Stale-while-revalidate: quem chega recebe o valor antigo enquanto o novo é gerado em segundo plano. Desde o 16 o segundo argumento (perfil) é exigido. |
| `revalidatePath(path)` | Actions e Route Handlers | Invalida tudo de uma rota. |
| `refresh()` | só Server Actions | Não mexe no cache; re-renderiza os dados *não cacheados* da página (ex.: contador de notificações). |

```ts [app/admin/actions.ts]
'use server';
import { updateTag, revalidateTag } from 'next/cache';

export async function alterarPreco(slug: string, preco: number) {
  await exigirAdmin();
  await db.produto.update({ where: { slug }, data: { preco } });
  updateTag(`produto-${slug}`);        // o admin vê o preço novo já no retorno da action
}

// Webhook do CMS: consistência eventual basta
export async function POST() {
  revalidateTag('produtos', 'max');
  return Response.json({ ok: true });
}
```

### O modelo anterior (projetos sem cacheComponents)

Você vai encontrar isso em código existente. A diferença conceitual: o cache era configurado por rota e por `fetch`, não por componente.

| Modelo anterior | Equivalente com Cache Components |
| --- | --- |
| `fetch(url, { next: { revalidate: 60, tags: ['x'] } })` | função com `'use cache'` + `cacheLife` + `cacheTag` |
| `unstable_cache(fn, keys, opts)` | `'use cache'` na função |
| `export const revalidate = 60` | `cacheLife` no componente ou layout |
| `export const dynamic = 'force-dynamic'` | desnecessário: dinâmico é o padrão |
| `export const dynamic = 'force-static'` | `'use cache'` + `ensureStatic` |

Detalhe histórico que cai em entrevista: até o Next 14, `fetch` era cacheado por padrão, o que surpreendia muita gente. No 15 o padrão virou **não cachear**, e o modelo Cache Components tornou isso a regra para tudo.
