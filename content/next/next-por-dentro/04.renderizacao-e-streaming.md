Toda rota é renderizada em um de dois momentos: **antes** (pré-renderização no build ou em revalidação, servida como arquivo estático) ou **na requisição** (por usuário). O que decide é o que o código acessa:

- **Torna dinâmico:** `cookies()`, `headers()`, `searchParams`, `connection()`, `draftMode()`, e no modelo Cache Components qualquer busca de dados fora de `'use cache'`.
- **Pode ser pré-renderizado:** JSX estático, dados de `'use cache'`, params de `generateStaticParams`.

### Streaming com Suspense

O servidor não precisa esperar a página inteira. Ele envia primeiro o HTML de tudo que está pronto, com os *fallbacks* dos `<Suspense>` no lugar das partes lentas, e mantém a conexão aberta. Cada parte que termina chega depois no mesmo response, como um trecho de HTML e um script que o encaixa no lugar.

**Partial Prerendering (PPR)** leva isso mais longe e é a base do modelo Cache Components. A casca estática da página (tudo fora dos Suspense dinâmicos) é gerada no build e servida da CDN. Só os "buracos" dinâmicos são renderizados na requisição e enviados por streaming, tudo na mesma resposta HTTP.

### Navegação no cliente

A primeira visita recebe HTML. Depois disso, um `<Link>` faz **navegação suave**: o cliente busca só o RSC payload dos segmentos que mudaram, os layouts compartilhados ficam montados e o estado deles é preservado. O prefetch baixa antecipadamente o que for possível da rota de destino quando o link aparece na tela.

- **Partial Prefetching** (16.3, flag `partialPrefetching`) permite que o prefetch traga só a casca de carregamento ou o quanto você quiser da página de destino.
- No 16.4, `await navigation()` dentro de um componente o exclui do prefetch, adiando aquele trabalho para o clique real. `await prefetch()` o tira da casca e só o inclui em prefetch explícito.
- `export const ensureStatic = 'navigation'` (16.4) faz o build falhar se algum componente dinâmico entrar na rota. Útil em blogs, lojas e páginas de marketing.
