React descreve interface. Ele não decide como as URLs viram telas, onde o código roda, como os dados chegam nem como a página é entregue. O Next é o framework que responde essas perguntas:

- **Roteamento por arquivos** dentro de `app/`, com layouts aninhados que persistem entre navegações.
- **Renderização no servidor** com React Server Components: componentes que rodam só no servidor e nunca mandam JavaScript para o navegador.
- **Pré-renderização e streaming**: partes da página podem ser geradas no build e servidas de CDN, outras renderizadas por requisição e enviadas aos poucos.
- **Mutações via Server Actions**: funções do servidor chamadas direto de formulários e componentes.
- **Bundler e otimizações**: Turbopack (padrão desde o 16), imagens, fontes, prefetch de links e metadados.

### App Router e Pages Router

O **Pages Router** (`pages/`, `getServerSideProps`, `getStaticProps`) ainda é suportado, mas tudo o que é novo acontece no **App Router** (`app/`). Este material trata só do App Router. Se você vem de projetos antigos, a principal mudança de mentalidade é: em vez de funções de data fetching separadas por página, qualquer componente de servidor pode ser `async` e buscar o que precisa.

::note{type="note" title="Onde estamos em nov/2026"}
O modelo **Cache Components** (diretiva `'use cache'` + Partial Prefetching) é recomendado para todo app desde o 16.4 e já vem ligado em projetos novos do `create-next-app`. Ele vira o padrão no Next 17. Muitos projetos em produção ainda usam o modelo anterior de cache; o capítulo 06 cobre os dois.
::
