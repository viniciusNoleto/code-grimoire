Proteção em camadas, da mais importante para a mais cosmética:

1. **Rotas de servidor** verificam a sessão em todo endpoint que lê ou altera dados do usuário. É a única barreira real.
2. **Sessão em cookie `httpOnly`**, inacessível ao JavaScript do navegador (protege contra roubo de token por XSS).
3. **Middleware de rota** redireciona quem não está logado, para a interface não mostrar telas inúteis.

```ts [server/utils/sessao.ts]
// h3 tem sessões seladas (criptografadas) em cookie embutidas
const opcoes = () => ({ password: useRuntimeConfig().sessaoSegredo, name: 'sessao', maxAge: 60 * 60 * 24 * 7 });

export async function exigirUsuario(event: H3Event) {
  const sessao = await useSession<{ usuarioId?: string }>(event, opcoes());
  if (!sessao.data.usuarioId) throw createError({ statusCode: 401, statusMessage: 'Não autenticado' });
  return { id: sessao.data.usuarioId };
}

// server/api/login.post.ts
export default defineEventHandler(async (event) => {
  const { email, senha } = await readValidatedBody(event, LoginSchema.parse);
  const usuario = await verificarCredenciais(email, senha);
  const sessao = await useSession(event, opcoes());
  await sessao.update({ usuarioId: usuario.id });     // Set-Cookie httpOnly
  return { nome: usuario.nome };
});
```

```ts [app/composables/useUsuario.ts]
export function useUsuario() {
  const usuario = useState<{ nome: string } | null>('usuario', () => null);
  const loggedIn = computed(() => !!usuario.value);

  async function buscar() {
    // no SSR, useRequestFetch repassa o cookie da requisição original
    usuario.value = await useRequestFetch()('/api/eu').catch(() => null);
  }
  return { usuario, loggedIn, buscar };
}
// app/plugins/usuario.ts → await useUsuario().buscar() uma vez por requisição
```

O módulo `nuxt-auth-utils` empacota esse padrão (sessão selada, `useUserSession()` no cliente, `requireUserSession(event)` no servidor) e adiciona provedores OAuth. A versão 4.6 também trouxe suporte a sessões no próprio Nuxt; consulte a documentação para a API.
