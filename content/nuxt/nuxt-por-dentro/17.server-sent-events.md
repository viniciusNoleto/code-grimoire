Com o Nitro, o servidor e o cliente do stream ficam no mesmo projeto. O h3 oferece `createEventStream`, que cuida dos headers, do formato `text/event-stream` e do fechamento.

::workbench{demo="sse-simulator" title="Simulador de stream"}
Um servidor falso escreve no fio e um parser seguindo as regras do EventSource monta os eventos. Derrube a conexão para ver a reconexão com `Last-Event-ID`.
::

```ts [server/api/cotacoes.get.ts]
export default defineEventHandler(async (event) => {
  await exigirUsuario(event);                        // o cookie de sessão vai junto no EventSource
  const stream = createEventStream(event);

  let id = Number(getHeader(event, 'last-event-id') ?? 0);
  const timer = setInterval(async () => {
    await stream.push({ id: String(++id), event: 'preco', data: JSON.stringify({ ativo: 'PETR4', valor: 38 + Math.random() }) });
  }, 1000);

  stream.onClosed(async () => {                      // cliente fechou ou caiu
    clearInterval(timer);
    await stream.close();
  });

  return stream.send();
});
```

```vue [app/components/Cotacoes.client.vue]
<script setup>
// .client.vue: EventSource só existe no navegador
const precos = reactive({});
const status = ref('conectando');
let es;

onMounted(() => {
  es = new EventSource('/api/cotacoes', { withCredentials: true });
  es.onopen = () => (status.value = 'aberto');
  es.onerror = () => (status.value = es.readyState === EventSource.CLOSED ? 'fechado' : 'reconectando');
  es.addEventListener('preco', (e) => {
    const { ativo, valor } = JSON.parse(e.data);
    precos[ativo] = valor;
  });
});
onBeforeUnmount(() => es?.close());
</script>
```

- **Não use `useFetch` para SSE**: ele espera uma resposta que termina e serializa no payload. O stream é assunto do cliente.
- **Streaming via POST** (comum em APIs de LLM): `EventSource` só faz GET. Use `$fetch(url, { method: 'POST', body, responseType: 'stream' })` e leia o `ReadableStream` manualmente.
- **Deploy:** plataformas serverless limitam o tempo de execução e algumas bufferizam a resposta. Para streams longos, prefira o preset `node-server`, um runtime que suporte streaming, ou envie heartbeats (`: ping`).
- **Route rules:** garanta que a rota do stream não esteja sob uma regra de cache (`swr`, `isr`).
