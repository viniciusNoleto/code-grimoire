Workers são uma API do navegador: no Nuxt, a regra extra é **criá-los só no cliente**. O setup roda também no servidor, onde `Worker` não existe. O composable `useWorker` do tomo de Vue funciona igual, desde que a instância seja criada em `onMounted` ou atrás de `import.meta.client`.

::workbench{demo="main-thread-vs-worker" title="Main thread vs Worker"}
A bolinha é movida por `requestAnimationFrame` e só anda com a main thread livre. Rode o mesmo cálculo (Fibonacci recursivo) nos dois lugares.
::

```ts [app/composables/useCsvWorker.ts]
export function useCsvWorker() {
  const resumo = shallowRef<Resumo | null>(null);
  const ocupado = ref(false);
  let worker: Worker | null = null;

  onMounted(() => {                                     // só no cliente
    worker = new Worker(new URL('../workers/csv.worker.ts', import.meta.url), { type: 'module' });
    worker.onmessage = (e) => { resumo.value = e.data; ocupado.value = false; };
  });
  onBeforeUnmount(() => worker?.terminate());

  function processar(arquivo: File) {
    ocupado.value = true;
    arquivo.text().then(texto => worker!.postMessage(texto));
  }
  return { resumo, ocupado, processar };
}
```

- **Componente que usa o worker** pode ser `.client.vue` ou ficar em `<ClientOnly>`; o HTML do servidor mostra o fallback.
- **Trabalho pesado pode ir para o servidor**: no Nuxt você tem a opção de processar numa rota de `server/api` em vez de no navegador. Worker vale quando os dados são do usuário (arquivo local), a latência importa ou o servidor não deve pagar o custo.
- **No servidor (Node)**, o equivalente é `node:worker_threads`, usado dentro de handlers do Nitro para CPU pesada sem travar outras requisições.
