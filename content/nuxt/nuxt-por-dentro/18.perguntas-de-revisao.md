Tente responder antes de abrir.

::question
#title
Por que não usar `$fetch` direto no setup de uma página?

#default
O setup roda no servidor e de novo na hidratação. Com `$fetch`, a API é chamada duas vezes, e o resultado do servidor não vai no payload, o que pode causar mismatch e flash de conteúdo. `useFetch` e `useAsyncData` guardam o resultado no payload e o cliente reaproveita.
::

::question
#title
O que `lazy: true` muda na primeira visita?

#default
Quase nada: no SSR o servidor espera a busca mesmo assim. `lazy` afeta a navegação no cliente, que deixa de esperar a busca e mostra a página com estado de carregamento.
::

::question
#title
Por que `export const usuario = ref(null)` num arquivo é perigoso?

#default
No servidor, o módulo é carregado uma vez e compartilhado por todas as requisições. O usuário de uma requisição vaza para as outras. Use `useState`, Pinia ou estado criado dentro de funções.
::

::question
#title
O que causa hydration mismatch e como evitar?

#default
HTML do servidor diferente do que o cliente renderiza: datas, valores aleatórios, fuso horário, `window`, conteúdo que depende de `localStorage`. Gere o valor uma vez no servidor e transporte com `useState`, ou renderize no cliente com `<ClientOnly>`, `.client.vue` ou `<NuxtTime>`.
::

::question
#title
Qual a diferença entre `isr` e `swr` em routeRules?

#default
Os dois servem o cache e revalidam em segundo plano quando ele expira. `swr` usa o cache do próprio servidor Nitro; `isr` delega o cache à CDN da plataforma (Vercel, Netlify), normalmente invalidado a cada deploy.
::

::question
#title
Middleware de rota protege meus dados?

#default
Não. Ele roda no cliente nas navegações e serve para a experiência. Qualquer um pode chamar a API direto. Verifique a sessão nas rotas de `server/`.
::

::question
#title
`runtimeConfig` ou `app.config`?

#default
`runtimeConfig` para valores por ambiente, sobrescritos por variáveis `NUXT_*` sem rebuild, com parte privada só no servidor. `app.config` para configuração pública decidida no build (tema, textos, flags de UI), reativa e sem segredos.
::

::question
#title
Quando usar `callOnce`?

#default
Para efeitos colaterais que devem rodar uma vez por carga do app, como inicializar um store do Pinia. No SSR roda no servidor e não se repete na hidratação. `useAsyncData` serve para buscar e cachear dados, e seu handler deve ser puro.
::

::question
#title
O que o prefixo `Lazy` e `hydrate-on-visible` fazem de diferente?

#default
`Lazy` sozinho divide o código e só o baixa quando o componente é renderizado. Com `hydrate-on-visible`, o componente renderiza no servidor (o HTML aparece), mas só baixa e executa o JS para ficar interativo quando entra na tela.
::

::question
#title
Como um handler do servidor recebe o cookie do usuário numa busca feita no SSR?

#default
`useFetch` com URL relativa repassa os headers da requisição original automaticamente. Com `$fetch`, use `useRequestFetch()` ou passe `useRequestHeaders(['cookie'])`. Sem isso, a chamada interna sai sem cookie e o servidor responde como se o usuário não estivesse logado.
::

::question
#title
Como fazer SSE no Nuxt?

#default
No servidor, `createEventStream(event)` do h3, com `push`, `onClosed` e `send`. No cliente, um `EventSource` criado em `onMounted` (ou num componente `.client.vue`), fechado no unmount. Não use `useFetch` e não deixe a rota sob regra de cache.
::
