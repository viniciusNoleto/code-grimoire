| Arquivo em app/pages | URL |
| --- | --- |
| `index.vue` | `/` |
| `produtos/[id].vue` | `/produtos/42` → `route.params.id` |
| `blog/[...slug].vue` | `/blog/2026/11/x` → `slug: ['2026','11','x']` |
| `[[lang]]/sobre.vue` | `/sobre` e `/en/sobre` (param opcional) |
| `(marketing)/contato.vue` | `/contato` (grupo não entra na URL) |
| `conta.vue` + `conta/perfil.vue` | rota aninhada: `conta.vue` renderiza `<NuxtPage />` para o filho |
| `painel@lateral.vue` :version[4.5] | named view: preenche `<NuxtPage name="lateral" />` |

### definePageMeta

```vue [app/pages/produtos/[id].vue]
<script setup lang="ts">
definePageMeta({
  layout: 'loja',                         // app/layouts/loja.vue
  middleware: ['auth'],                   // app/middleware/auth.ts
  validate: (route) => /^\d+$/.test(route.params.id as string), // false = 404
  keepalive: true,                        // mantém a instância ao navegar (KeepAlive)
  key: (route) => route.fullPath,         // força remontar ao trocar de produto
});

const route = useRoute();
const { data: produto } = await useFetch(() => `/api/produtos/${route.params.id}`);
</script>
```

`definePageMeta` é uma macro de compilação: o objeto é extraído no build, então ele não pode usar variáveis do componente (só imports e valores literais).

### Navegação

- **`<NuxtLink to="/x">`** faz navegação no cliente e prefetch do código da rota quando o link aparece na tela. Para links externos, vira `<a>` comum com `rel` adequado.
- **`await navigateTo('/x')`** navega por código; funciona no servidor (vira redirect HTTP) e no cliente. Aceita `{ replace, redirectCode, external, open }`. Em middleware, **retorne** o resultado.
- **`useRoute()`** lê params, query e meta da rota atual; **`useRouter()`** dá acesso ao Vue Router.

### Layouts

```vue [app/layouts/loja.vue]
<template>
  <div class="loja">
    <CabecalhoLoja />
    <slot />                <!-- a página entra aqui -->
    <RodapeLoja />
  </div>
</template>
```

Com `<NuxtLayout>` no `app.vue`, cada página usa `default.vue` ou o layout que declarar. Para trocar em tempo de execução, `setPageLayout('outro')`; para ler o layout resolvido, `useLayout()` :version[4.5].

### Middleware de rota

```ts [app/middleware/auth.ts]
export default defineNuxtRouteMiddleware((to, from) => {
  const { loggedIn } = useUsuario();                  // composable seu
  if (!loggedIn.value) {
    return navigateTo({ path: '/login', query: { volta: to.fullPath } });
  }
  // não retornar nada = deixa passar; abortNavigation() = cancela com erro
});

// auth.global.ts → roda em TODA navegação, sem precisar declarar na página
// definePageMeta({ middleware: [(to) => { ... }] }) → middleware inline
```

::note{type="pitfall" title="Middleware de rota ≠ segurança"}
Middleware de rota roda no servidor na primeira carga e **no cliente** nas navegações seguintes. Ele serve para a experiência (redirecionar quem não está logado), não para proteger dados: qualquer um pode chamar sua API direto. A verificação de verdade fica nas rotas de `server/` (capítulo [15](#autenticacao)).
::
