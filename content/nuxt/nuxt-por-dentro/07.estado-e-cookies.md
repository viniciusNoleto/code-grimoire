### useState

::signature
`const contador = useState<number>('contador', () => 0)`
::

Um `ref` compartilhado por chave e **seguro para SSR**. O valor criado no servidor vai no payload e o cliente começa com ele, sem mismatch. Todos os componentes que chamam `useState('contador')` recebem o mesmo ref.

```ts [composables/useTema.ts]
export const useTema = () => useState<'claro' | 'escuro'>('tema', () => 'claro');

// Qualquer componente:
const tema = useTema();
tema.value = 'escuro';   // todos que usam useTema() atualizam
```

::note{type="pitfall" title="Nunca use ref() no topo de um módulo"}
No servidor, um módulo é carregado uma vez e serve **todas as requisições**. `export const usuario = ref(null)` num arquivo vira estado compartilhado entre usuários diferentes: o dado de um vaza para o outro (*cross-request state pollution*). Crie estado dentro de funções, com `useState` ou com Pinia, que isolam por requisição. O valor de `useState` precisa ser serializável (nada de funções ou classes).
::

### useCookie

::signature
`const token = useCookie<string | null>('token', { maxAge, secure, sameSite, httpOnly, default, watch })`
::

Um ref ligado a um cookie: no servidor lê do header da requisição e escreve no `Set-Cookie` da resposta; no cliente lê e escreve em `document.cookie`. Valores são serializados como JSON. Se um cookie for alterado por uma chamada de API, `refreshCookie('nome')` sincroniza o ref.

```vue [consentimento.vue]
<script setup>
const consentimento = useCookie('consentimento', {
  default: () => ({ analytics: false }),
  maxAge: 60 * 60 * 24 * 365,
  sameSite: 'lax',
});
</script>

<template>
  <label><input type="checkbox" v-model="consentimento.analytics" /> Permitir analytics</label>
</template>
```

Cookies `httpOnly` (o certo para sessão) não são acessíveis pelo JavaScript do navegador; leia e escreva no servidor (capítulo [15](#autenticacao)).
