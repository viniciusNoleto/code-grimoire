Três ferramentas, três papéis:

- **`useFetch(url, opções)`**: buscar uma URL durante o setup. Roda no servidor, guarda o resultado no payload e o cliente reaproveita na hidratação.
- **`useAsyncData(chave, () => …)`**: o mesmo, para qualquer função assíncrona (SDK de CMS, várias chamadas combinadas, banco via função).
- **`$fetch(url)`**: chamada HTTP simples, para ações disparadas pelo usuário (submit, clique) e dentro de handlers do servidor. No setup, busca duas vezes.

::workbench{demo="data-fetching" title="Quantas vezes a API é chamada?"}
A mesma página de produtos escrita de quatro formas. Veja o que acontece na primeira visita (SSR + hidratação) e numa navegação no cliente.
::

```vue [app/pages/produtos/index.vue]
<script setup lang="ts">
const route = useRoute();
const pagina = computed(() => Number(route.query.pagina ?? 1));

const { data, status, error, refresh } = await useFetch('/api/produtos', {
  query: { pagina },                     // ref na query: muda a página → refaz a busca
  pick: ['itens', 'total'],              // só esses campos vão para o payload
  default: () => ({ itens: [], total: 0 }),
});
// data é tipado pelo retorno de server/api/produtos.get.ts
</script>

<template>
  <p v-if="status === 'pending'">Carregando…</p>
  <p v-else-if="error">Erro: {{ error.message }} <button @click="refresh()">Tentar de novo</button></p>
  <ProdutoCartao v-for="p in data.itens" v-else :key="p.id" :produto="p" />
</template>
```

### Opções de useFetch e useAsyncData

| Opção | Padrão | Efeito |
| --- | --- | --- |
| `key` | gerada | Chamadas com a mesma chave compartilham `data`, `error` e `status`. Pode ser reativa (mudou → nova busca). |
| `server` | `true` | `false` busca só no cliente, depois da hidratação. |
| `lazy` | `false` | Não bloqueia a navegação no cliente; renderize o estado de carregamento. No SSR, o servidor espera mesmo assim. |
| `immediate` | `true` | `false` só busca quando você chamar `execute()`. |
| `enabled` :version[4.5] | `true` | Flag reativa: enquanto `false`, nenhuma busca acontece; desligar cancela a que está em voo. |
| `watch` | opções reativas | Fontes extras que disparam nova busca. `false` desliga o rastreamento. |
| `default`, `transform`, `pick` | – | Valor inicial; pós-processar; reduzir o payload (a busca acontece inteira mesmo assim). |
| `deep` | `false` | `data` é um `shallowRef` por padrão: troque o valor inteiro em vez de mutar. |
| `dedupe` | `'cancel'` | Nova chamada com outra em andamento: cancela a anterior ou espera (`'defer'`). |
| `getCachedData` | payload | Decide de onde ler cache (ex.: reaproveitar dados entre navegações). |
| `timeout`, `serialize` | –, `true` | Limite em ms; `false` deixa o dado fora do payload (o cliente busca de novo). |

O retorno é sempre `{ data, status, pending, error, refresh, execute, clear }`. `status` vale `'idle'`, `'pending'`, `'success'` ou `'error'`.

### useAsyncData com chave reativa

```ts [composables/useProduto.ts]
export function useProduto(id: MaybeRefOrGetter<string>) {
  return useAsyncData(
    () => `produto-${toValue(id)}`,               // chave explícita: composables devem sempre ter uma
    (_nuxtApp, { signal }) => Promise.all([
      $fetch(`/api/produtos/${toValue(id)}`, { signal }),
      $fetch(`/api/produtos/${toValue(id)}/estoque`, { signal }),
    ]).then(([produto, estoque]) => ({ ...produto, estoque })),
  );
}

// Em outro componente, sem buscar de novo:
const { data } = useNuxtData('produto-42');
// Depois de uma mutação:
await refreshNuxtData('produto-42');   // ou clearNuxtData('produto-42')
```

### $fetch em ações e headers no SSR

```ts [acoes.ts]
// Ação do usuário: $fetch direto (roda só no cliente)
async function adicionarAoCarrinho(id: string) {
  await $fetch('/api/carrinho', { method: 'POST', body: { id } });
  await refreshNuxtData('carrinho');
}

// No SSR, useFetch com URL relativa já repassa os cookies do usuário.
// Para usar $fetch no servidor com os mesmos headers:
const requestFetch = useRequestFetch();
const eu = await requestFetch('/api/eu');

// Padrões reutilizáveis (baseURL, token) para uma API externa:
export const useApi = createUseFetch({ baseURL: 'https://api.loja.com' });
```

::note{type="pitfall" title="Serialização"}
O payload usa `devalue`, que preserva `Date`, `Map` e `Set`. Já as respostas de rotas de API passam por `JSON.stringify`: um `Date` retornado pelo servidor chega como string, mesmo com o tipo inferido dizendo `Date`. Converta no `transform` ou defina `toJSON`.
::

::note{type="pitfall" title="Onde chamar"}
`useFetch` e `useAsyncData` só funcionam no setup, em plugins ou middleware, ou no topo de hooks de ciclo de vida. Num handler de clique, use `$fetch` ou o `refresh()` de um `useFetch` já criado. E o handler de `useAsyncData` deve ser sem efeitos colaterais: para inicializar um store, use `callOnce`.
::
