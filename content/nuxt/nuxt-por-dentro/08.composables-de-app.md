### useNuxtApp

Dá acesso ao contexto do app: `nuxtApp.vueApp`, `nuxtApp.payload`, `nuxtApp.hook('page:finish', …)`, `nuxtApp.isHydrating` e o que plugins forneceram com `provide` (acessível como `nuxtApp.$nome`). Use dentro do contexto do Nuxt (setup, plugins, middleware). Fora dele, o erro "nuxt instance unavailable" significa que você chamou depois de um `await` num lugar sem contexto ou fora do ciclo do app.

### useRuntimeConfig e useAppConfig

```ts [nuxt.config.ts + uso]
// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    stripeSecret: '',                    // só no servidor
    public: { apiBase: '/api' },         // vai para o cliente também
  },
});
// Sobrescreva em produção por variável de ambiente: NUXT_STRIPE_SECRET, NUXT_PUBLIC_API_BASE

// componente
const config = useRuntimeConfig();
config.public.apiBase;                   // ok no cliente
// config.stripeSecret é undefined no cliente

// server/api/pagar.post.ts
export default defineEventHandler((event) => {
  const { stripeSecret } = useRuntimeConfig(event);
});
```

`useAppConfig()` lê o `app/app.config.ts`: configuração **pública, decidida no build** e reativa (tema, nome da marca, flags de UI). Não coloque segredos nele. Para valores que mudam por ambiente sem rebuild, use `runtimeConfig`.

### Head e SEO

```ts [seo.ts]
useHead({
  title: () => produto.value?.nome,          // getters/refs mantêm o título reativo
  titleTemplate: '%s · Loja MX',
  htmlAttrs: { lang: 'pt-BR' },
  link: [{ rel: 'canonical', href: `https://loja.com/produtos/${id}` }],
  script: [{ src: 'https://cdn.exemplo.com/widget.js', defer: true }],
});

useSeoMeta({                                  // meta tags tipadas, sem errar o nome do atributo
  description: () => produto.value?.resumo,
  ogTitle: () => produto.value?.nome,
  ogImage: () => produto.value?.imagem,
  twitterCard: 'summary_large_image',
});

useHeadSafe({ meta: [{ name: 'author', content: textoDoUsuario }] }); // sanitiza entrada não confiável
// useServerSeoMeta: igual, mas só no servidor (menos JS no cliente)
```

### Requisição e resposta (SSR)

| API | Uso |
| --- | --- |
| `useRequestEvent()` | O evento h3 da requisição (no cliente, `undefined`). |
| `useRequestHeaders(['cookie'])`, `useRequestHeader('accept-language')` | Ler headers recebidos. |
| `useRequestURL()` | `URL` completa da requisição, funciona nos dois lados. |
| `useResponseHeader('cache-control')` | Ref para definir um header da resposta. |
| `setResponseStatus(event, 410)` | Mudar o status HTTP da página. |

### Erros

```ts [erros.ts]
// Numa página: erro fatal → renderiza app/error.vue com o status certo
const { data } = await useFetch(`/api/produtos/${id}`);
if (!data.value) throw createError({ statusCode: 404, statusMessage: 'Produto não encontrado', fatal: true });

// Em qualquer lugar do cliente:
showError({ statusCode: 500, statusMessage: 'Falha ao processar' });

// app/error.vue
const props = defineProps<{ error: NuxtError }>();
const voltar = () => clearError({ redirect: '/' });   // limpa o erro e navega
// useError() lê o erro atual de qualquer componente
```

Desde a 4.6.4, detalhes de erros em produção são removidos, a menos que o erro tenha sido criado com `createError`. Use-o para mensagens que o usuário deve ver.

### Os demais

- **`useLoadingIndicator()`**: controla a barra do `<NuxtLoadingIndicator>` (`start`, `finish`, `progress`).
- **`usePreviewMode()`**: modo de pré-visualização para conteúdo de CMS ainda não publicado.
- **`useHydration(chave, obter, definir)`**: transporta valores de classes não serializáveis do servidor para o cliente.
- **`onPrehydrate(() => …)`**: roda um script no cliente *antes* da hidratação (ex.: aplicar tema salvo sem piscar). A função é serializada, então não acessa variáveis externas.
- **`useRouteAnnouncer()`**: anuncia a troca de página para leitores de tela.
- **`useRuntimeHook('page:finish', fn)`**: registra um hook do app que é removido junto com o componente.
