### ref

::signature
`const r = ref<T>(valor)  // Ref<T> com .value`
::

Funciona com qualquer tipo, pode ser reatribuído (`lista.value = novaLista`) e mantém a reatividade quando passado para funções e composables. Objetos atribuídos ao `.value` ficam profundamente reativos.

### reactive e readonly

::signature
`const s = reactive({ … })   ·   const leitura = readonly(s)`
::

`readonly` devolve um proxy profundo só leitura que **continua reativo ao original**: mudanças em `s` disparam quem lê `leitura`. Escritas no proxy readonly falham com aviso. É o padrão para expor estado sem permitir mutação de fora (provide/inject e composables).

### Utilitários

| API | O que faz |
| --- | --- |
| `isRef(x)` | Verifica se é um ref. |
| `unref(x)` | `isRef(x) ? x.value : x`. |
| `toValue(x)` :version[3.3] | Como `unref`, mas também chama getters. Ideal para argumentos de composables que aceitam valor, ref ou função. |
| `toRef(obj, 'chave')` | Ref ligado a uma propriedade: ler e escrever refletem no original. `toRef(() => props.x)` cria um ref só leitura a partir de um getter. |
| `toRefs(obj)` | Objeto comum com um ref por propriedade; permite desestruturar sem perder reatividade. |
| `isProxy`, `isReactive`, `isReadonly` | Inspecionam proxies criados pelo Vue. |

```js [useBusca.js]
import { ref, watch, toValue } from 'vue';

// aceita string, ref ou getter: useBusca('vue'), useBusca(termo), useBusca(() => props.q)
export function useBusca(termo) {
  const resultados = ref([]);
  watch(() => toValue(termo), async (q) => {
    resultados.value = await api.buscar(q);
  }, { immediate: true });
  return { resultados };
}
```

### Reatividade rasa: shallowRef, triggerRef, shallowReactive, shallowReadonly

::signature
`const dados = shallowRef(listaEnorme)  // só a troca de .value é reativa`
::

Para estruturas grandes ou objetos de bibliotecas externas, a reatividade profunda é desperdício. Com `shallowRef`, só `dados.value = …` dispara; mutações internas não. Se você precisar mutar por dentro, chame `triggerRef(dados)` depois. `shallowReactive` e `shallowReadonly` aplicam a mesma ideia ao primeiro nível de um objeto.

```js [shallowRef.js]
const linhas = shallowRef([]);                // 50 mil linhas de um CSV

linhas.value = await parseCsv(arquivo);       // ✅ dispara: troca inteira
linhas.value.push(novaLinha);                 // não dispara (raso)
triggerRef(linhas);                           // força o disparo manualmente
linhas.value = [...linhas.value, novaLinha];  // ou: troca imutável (preferível)
```

### customRef

::signature
`customRef((track, trigger) => ({ get() { track(); … }, set(v) { …; trigger() } }))`
::

```js [useRefDebounced.js]
import { customRef } from 'vue';

export function useRefDebounced(valor, atraso = 300) {
  let timer;
  return customRef((track, trigger) => ({
    get() { track(); return valor; },
    set(novo) {
      clearTimeout(timer);
      timer = setTimeout(() => { valor = novo; trigger(); }, atraso); // só dispara quando parar de digitar
    },
  }));
}
// <input v-model="termo"> com const termo = useRefDebounced('')
```

#### Exemplo: estado persistido e sincronizado entre abas

O mesmo `customRef` liga um valor ao `localStorage`. Ler chama `track()`; gravar salva e chama `trigger()`. O evento `storage` avisa quando **outra aba** mudou a chave, e aí basta disparar de novo.

```js [useLocalStorage.js]
import { customRef, onScopeDispose } from 'vue';

export function useLocalStorage(chave, inicial) {
  const ler = () => { const v = localStorage.getItem(chave); return v === null ? inicial : JSON.parse(v); };
  let disparar;
  const valor = customRef((track, trigger) => {
    disparar = trigger;
    return {
      get() { track(); return ler(); },
      set(novo) { localStorage.setItem(chave, JSON.stringify(novo)); trigger(); },
    };
  });
  const aoMudar = (e) => { if (e.key === chave) disparar(); };   // mudança vinda de outra aba
  window.addEventListener('storage', aoMudar);
  onScopeDispose(() => window.removeEventListener('storage', aoMudar));
  return valor;
}

// const tema = useLocalStorage('tema', 'claro');  → tema.value = 'escuro' troca em todas as abas
// Só no cliente: em SSR (Nuxt), crie dentro de onMounted ou use useCookie.
```

Objetos guardados assim só disparam quando você **substitui** o valor (`prefs.value = { ...prefs.value, x }`); mutar uma propriedade não passa pelo `set`. O `useStorage` do VueUse resolve isso com um ref profundo. Os canais entre abas (`BroadcastChannel`, `storage`, Web Locks) e os limites de cada armazenamento estão em [Comunicação entre contextos](/web#comunicacao-entre-contextos) e [Armazenamento](/web#armazenamento), no tomo Web.

### toRaw e markRaw

- **`toRaw(proxy)`** devolve o objeto original, sem rastreamento. Útil para leituras pesadas pontuais e para passar dados a bibliotecas que comparam identidade (ou para `structuredClone`, que não aceita proxies).
- **`markRaw(obj)`** marca o objeto para nunca virar proxy. Use com instâncias de terceiros guardadas no estado: mapas do Leaflet, gráficos, `Worker`, `EventSource`. Sem isso, o Vue tenta tornar reativa uma instância complexa e quebra comparações internas da biblioteca.
