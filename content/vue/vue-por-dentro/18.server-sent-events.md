SSE é um canal unidirecional do servidor para o cliente sobre HTTP comum (`Content-Type: text/event-stream`). O `EventSource` do navegador faz o parsing, reconecta sozinho e envia `Last-Event-ID` para retomar. O protocolo e a comparação com WebSocket, WebTransport e WebRTC estão em [Tempo real](/web#tempo-real), no tomo Web, e o servidor em Node no [tomo de React](/react#server-sent-events); aqui o foco é a integração com a reatividade do Vue.

::workbench{demo="sse-simulator" title="Simulador de stream"}
Um servidor falso escreve no fio e um parser seguindo as regras do EventSource monta os eventos. Derrube a conexão para ver a reconexão com `Last-Event-ID`.
::

### Composable useEventSource

```ts [composables/useEventSource.ts]
import { ref, shallowRef, watch, toValue, onWatcherCleanup, type MaybeRefOrGetter } from 'vue';

type Status = 'conectando' | 'aberto' | 'reconectando' | 'fechado';

export function useEventSource<T>(url: MaybeRefOrGetter<string | null>, tipos: string[] = ['message']) {
  const status = ref<Status>('fechado');
  const ultimo = shallowRef<{ tipo: string; dados: T; id: string } | null>(null);

  // watch com immediate: reconecta sozinho quando a URL (ref ou getter) muda
  watch(() => toValue(url), (u) => {
    if (!u) { status.value = 'fechado'; return; }

    const es = new EventSource(u, { withCredentials: true });
    status.value = 'conectando';
    es.onopen = () => { status.value = 'aberto'; };
    es.onerror = () => {
      status.value = es.readyState === EventSource.CLOSED ? 'fechado' : 'reconectando';
    };
    const ouvir = (e: MessageEvent) => {
      ultimo.value = { tipo: e.type, dados: JSON.parse(e.data), id: e.lastEventId };
    };
    tipos.forEach(t => es.addEventListener(t, ouvir));

    onWatcherCleanup(() => es.close());   // URL mudou ou componente desmontou: fecha
  }, { immediate: true });

  return { status, ultimo };
}
```

```vue [Cotacoes.vue]
<script setup>
import { reactive, watch } from 'vue';

const props = defineProps({ carteira: String });
const { status, ultimo } = useEventSource(() => `/stream?carteira=${props.carteira}`, ['preco']);

// alimenta um store ou um reactive; só a linha do ativo alterado re-renderiza
const precos = reactive({});
watch(ultimo, (ev) => { if (ev) precos[ev.dados.ativo] = ev.dados.valor; });
</script>

<template>
  <p>Conexão: {{ status }}</p>
  <LinhaCotacao v-for="(valor, ativo) in precos" :key="ativo" :ativo="ativo" :valor="valor" />
</template>
```

- **Reconexão por reatividade:** como a URL é um getter, trocar `props.carteira` fecha a conexão antiga (cleanup) e abre a nova, sem código extra.
- **Alta frequência:** eventos que mudam muitos campos por segundo podem ir para um `shallowRef` substituído em lote (a cada 100 ms, por exemplo), em vez de mutar um objeto profundo a cada mensagem.
- **Autenticação:** `EventSource` não aceita headers. Use cookie (`withCredentials`), token curto na query, ou `fetch` com leitura de stream.
- **VueUse** tem `useEventSource` pronto, com reconexão configurável.

### WebSocket com o mesmo padrão

Quando os dois lados precisam enviar, troque o `EventSource` por um `WebSocket`. O `watch` com `onWatcherCleanup` continua cuidando de fechar e reabrir quando a URL muda; o que muda é que o WebSocket **não reconecta sozinho**, então o composable faz backoff com jitter.

```ts [composables/useWebSocket.ts]
import { ref, shallowRef, watch, toValue, onWatcherCleanup, type MaybeRefOrGetter } from 'vue';

export function useWebSocket<T>(url: MaybeRefOrGetter<string | null>) {
  const status = ref<'conectando' | 'aberto' | 'reconectando' | 'fechado'>('fechado');
  const ultimo = shallowRef<T | null>(null);
  let ws: WebSocket | null = null;

  watch(() => toValue(url), (u) => {
    if (!u) return;
    let tentativa = 0, timer: ReturnType<typeof setTimeout>, encerrado = false;

    const conectar = () => {
      ws = new WebSocket(u);
      status.value = tentativa ? 'reconectando' : 'conectando';
      ws.onopen = () => { tentativa = 0; status.value = 'aberto'; };
      ws.onmessage = (e) => { ultimo.value = JSON.parse(e.data); };
      ws.onclose = (e) => {
        if (encerrado || e.code === 1000) { status.value = 'fechado'; return; }
        status.value = 'reconectando';
        timer = setTimeout(conectar, Math.min(30_000, 1000 * 2 ** tentativa++) * (0.5 + Math.random()));
      };
    };
    conectar();

    onWatcherCleanup(() => { encerrado = true; clearTimeout(timer); ws?.close(1000); });
  }, { immediate: true });

  const enviar = (dados: unknown) => {
    if (ws?.readyState === WebSocket.OPEN) ws.send(JSON.stringify(dados));
  };
  return { status, ultimo, enviar };
}
```

- **Uma conexão por app:** se vários componentes usam o mesmo canal, chame o composable dentro de uma store do Pinia (ou de um `effectScope` compartilhado) e leia o estado de lá.
- **Dados reativos no `send`:** `JSON.stringify` lê o proxy normalmente, mas `postMessage` e structured clone não; para Workers e `BroadcastChannel`, passe `toRaw(estado)`.
- **VueUse** tem `useWebSocket` com heartbeat e reconexão configuráveis.
