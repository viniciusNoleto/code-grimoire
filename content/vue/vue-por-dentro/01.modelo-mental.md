No React, um componente renderiza de novo porque alguém chamou um setter, e o React decide o que comparar. No Vue a lógica é invertida: **o próprio estado sabe quem o leu**. Cada componente tem um *efeito de render*. Enquanto ele roda, toda leitura de dado reativo fica registrada como dependência. Quando um desses dados muda, só os efeitos que o leram são agendados.

O template é compilado (no build, pelo Vite) para uma **render function** que produz VNodes. O compilador anota cada nó dinâmico com *patch flags* ("só o texto muda", "só a classe muda") e eleva o conteúdo estático para fora do render. Na hora de comparar, o Vue pula tudo o que sabe ser estático.

1. **Mutação.** Escrever em um `ref` ou numa propriedade de `reactive` passa pelo `set` do Proxy (ou pelo setter do ref).
2. **Trigger.** O Vue procura os efeitos que leram aquela chave (renders, `computed`, watchers) e marca cada um como sujo. `computed` só marca; o recálculo acontece quando alguém lê.
3. **Fila.** Renders e watchers vão para uma fila deduplicada que é executada numa microtask. Por isso, dez mutações seguidas geram **um** render.
4. **Render e patch.** Cada componente sujo roda sua render function, de pai para filho, e o Vue aplica a diferença no DOM.

::note{type="note" title="Vue 3.6 (release candidate)"}
A 3.6 traz o **Vapor Mode**, um modo de compilação opcional (`<script setup vapor>`) que gera código que atualiza o DOM diretamente, sem Virtual DOM, e funciona só com Composition API. A reatividade também foi reescrita sobre alien-signals, com ganho de performance e memória. A API pública descrita aqui não muda.
::
