O `setup` (ou o `<script setup>`) roda **uma vez** por instância, antes de tudo. Diferente de um componente React, ele não roda a cada render: só a render function re-executa. Os hooks de ciclo de vida precisam ser registrados de forma síncrona dentro do setup.

| Hook | Quando roda | Uso típico |
| --- | --- | --- |
| `onBeforeMount` | Antes do primeiro render no DOM. | Raro. |
| `onMounted` | Após inserir no DOM (filhos já montados). | Acessar o DOM, iniciar libs, adicionar listeners. Não roda no SSR. Medir aqui ainda é antes da pintura; leituras e escritas intercaladas forçam layout ([layout thrashing](/web#renderizacao-e-animacao)). |
| `onBeforeUpdate` | Antes de aplicar um re-render. | Ler o DOM antes da mudança. |
| `onUpdated` | Depois de um re-render. | Evite mutar estado aqui (loop); prefira `watch` com `flush: 'post'`. |
| `onBeforeUnmount` | Antes de desmontar; instância ainda funcional. | Salvar algo, desconectar. |
| `onUnmounted` | Depois de desmontar. | Limpar timers, listeners, conexões. |
| `onErrorCaptured` | Um descendente lançou erro. | Error boundary. Retornar `false` impede a propagação. |
| `onActivated` / `onDeactivated` | Entrou ou saiu da tela dentro de `<KeepAlive>`. | Pausar e retomar polling. |
| `onServerPrefetch` | No servidor, antes do render (pode ser async). | Buscar dados no SSR. |
| `onRenderTracked` / `onRenderTriggered` | Só em dev: dependência rastreada; dependência que disparou o render. | Descobrir por que um componente renderiza. |

```vue [ErrorBoundary.vue]
<script setup>
import { ref, onErrorCaptured } from 'vue';

const erro = ref(null);
onErrorCaptured((e, instancia, info) => {
  erro.value = e;
  reportar(e, info);   // info: "render function", "setup function", ...
  return false;        // não propaga para cima
});
</script>

<template>
  <p v-if="erro">Algo deu errado. <button @click="erro = null">Tentar de novo</button></p>
  <slot v-else />
</template>
```

Erros que nenhum boundary trata vão para `app.config.errorHandler` (capítulo [12](#api-global-e-app)).
