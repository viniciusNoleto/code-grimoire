A Options API continua suportada e aparece em muito código legado (e em todo o Vue 2). As duas APIs usam o mesmo sistema de reatividade; a Composition API organiza o código por funcionalidade em vez de por tipo de opção, e é a única suportada no Vapor Mode.

| Options API | Composition API |
| --- | --- |
| `data() { return { n: 0 } }` | `const n = ref(0)` |
| `computed: { dobro() { … } }` | `const dobro = computed(() => …)` |
| `watch: { n(novo, antigo) { … } }` | `watch(n, (novo, antigo) => …)` |
| `methods: { salvar() { … } }` | `function salvar() { … }` |
| `props: { … }`, `emits: [...]` | `defineProps`, `defineEmits` |
| `mounted()`, `beforeUnmount()`, `unmounted()` | `onMounted`, `onBeforeUnmount`, `onUnmounted` |
| `this.$refs.campo` | `useTemplateRef('campo')` |
| `this.$emit('x')`, `this.$attrs`, `this.$slots` | `emit('x')`, `useAttrs()`, `useSlots()` |
| `this.$nextTick()`, `this.$watch()`, `this.$forceUpdate()` | `nextTick()`, `watch()`, (evite) |
| `provide` / `inject` como opções | `provide()` / `inject()` |
| `mixins: [...]` | composables (sem colisão de nomes, origem explícita) |

::note{type="note" title="Por que composables venceram os mixins"}
Com mixins, não dá para saber de onde vem `this.carregando`, dois mixins podem sobrescrever a mesma chave em silêncio, e não há como parametrizar. Um composable é uma função: você vê o que importa, renomeia na desestruturação e passa argumentos.
::
