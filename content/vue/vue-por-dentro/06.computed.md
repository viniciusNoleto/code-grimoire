::signature
`const v = computed((anterior) => …)   ·   computed({ get, set })`
::

Um `computed` é um ref derivado e **cacheado**. Ele rastreia o que lê no getter, só recalcula quando uma dessas dependências muda e, mesmo assim, só quando alguém lê o valor (avaliação preguiçosa). Um método chamado no template roda em todo render; um computed, não.

```vue [Carrinho.vue]
<script setup>
import { ref, computed } from 'vue';

const itens = ref([{ nome: 'Teclado', preco: 320, qtd: 1 }]);
const cupom = ref(null);

const subtotal = computed(() => itens.value.reduce((s, i) => s + i.preco * i.qtd, 0));
const total = computed(() => cupom.value === 'DEV10' ? subtotal.value * 0.9 : subtotal.value);

// computed gravável: útil para ligar v-model a uma forma derivada
const nomeCompleto = computed({
  get: () => `${nome.value} ${sobrenome.value}`,
  set: (v) => { [nome.value, sobrenome.value] = v.split(' '); },
});
</script>

<template>
  <p>Total: {{ total.toFixed(2) }}</p>
</template>
```

### Valor anterior :version[3.4]

O getter recebe o valor anterior como argumento (`undefined` na primeira vez). Além disso, desde a 3.4 um computed que recalcula para o **mesmo valor** não dispara quem depende dele, o que evita cascatas.

```js [computed-anterior.js]
// mantém o último valor válido enquanto count passar de 3
const ultimoValido = computed((anterior) => count.value <= 3 ? count.value : anterior);
```

::note{type="pitfall" title="Regras do getter"}
Sem efeitos colaterais (nada de mutar estado, fazer requisição ou mexer no DOM) e sem `async`: um computed devolve um valor síncrono. Para reagir com efeitos ou buscar dados, use `watch`. E não mute o valor retornado (`total.value.push(…)`): ele é um snapshot derivado.
::
