Pinia é o gerenciador de estado oficial (substituto do Vuex). Um store é um conjunto de estado reativo, valores derivados (getters) e funções que o alteram (actions), compartilhado pelo app inteiro, com suporte a DevTools, SSR e plugins. Pinia 3 é a versão atual e suporta só Vue 3.

### Setup store (recomendado com Composition API)

```ts [stores/carrinho.ts]
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useCarrinhoStore = defineStore('carrinho', () => {
  // state = refs · getters = computed · actions = funções
  const itens = ref<Item[]>([]);
  const cupom = ref<string | null>(null);

  const subtotal = computed(() => itens.value.reduce((s, i) => s + i.preco * i.qtd, 0));
  const total = computed(() => cupom.value === 'DEV10' ? subtotal.value * 0.9 : subtotal.value);

  function adicionar(produto: Produto) {
    const existente = itens.value.find(i => i.id === produto.id);
    existente ? existente.qtd++ : itens.value.push({ ...produto, qtd: 1 }); // mutar é permitido
  }
  function remover(id: string) { itens.value = itens.value.filter(i => i.id !== id); }
  async function finalizar() {
    await api.criarPedido(itens.value, cupom.value);
    itens.value = []; cupom.value = null;
  }

  return { itens, cupom, subtotal, total, adicionar, remover, finalizar };
});
```

```vue [ResumoCarrinho.vue]
<script setup>
import { storeToRefs } from 'pinia';
import { useCarrinhoStore } from '@/stores/carrinho';

const carrinho = useCarrinhoStore();
const { itens, total } = storeToRefs(carrinho);   // ❗ desestruturar direto perde reatividade
const { adicionar, remover } = carrinho;          // actions podem ser desestruturadas direto
</script>

<template>
  <p>{{ itens.length }} itens · {{ total }}</p>
</template>
```

### Option store e utilitários

```js [stores/preferencias.js]
export const usePreferencias = defineStore('preferencias', {
  state: () => ({ tema: 'claro', idioma: 'pt-BR' }),
  getters: { escuro: (state) => state.tema === 'escuro' },
  actions: { alternarTema() { this.tema = this.escuro ? 'claro' : 'escuro'; } },
});

const prefs = usePreferencias();
prefs.$patch({ tema: 'escuro', idioma: 'en' });   // várias mudanças, uma entrada no DevTools
prefs.$reset();                                    // volta ao state() inicial (só option stores)
prefs.$subscribe((mutacao, estado) => {           // persiste a cada mudança
  localStorage.setItem('prefs', JSON.stringify(estado));
});
```

O que pode (e o que não deve) ir para o `localStorage`, e como sincronizar entre abas, está em [Armazenamento](/web#armazenamento), no tomo Web.

- **Stores usando stores:** chame `useOutroStore()` dentro de uma action ou getter, não no topo do arquivo.
- **Fora de componentes** (guards do router, utilitários): chame `useStore()` depois que o Pinia foi instalado no app.
- **Re-render granular:** um componente que lê só `total` não renderiza quando `cupom` muda sem alterar o total. É o mesmo rastreamento do capítulo [02](#como-a-reatividade-funciona).

::note{type="note" title="Pinia e o useReducer do React"}
No React, o reducer centraliza transições porque estado é imutável e cada mudança precisa de um objeto novo. No Vue, mutar é o caminho normal (o Proxy detecta), então as actions do Pinia mutam direto. A ideia de centralizar as regras de mudança num lugar testável é a mesma.
::
