### Transition e TransitionGroup

`<Transition name="fade">` anima um único elemento ou componente que entra ou sai (via `v-if`, `v-show`, troca de `key` ou `<component :is>`). O Vue aplica classes em cada fase: `fade-enter-from`, `fade-enter-active`, `fade-enter-to` e as equivalentes de `leave`. `mode="out-in"` espera a saída terminar antes da entrada. `<TransitionGroup tag="ul">` faz o mesmo para listas e ainda anima a reordenação com a classe `-move`.

```vue [Aviso.vue]
<template>
  <Transition name="fade" mode="out-in">
    <p v-if="mensagem" :key="mensagem">{{ mensagem }}</p>
  </Transition>
</template>

<style>
.fade-enter-active, .fade-leave-active { transition: opacity .2s ease; }
.fade-enter-from, .fade-leave-to { opacity: 0; }
</style>
```

Anime `opacity` e `transform`: o navegador anima essas propriedades no compositor, fora da main thread. Animar `height` ou `top` refaz o layout em todo frame ([Renderização e animação](/web#renderizacao-e-animacao), no tomo Web).

#### View Transitions com nextTick

O Vue não tem um componente para a View Transition API, mas não precisa: `document.startViewTransition` espera a promessa do callback, e `nextTick` resolve quando o DOM já reflete o estado novo.

```js [useViewTransition.js]
import { nextTick } from 'vue';

export async function comTransicao(mudar) {
  if (!document.startViewTransition) return mudar();     // sem suporte: só muda
  await document.startViewTransition(async () => {
    mudar();               // muta o estado reativo
    await nextTick();      // o navegador tira a "foto nova" depois do patch do Vue
  }).finished;
}

// comTransicao(() => { produtoAberto.value = id })
// CSS: .foto { view-transition-name: foto-produto; }  → a miniatura "voa" até a foto grande
```

No Nuxt, `experimental.viewTransition` liga isso para toda navegação entre rotas. Como o navegador tira as fotos e anima os pseudo-elementos está em [View Transitions](/web#renderizacao-e-animacao), no tomo Web.

### KeepAlive

::signature
`<KeepAlive :include="['Inbox']" :max="5"><component :is="aba" /></KeepAlive>`
::

Ao alternar componentes dinâmicos, guarda as instâncias em cache em vez de destruí-las: o estado (scroll, formulário, dados carregados) volta intacto. Os componentes em cache recebem `onDeactivated` e `onActivated` em vez de unmount e mount. `include` e `exclude` filtram pelo `name` do componente; `max` limita o cache (LRU). É o equivalente aproximado do `<Activity>` do React.

### Teleport

::signature
`<Teleport to="body" :disabled="isMobile" defer>…</Teleport>`
::

Renderiza o conteúdo em outro ponto do DOM (modais, toasts), mas o componente continua no mesmo lugar da árvore lógica: recebe props, injeções e eventos normalmente. `disabled` renderiza no lugar original. `defer` :version[3.5] espera o resto do app montar, permitindo teleportar para um alvo renderizado pelo próprio Vue mais adiante.

```vue [Modal.vue]
<template>
  <button @click="aberto = true">Abrir</button>
  <Teleport to="body">
    <div v-if="aberto" class="fundo" @click.self="aberto = false">
      <div role="dialog" aria-modal="true"><slot /></div>
    </div>
  </Teleport>
</template>
```

Hoje o `<dialog>` nativo com `showModal()` já prende o foco, fecha com `Esc` e fica na camada superior, sem Teleport. Foco, `inert` e `aria-live` estão em [Semântica e acessibilidade](/web#semantica-e-acessibilidade), no tomo Web.

### Suspense (experimental)

`<Suspense>` mostra o slot `#fallback` enquanto algum descendente assíncrono resolve: componentes com `await` no topo do script setup ou componentes de `defineAsyncComponent`. Ainda é marcado como experimental na documentação, com API que pode mudar. Emite `pending`, `resolve` e `fallback`. Nuxt o usa extensivamente.

```vue [Painel.vue]
<template>
  <Suspense>
    <PainelVendas />            <!-- tem await no topo do script setup -->
    <template #fallback><Carregando /></template>
  </Suspense>
</template>
```
