`<script setup>` é açúcar de compilação: o conteúdo vira o corpo de `setup()`, e tudo declarado no topo (variáveis, funções, imports, componentes) fica disponível no template. As **macros** (`define*`) não precisam de import e são removidas no build.

### defineProps e destructure reativo :version[3.5]

```vue [CartaoProduto.vue]
<script setup lang="ts">
import { computed, watch } from 'vue';

// 3.5: desestruturar mantém a reatividade e permite defaults nativos do JS
const { nome, preco, moeda = 'BRL', destaque = false } = defineProps<{
  nome: string;
  preco: number;
  moeda?: string;
  destaque?: boolean;
}>();

const formatado = computed(() =>
  preco.toLocaleString('pt-BR', { style: 'currency', currency: moeda }) // compilado para props.preco
);

watch(() => preco, (p) => console.log('mudou', p));  // ainda precisa do getter em watch
</script>
```

Antes da 3.5, o padrão era `const props = withDefaults(defineProps<…>(), { moeda: 'BRL' })` e acessar `props.moeda`. Você vai ver muito isso em código existente. Props são **somente leitura**: para alterar, emita um evento ou use `defineModel`.

### defineEmits

```ts [defineEmits.ts]
const emit = defineEmits<{
  salvar: [id: string, dados: Produto];
  cancelar: [];
}>();

emit('salvar', produto.id, produto);   // no pai: <Form @salvar="onSalvar" />
```

### defineModel :version[3.4]

::signature
`const model = defineModel<T>(nome?, { required, default, get, set })`
::

Declara a prop `modelValue` e o evento `update:modelValue` de uma vez e devolve um ref: ler o ref lê a prop, escrever emite o evento. Aceita nomes para vários `v-model` e modificadores customizados.

```vue [CampoMoeda.vue]
<script setup>
const valor = defineModel({ type: Number, default: 0 });  // v-model
const moeda = defineModel('moeda', { default: 'BRL' });   // v-model:moeda

const [texto, modificadores] = defineModel('texto', {     // v-model:texto.maiusculo
  set: (v) => modificadores.maiusculo ? v.toUpperCase() : v,
});
</script>

<template>
  <input type="number" v-model="valor" />
  <select v-model="moeda"><option>BRL</option><option>USD</option></select>
</template>

<!-- Pai: <CampoMoeda v-model="preco" v-model:moeda="moedaSelecionada" /> -->
```

### defineExpose, defineOptions, defineSlots e generic

- **`defineExpose({ focar, limpar })`**: componentes com script setup são *fechados* por padrão. O pai que pega uma ref do componente só vê o que for exposto.
- **`defineOptions({ name, inheritAttrs: false })`** :version[3.3]: opções do componente sem um segundo bloco `<script>`.
- **`defineSlots<{ default(props: { item: T }): any }>()`**: tipa os slots para o TypeScript.
- **`<script setup lang="ts" generic="T extends { id: string }">`**: componentes genéricos, como uma lista tipada pelo item.

### useTemplateRef :version[3.5]

::signature
`const el = useTemplateRef<HTMLInputElement>('chave')`
::

```vue [BuscaRapida.vue]
<script setup>
import { useTemplateRef, onMounted } from 'vue';

const input = useTemplateRef('campo');     // casa com ref="campo" no template
const editor = useTemplateRef('editor');   // num componente: recebe o que ele expôs com defineExpose

onMounted(() => input.value.focus());      // null antes de montar
</script>

<template>
  <input ref="campo" type="search" />
  <EditorRico ref="editor" />
</template>
```

Antes da 3.5, o padrão era declarar `const campo = ref(null)` com o mesmo nome do atributo `ref`. Ainda funciona. Em `v-for`, a ref vira um array de elementos.

### useId :version[3.5], useAttrs e useSlots

```vue [CampoRotulado.vue]
<script setup>
import { useId, useAttrs } from 'vue';

defineOptions({ inheritAttrs: false });   // não joga os atributos no elemento raiz
const id = useId();                       // igual no servidor e no cliente
const attrs = useAttrs();                 // class, placeholder, @input… vindos do pai
</script>

<template>
  <div class="campo">
    <label :for="id"><slot name="rotulo" /></label>
    <input :id="id" v-bind="attrs" />      <!-- atributos vão para o input -->
  </div>
</template>
```

O que o leitor de tela faz com o vínculo entre `<label>` e campo, e as outras regras de semântica e foco, estão em [Semântica e acessibilidade](/web#semantica-e-acessibilidade), no tomo Web.

**Atributos repassados (fallthrough)**: atributos e listeners que o pai passa e não são props (`class`, `style`, `id`, `@click`) vão automaticamente para o elemento raiz. Com `inheritAttrs: false` e `v-bind="attrs"` você escolhe o destino.

### await no topo

Um `await` no topo do `<script setup>` torna o componente assíncrono: ele só funciona dentro de um `<Suspense>`. O compilador preserva o contexto da instância depois do `await`, o que não acontece num `setup()` manual.
