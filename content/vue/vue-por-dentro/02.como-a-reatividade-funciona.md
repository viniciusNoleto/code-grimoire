Há duas formas de criar estado reativo:

- **`ref(valor)`** embrulha qualquer valor num objeto com `.value`. O getter de `.value` rastreia, o setter dispara. Se o valor for um objeto, ele é convertido em `reactive` por dentro.
- **`reactive(objeto)`** devolve um **Proxy** profundo do objeto. Toda leitura de propriedade rastreia, toda escrita dispara, em qualquer nível de profundidade.

A documentação recomenda `ref` como padrão. `reactive` tem três limitações que causam bugs: só aceita objetos, não pode ser reatribuído (substituir o objeto inteiro desconecta quem o lia) e perde reatividade quando desestruturado.

```js [ref-vs-reactive.js]
import { ref, reactive, toRefs } from 'vue';

const count = ref(0);
count.value++;                       // no <script> usa .value
// no template: {{ count }} — refs de topo são desembrulhados automaticamente

const estado = reactive({ itens: [], filtro: '' });
estado.itens.push('a');              // mutação profunda: reativa

// ❌ armadilhas do reactive
let s = reactive({ n: 0 });
s = reactive({ n: 1 });              // quem lia o proxy antigo não percebe
const { n } = estado;                // n é um número solto, sem reatividade
fazerAlgo(estado.filtro);            // passa o valor, não a fonte

// ✅ toRefs converte cada propriedade num ref ligado ao original
const { itens, filtro } = toRefs(estado);
```

### O que o Vue rastreia, exatamente

O rastreamento acontece **na leitura**, durante a execução de um efeito. Se o render lê `usuario.nome`, ele depende de `usuario.nome`, e não de `usuario.email`. Ler dentro de um `setTimeout` ou depois de um `await` não é rastreado, porque o efeito já terminou.

- **Identidade:** `reactive(obj) !== obj`. Trabalhe só com o proxy. Chamar `reactive` no mesmo objeto devolve o mesmo proxy.
- **Desembrulho:** refs dentro de `reactive` são desembrulhados ao ler a propriedade, mas não dentro de arrays nem de `Map` (lá você ainda precisa de `.value`).
- **Coleções:** `Map`, `Set`, `WeakMap` e `WeakSet` são suportados; métodos como `.get()` e `.add()` rastreiam e disparam.

### Atualizações assíncronas e nextTick

Mudar o estado não atualiza o DOM na hora. O Vue agrupa as mudanças e aplica tudo no próximo tick. Se você precisa ler o DOM já atualizado (medir altura, rolar até um item novo), use `await nextTick()`. O "próximo tick" é uma **microtask**: roda depois do seu código síncrono e antes de o navegador pintar. Tasks, microtasks e frames estão no [event loop do tomo Web](/web#event-loop).

::workbench{demo="next-tick" title="O DOM só muda no próximo tick"}
Três incrementos seguidos e duas leituras do DOM: uma logo depois de mudar o estado, outra depois de `await nextTick()`.
::

```js [nextTick.js]
import { nextTick } from 'vue';

async function adicionar(item) {
  itens.value.push(item);
  console.log(lista.value.children.length); // ainda o número antigo
  await nextTick();
  lista.value.lastElementChild.scrollIntoView(); // agora o nó existe
}
```
