::question
#title
Quando o pai renderiza, o filho renderiza junto?

#default
Só se as props do filho mudaram (comparação rasa) ou se o conteúdo de slot dinâmico mudou. Sem isso, o Vue pula o filho automaticamente. É o oposto do padrão do React, onde o filho renderiza junto a menos que use `memo`.
::

::question
#title
Por que mutar `perfil.pontos` não re-renderiza o pai que passou `perfil` como prop?

#default
Porque o rastreamento é por propriedade lida. O render do pai nunca leu `perfil.pontos`; só o filho leu. A mutação dispara apenas os efeitos que dependem daquela chave.
::

::question
#title
`ref` ou `reactive`?

#default
`ref` é o padrão recomendado: aceita qualquer tipo, pode ser reatribuído e não perde reatividade ao ser passado adiante. `reactive` só aceita objetos, não pode ser substituído e perde reatividade ao desestruturar (sem `toRefs`).
::

::question
#title
Qual a diferença entre `computed` e um método no template?

#default
O computed é cacheado: só recalcula quando uma dependência muda, e só quando alguém lê. Um método roda em todo render do componente. Computeds também devem ser puros e síncronos.
::

::question
#title
Por que `watch(estado.pagina, cb)` não funciona?

#default
Porque você passou o valor atual (um número), não uma fonte reativa. O watch precisa de um ref, um reactive, um getter ou um array deles: `watch(() => estado.pagina, cb)`.
::

::question
#title
`watch` ou `watchEffect`?

#default
`watch` é preguiçoso, observa fontes explícitas e dá acesso ao valor anterior. `watchEffect` roda na hora e rastreia tudo o que lê. Use `watch` quando quer controlar exatamente o que dispara (ou precisa do valor antigo), e `watchEffect` quando as dependências são as mesmas que o corpo usa.
::

::question
#title
Por que ler o DOM logo depois de mudar o estado retorna o valor antigo?

#default
O Vue agrupa as mudanças e atualiza o DOM numa microtask. Use `await nextTick()` ou um watcher com `flush: 'post'` para ler o DOM atualizado.
::

::question
#title
Desestruturar props perde a reatividade?

#default
Desde a 3.5, não, quando feito direto no `defineProps`: o compilador reescreve `preco` para `props.preco`. Mas para observar, ainda use um getter em `watch(() => preco, …)`, e ao passar para um composable, passe um getter (`() => preco`) em vez do valor.
::

::question
#title
Desestruturar um store do Pinia funciona?

#default
State e getters perdem a reatividade se desestruturados direto do store. Use `storeToRefs(store)` para eles. Actions podem ser desestruturadas normalmente.
::

::question
#title
Como o provide/inject do Vue difere do Context do React em performance?

#default
No React, mudar o value do Provider renderiza todos os consumidores. No Vue, se o valor fornecido é reativo, só os componentes que leem o dado específico que mudou renderizam, e o componente que fornece não precisa renderizar.
::

::question
#title
Para que servem `markRaw` e `shallowRef` com Workers e libs externas?

#default
`markRaw` impede que instâncias complexas (Worker, EventSource, mapas, gráficos) virem proxies, o que quebraria comparações internas e custaria memória. `shallowRef` evita converter resultados grandes em milhares de proxies: só a troca do `.value` é reativa.
::

::question
#title
Onde registrar o cleanup de uma conexão aberta num watcher?

#default
Com `onWatcherCleanup` (3.5), chamado de forma síncrona dentro do callback. Ele roda antes da próxima execução e quando o watcher para, o que acontece automaticamente na desmontagem se o watcher foi criado de forma síncrona no setup.
::

::question
#title
Qual a diferença entre `v-if` e `v-show`?

#default
`v-if` cria e destrói o elemento (e o estado dos componentes dentro dele); `v-show` só alterna `display`. `v-show` tem custo inicial maior e alternância barata; `v-if` tem custo inicial menor e alternância cara.
::

::question
#title
Como preservar o estado de uma aba ao alternar?

#default
Envolva o `<component :is>` com `<KeepAlive>`. As instâncias ficam em cache e recebem `onDeactivated`/`onActivated` em vez de serem destruídas.
::
