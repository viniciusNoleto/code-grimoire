### createRoot e hydrateRoot

```jsx [main.jsx]
import { createRoot, hydrateRoot } from 'react-dom/client';

// SPA: o React cria todo o DOM
const root = createRoot(document.getElementById('root'), {
  onUncaughtError: (erro, info) => reportar(erro, info.componentStack),  // React 19
  onCaughtError: (erro) => console.warn('capturado por boundary', erro),
});
root.render(<App />);
// root.unmount() para desmontar

// SSR: o HTML já veio do servidor; o React só "liga" os handlers
hydrateRoot(document.getElementById('root'), <App />);
```

### createPortal

::signature
`createPortal(filhos, noDoDom, key?)`
::

Renderiza filhos em outro lugar do DOM (modais, toasts, tooltips fora de um container com `overflow: hidden`). O portal continua sendo filho **na árvore do React**: recebe contexto do pai e eventos sobem pela árvore do React, não pela do DOM.

```jsx [Modal.jsx]
import { createPortal } from 'react-dom';

function Modal({ aberto, onFechar, children }) {
  if (!aberto) return null;
  return createPortal(
    <div className="fundo" onClick={onFechar}>
      <div role="dialog" aria-modal="true" onClick={e => e.stopPropagation()}>{children}</div>
    </div>,
    document.body
  );
}
```

Hoje o `<dialog>` nativo com `showModal()` já prende o foco, fecha com `Esc` e fica na camada superior, sem portal. Foco, `inert` e `aria-live` estão em [Semântica e acessibilidade](/web#semantica-e-acessibilidade), no tomo Web.

### flushSync

::signature
`flushSync(() => setEstado(…))`
::

Força o React a aplicar a atualização e mexer no DOM **antes** da próxima linha. Útil quando a linha seguinte depende do DOM atualizado (rolar até um item recém-adicionado, integração com API imperativa). Custa performance e anula o batching; use pouco.

```jsx [flushSync.jsx]
function adicionar(item) {
  flushSync(() => setItens(lista => [...lista, item]));
  ultimoRef.current.scrollIntoView({ behavior: 'smooth' }); // o nó já existe aqui
}
```

### Metadados e recursos no componente :version[19]

Você pode renderizar `<title>`, `<meta>` e `<link>` em qualquer componente; o React os move para o `<head>`. Folhas de estilo com `precedence` e scripts `async` são deduplicados. As APIs de carregamento antecipado avisam o navegador antes de o recurso ser necessário:

```jsx [recursos.jsx]
import { preconnect, prefetchDNS, preload, preinit } from 'react-dom';

function PaginaProduto({ produto }) {
  preconnect('https://cdn.loja.com');                               // abre conexão cedo
  preload(produto.imagemGrande, { as: 'image' });                   // baixa sem executar
  preinit('https://cdn.loja.com/zoom.js', { as: 'script' });        // baixa e executa

  return (<>
    <title>{produto.nome} · Loja MX</title>
    <meta name="description" content={produto.resumo} />
    <link rel="stylesheet" href="/produto.css" precedence="default" />
    <Detalhes produto={produto} />
  </>);
}
```

O que cada dica faz no navegador (`preconnect`, `preload`, `modulepreload`, `fetchpriority`) está em [Carregamento de recursos](/web#carregamento-de-recursos), no tomo Web.

### dangerouslySetInnerHTML e XSS

O React escapa todo texto renderizado: `{comentario}` com `<script>` dentro aparece como texto. A única porta para HTML cru é `dangerouslySetInnerHTML`, e o nome é o aviso. Se o HTML vier do usuário ou de uma API, **sanitize antes**:

```jsx [Comentario.jsx]
import DOMPurify from 'dompurify';

function Comentario({ html }) {
  // ❌ <div dangerouslySetInnerHTML={{ __html: html }} />  → <img src=x onerror=roubar()> executa
  const limpo = useMemo(() => DOMPurify.sanitize(html), [html]);
  return <div dangerouslySetInnerHTML={{ __html: limpo }} />;
}

// Outras portas de XSS que o escape não cobre:
<a href={urlDoUsuario}>perfil</a>   // "javascript:..." executa ao clicar; valide o esquema (http/https)
```

XSS, CSP com nonce e Trusted Types estão em [Origem e segurança](/web#origem-e-seguranca), no tomo Web.

### Custom elements :version[19]

Até o React 18, props em tags com hífen viravam sempre atributos de string, e eventos customizados não funcionavam com `onX`. O React 19 passou a tratar custom elements direito: se o elemento tem uma **propriedade** com o nome da prop, ele atribui a propriedade (objetos e arrays chegam intactos); senão, usa atributo. Props `on` + nome viram `addEventListener` para eventos customizados.

```jsx [Estoque.jsx]
function Estoque({ produto }) {
  return (
    <contador-estoque
      qtd={produto.qtd}                       // propriedade, se o elemento a define
      opcoes={{ alerta: 5 }}                  // objeto passado como propriedade, sem JSON.stringify
      onesgotado={(e) => avisar(e.detail)}    // CustomEvent('esgotado') vira listener
    >
      <span slot="rotulo">Restam</span>
    </contador-estoque>
  );
}
// Com TypeScript, declare o elemento em JSX.IntrinsicElements para ter tipos nas props.
```

Custom Elements, Shadow DOM e slots estão em [Web Components](/web#web-components), no tomo Web.

### Testes e depuração

- **`act(async () => { … })`** garante que renders, efeitos e atualizações disparados dentro dele foram processados antes das asserções. Testing Library já chama `act` por você na maioria dos casos.
- **`captureOwnerStack()`** retorna, só em desenvolvimento, a pilha de componentes "donos" (quem renderizou quem) para enriquecer logs de erro.

### APIs removidas no React 19

| Removida | Use |
| --- | --- |
| `ReactDOM.render` | `createRoot(el).render()` |
| `ReactDOM.hydrate` | `hydrateRoot` |
| `unmountComponentAtNode` | `root.unmount()` |
| `findDOMNode` | refs |
| `propTypes` e `defaultProps` em funções | TypeScript e valores padrão na desestruturação |
| refs de string, contexto legado (`contextTypes`) | callback refs / `useRef`, `createContext` |
