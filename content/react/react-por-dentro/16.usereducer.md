`useReducer` troca "como mudar o estado" espalhado em handlers por uma função central `(estado, ação) => novoEstado`. Os componentes passam a descrever **o que aconteceu** (`dispatch({ type: 'item_adicionado' })`) e o reducer decide **como o estado muda**.

### Quando vale mais que useState

- Vários campos que mudam juntos (status + dados + erro de uma requisição).
- O próximo estado depende do anterior com regras não triviais.
- Você quer transições explícitas e testáveis sem renderizar nada: o reducer é uma função pura, basta chamar com estado e ação.
- Você precisa passar "como atualizar" para longe via contexto: `dispatch` é estável, ao contrário de callbacks.

```ts [carrinhoReducer.ts]
type Item = { id: string; nome: string; preco: number; qtd: number };
type Estado = { itens: Item[]; cupom: string | null };

type Acao =
  | { type: 'item_adicionado'; item: Omit<Item, 'qtd'> }
  | { type: 'item_removido'; id: string }
  | { type: 'cupom_aplicado'; codigo: string }
  | { type: 'carrinho_limpo' };

export function carrinhoReducer(estado: Estado, acao: Acao): Estado {
  switch (acao.type) {
    case 'item_adicionado': {
      const existe = estado.itens.find(i => i.id === acao.item.id);
      const itens = existe
        ? estado.itens.map(i => i.id === acao.item.id ? { ...i, qtd: i.qtd + 1 } : i)
        : [...estado.itens, { ...acao.item, qtd: 1 }];
      return { ...estado, itens };
    }
    case 'item_removido':
      return { ...estado, itens: estado.itens.filter(i => i.id !== acao.id) };
    case 'cupom_aplicado':
      return { ...estado, cupom: acao.codigo };
    case 'carrinho_limpo':
      return { itens: [], cupom: null };
    default: {
      const _exaustivo: never = acao; // erro de compilação se faltar um case
      return estado;
    }
  }
}

// Inicialização preguiçosa: 3º argumento recebe o 2º
const [estado, dispatch] = useReducer(carrinhoReducer, 'carrinho', chave =>
  JSON.parse(localStorage.getItem(chave) ?? '{"itens":[],"cupom":null}')
);
```

::note{type="pitfall" title="Armadilhas"}
O reducer precisa ser puro: nada de `fetch`, `Math.random()`, `Date.now()` ou mutação do estado recebido. No StrictMode ele roda duas vezes, e efeitos colaterais aparecem duplicados. Gere IDs e timestamps no handler e mande na ação. Nomeie ações como eventos no passado (`item_adicionado`), não como comandos (`setItens`).
::
