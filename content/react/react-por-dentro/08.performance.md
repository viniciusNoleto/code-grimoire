### useMemo

::signature
`const valor = useMemo(() => calcular(a, b), [a, b])`
::

Guarda o resultado entre renders e só recalcula quando uma dependência muda. Dois usos legítimos: **cálculo caro** (filtrar ou ordenar milhares de itens) e **estabilizar uma referência** passada para um filho com `memo` ou usada como dependência de efeito. É uma otimização, não uma garantia: o React pode descartar o cache.

```jsx [useMemo.jsx]
function ListaTarefas({ tarefas, filtro, tema }) {
  // só refiltra quando tarefas ou filtro mudam; trocar o tema não recalcula
  const visiveis = useMemo(() => filtrarTarefas(tarefas, filtro), [tarefas, filtro]);
  return <Lista itens={visiveis} tema={tema} />;
}
```

### useCallback

::signature
`const fn = useCallback((args) => { … }, [deps])`
::

É `useMemo(() => fn, deps)`: cacheia a função em si, não o resultado. Só faz diferença quando a função vai para um filho com `memo`, para dependências de outro hook ou para um hook customizado que a recebe. Em um `<button onClick>` comum, não ajuda em nada.

### memo

::signature
`const Comp = memo(Componente, saoIguais?)`
::

Pula o render quando todas as props são iguais por `Object.is` (ou pela sua função `saoIguais(antes, depois)`). Não bloqueia renders vindos do próprio estado nem de contextos lidos. O capítulo 03 tem a bancada que mostra os casos.

::note{type="note" title="React Compiler"}
O React Compiler (v1.0 desde outubro de 2025) insere essa memoização automaticamente no build. Em projetos que o usam, `useMemo`, `useCallback` e `memo` manuais ficam quase desnecessários. Ele depende de código que respeite as regras do React (capítulo 14).
::

### useTransition e startTransition

::note{type="tip" title="Por que isso importa"}
Um render grande é uma *long task*: enquanto ela roda, cliques e teclas esperam, e o INP piora. Long tasks, `scheduler.yield` e como o navegador mede a resposta estão no tomo Web, em [Event loop](/web#event-loop) e [Core Web Vitals](/web#core-web-vitals).
::

::signature
`const [isPending, startTransition] = useTransition()`
::

Marca uma atualização como **não urgente**. O React começa a renderizá-la em segundo plano e, se algo urgente chegar (uma tecla digitada), interrompe e descarta o trabalho. Enquanto isso, a UI antiga continua na tela e `isPending` fica `true`. No React 19 a função passada pode ser `async`, o que transforma a transição numa *Action*.

```jsx [Abas.jsx]
function Abas() {
  const [aba, setAba] = useState('sobre');
  const [isPending, startTransition] = useTransition();

  function selecionar(proxima) {
    startTransition(() => setAba(proxima));  // a aba lenta não trava os cliques
  }

  return (<>
    <BotaoAba ativo={aba === 'sobre'} onClick={() => selecionar('sobre')}>Sobre</BotaoAba>
    <BotaoAba ativo={aba === 'posts'} onClick={() => selecionar('posts')}>Posts (lento)</BotaoAba>
    <div style={{ opacity: isPending ? 0.6 : 1 }}>{aba === 'posts' ? <PostsLentos /> : <Sobre />}</div>
  </>);
}

// Async transition (React 19): isPending cobre a requisição inteira
startTransition(async () => {
  const erro = await atualizarNome(nome);
  startTransition(() => { if (erro) setErro(erro); else redirecionar('/perfil'); });
});
```

`startTransition` importado direto de `react` faz o mesmo sem o `isPending`, e pode ser usado fora de componentes. Uma transição não serve para o valor de um input controlado: a digitação precisa ser urgente.

### useDeferredValue

::signature
`const adiado = useDeferredValue(valor, valorInicial?)`
::

Em vez de marcar o *setter* como transição, você marca o *valor*. Na digitação, o React renderiza primeiro com o valor antigo (rápido) e depois tenta o novo em segundo plano. Funciona quando a parte lenta está num filho com `memo` que recebe o valor adiado. Use quando você não controla o setter (o valor vem de props ou de outra lib).

::workbench{demo="slow-list" title="Digitação com uma lista lenta"}
Cada linha da lista gasta 1 ms para renderizar (200 linhas ≈ 200 ms por render). Digite rápido no campo nos três modos e compare a resposta do input.
::
