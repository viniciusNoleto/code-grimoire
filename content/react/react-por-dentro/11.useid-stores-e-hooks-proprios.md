### useId

::signature
`const id = useId()`
::

Gera um ID único por instância do componente e **igual no servidor e no cliente**, o que evita erros de hidratação. Use para ligar `<label htmlFor>`, `aria-describedby` e afins. Não use como `key` de lista: keys vêm dos dados.

```jsx [CampoSenha.jsx]
function CampoSenha() {
  const id = useId();
  return (<>
    <label htmlFor={id + '-senha'}>Senha</label>
    <input id={id + '-senha'} type="password" aria-describedby={id + '-dica'} />
    <p id={id + '-dica'}>Mínimo de 12 caracteres.</p>
  </>);
}
// Duas instâncias de <CampoSenha /> na página não colidem
```

O que o leitor de tela faz com esses vínculos, e as outras regras de semântica e foco, estão em [Semântica e acessibilidade](/web#semantica-e-acessibilidade), no tomo Web.

### useSyncExternalStore

::signature
`const snapshot = useSyncExternalStore(subscribe, getSnapshot, getServerSnapshot?)`
::

A forma correta de ler dados que vivem **fora do React** (uma store, uma API do navegador) sem "tearing", que é partes da tela mostrando versões diferentes do mesmo dado durante um render concorrente. É o que Redux, Zustand e afins usam por baixo. `getSnapshot` deve retornar o mesmo valor (mesma referência) enquanto a store não mudar.

```js [useOnline.js]
function subscribe(callback) {
  window.addEventListener('online', callback);
  window.addEventListener('offline', callback);
  return () => {
    window.removeEventListener('online', callback);
    window.removeEventListener('offline', callback);
  };
}

export function useOnline() {
  return useSyncExternalStore(
    subscribe,                     // definido fora do componente: identidade estável
    () => navigator.onLine,        // snapshot no cliente
    () => true                     // snapshot no servidor (SSR)
  );
}
```

```js [store-minima.js]
// Uma store mínima, útil para estado global de alta frequência (cotações via SSE, por exemplo)
export function criarStore(inicial) {
  let estado = inicial;
  const ouvintes = new Set();
  return {
    get: () => estado,
    set: (fn) => { estado = fn(estado); ouvintes.forEach(l => l()); },
    subscribe: (l) => { ouvintes.add(l); return () => ouvintes.delete(l); },
  };
}

const cotacoes = criarStore({});
export function useCotacao(ativo) {
  // seletor: só re-renderiza quando o valor DESTE ativo muda
  return useSyncExternalStore(cotacoes.subscribe, () => cotacoes.get()[ativo]);
}
```

#### Exemplo: estado persistido e sincronizado entre abas

`localStorage` é uma store externa como qualquer outra. O evento `storage` avisa as **outras** abas quando um valor muda; para a própria aba, o hook avisa os ouvintes à mão. Como `getSnapshot` devolve a string crua, a referência só muda quando o valor muda de verdade.

```js [useLocalStorage.js]
const ouvintes = new Set();
function subscribe(cb) {
  ouvintes.add(cb);
  window.addEventListener('storage', cb);        // mudanças vindas de outras abas
  return () => { ouvintes.delete(cb); window.removeEventListener('storage', cb); };
}

export function useLocalStorage(chave, inicial) {
  const cru = useSyncExternalStore(
    subscribe,
    () => localStorage.getItem(chave),           // string: comparável por Object.is
    () => null,                                  // no servidor não há localStorage
  );
  const valor = cru === null ? inicial : JSON.parse(cru);
  const setValor = useCallback((novo) => {
    localStorage.setItem(chave, JSON.stringify(novo));
    ouvintes.forEach(cb => cb());                // o evento storage não dispara na própria aba
  }, [chave]);
  return [valor, setValor];
}

// const [tema, setTema] = useLocalStorage('tema', 'claro');  → trocar numa aba troca em todas
```

Para mensagens que não precisam ser persistidas (logout em todas as abas, carrinho), um `BroadcastChannel` no `subscribe` faz o mesmo papel. Os canais entre abas, iframes e workers e os limites de cada armazenamento estão em [Comunicação entre contextos](/web#comunicacao-entre-contextos) e [Armazenamento](/web#armazenamento), no tomo Web.

### useDebugValue

::signature
`useDebugValue(valor, formatar?)`
::

Mostra um rótulo para o seu hook customizado no React DevTools (ex.: "Online" / "Offline"). Só tem efeito no DevTools.

### Hooks customizados

Um hook customizado é uma função que começa com `use` e chama outros hooks. Ele **compartilha lógica, não estado**: dois componentes que chamam `useOnline()` têm cada um sua própria assinatura. Bons candidatos: conexões (o `useEventSource` e o `useWorker` mais abaixo), formulários, media queries, debounce.

```js [useDebounce.js]
export function useDebounce(valor, atraso = 300) {
  const [debounced, setDebounced] = useState(valor);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(valor), atraso);
    return () => clearTimeout(t);   // cada tecla cancela o timer anterior
  }, [valor, atraso]);
  return debounced;
}

```
