::signature
`const [estado, setEstado] = useState(valorInicial | () => valorInicial)`
::

O capítulo 02 cobriu o modelo mental (snapshot, batching, `Object.is`). Aqui ficam os detalhes da API que aparecem no dia a dia.

- **O setter tem identidade estável.** Não precisa entrar em dependências de `useEffect` nem de `useCallback`.
- **Duas formas de atualizar:** valor (`setN(5)`) ou função (`setN(n => n + 1)`). Use a forma de função sempre que o próximo valor depender do anterior.
- **Guardar uma função no estado** exige embrulhar: `setFn(() => minhaFuncao)`. Sem isso, o React chama `minhaFuncao` como updater.
- **Chamar o setter durante o render** só é permitido para o próprio componente e com condição (padrão "ajustar estado quando uma prop muda"). Fora disso, gera loop infinito.
- **Um estado ou vários?** Agrupe valores que sempre mudam juntos (posição `{ x, y }`); separe os independentes. Se as transições entre eles têm regras, migre para `useReducer`.

```jsx [formulario-controlado.jsx]
function Cadastro() {
  const [form, setForm] = useState({ nome: '', email: '', aceita: false });

  // um handler genérico para todos os campos
  function atualizar(e) {
    const { name, type, value, checked } = e.target;
    setForm(f => ({ ...f, [name]: type === 'checkbox' ? checked : value }));
  }

  const valido = form.nome.length > 1 && form.email.includes('@') && form.aceita; // derivado

  return (
    <form>
      <input name="nome" value={form.nome} onChange={atualizar} />
      <input name="email" value={form.email} onChange={atualizar} />
      <input name="aceita" type="checkbox" checked={form.aceita} onChange={atualizar} />
      <button disabled={!valido}>Criar conta</button>
    </form>
  );
}
```

```jsx [ajustar-estado-quando-prop-muda.jsx]
// Raro, mas oficial: evita um render extra que o useEffect causaria
function Lista({ itens }) {
  const [selecionado, setSelecionado] = useState(null);
  const [itensAnteriores, setItensAnteriores] = useState(itens);

  if (itens !== itensAnteriores) {   // a prop mudou
    setItensAnteriores(itens);
    setSelecionado(null);            // React re-renderiza na hora, antes de pintar
  }
  // ...
}
// Quase sempre há opção melhor: uma key no pai, ou derivar o valor no render.
```

::note{type="note" title="Controlado ou não controlado"}
Um input é **controlado** quando recebe `value` e `onChange`: o estado do React é a fonte da verdade. É **não controlado** quando usa `defaultValue` e você lê o valor no submit (via `FormData` ou ref). Com as actions do React 19, formulários não controlados voltaram a ser a opção mais simples para muitos casos (capítulo 10).
::
