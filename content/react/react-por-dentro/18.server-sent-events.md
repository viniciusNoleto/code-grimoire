SSE é um canal **unidirecional, do servidor para o cliente**, sobre uma requisição HTTP comum que nunca termina. O servidor responde com `Content-Type: text/event-stream` e vai escrevendo blocos de texto. O navegador oferece a API `EventSource`, que já faz parsing, reconexão automática e retomada a partir do último ID recebido. É o que muitas APIs de LLM usam para enviar tokens em streaming.

A comparação com WebSocket, WebTransport e WebRTC, e o que acontece no protocolo, estão em [Tempo real](/web#tempo-real), no tomo Web.

### O formato no fio

Cada evento é um conjunto de linhas `campo: valor` terminado por uma **linha em branco**. São só quatro campos:

```text [GET /stream → text/event-stream]
retry: 3000

: comentário, ignorado pelo cliente (usado como heartbeat)

id: 41
event: preco
data: {"ativo":"PETR4","valor":38.42}

id: 42
data: linha um
data: linha dois
```

- `data`: o conteúdo. Várias linhas `data` são unidas com `\n`.
- `event`: o tipo. Sem ele, o evento chega em `onmessage` (tipo `message`); com ele, só em `addEventListener('preco', …)`.
- `id`: vira `lastEventId`. Ao reconectar, o navegador envia o header `Last-Event-ID` e o servidor pode continuar de onde parou.
- `retry`: quantos milissegundos esperar antes de reconectar.

Um servidor falso escreve no fio e um parser seguindo as regras do EventSource monta os eventos. Derrube a conexão para ver a reconexão com `Last-Event-ID`.

### Servidor (Node/Express)

```js [server/stream.js]
app.get('/stream', (req, res) => {
  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    'Connection': 'keep-alive',   // só HTTP/1.1; em HTTP/2 omita
    'X-Accel-Buffering': 'no',    // impede o nginx de bufferizar a resposta
  });
  res.write('retry: 5000\n\n');

  let id = Number(req.headers['last-event-id'] ?? 0); // retomada após queda

  const enviar = (event, data) => {
    id++;
    res.write(`id: ${id}\nevent: ${event}\ndata: ${JSON.stringify(data)}\n\n`);
  };

  const tick = setInterval(() => enviar('preco', { ativo: 'PETR4', valor: 38 + Math.random() }), 1000);
  const ping = setInterval(() => res.write(': ping\n\n'), 15000); // mantém proxies acordados

  req.on('close', () => { clearInterval(tick); clearInterval(ping); });
});
```

### Cliente: um hook com cleanup

```ts [src/hooks/useEventSource.ts]
import { useEffect, useLayoutEffect, useRef, useState } from 'react';

type Status = 'conectando' | 'aberto' | 'reconectando' | 'fechado';

export function useEventSource(
  url: string | null,
  tipos: string[],
  onEvento: (tipo: string, dados: unknown, id: string) => void,
) {
  const [status, setStatus] = useState<Status>('conectando');

  // callback sempre atualizado sem reabrir a conexão
  const handler = useRef(onEvento);
  useLayoutEffect(() => { handler.current = onEvento; });

  const chaveTipos = tipos.join(',');

  useEffect(() => {
    if (!url) return;
    const es = new EventSource(url, { withCredentials: true }); // envia cookies

    es.onopen = () => setStatus('aberto');
    es.onerror = () =>
      setStatus(es.readyState === EventSource.CLOSED ? 'fechado' : 'reconectando');

    const ouvir = (e: MessageEvent) =>
      handler.current(e.type, JSON.parse(e.data), e.lastEventId);
    chaveTipos.split(',').forEach(t => es.addEventListener(t, ouvir));

    return () => es.close(); // essencial: sem isso, cada remount abre outra conexão
  }, [url, chaveTipos]);

  return status;
}

// Uso com useReducer: o stream vira ações
const [cotacoes, dispatch] = useReducer(cotacoesReducer, {});
const status = useEventSource('/stream', ['preco'], (_tipo, dados) =>
  dispatch({ type: 'preco_recebido', dados })
);
```

### Limitações e como contornar

- **Sem headers customizados.** `EventSource` não aceita `Authorization`. Use cookie de sessão (`withCredentials`), um token curto na query, ou troque por `fetch` + leitura do stream (a lib `@microsoft/fetch-event-source` faz isso com reconexão).
- **Limite de conexões em HTTP/1.1:** cerca de 6 por domínio no navegador, somando todas as abas. Com HTTP/2 o limite deixa de ser problema, porque tudo é multiplexado.
- **Só texto UTF-8.** Binário precisa ir em base64 ou por outro canal.
- **Reconexão tem regras:** se o servidor responder um status diferente de 200 ou outro `Content-Type`, o EventSource desiste de vez (`readyState` vira `CLOSED`). Erro de rede faz ele tentar de novo.
- **Eventos em alta frequência** geram um render por evento. Agrupe (acumule num ref e faça flush a cada 100 ms) ou leve para uma store externa com `useSyncExternalStore`.

```ts [sse-com-fetch.ts]
// Alternativa quando você precisa do header Authorization
const res = await fetch('/stream', {
  headers: { Authorization: `Bearer ${token}` },
  signal: controller.signal,
});
const reader = res.body!.pipeThrough(new TextDecoderStream()).getReader();
let buffer = '';
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += value;
  const blocos = buffer.split('\n\n');
  buffer = blocos.pop()!;            // último pode estar incompleto
  blocos.forEach(processarBloco);    // você implementa o parsing e a reconexão
}
```

### WebSocket com o mesmo padrão

Quando os dois lados precisam enviar, o hook muda pouco: a conexão nasce no efeito e morre no cleanup. A diferença é que o WebSocket **não reconecta sozinho**, então o hook faz backoff com jitter, e o envio precisa de uma referência estável para a conexão atual.

```ts [src/hooks/useWebSocket.ts]
import { useCallback, useEffect, useLayoutEffect, useRef, useState } from 'react';

export function useWebSocket(url: string | null, onMensagem: (dados: unknown) => void) {
  const [status, setStatus] = useState<'conectando' | 'aberto' | 'reconectando' | 'fechado'>('fechado');
  const ws = useRef<WebSocket | null>(null);
  const handler = useRef(onMensagem);
  useLayoutEffect(() => { handler.current = onMensagem; });

  useEffect(() => {
    if (!url) return;
    let tentativa = 0;
    let timer: ReturnType<typeof setTimeout>;
    let encerrado = false;

    const conectar = () => {
      const s = new WebSocket(url);
      ws.current = s;
      setStatus(tentativa ? 'reconectando' : 'conectando');
      s.onopen = () => { tentativa = 0; setStatus('aberto'); };
      s.onmessage = (e) => handler.current(JSON.parse(e.data));
      s.onclose = (e) => {
        if (encerrado || e.code === 1000) return setStatus('fechado');
        const espera = Math.min(30_000, 1000 * 2 ** tentativa++) * (0.5 + Math.random());
        setStatus('reconectando');
        timer = setTimeout(conectar, espera);           // backoff exponencial com jitter
      };
    };
    conectar();

    return () => {                                        // url mudou ou desmontou
      encerrado = true;
      clearTimeout(timer);
      ws.current?.close(1000);
    };
  }, [url]);

  const enviar = useCallback((dados: unknown) => {
    if (ws.current?.readyState === WebSocket.OPEN) ws.current.send(JSON.stringify(dados));
  }, []);

  return { status, enviar };
}
```

- **Uma conexão por app**, não por componente: se vários componentes precisam do mesmo canal, abra a conexão num provider ou numa store externa (`useSyncExternalStore`) e distribua as mensagens.
- **StrictMode** monta, desmonta e monta de novo em desenvolvimento: sem o cleanup, você veria duas conexões.

### SSE, WebSocket ou polling

|  | SSE | WebSocket | Polling |
| --- | --- | --- | --- |
| Direção | servidor → cliente | bidirecional | cliente pergunta |
| Protocolo | HTTP comum | upgrade para `ws://` | HTTP comum |
| Reconexão | automática, com retomada | você implementa | implícita |
| Dados | texto | texto e binário | qualquer |
| Infra | passa por proxies e CDNs comuns | exige suporte a upgrade | trivial |
| Bom para | feeds, notificações, progresso, streaming de LLM | chat, jogos, colaboração em tempo real | dados que mudam pouco |
