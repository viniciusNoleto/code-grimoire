Tente responder antes de abrir.

::question
#title
Um componente filho renderiza se as props dele não mudaram?

#default
Sim, se o pai renderizou. O padrão é renderizar todos os filhos. Só com `React.memo` (ou o React Compiler) as props passam a ser comparadas, e mesmo assim o filho renderiza se o estado dele ou um contexto lido mudar.
::

::question
#title
Por que `setCount(count + 1)` três vezes seguidas soma só 1?

#default
Porque `count` é o snapshot daquele render. As três chamadas agendam o mesmo valor. A forma com função (`c => c + 1`) entra numa fila e cada atualização recebe o resultado da anterior.
::

::question
#title
Qual a diferença entre render e commit?

#default
Render é o React chamar os componentes e calcular a nova árvore; é puro e pode ser descartado. Commit é aplicar as diferenças no DOM, atualizar refs e rodar layout effects; é síncrono. Um componente pode renderizar sem gerar nenhuma mudança no DOM.
::

::question
#title
Um consumidor de contexto dentro de `React.memo` renderiza quando o contexto muda?

#default
Sim. `memo` compara só props. A mudança de contexto propaga direto para quem lê o contexto, ignorando o memo. Por isso separar contextos e memoizar o `value` importa.
::

::question
#title
Por que separar o contexto de estado do contexto de dispatch?

#default
`dispatch` de `useReducer` tem identidade estável. Componentes que só enviam ações leem apenas o contexto de dispatch, cujo valor nunca muda, e por isso não renderizam quando o estado muda.
::

::question
#title
O que acontece se o reducer fizer `estado.itens.push(item); return estado`?

#default
Retorna a mesma referência, então `Object.is` diz que nada mudou e o React pode pular o render. Pior: no StrictMode o push roda duas vezes. Reducers devem retornar objetos novos sem mutar o recebido.
::

::question
#title
Quando um Web Worker não ajuda?

#default
Quando o trabalho é rápido (o custo de serializar e trocar mensagens supera o ganho), quando precisa do DOM, ou quando o gargalo é renderizar muitos componentes. Neste último caso, `useTransition`, `useDeferredValue` ou virtualização resolvem melhor.
::

::question
#title
Como enviar um token JWT para um endpoint SSE?

#default
`EventSource` não permite headers. As opções são: cookie HttpOnly com `withCredentials: true`, um token de curta duração na query string (cuidado com logs), ou usar `fetch` com leitura de stream e implementar parsing e reconexão (ou usar uma lib como `@microsoft/fetch-event-source`).
::

::question
#title
Por que meu EventSource abre duas conexões em desenvolvimento?

#default
O StrictMode monta, desmonta e monta os efeitos de novo. Se o efeito retorna `() => es.close()`, a primeira conexão é fechada e só a segunda fica. Se você vê duas conexões abertas ao mesmo tempo, falta o cleanup, e isso também vazaria conexões em produção ao navegar.
::

::question
#title
Como o SSE retoma eventos perdidos após uma queda?

#default
Cada evento com `id` atualiza o `lastEventId`. Na reconexão, o navegador envia `Last-Event-ID` no header. O servidor precisa guardar um histórico recente (ou ter IDs consultáveis, como offsets de um log) para reenviar o que veio depois.
::

::question
#title
Qual a diferença entre `useRef` e `useState` para guardar um valor?

#default
Mudar estado agenda um render e o novo valor só aparece no próximo snapshot. Mudar `ref.current` é imediato e não renderiza nada. Se o valor aparece na tela, é estado; se só é usado em handlers e efeitos (ID de timer, instância, flag), é ref.
::

::question
#title
Quando usar `useLayoutEffect` em vez de `useEffect`?

#default
Quando você precisa ler o layout (tamanho, posição) e ajustar algo antes de o navegador pintar, para evitar um "pulo" visível. Ele roda de forma síncrona após o commit e bloqueia o paint, então só use nesses casos.
::

::question
#title
Que problema o `useEffectEvent` resolve?

#default
Ler o valor mais recente de uma prop ou estado dentro de um efeito sem que esse valor vire dependência. Exemplo: notificar respeitando a preferência "mudo" sem reconectar o chat toda vez que ela muda.
::

::question
#title
`useTransition` ou `useDeferredValue`?

#default
Os dois marcam trabalho como não urgente. Use `useTransition` quando você controla o setter e quer o `isPending`. Use `useDeferredValue` quando só tem o valor (veio de props ou de outra lib) e quer que a parte lenta, num filho com `memo`, use uma versão atrasada dele.
::

::question
#title
Por que `use(fetch(url))` num Client Component entra em loop?

#default
Cada render cria uma Promise nova. O componente suspende, quando ela resolve ele renderiza de novo, cria outra Promise e suspende outra vez. A Promise passada para `use` precisa ser estável: vinda de um Server Component, de um cache ou criada fora do render.
::

::question
#title
Como capturar um erro de render?

#default
Com um Error Boundary, que ainda é um componente de classe (`getDerivedStateFromError` + `componentDidCatch`) ou a lib `react-error-boundary`. Ele não pega erros de handlers de evento nem de código assíncrono fora do render; para esses, use `try/catch`. No React 19, `createRoot` também aceita `onUncaughtError` e `onCaughtError` para reportar.
::

::question
#title
Esconder com `<Activity>` ou com renderização condicional?

#default
A condicional desmonta: perde estado e DOM. A Activity esconde com `display: none`, preserva estado e DOM e limpa os efeitos, recriando-os ao mostrar. Use Activity quando o usuário vai voltar àquela UI (abas, sidebar) ou para pré-renderizar a próxima tela.
::

::question
#title
Posso usar o `useId` como key de lista?

#default
Não. Ele gera um ID por instância de componente, para ligar label e input ou atributos ARIA de forma estável entre servidor e cliente. Keys precisam identificar o item dos dados, e por isso devem vir dos próprios dados.
::
