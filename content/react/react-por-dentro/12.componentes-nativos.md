### Fragment

Agrupa elementos sem adicionar nó ao DOM. A forma curta `<>…</>` não aceita props; use `<Fragment key={id}>` em listas. Desde o 19.3, também aceita `ref`.

```jsx [Fragment.jsx]
import { Fragment, useRef, useEffect } from 'react';

function Glossario({ termos }) {
  return <dl>{termos.map(t => (
    <Fragment key={t.id}><dt>{t.nome}</dt><dd>{t.definicao}</dd></Fragment>
  ))}</dl>;
}

function Resultados({ itens }) {
  const grupo = useRef(null);
  useEffect(() => { grupo.current.focus(); }, []);   // foca o primeiro filho focável
  return <Fragment ref={grupo}>{itens.map(i => <a key={i.id} href={i.url}>{i.titulo}</a>)}</Fragment>;
}
```

### StrictMode

Só em desenvolvimento, para a árvore dentro dele: renderiza componentes duas vezes (expõe render impuro), roda setup → cleanup → setup nos efeitos e nos callback refs (expõe cleanup faltando), e avisa sobre APIs depreciadas. Também simula esconder e mostrar com `<Activity>`. Em produção, não faz nada.

### Profiler

::signature
`<Profiler id="Painel" onRender={(id, phase, actualDuration, baseDuration, startTime, commitTime) => …}>`
::

Mede quanto tempo uma subárvore leva para renderizar e reporta a cada commit. `actualDuration` é o tempo do render atual; `baseDuration` estima quanto custaria sem nenhuma memoização. Desativado em produção, a menos que você use o build de profiling. Para investigação manual, o Profiler do DevTools e as Performance Tracks do Chrome (React 19.2) são mais práticos.

### Activity :version[19.2]

::signature
`<Activity mode={'visible' | 'hidden'}>{filhos}</Activity>`
::

Esconder com Activity é diferente de desmontar. O React aplica `display: none`, **preserva o estado e o DOM** (rascunho de um textarea, posição de um vídeo) e **limpa os efeitos**. Ao voltar a `visible`, os efeitos são recriados. Uma Activity que começa escondida ainda renderiza os filhos em baixa prioridade, o que serve para pré-carregar a próxima tela.

```jsx [Activity.jsx]
import { Activity } from 'react';

// Antes: fechar a sidebar desmontava e perdia o estado interno
{mostrarSidebar && <Sidebar />}

// Depois: estado preservado, efeitos pausados enquanto escondida
<Activity mode={mostrarSidebar ? 'visible' : 'hidden'}>
  <Sidebar />
</Activity>

// Abas: a inativa fica pré-renderizada, a troca é instantânea
<Activity mode={aba === 'inbox' ? 'visible' : 'hidden'}><Inbox /></Activity>
<Activity mode={aba === 'enviados' ? 'visible' : 'hidden'}><Enviados /></Activity>
```

::note{type="pitfall" title="Efeitos colaterais do DOM"}
Como o DOM escondido continua existindo, um `<video>` continua tocando. Pause no cleanup de um `useLayoutEffect`, que roda quando a Activity esconde. O mesmo vale para `<audio>` e `<iframe>`.
::

### ViewTransition e addTransitionType :version[19.3]

::signature
`<ViewTransition enter exit update share name>{filhos}</ViewTransition>`
::

Anima elementos que entram, saem, mudam ou "viajam" entre posições usando a View Transition API do navegador. Só anima atualizações feitas em **transições** (`startTransition`, revelação de Suspense, `useDeferredValue`). Por padrão faz cross-fade; você personaliza com classes CSS ou com os eventos `onEnter`, `onExit`, `onUpdate` e `onShare`. Como o navegador tira a "foto" e anima os pseudo-elementos está em [View Transitions](/web#renderizacao-e-animacao), no tomo Web.

```jsx [Carrossel.jsx]
import { ViewTransition, startTransition, addTransitionType } from 'react';

function Carrossel({ slides }) {
  const [i, setI] = useState(0);

  function ir(direcao) {
    startTransition(() => {
      addTransitionType(direcao);             // 'proximo' ou 'anterior'
      setI(n => direcao === 'proximo' ? n + 1 : n - 1);
    });
  }

  return (
    <ViewTransition key={i}
      enter={{ proximo: 'entra-direita', anterior: 'entra-esquerda' }}
      exit={{ proximo: 'sai-esquerda', anterior: 'sai-direita' }}>
      <Slide dados={slides[i]} />
    </ViewTransition>
  );
}
// As classes 'entra-direita' etc. são definidas em CSS com ::view-transition-*
```
