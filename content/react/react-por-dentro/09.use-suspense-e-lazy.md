### use :version[19]

::signature
`const valor = use(promessa | contexto | browser())`
::

`use` lê um **recurso**. Com uma Promise, o componente suspende até ela resolver e o `<Suspense>` mais próximo mostra o fallback; se ela rejeitar, o Error Boundary mais próximo assume. Com um contexto, funciona como `useContext`. Diferente dos outros hooks, **pode ser chamado dentro de `if` e loops**.

```jsx [Comentarios.jsx]
import { use, Suspense } from 'react';

function Comentarios({ comentariosPromise }) {
  const comentarios = use(comentariosPromise);     // suspende até resolver
  return comentarios.map(c => <p key={c.id}>{c.texto}</p>);
}

function Post({ post, comentariosPromise }) {
  return (<>
    <article>{post.corpo}</article>
    <ErrorBoundary fallback={<p>Não foi possível carregar os comentários.</p>}>
      <Suspense fallback={<p>Carregando comentários…</p>}>
        <Comentarios comentariosPromise={comentariosPromise} />
      </Suspense>
    </ErrorBoundary>
  </>);
}

function Titulo({ mostrar }) {
  if (!mostrar) return null;
  const tema = use(TemaContext);                   // condicional: permitido com use
  return <h1 className={tema}>…</h1>;
}
```

::note{type="pitfall" title="A Promise precisa ser estável"}
Não crie a Promise no render de um Client Component (`use(fetch(url))`): cada render cria uma nova, o componente suspende de novo, e você entra em loop. A Promise deve vir de um Server Component, de uma lib de dados que a cacheia, ou ser criada fora do render e guardada. E não envolva `use` em `try/catch`: erros vão para o Error Boundary.
::

### Suspense

::signature
`<Suspense fallback={<Carregando />}>{filhos}</Suspense>`
::

- Se qualquer filho suspender (`use` em Promise, `lazy`, framework com dados), o boundary inteiro mostra o fallback. Use vários boundaries para revelar partes de forma independente, ou um só para revelar juntas.
- Se a atualização que causou a suspensão for uma **transição**, o React mantém a UI antiga na tela em vez de voltar ao fallback.
- Para mostrar o fallback de novo ao trocar de item (ex.: outro perfil), passe uma `key` ao conteúdo.
- No servidor, Suspense permite **streaming**: o HTML do fallback sai primeiro e o conteúdo chega depois.

### lazy

::signature
`const Comp = lazy(() => import('./Comp'))`
::

```jsx [lazy.jsx]
import { lazy, Suspense } from 'react';

// Sempre no topo do módulo, nunca dentro de um componente (perderia o estado a cada render)
const Editor = lazy(() => import('./EditorMarkdown'));  // precisa de export default

function Pagina({ editando }) {
  return editando
    ? <Suspense fallback={<p>Carregando editor…</p>}><Editor /></Suspense>
    : <Preview />;
}
```

Por baixo, `lazy` é um `import()` dinâmico: o bundler separa o componente num arquivo próprio. Prioridades de download, `modulepreload` e `prefetch` estão em [Carregamento de recursos](/web#carregamento-de-recursos), no tomo Web.

### Error Boundaries

Ainda não existe hook para capturar erros de render. Um Error Boundary é um **componente de classe** com `static getDerivedStateFromError` (para mostrar o fallback) e `componentDidCatch` (para logar). Na prática, use a biblioteca `react-error-boundary`. Ele não captura erros em handlers de eventos nem em código assíncrono fora do render; esses você trata com `try/catch`.

```jsx [ErrorBoundary.jsx]
class ErrorBoundary extends React.Component {
  state = { erro: null };
  static getDerivedStateFromError(erro) { return { erro }; }
  componentDidCatch(erro, info) { reportar(erro, info.componentStack); }
  render() {
    return this.state.erro ? this.props.fallback : this.props.children;
  }
}
```

### cache e cacheSignal (Server Components)

`cache(fn)` memoiza uma função por argumentos **durante uma requisição** no servidor: várias partes da árvore chamam `getUsuario(id)` e a busca acontece uma vez. `cacheSignal()` devolve um `AbortSignal` que aborta quando o render termina (com sucesso, erro ou cancelamento), para cancelar trabalho que ninguém vai usar. No cliente, ele retorna `null`.

```js [dados.server.js]
import { cache, cacheSignal } from 'react';

export const getUsuario = cache(async (id) => {
  const res = await fetch(`https://api.exemplo.com/usuarios/${id}`, { signal: cacheSignal() });
  return res.json();
});
```

### browser() :version[19.3]

Do `react-dom`, usado com `use`: no servidor ele suspende (o fallback vai para o HTML) e no cliente não. Substitui o padrão antigo de `const [montado, setMontado] = useState(false)` + efeito para conteúdo que só faz sentido no navegador.

```jsx [FusoHorario.jsx]
import { Suspense, use } from 'react';
import { browser } from 'react-dom';

function FusoHorario() {
  use(browser());   // só renderiza no navegador
  return <p>{Intl.DateTimeFormat().resolvedOptions().timeZone}</p>;
}

// <Suspense fallback="…"><FusoHorario /></Suspense>
```
