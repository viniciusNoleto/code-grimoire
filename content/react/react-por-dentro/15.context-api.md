Context resolve **prop drilling**: disponibilizar um valor para qualquer descendente sem passar por cada nível. Ele é um mecanismo de *injeção de dependência*, não um gerenciador de estado. O estado continua vivendo em um `useState` ou `useReducer` no Provider; o contexto só transporta.

```jsx [AuthContext.jsx]
import { createContext, useContext, useMemo, useState, useCallback } from 'react';

// undefined como default para detectar uso fora do Provider
const AuthContext = createContext(undefined);

export function AuthProvider({ children }) {
  const [usuario, setUsuario] = useState(null);

  const entrar = useCallback(async (email, senha) => {
    const u = await api.login(email, senha);
    setUsuario(u);
  }, []);
  const sair = useCallback(() => setUsuario(null), []);

  // useMemo: sem ele, todo render do Provider cria um objeto novo
  // e TODOS os consumidores renderizam.
  const value = useMemo(() => ({ usuario, entrar, sair }), [usuario, entrar, sair]);

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
  // React 19: <AuthContext value={value}>{children}</AuthContext>
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (ctx === undefined) throw new Error('useAuth precisa estar dentro de <AuthProvider>');
  return ctx;
}
```

### A regra de re-render do contexto

Quando o `value` do Provider muda (por `Object.is`), **todo componente que lê aquele contexto renderiza**, mesmo que use só uma parte do valor, e mesmo que esteja dentro de `React.memo`. Não existe seletor nativo. Na bancada do capítulo 3, a caixa `Consumidor` é memoizada e ainda assim acende ao alternar o tema.

### Padrões para não pagar caro

- **Memoize o value** (exemplo acima). Valor inline `value={{ a, b }}` é o erro mais comum.
- **Separe estado de ações.** Um contexto para o estado e outro para `dispatch`/funções. Componentes que só disparam ações (botões) nunca renderizam quando o estado muda, porque `dispatch` tem identidade estável.
- **Separe por frequência de mudança.** Tema e usuário mudam raramente; posição do mouse ou cotações mudam muito. Misturar os dois no mesmo contexto faz tudo renderizar no ritmo do mais rápido.
- **Mantenha o Provider perto de quem usa.** Nem todo contexto precisa estar na raiz.
- **Para estado global de alta frequência**, prefira uma store externa com seletores (Zustand, Redux, Jotai) ou `useSyncExternalStore`.

```jsx [contextos-separados.jsx]
const CarrinhoEstado = createContext(null);
const CarrinhoDispatch = createContext(null);

export function CarrinhoProvider({ children }) {
  const [estado, dispatch] = useReducer(carrinhoReducer, estadoInicial);
  return (
    <CarrinhoDispatch.Provider value={dispatch}>   {/* dispatch é estável */}
      <CarrinhoEstado.Provider value={estado}>
        {children}
      </CarrinhoEstado.Provider>
    </CarrinhoDispatch.Provider>
  );
}

export const useCarrinho = () => useContext(CarrinhoEstado);
export const useCarrinhoDispatch = () => useContext(CarrinhoDispatch);

// <BotaoAdicionar> só usa dispatch → não renderiza quando o carrinho muda
```

::note{type="note" title="React 19"}
`use(Contexto)` lê um contexto como `useContext`, mas pode ser chamado dentro de `if` e loops. E o próprio objeto de contexto pode ser usado como Provider: `<ThemeContext value="dark">`.
::
