O navegador oferece vários lugares para guardar dados, com APIs, limites e garantias bem diferentes.

| Mecanismo | API | Tamanho | Uso |
| --- | --- | --- | --- |
| Cookies | síncrona, string | \~4 KB cada | Sessão. Vão em toda requisição: mantenha pequenos. |
| `localStorage` | síncrona, string | \~5 MB | Preferências pequenas. Bloqueia a main thread; indisponível em Workers. |
| `sessionStorage` | síncrona, string | \~5 MB | Estado por aba, apagado ao fechá-la. |
| IndexedDB | assíncrona, objetos, índices, transações | grande (fração do disco) | Dados offline, filas, caches estruturados. Funciona em Workers. |
| Cache API | assíncrona, pares Request/Response | grande | Respostas HTTP, normalmente via Service Worker. |
| OPFS | sistema de arquivos privado da origem | grande | Arquivos binários; acesso síncrono rápido em Workers (SQLite em WASM usa isso). |

```js [storage.js]
// Quanto espaço tenho e posso pedir que não seja apagado?
const { usage, quota } = await navigator.storage.estimate();
const persistente = await navigator.storage.persist();   // o navegador pode negar

// IndexedDB fica bem mais simples com um wrapper como "idb"
const db = await openDB('loja', 1, {
  upgrade(db) { db.createObjectStore('rascunhos', { keyPath: 'id' }).createIndex('porData', 'atualizadoEm'); },
});
await db.put('rascunhos', { id: 'pedido-1', itens, atualizadoEm: Date.now() });
const recentes = await db.getAllFromIndex('rascunhos', 'porData');
```

::note{type="pitfall" title="Nada é garantido"}
Armazenamento não persistente pode ser apagado pelo navegador sob pressão de espaço. O Safari remove dados de sites não visitados há 7 dias (exceto PWAs instalados). Janelas privadas apagam tudo ao fechar. Trate o armazenamento local como cache, com o servidor como fonte da verdade. E nunca guarde tokens de sessão em `localStorage`: qualquer XSS os lê.
::
