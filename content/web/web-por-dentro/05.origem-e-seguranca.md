Todo o modelo de segurança do navegador gira em torno de uma pergunta: de qual **origem** veio este código, e o que ele pode ler de outras?

### Same-origin policy

Uma **origem** é a tripla esquema + host + porta: `https://app.loja.com:443`. Scripts de uma origem não podem ler respostas, DOM ou armazenamento de outra. Já **site** é mais amplo (esquema + domínio registrável: `loja.com`), e é o que importa para cookies `SameSite`. `app.loja.com` e `api.loja.com` são origens diferentes, mas o mesmo site.

### CORS

CORS é o mecanismo pelo qual um servidor **autoriza** outra origem a ler suas respostas. Ele não protege o servidor: a requisição chega e é executada mesmo assim. O que o navegador bloqueia é o JavaScript de ler a resposta.

- **Requisição simples** (GET/HEAD/POST com cabeçalhos e `Content-Type` básicos): vai direto; o navegador verifica `Access-Control-Allow-Origin` na resposta.
- **Preflight**: qualquer outra coisa (`PUT`, `Content-Type: application/json`, `Authorization`) dispara antes um `OPTIONS` perguntando se pode. Cacheie com `Access-Control-Max-Age`.
- **Com credenciais** (`credentials: 'include'`): o servidor precisa responder a origem exata (não `*`) e `Access-Control-Allow-Credentials: true`.

```http [preflight]
→ OPTIONS /api/pedidos
  Origin: https://app.loja.com
  Access-Control-Request-Method: PUT
  Access-Control-Request-Headers: content-type, authorization

← 204 No Content
  Access-Control-Allow-Origin: https://app.loja.com
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE
  Access-Control-Allow-Headers: content-type, authorization
  Access-Control-Allow-Credentials: true
  Access-Control-Max-Age: 600
  Vary: Origin
```

### Cookies

```http [Set-Cookie]
Set-Cookie: __Host-sessao=abc123; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=604800
```

| Atributo | Efeito |
| --- | --- |
| `HttpOnly` | Invisível ao JavaScript: um XSS não consegue ler o cookie. |
| `Secure` | Só em HTTPS. |
| `SameSite=Lax` (padrão dos navegadores) | Não vai em requisições cross-site, exceto navegação de topo com GET (clicar num link). Protege contra a maioria dos CSRF. |
| `SameSite=Strict` | Nunca em cross-site, nem clicando num link vindo de outro site. |
| `SameSite=None` | Vai sempre (exige `Secure`). Para embeds e integrações cross-site. |
| `Partitioned` (CHIPS) | Cookie de terceiro isolado por site de topo, compatível com o bloqueio de cookies de terceiros. |
| Prefixo `__Host-` | Obriga `Secure`, `Path=/` e nenhum `Domain`: um subdomínio comprometido não consegue sobrescrevê-lo. |

### XSS e Content Security Policy

XSS é conseguir executar JavaScript na sua origem: o script roubado age como o usuário. A defesa principal é **nunca inserir dados como HTML** (`textContent` em vez de `innerHTML`). Frameworks escapam por padrão; as exceções são justamente as portas de entrada: [`v-html` no Vue](/vue#template-e-diretivas) e [`dangerouslySetInnerHTML` no React](/react#react-dom). A segunda camada é a **CSP**, que diz ao navegador de onde scripts podem vir.

```http [CSP estrita]
Content-Security-Policy:
  script-src 'nonce-R4nd0m' 'strict-dynamic';   # só scripts com o nonce desta resposta
  object-src 'none';
  base-uri 'none';
  frame-ancestors 'self';                        # impede clickjacking (substitui X-Frame-Options)
  require-trusted-types-for 'script';            # Trusted Types: innerHTML só aceita valores sanitizados
```

Comece com `Content-Security-Policy-Report-Only` para descobrir o que quebraria antes de aplicar.

### CSRF

CSRF é outro site fazer o navegador do usuário enviar uma requisição autenticada para o seu (um formulário que posta para `/transferir`). Defesas, em camadas: `SameSite=Lax` ou `Strict`; verificar `Origin` ou `Sec-Fetch-Site` em requisições que alteram estado; token anti-CSRF em formulários; nunca alterar estado em GET.

### Outros cabeçalhos de segurança

| Cabeçalho | Para quê |
| --- | --- |
| `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` | HSTS: só HTTPS, mesmo se o usuário digitar http://. |
| `X-Content-Type-Options: nosniff` | Não "adivinhar" o tipo do arquivo. |
| `Referrer-Policy: strict-origin-when-cross-origin` | Não vazar caminhos e query strings para outros sites. |
| `Permissions-Policy: camera=(), geolocation=(self)` | Restringe APIs poderosas, inclusive em iframes. |
| `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp` | Isolamento cross-origin: habilita `SharedArrayBuffer` e timers de alta precisão. |
| `Cross-Origin-Resource-Policy: same-site` | Impede que outros sites embutam seus recursos. |

**Subresource Integrity** (`<script src="…" integrity="sha384-…" crossorigin>`) garante que um arquivo de CDN não foi alterado.
