JavaScript roda numa thread com uma **pilha de chamadas**. Tudo que é assíncrono (timers, rede, eventos) é tratado colocando callbacks em **filas**. O event loop repete, para sempre:

1. Pega **uma task** (macrotask) da fila: um evento de clique, um `setTimeout`, uma mensagem de `postMessage`, o parse de um script.
2. Executa até a pilha esvaziar.
3. Esvazia a fila de **microtasks inteira**: callbacks de Promise (`then`, `await`), `queueMicrotask`, `MutationObserver`. Microtasks criadas aqui também rodam antes de seguir.
4. Se for hora de um frame (\~16,7 ms a 60 Hz): roda os `requestAnimationFrame`, recalcula estilo e layout, pinta.
5. Se sobrar tempo antes do próximo frame: `requestIdleCallback`.

::note{type="pitfall" title="Microtasks podem travar a página"}
Como a fila de microtasks é esvaziada por completo antes de renderizar, uma Promise que agenda outra Promise em loop congela a página tanto quanto um `while (true)`. Já um `setTimeout(fn, 0)` em loop deixa o navegador renderizar entre uma task e outra.
::

::note{type="tip" title="Nos frameworks"}
O Vue agenda o re-render numa **microtask** (é isso que o [`nextTick`](/vue#como-a-reatividade-funciona) espera). O React agrupa as atualizações do mesmo tick num render só ([batching](/react#como-o-estado-funciona)) e torna o próprio render interrompível com [transições](/react#performance).
::

### Long tasks e como dividi-las

Qualquer task acima de **50 ms** é uma *long task*: durante ela, cliques e teclas esperam. Para trabalho pesado na main thread, quebre em pedaços e devolva o controle ao navegador entre eles:

```js [ceder.js]
async function processarTudo(itens) {
  for (let i = 0; i < itens.length; i++) {
    processar(itens[i]);
    if (i % 200 === 0) await ceder();   // deixa o navegador tratar eventos e pintar
  }
}

// scheduler.yield() (Chromium e Firefox): retoma com prioridade sobre outras tasks
const ceder = () => globalThis.scheduler?.yield
  ? scheduler.yield()
  : new Promise(r => setTimeout(r, 0));

// Prioridades explícitas
scheduler.postTask(() => enviarAnalytics(), { priority: 'background' });
requestIdleCallback((deadline) => { while (deadline.timeRemaining() > 1) fazerAlgo(); });
```

Se o trabalho não depende do DOM, a solução melhor é tirá-lo da main thread com um Web Worker ([capítulo 06](#web-workers)).
