Depois que o DOM existe, cada mudança passa de novo por parte do pipeline do [capítulo 01](#como-o-navegador-funciona). Ficar rápido é fazer o navegador refazer o mínimo possível.

### Layout thrashing

Ler uma propriedade geométrica (`offsetHeight`, `getBoundingClientRect()`) depois de alterar estilos obriga o navegador a calcular o layout **na hora** (*forced synchronous layout*). Fazer isso num loop recalcula o layout a cada volta.

```js [thrashing.js]
// ❌ lê, escreve, lê, escreve: um layout por item
cards.forEach(c => { c.style.height = c.offsetWidth * 0.75 + 'px'; });

// ✅ todas as leituras, depois todas as escritas: um layout só
const larguras = cards.map(c => c.offsetWidth);
cards.forEach((c, i) => { c.style.height = larguras[i] * 0.75 + 'px'; });

// Escritas visuais que dependem de leituras: agrupe num requestAnimationFrame
requestAnimationFrame(() => aplicarPosicoes());
```

::note{type="tip" title="Nos frameworks"}
Medir o DOM antes da pintura é o caso de [`useLayoutEffect` no React](/react#efeitos); no Vue, a medição vai em [`onMounted`/`onUpdated` ou depois de `nextTick`](/vue#ciclo-de-vida).
::

### Animar sem travar

- **`transform` e `opacity`** podem ser animados só pelo compositor, fora da main thread: continuam suaves mesmo com JavaScript ocupado. Animar `top`, `width` ou `margin` refaz layout em todo frame.
- **`will-change: transform`** promove o elemento para uma camada própria antes da animação. Use com parcimônia: cada camada consome memória de GPU.
- **Web Animations API** (`el.animate(keyframes, { duration })`) dá o desempenho das animações CSS com controle via JavaScript (pausar, inverter, aguardar `finished`).
- **`prefers-reduced-motion`**: reduza ou remova animações para quem pediu.

### Contenção

```css [contencao.css]
.card { contain: layout paint; }          /* mudanças aqui dentro não afetam o resto da página */
.secao-longa {
  content-visibility: auto;                /* não renderiza o que está fora da tela */
  contain-intrinsic-size: auto 800px;      /* tamanho estimado para a barra de rolagem não pular */
}
```

### View Transitions

A **View Transition API** anima a passagem entre dois estados da página. O navegador tira uma "foto" do estado antigo, você atualiza o DOM, e ele anima entre a foto e o novo estado; elementos com o mesmo `view-transition-name` se transformam um no outro. Funciona dentro da mesma página (`document.startViewTransition`) e, em navegadores que suportam, entre páginas de um site de várias páginas com `@view-transition { navigation: auto; }`.

```js [view-transition.js]
function abrirProduto(id) {
  if (!document.startViewTransition) return renderizarProduto(id);    // sem suporte: só atualiza
  document.startViewTransition(() => renderizarProduto(id));
}
// CSS: .foto-produto { view-transition-name: foto; }  → a miniatura "voa" até a foto grande
// ::view-transition-old(root), ::view-transition-new(root) { animation-duration: .25s; }
```

::note{type="tip" title="Nos frameworks"}
O React tem o componente [`<ViewTransition>`](/react#componentes-nativos); no Vue, a transição se faz com [`startViewTransition` e `nextTick`](/vue#componentes-embutidos), e as animações de entrada e saída com `<Transition>`.
::
