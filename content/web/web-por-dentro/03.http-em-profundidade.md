Toda conversa entre o navegador e o servidor é uma requisição e uma resposta HTTP. O método diz a intenção, o código de status diz o resultado e os cabeçalhos dizem como tratar o corpo.

### Métodos e semântica

| Método | Seguro | Idempotente | Uso |
| --- | --- | --- | --- |
| `GET` | sim | sim | Ler. Cacheável. Nunca altere estado num GET (crawlers e prefetch o chamam). |
| `HEAD` | sim | sim | Como GET, só cabeçalhos. |
| `OPTIONS` | sim | sim | Capacidades; usado no preflight de CORS. |
| `POST` | não | não | Criar, ações. Repetir pode duplicar: use uma *Idempotency-Key* em pagamentos. |
| `PUT` | não | sim | Substituir o recurso inteiro. |
| `PATCH` | não | depende | Alterar parte do recurso. |
| `DELETE` | não | sim | Remover. |

**Idempotente** significa que repetir a mesma requisição tem o mesmo efeito que fazê-la uma vez. Isso decide se é seguro tentar de novo após um timeout.

### Códigos de status que importam

| Código | Significado |
| --- | --- |
| `200` / `201` / `204` | OK / criado (com `Location`) / sem corpo. |
| `206` | Conteúdo parcial (requisições com `Range`: vídeo, downloads retomáveis). |
| `301` / `308` | Movido permanentemente (308 preserva o método). |
| `302` / `303` / `307` | Redirecionamento temporário (303 força GET, ideal após POST; 307 preserva o método). |
| `304` | Não modificado: use sua cópia em cache. |
| `400` / `422` | Requisição malformada / bem formada mas inválida. |
| `401` / `403` | Não autenticado / autenticado mas sem permissão. |
| `404` / `410` | Não existe / existia e foi removido. |
| `409` / `412` | Conflito de estado / precondição falhou (`If-Match`). |
| `429` | Muitas requisições; respeite `Retry-After`. |
| `500` / `502` / `503` / `504` | Erro interno / proxy recebeu resposta ruim / indisponível / proxy esperou demais. |

### HTTP/1.1, HTTP/2 e HTTP/3

|  | HTTP/1.1 | HTTP/2 | HTTP/3 |
| --- | --- | --- | --- |
| Transporte | TCP | TCP | QUIC sobre UDP |
| Requisições por conexão | uma de cada vez (navegadores abrem \~6 por origem) | muitas, multiplexadas | muitas, multiplexadas |
| Bloqueio por perda de pacote | na conexão | um pacote perdido trava todos os streams (head-of-line no TCP) | só o stream afetado |
| Cabeçalhos | texto, repetidos | comprimidos (HPACK) | comprimidos (QPACK) |
| Handshake | TCP + TLS | TCP + TLS | combinado; 0-RTT em reconexões; sobrevive a troca de rede (Wi-Fi → 4G) |

Com HTTP/2 e 3, truques da era HTTP/1 viram contraproducentes: *domain sharding*, concatenar tudo num arquivo enorme e sprites. Muitos arquivos pequenos e bem cacheados funcionam bem.

### Compressão e negociação

O cliente anuncia o que aceita (`Accept-Encoding: gzip, br, zstd`; `Accept-Language`; `Accept`) e o servidor responde com `Content-Encoding` e, se a resposta varia conforme esses cabeçalhos, `Vary`. Brotli comprime melhor que gzip para texto; zstd é rápido e já tem suporte amplo. Imagens e vídeos já são comprimidos: não comprima de novo.
