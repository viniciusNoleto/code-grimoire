Um Service Worker é um Worker que se registra para uma origem e um escopo e passa a **interceptar todas as requisições** das páginas nesse escopo, como um proxy programável dentro do navegador. Ele continua existindo sem abas abertas (o navegador o acorda para eventos e o desliga quando ocioso). Exige HTTPS (exceto em localhost).

### Ciclo de vida

1. **register**: a página chama `navigator.serviceWorker.register('/sw.js')`.
2. **install**: a hora de pré-carregar arquivos no Cache API.
3. **waiting**: se já existe um SW ativo controlando abas, o novo espera todas fecharem (para não misturar versões). `self.skipWaiting()` pula a espera.
4. **activate**: a hora de apagar caches antigos. `clients.claim()` assume as abas já abertas.
5. **fetch**, **push**, **sync**, **message**: eventos que ele trata dali em diante.

```js [sw.js]
const VERSAO = 'v42';
const ESSENCIAIS = ['/', '/offline.html', '/assets/app.4f9e1c.js', '/assets/app.8a1d.css'];

self.addEventListener('install', (e) => {
  e.waitUntil(caches.open(VERSAO).then(c => c.addAll(ESSENCIAIS)));
});

self.addEventListener('activate', (e) => {
  e.waitUntil(caches.keys().then(chaves =>
    Promise.all(chaves.filter(k => k !== VERSAO).map(k => caches.delete(k)))
  ));
});

self.addEventListener('fetch', (e) => {
  const url = new URL(e.request.url);
  if (e.request.mode === 'navigate') {
    // Páginas: rede primeiro, cache como reserva, página offline por último
    e.respondWith(fetch(e.request).catch(async () =>
      (await caches.match(e.request)) ?? caches.match('/offline.html')));
  } else if (url.pathname.startsWith('/assets/')) {
    // Assets com hash: cache primeiro
    e.respondWith(caches.match(e.request).then(r => r ?? fetch(e.request)));
  }
  // o resto segue para a rede normalmente
});
```

| Estratégia | Como funciona | Bom para |
| --- | --- | --- |
| Cache first | Cache; rede só se não houver. | Assets versionados, fontes. |
| Network first | Rede; cache se falhar. | HTML, dados que devem estar atuais. |
| Stale-while-revalidate | Responde do cache e atualiza em segundo plano. | Avatares, dados que toleram atraso. |
| Network only / cache only | Sem fallback. | Pagamentos / app totalmente offline. |

### PWA

- **Web App Manifest** (`<link rel="manifest">`): nome, ícones, cores, `display: standalone`. Junto com um Service Worker, permite instalar o site como app.
- **Push**: `PushManager.subscribe()` com chaves VAPID; o servidor envia pelo serviço de push do navegador e o SW mostra a notificação mesmo com o site fechado. No iOS, só para PWAs instalados.
- **Background Sync**: adia uma requisição até haver conexão (suporte limitado a Chromium).
- **Navigation preload**: o navegador começa a requisição da página enquanto o SW acorda, evitando o atraso de inicialização.

::note{type="pitfall" title="Armadilhas"}
Um bug no Service Worker pode deixar usuários presos numa versão velha. Nunca sirva o próprio `sw.js` com cache longo, tenha um plano para desregistrar (`registration.unregister()`) e teste o fluxo de atualização. Ferramentas como Workbox implementam as estratégias com menos risco.
::
