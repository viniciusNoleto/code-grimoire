Três métricas, medidas em usuários reais no percentil 75, que o Google usa para avaliar a experiência de uma página:

| Métrica | Mede | Bom | Causas comuns de nota ruim |
| --- | --- | --- | --- |
| **LCP** (Largest Contentful Paint) | Quando o maior elemento visível (imagem de destaque, título) aparece. | ≤ 2,5 s | Servidor lento (TTFB), imagem de destaque descoberta tarde ou com `loading="lazy"`, CSS e JS bloqueantes, renderização só no cliente. |
| **INP** (Interaction to Next Paint) | A demora entre uma interação e a próxima pintura, na pior interação da visita. | ≤ 200 ms | Long tasks, handlers pesados, hidratação, re-renders grandes, layout thrashing. |
| **CLS** (Cumulative Layout Shift) | Quanto o conteúdo pula sem o usuário pedir. | ≤ 0,1 | Imagens sem dimensões, anúncios e embeds injetados, fontes que trocam de tamanho, banners inseridos no topo. |

Métricas de apoio: **TTFB** (tempo até o primeiro byte) e **FCP** (primeira pintura de conteúdo). O INP substituiu o FID em 2024 porque mede todas as interações, não só a primeira.

```js [medir.js]
// Em produção (RUM): a biblioteca web-vitals usa as APIs abaixo e trata os casos difíceis
import { onLCP, onINP, onCLS } from 'web-vitals';
onINP(({ value, attribution }) => enviar('inp', value, attribution.interactionTarget));

// Por baixo: PerformanceObserver
new PerformanceObserver((lista) => {
  for (const e of lista.getEntries()) console.log('LCP', e.startTime, e.element);
}).observe({ type: 'largest-contentful-paint', buffered: true });

new PerformanceObserver((lista) => {
  for (const e of lista.getEntries()) if (e.duration > 50) console.log('long task', e.duration);
}).observe({ type: 'longtask', buffered: true });   // 'long-animation-frame' dá mais detalhes

// Marcar e medir trechos do seu código
performance.mark('filtro-inicio'); aplicarFiltro(); performance.mark('filtro-fim');
performance.measure('filtro', 'filtro-inicio', 'filtro-fim');
```

**Dados de laboratório** (Lighthouse, aba Performance do DevTools) ajudam a investigar; **dados de campo** (RUM, relatório CrUX) dizem o que os usuários de verdade vivem, em celulares lentos e redes ruins.
